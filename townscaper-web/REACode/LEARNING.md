## 新文件

**`src/lighting.js`** —— 把 `townmesh.js#bakeLighting` 里那份私有栅格抽出来，变成任意多份体素集共用的一层：

| 导出 | 作用 |
|---|---|
| `buildVoxelField({ grid, levelHeight, sets:[{town, cells?, y?, colorOf?}], res, pad, blurRadius })` | 每份 set 一个 `y` 偏移（台地上的房子就是 `y = 台地顶`）。所有 set 栅格进同一组层 → 一次可分离盒式模糊（两遍≈高斯）|
| `field.sample/sampleOcc/sampleBounce(x,y,z)` | XZ 双线性 + 层间线性 |
| `field.texture()` | RGBA float `DataTexture`，层当行堆（层 l 占 `[l*H,(l+1)*H)`），一次上传 |
| `field.sliceCanvas(layer)` | 调试：某一层的占用footprint，透明表示空 |
| `bakeVertexAO(field, pos, col)` | CPU 路径（等价于原来 TownMesh 的做法），读的是同一份场 |
| `patchMaterial(mat, uniforms)` | GPU 路径：`#include <color_vertex>` 后乘 `ao + bounce*avgColor*occ`，两套数学完全一致 |

**`src/terrainmesh.js`** —— 地形就是 `Town` 的列，不是另一套高度图：

- 一格落差：两侧共用同一条棱高（`edgeY = t+1`，角取两条棱的 max）→ 低格抬边做成坡。**这里踩过一个坑**：第一版角高取相邻两棱的**平均**，于是同一格角在相邻两格里算出 1.5 / 2.5，接缝裂开、草地里能看见海。改成 max 之后两边算出来一样，缝就没了。
- 两格以上落差：垂直崖面，按层做色差（层积岩感）。
- 水面一侧（邻格为空 / 网格边缘）永远是挡土墙，不会误判成坡。
- 材质：平顶草、坡面草（`1063115611289645057`"grass on slopes to make navigability easier to read"）、一级沙滩、崖面石。

**`src/fusion.js` + `fusion.html`** —— 第 7 步的场景：

- 同一张 `quadgrid`；噪声高度量化成体素列 → 台地（TERRACE=3，可建）+ 沙滩（1）+ 两处坡道（`TERRACE-1`）+ 外圈低岩台。
- 房子用**没改过一行**的 `TownMesh`，整块 `position.y = TERRACE*levelHeight` 抬到台地顶（简化：只有一级可建台地）。
- 岸浪 `buildShore(land, ...)` 只看地块那一份 Town。
- AO 来自一个 `buildVoxelField({ sets:[{land,y:0},{town,y:1.5}] })`，**两个 material 共用一个 uniforms 对象**，在顶点着色器里采样。

## 补记 15:50 · soft-slope 裂缝（修 `src/terrainmesh.js`）

融合场景（`fusion.html`）落地后做截图检查，发现草坡和崖面上一片片**青色三角** —— 海面从地形缝里透出来。

- **量化**：从画框边缘泛洪标出"外面那片海"，剩下的海色像素就是洞：**1369 px / 9 个 ≥20px 碎块**（容差 ±8）。
  注：第一次用的容差是 ±14，把蓝色墙面也算成了海（2065 px），后面统一改成 ±8。
- **根因**：格角高度是"每格自己算"的（棱高取两侧 max、角取两条棱 max）。这在**棱**上自洽，但一个顶点常被两三个
  等高格共用 —— 软坡只抬"该抬的那条棱"，其余格子不抬，于是同一个顶点得到两套高度。直接量出来：**912 个顶点里 84 个冲突，
  最大差 2 层（1.0 世界单位）**。
- **修法**：高度改成**按顶点存**（`Map<point, y>`，`y(v) = max over 共用它的格子`，抬角封顶 `t+1`），所有格子读同一个值；
  墙顶从平的 `t*L` 改成**跟两个端点的角点高度走**（梯形），否则抬起的角悬空。
- **踩到的第二个坑**：为了保险把补墙判据改成"这条棱上还有没盖住的高度"，结果**等高格互相补一遍墙**，两块面片重合 →
  z-fighting，画面上是一条条虚线黑边。判据必须还是"邻居比我低"。
- **结果**：洞 **1369 → 115 px**，≥20px 的碎块 **9 → 1**；面数 1046、三角 2092 **不变**（纯顶点高度修正，没有多画几何）。

## 补记 17:00 · SDF 距离场 + 6 方向光体积（把「还没做」里的两张图补上）

上一节末尾写"不是真 SDF 体积、没有光体积"。这一节把它们做了出来 —— 原文那条帖子本来就是**三张图**：

> "1st texture here is an **sdf volume**. The distance lives in the alpha… 2nd is a **baked 6 directional
> light volume**, raycast against the sdf, sampling the mega texture using the UVs where it hits the sdf.
> 3rd is the lit mega texture"

现在对上了两张，第三张（mega texture 的 UV 反查）仍然缺，因为我们的墙只有投影 UV、没有 unwrap。

**① SDF 体积 —— `buildSDF(field, {stride:3})`**
- 在体素场上做 3D chamfer 距离变换，存"到最近实心格的距离"（世界单位）。
- **两个坑**：栅格是各向异性的（水平 0.08 / 竖直 0.5，差 6 倍），所以代价必须按世界单位算，
  否则竖直方向被低估、球体追踪会一头撞进地板；另外只在**降采样**（0.24）上建 ——
  细格 171k × 26 邻居 × 2 遍 = 9M 次，每次重建都做不值；粗格 19k 格只要 **6.9ms**。
- 有了距离场，`bakeRayBounce` 改成**球体追踪**：一步跳 `min(0.35, 0.6·d)`。
  于是同样开销能走 **2.0 → 4.0** 世界单位（实测 13.6ms，比固定步长版 8.6ms 只贵一点，
  却多走一倍距离）。跳跃上限 0.35 是保险：粗距离场在薄墙处会高估，0.8·d 会直接穿过去。

**② 6 方向光体积 —— `bakeSixDirVolume(field)` + `bakeVertexLight6(field, pos, col)`**
- 对每个粗格 × 6 个轴向各打一条射线（同样用 SDF 跳），打中就把命中处的墙色按 `1/(1+0.6d)` 存进体积。
- 顶点采样时按 `n·axis` 加权求和 —— 这就是原文的"6 directional light volume"。
- 为什么值得换成体积：逐三角形打射线时，同一面墙上不同三角形各自采样，反弹量在三角形边界跳变，
  放大看是一块块色阶；烘进体积后顶点做**三线性**，得到连续梯度（原文用体积就是这个原因）。

**量到的**（index.html，900×640，demo 城，三角 10,994 不变）
| 版本 | 命中 | 耗时 | 相对"关"的屏幕变化 |
|---|---|---|---|
| 逐三角形打射线（SDF 球体追踪 reach 4.0） | 6,536 三角 | 13.6ms + SDF 7ms | 39.3% 像素 / 平均 3.97 |
| **6 方向光体积**（43×8×56 ×6 向）+ 顶点三线性 | 13,314 条射线 | **37.5ms** + 采样 5.4ms | 30.5% 像素 / 平均 4.11 |
| 两者互相 | — | — | **32.5%** 像素 / 平均 3.49（确实不是同一个东西） |

**结论 / 取舍**：体积版**更平滑但贵一倍**（43ms vs 20ms），所以 `raybounce` 默认仍然是关的，
`townMesh.rayVolume = true` 时走体积、`false` 时走逐三角形（留作对照）。真要在产品里用，
应该把体积烘到 GPU（原文就是烘进贴图）。

**没做的**（仍然如实）：mega texture 的 UV 反查；半球积分的球谐近似；风场（本场景没有消费者）。

**补的那一条：脏区增量**
问题原话（三处文档都写着）："整张场每次重建都重烤（3.4 + 13.5ms），没做脏区增量"。

做法（`src/lightingcache.js` + `lighting.js` 里两个小钩子）：

1. `buildVoxelField({ keepRaw })` 多留一份**未模糊底片**；
2. 每格记两个东西：**签名**（top + 逐层实心位 + 颜色）和**它刷过的 texel 下标**；
3. 重建时比对签名，只对改动格"擦掉旧印章 → 重刷新印章"；
4. 只重模糊 **rect ± R·P** 那一条砖；`reblurRect()` 的窗口再往外留一圈 R·P，让卷积核完整。

**为什么这是"同一个算术"而不是近似**：可分离箱式模糊 P 遍、半径 R，最多只读 P·R 个 texel。
把窗口放大到 rect ± 2·R·P 之后，凡是碰到 rect 的卷积核都完整落在窗口内，窗口边缘的 clamp 只影响我们不写回的地方。

**踩的坑（这个必须记）**：第一版窗口只留一圈 R·P、也只写回 rect 本身，结果 **497 个 texel 与全量重烤不一致**，
最差的一个正好在 `j1+1`——改动的影响范围是 rect ± R·P，写回范围必须跟着放大，否则外面那一圈停在旧值。

**验收数字**

### 落地 1：`src/patchblend.js` —— 无缝 patch 混合

三个 patch 故意重叠：水 `elev<水线`、陆 `elev>水线`、岸带 `|有符号距离 sd| ≤ 14px`；
重叠区按**各自高度**排序，只混前两名，权重 = `smoothstep((h1-h2)/band)`，`band=0.018` 是**高度单位**不是像素。

| 合成模式 | 跨边界一像素跳跃 | 边界带梯度（纹理细节） | 细节留存 | seam 能量比 | 过渡带宽 |
|---|---|---|---|---|---|
| `hard` 硬切 | **0.2643** | 0.0412 | 100% | 3.17 | 1px |
| `alpha` 覆盖到的全平均 | 0.1074（−59%） | **0.0230** | **56%** | 1.81 | 无（整片糊） |
| `height` 按高度混前两名 | **0.0504（−81%）** | 0.0332 | **81%** | 2.55 | 2.5px |

**这张表是本轮最想给的东西**：只看「缝」的话 alpha 赢（梯度比 1.81 最低），但它把 2~3 份不同花纹平均成一片糊，
边界带的高频只剩 56%——参考帧里草地圆点、水面网纹在岸带附近**都是清楚的**，所以 alpha 是错解。
`height` 缝减 81%、纹理留 81%，两头都占。

副产物：`band` 用世界高度单位，所以过渡带在陡岸窄、缓滩宽（量出来的平均 2.5px/边界像素，但分布不均）。

### 落地 2：`src/wobbletex.js` —— 非直线沉积层

三步照做：`w = W(p)` 抖开 → 贴图数学照旧（就是 `(bottom-y)/层厚` 的阶梯）→ 几何不抖（`W⁻¹` 只在需要时用）。

| 量 | 值 |
|---|---|
| 层线峰峰值（11 条平均） | 0（直线）→ **11.58px**（单层：k1 10.0 / k11 22.7，越靠下弯得越多） |
| 平均曲率（二阶差分 px/px²） | 0 → **0.033** |
| `W⁻¹` 定点迭代残差 max（1/2/3/4 次） | 9.69 / 3.62 / **1.61** / **0.84** px（`|∂D/∂x|` = 0.58） |
| 忘了第 3 步（几何也留在抖动位置） | 岛面积漂 **−0.27%** |
| 错解：逐面独立抖，跨面同层线错位 | 均值 **5.71px**、最大 17.82px ≈ **17% 层厚** |

**为什么"整体抖一次"比"每条线自己抖"好**：位移场是全局面函数，同一个世界 Y 在哪儿都是同一个 Y，

### 落地 3：`src/surfaceshadow.js` —— 投射高度 ≠ z 测试高度

### 踩的坑（9 条，都改在代码里、注释写清了）

1. **单位混用**：高度场只有 0..1、地图 300px 宽，我按真实角度写 `tan=0.95` → 影长 0.4px，覆盖率**恒为 0**。改成 `tan=0.035`（≈1 高度单位 = 28px）。
2. **归因写错**：第一版统计「阴影 ∩ 屋顶」，恒为 0——顶视图里屋顶投的影子落在地上，不落在屋顶上。改成「距屋顶 12px 内」vs「距崖口 12px 内」。
3. **不归一化就没有信号**：山体三种模式 r 全是 0.15，看着像"三种都一样"，其实是坡度太小、N·L 几乎不变。
4. **描边阈值**：逐像素差分 + p97 → 整图撒黑点（像雀斑）。要先把高度模糊 3 格再差分，阈值 p99.7。
5. **岸带覆盖用「|elev−水线| < 常数」**：平缓海岸处带宽在像素上暴涨成一块块桃色斑。改用有符号距离 `sd=(elev−水线)/|∇elev|`。
6. **手工 UV 的 v 轴不进图案** → 花纹沿射线恒定，岛变成**海胆**（放射状条纹）。v 轴必须参与图案。
7. **沿岸弧长不能用「角度×常数」**：那只对圆岛成立，结果是白点在上下缘挤成一堆。要沿 360 个方向找水线半径再累加成 `A(θ)`。
8. **alpha 平均的"无缝"是假的**：梯度比最低（1.81）但细节被抹平。只盯"缝"这个指标会选错方案，还得看"过渡带里纹理还剩多少"。
9. **错解要能量出不合理**：一开始用"相邻列梯度差"当逐面抖的指标，两种模式几乎一样（0.228 vs 0.195）；换成"相邻面同一层线的位移差"才量出 5.71px。

### 踩的坑（这轮四个，每个都改了代码）

1. **`visible()` 把自己挡住了。** 高度场里判可见性要沿射线取中间格，第一版没有排除起点格 ——
   t≈0.13 那一步又落回起点格，而起点格高度**必然**等于射线起点高度，"被自己挡住"。
   后果：252 个采样点里 92 个过了 cos 检查、**可见的 0 个**，整座岛的 bounce 恒等于 0
   （暗部增益 1.001，看起来像"算法没错只是效果小"）。跳过起点/终点格之后才动。
2. **面积不能用 pitch²。** 高度场里一道垂直崖壁只是一格的高差，真实面积是 `pitch²·√(1+|∇h|²)`
   —— 对 2 单位高、1 格宽的崖面就是 8 倍。用 pitch² 时合成"圆柱坑"对照测出 0.014 vs 蒙特卡洛 0.568（差 40 倍）。
   改完 0.063，仍差 9 倍，剩下的差是**近场点采样低估**（格子越粗越狠：res 40 差 9.1×、res 80 差 4.1×），
   所以最后加了一个**实测**定标系数 4.0（不是物理常数，文件头写清楚了它是怎么量出来的）。
3. **归一化到"理想球腔"是错的物理。** 一开始想把 ΣF 归一到 1（分母 = 把本格完全包住的球腔），
   等于假设峡谷包住一半，结果系统性压暗 35 倍（bestFitScale 0.028）。正确写法就是老老实实求积：
   `E_i = albedo_i · Σ (E_j/π)·(cosI·cosJ·A/r²)`，π 是 radiosity↔radiance 的换算，不需要额外定标。
4. **拉丝采样不能 round。** 双线性之前，波浪把采样点抖到半像素上就出台阶 —— 竖梯度从 0.51 **涨到** 4.38

5. **柱状画家算法渲染器完全不能用**（第一版）：每格画一根 1px 宽竖条，四舍五入后互相盖不住，

### 踩的坑

1. **撞车不是"id 有没有出现在代码里"，是"pipeline.js 有没有这条"。** 我先 grep 全仓确认这 6 个 id 没被实现过，
   但 `1590669875869286400` / `1707490274425884929` 在同一小时被另一条会话用 `src/edgeplant.js` 落了 —— 它们的 id
   出现在 `pipeline.js` 而**不在** `src/*.js`（那一条只写了 `where`）。开跑前要看 `learn/pipeline.js` 的最新条目，不能只看 data.js 的 status。
2. **维度字段名不一致 → 函数静默返回全 0。** 页面把 `ImageData`（`width/height`）直接喂给只读 `{w,h}` 的 `smear()`，
   两层循环一次都不进，输出全 0：**画布是黑的、但所有数字都对**。修法是同时认两套字段并显式 throw。这次又是"数字对、画面错"。
3. **整像素采样会让 <2px 的位移等于没位移**：ω=0.6（外圈 1.44px）整像素取整后锐度掉 **0.0%**，看着像"拖影没生效"。
   必须双线性。
4. **全图 p95 会被中心的强边缘主导**：同一个拖影，全图只掉 4%，外圈频带掉 9%。要看"效果发生在哪"，就在那个频带里量
   （跟上一轮"别只看 mean"是同一条教训，换了个指标又踩）。
5. **"环"不能用 cycle rank 判。** 两格厚的一条 C 形悬臂，`E − V + 1` 还有 18（任意 2×2 格子就自带一个 4 圈），
   按它会判成"能飞"。改成"**必须围出空洞**"之后才分得开：整圈 0 条腿、缺口 45 条腿。
6. **`Town.fill(cell, h)` 是"从 1 填到 h"。** 想造"只填第 3 层、底下是空的"，必须 `setSolid(cell, 3, true)`，
   否则每根柱子都落地，`floatingComps` 恒为 0（第一版就是这样，白跑一轮）。
7. **卡片的朝向随机会把信息平均掉。** 第一版草卡朝向随机 → 按方位角扫一圈，均值全是 0.83（波动 0.008），
   看着像"这个指标没用"。改成"朝向跟边线走"之后才有正确的读法：每张卡确实随方位变薄，但**整岛的平均不随方位变**
   —— 这恰恰是想要的性质（转相机时不会整片变淡）。
8. **WFC 的 tile 会不会"永远不出现"，跟边界锁强相关。** 8 个 tile 里 `rock` 出现 **0 块**：边界格锁 socket 0，
   传播一圈就把 rock（四边都是 1）从所有格子里消光了 —— 跟上一轮的 `1670794261669769217` 是同一类 bug，
   只不过这次是**约束链**造成的，不是概率太低。
