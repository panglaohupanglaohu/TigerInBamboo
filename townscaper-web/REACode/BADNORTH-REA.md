## 0. 结论先行

**这个网址上没有游戏。** badnorth.com 是 Squarespace 搭的营销站，19 个 `<script>` 标签全部是
Squarespace / Typekit，唯一的一个 `<iframe>` 是 Steam 商店挂件（`store.steampowered.com/widget/688420/`）。
页面里没有 canvas、没有 WebGL、没有 wasm、没有任何可执行的前端游戏代码。

所以「对这个游戏做 REA」这件事，**在这个 URL 上只能做到"成品像素级"这一层**：
用官方发布的 1920×1080 截图（那本身就是游戏帧缓冲的输出）反推渲染管线，再重建一版跑起来对照。
二进制级的 REA（拆 Unity 程序集 / il2cpp 元数据 / 着色器二进制）需要真实构建件，见 §7。

Bad North 由 Plausible Concept（Malmö，瑞典）开发，**Oskar Stålberg** + Richard Meredith + Martin Kvale，
2018 年发行。Oskar 就是 Townscaper 的作者 —— 这也是本仓库一直在追的那位。

## 2. 从像素里量到的六件事，以及它们对应的实现

测量脚本全部基于 `engine/ref/badnorth-summer1.jpg`（1920×1080）。

### (1) 没有地平线：雾的目标色是**屏幕空间的天空渐变**

左边缘（x=6..40）竖直剖面：`y=0 #c1c1c1` → `y=0.5H #a5aeb2` → `y=1 #c4c4c4`。
顶部比中部亮 26 —— 如果雾是单一颜色，远处的水会全部收敛到同一个值，顶部不可能更亮。

→ 水面 shader 的雾目标色，取「同一条屏幕空间渐变上同高度的色」：

```glsl
float fy = clamp(gl_FragCoord.y / uScreenH, 0.0, 1.0);
vec3 fogCol = mix(uSkyLow, uSkyMid, smoothstep(0.0, 0.46, fy));
fogCol = mix(fogCol, uSkyTop, smoothstep(0.46, 1.0, fy));
c = mix(c, fogCol, smoothstep(uFogNear, uFogFar, distance));
```

另外 12×8 网格平均色显示 **四角比中心亮**（`#bcbebf` vs `#a1abae`），是构图层的径向压暗，
用 `1 - 0.14·exp(-r²·3.4)` 复现。

### (2) 岛是「叠层岩板」：高度量化成台阶

dawn1 那张能清楚看到崖面上有横向板缝和竖向块缝，崖壁是**一块一块叠上去的**，不是连续曲面。

→ 高度场按 `STEP` 量化；侧面每块再竖切 3 段，段间压暗 6%（板缝）；相邻格高度相等则不生成面。
`STEP / 格子宽 ≈ 0.7` 是比例尺（`STEP=0.95`，格子 1.15）。

### (3) 崖面：每块面一个色 + 面内竖直渐变，暗部偏紫

k-means(k=14) 的四簇：`#9d8e97`(h325,s.10,v.62) 受光 / `#8b797e`(v.55) / `#705a67`(v.44) /
`#6d687e`(h254,s.18,v.50) 倒影与深影。

→ 光照模型 = 冷紫环境 + 暖阳直射；暗端用 `#705a67`，亮端 `#a89aa2`，竖直面用**水平**太阳方向算明暗
（原来的太阳太高，所有崖面 ndl 几乎一致 → 整圈一个色，这是第一版看起来"平"的原因）。

### (4) 草面是手绘笔触，不是平涂

`c_grass` 裁剪：密集深橄榄小点（约 10~18px）+ 少量大暗块 + 灌木下的软阴影。

→ 世界坐标 hash 的双尺度"笔触"（尺度 5.4 / 1.9），只作用在朝上的面。

### (5) 岸线是**两层等距轮廓**，颜色跟着环境走

`c_foam` 裁剪里能数出两条平行丝带；夏季帧是鲑鱼粉 `#d9a79e`，晨雾帧变成青色 `#a8e0e8`
—— 说明它跟着环境色走，不是沙。

→ 用一个 **海岸距离场**（点内测 + 两遍 chamfer）烘成 320² RGBA 纹理；
水面 shader 按 `d` 取两圈带（0.22~0.62 / 0.92~1.12）+ 崖根湿影 `exp(-3d)`。
**几何丝带在这里是死路**（见 §6 坑 3）。

### (6) 岛下是竖向柔化的倒影

比水暗、偏紫、近岸最深、越往下越散。

→ 地形镜像一份（`scale.y = -1`），紫调 `#6d687e`，alpha `0.40·exp(y/1.5)`。

## 4. 重建过程中修掉的 5 个 bug（这一节是给后来者的）

1. **`cell.id` 不等于数组下标**。`buildGrid` 的 sanitize 会删格，但 `id` 是 push 时的序号。
   用 `Float32Array` 按 `c.id` 存高度 → 越界写被静默丢弃 → 岛中央凭空出现一整圈"水洞"。
   代码几何完全正确，错的是索引。修法：`grid.cells.forEach((c,i)=>{c.id=i;})`。
2. **侧面绕向反了**。`(A0,B0,B1)` 的法线朝内，被背面剔除 → 从岛外能直接看穿崖体看到水面，
   画面上是"一条条水沟"。翻转成 `(A0,B1,B0)` 才封闭。这类错误 shader 不报任何错。
3. **`DataTexture` 没上传**。纹理对象的 `version` 停在 0（构造时那次 `needsUpdate` 没生效），
   three 根本没 upload → 采样拿到默认 1×1 白图 → 距离恒为 3 → 丝带和湿影**一个都不出现**。
   而 shader 编译零报错。必须显式 `coastTex.needsUpdate = true`。
4. **`ColorManagement` 把颜色降了一次伽马**。开着时 `Color.setHex` 会把 sRGB 转成线性存起来，
   而 ShaderMaterial 是直接写 `gl_FragColor`、不做回编码的 → 草地 `#b9b793` 被画成 `#8a8a55`。
   目标是复现量到的像素值，所以关掉管理、原样进出。
5. **水写深度 → 倒影永远不可见**。倒影在 `y<0`，永远比水面远，被深度测试剔掉。
   改成：水先画、不写深度 → 倒影后画 → 地形最后画。

另外两条 GLSL 经验：three 会**自动注入** `attribute vec3 color` / `attribute vec2 uv`，自己再声明一次是
`redefinition`（整个 material 编译失败、物体直接不画）；`mix()` 的 `t>1` 是**外插**，会把颜色推成负数变纯黑。

## 5. 工程上的取舍

- **不用几何丝带画岸线**：相邻格的边法线方向不同，拐角必开缝；两端延长补缝会在凸角戳出
  "粉色尖刺"。距离场是等距轮廓的天然表达。
- **不用标准材质**：这套风格几乎是纯色 + 一道棱光，`MeshStandardMaterial` 的高光与
  PBR 响应反而要一路关掉，不如自己写 `ShaderMaterial`。
- **不引入后处理**：参考帧没有 bloom、没有 DOF、没有色调映射肩部，`NoToneMapping` 直出即可。

## 7. 如果要做真正的二进制 REA，下一步

需要用户提供一份构建件（Steam 安装目录 / APK / IPA）。拿到之后按 REA 的路由：

- **若是 IL2CPP 构建** → `inspect_il2cpp_metadata` 读 `global-metadata.dat`（版本 24/27/29/31/39），
  拿类型、方法、字段、字符串字面量；配合 `binary_path` 还能拿静态地址。
  这一步能直接回答"岛是怎么生成的""单位状态机长什么样"。
- **若是 Mono 构建** → `Assembly-CSharp.dll` 是托管程序集，`inspect_managed_artifact` 直接反编译。
- **资源层** → `open_binary` 打开 `resources.assets` / `sharedassets*.assets`，
  或者先用 AssetRipper 解包，再 `analyze_javascript_application`（若为 WebGL 构建）。

## 9. 第二轮：把前几轮的技法搬进来（优化轮）

第一版是"能跑通"的版本：地形结构对了，但草面是平的、崖面只有一道板缝、
岛上没有植被。这一轮把仓库里前十几轮攒下来的东西挑了几件搬过去。

### 9.1 用了什么、来自哪一轮

| 技法 | 来源 | 在 Bad North 里的用途 |
|---|---|---|
| **贴图化笔触 + 低频密度场** | 第 4 轮 `blotch.js`（128² 三通道噪声图 / 96² chamfer 边缘场） | 草面：预烘 256² 划痕图集（`bnbrush.js`），三道通道分别当大划痕 / 中划痕 / 疏密场 |
| **边缘距离场做掩码** | 同上（"色块不渗过重要边缘"） | 台地沿口：笔触在沿口 0.16 单位内淡出，沿口一圈偏干（沙色） |
| **域扭曲做竖向条纹** | 第 4 轮 `surface.js` 的 `sWarp` 沉积线 | 崖面竖向水渍：同一张图集把 uv 的 y 频率压到 0.07，划痕被拉成竖条 |
| **球堆等值面 + 橡皮筋/气球松弛** | 第 12 轮 `src/blobrelax.js` | 树冠：`bncanopy.js` 里换成"1 大球 + 5 外围球"的紧凑球堆，等值面出来是实心团块 |
| **调试视角** | 第 11 轮 `surface.js` 的 `uViewMode` | `V` 键循环：正常 / 只看笔触遮罩 / 只看面明暗 |

### 9.2 关键实现：笔触为什么要"预烘 + 阈值化"

shader 里直接用 hash 撒点（第一版）的问题是"点太小、太均匀、彼此独立"，缩图后等于没有。
换成 CPU 光栅化的划痕图集后还要多做一步 **smoothstep 阈值化**：

```glsl
float coarse = texture2D(uBrush, buv).r;          // 连续值，均值 ~0.45
float aMask  = smoothstep(0.30, 0.72, coarse);    // ← 这一步不能省
base = mix(base, uDark, m * 0.55);
```

不阈值化直接当权重用，得到的是 0.1 左右的混合（`mix` 的结果只差 3~5 个色阶），
肉眼看就是"没画"。参考帧的草是**一笔是一笔**，必须把连续值压成硬边遮罩。

### 9.4 这一轮踩的坑（都是"零报错但没效果"）

1. **TypedArray 对非整数下标是静默丢弃的**。笔触图集的划痕中心是 `rnd()*size`（小数），
   我算索引时没有 `Math.round`，于是 `data[小数]` 全部无效写入 —— 整张图集是空的
   （实测 R 通道 `mean=0, max=0`），画面上一个笔触都没有，而**没有任何报错**。
   这条和上一轮"`cell.id` ≠ 数组下标"是同一类：静默失败。
2. **两遍采样抢同一个纹理单元**。写成 `uniform sampler2D uBrush, uLedge;` 时，
   three 的 uniform 解析只认第一个，`uLedge` 会和 `uBrush` 共用单元 —— 表现是
   "沿口场"实际采样到笔触图集的 B 通道（草地上出现一片片迷彩斑块）。**必须分两行声明。**
3. **`DataTexture` + `generateMipmaps` 在这台机器的后端上会得到一张不完整纹理**，
   采样恒为黑。和上一轮 `RedFormat` 恒返回 1.0 是同一类坑：纹理配置不支持时
   不会报错，只会给你一个常数。改成 `LinearFilter` + 手动 `fract()` 平铺。
4. **impostor 烘焙会把树冠裁成"绿碗"**。同一个 `createImpostors` 在 `world.html` 里是好的，
   但这里每棵树一千多顶点的等值面进正交相机时被 frustum 切了。二十几棵树用不上八方位
   烘焙，直接 `InstancedMesh` 更省事。
5. **`vN.y > 0.42` 分支里的变量在外面看不到**：调试视角要读笔触遮罩 `m`，
   而它声明在 `if` 块里 → `'m' : undeclared identifier`。提到 `main` 顶部即可。
6. **重复声明 uniform 会让整个 material 静默失效**：给两个材质都加 `uViewMode` 时，
   `replace` 把同一行文本改了两遍 → top 的 fragment 里出现两个 `uniform float uViewMode;`
   → `redefinition` → 该 material 不编译，**画面里顶面直接消失**（不是报错弹窗）。
