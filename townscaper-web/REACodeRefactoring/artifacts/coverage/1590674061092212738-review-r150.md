## 逐帧观察

- **0000–0049**：整帧就是一座多层岛，**没有 UI、没有帧率读数**。地面被涂成淡彩（粉 / 薰衣草 / 淡绿 / 淡蓝），色块边界不是格线而是**平滑的色带过渡 + 一条极细的深色折线**（反差纹理的诊断配色）。镜头贴近岛的东南坡缓慢环绕。
- **0050–0099**：镜头拉开，整岛入画（约 0055 起）。台地分层清楚：高处淡绿、中段淡紫、崖顶粉白；崖壁是灰褐色，**崖坡上一圈圈淡色叶丛**（草卡）压在各层台地的沿口与崖脚。
- **0100–0149**：镜头继续绕到岛的北侧，粉色块与淡紫块的位置随之改变（同一格在不同机位下仍是同一色 —— 配色是格级的，不是按视角变化的）。
- **0150–0180**：回到近景，只看到一大片淡紫台面 + 边缘的草卡带；0180 收在近景静止。
- **原尺寸 0000 / 0090 / 0150 的草卡细节（3× 最近邻裁切）**：
  - 0090 裁切：崖沿一排草卡压在淡绿台面上 —— **贴着台面外侧（背景是深绿/海）的那一圈草卡有明显深色外轮廓**，而同一排落在淡粉区域里的草卡几乎看不到轮廓（叶瓣之间还剩极淡的弧线）。
  - 0150 裁切：整片淡紫台面上的草卡是**白到发亮的团**，轮廓几乎不存在；同一帧里草卡压到相邻彩色块边界的地方才浮出灰线。
  - 结论：轮廓不是「崖边就有、内陆就没有」，而是**跟着身后的背景色走**；同一丛草在镜头转动时轮廓会变（原文 "not too jittery when turning the camera" 说的就是这个变化要平滑）。
- 全片没有第二种东西：无建造过程、无面板、无第二机位序列。片子的全部内容就是「诊断配色底 + 会随背景变轮廓的草卡 + 环绕镜头」。

## 判定

**有机制，且机制就是原文那句话**：
1. 一张**反差纹理**（每个格一个反差色，对比边被拉开、同色区趋同），并按格写顶高（`bakeContrastHeightMap` → RGBA，RGB=反差色、A=顶高）。
2. 草卡**顶点着色器里采两次**：① 站立处（草根 XZ）；② 沿「镜头 → 草」射线往背景步进，在高度场里找到第一个命中点再采一次；两次 RGB 之差 → `vEdge`。
3. `vEdge` 进片元：外轮廓宽度 `wOut = mix(0.035, 0.07, vEdge)`，且外轮廓墨量再乘 `smoothstep(0.06, 0.4, vEdge)` —— 背景同色就没轮廓，背景差大就粗。

不是「静态邻崖距离」那条旧代理：本仓 `aEdge` 是「格边到更低邻居的距离 < 0.11」的 0/1 静态标记，与镜头无关；片中轮廓明显随镜头转（0090 vs 0150 同一片草的不同观感），两者不是一件事（下面用 43% 的分歧率量化）。

## 代码落点与差距

- `src/world/view-c11-grassline.js`（文件头署本片 ID）：`patchTuftShader` 把 `vEdge = aEdge` 换成 `glOutline(origin, TH*scale*0.8)`；`install(view)` 烘图、挂 uniform（`uGL/uGLMap/uGLX/uGLMaxH/uGLGain/uGLDebug`）、按 World 版本重烘（`bakeMs` 260ms / 256² / 10064 三角）。
- `src/core/c11-maps.js`：`bakeContrastHeightMap`（反差求解 + 每格平均色 + 顶高）、`sampleMap`、`GRASS_RAY`（steps 28 / t0 0.06 / growth 1.12 / maxT 9 / gain 2.2）、`grassOutlineStrength`（着色器的 JS 孪生）、`GRASSLINE_VERT_PARS`（GLSL）。
- 页面入口：`index.html?c11=grassline`（`src/world/view-c11.js` 的 `C11_MODULES.grassline`）、面板入口 `src/ui/scene-enhancement.js` 的「草丛随背景反差描线」、诊断 `debug(true)` = `?shade=contrasttex` + `uGLDebug`（白 0 → 红 1）。
- 已有测试：`tests/c11-grass-shrub.mjs`（node，token 替换 + 烘图指标）、`tests/contrast-texture.mjs`（反差求解器）。
- **本轮之前缺的是运行验收**：全仓没有任何 `-browser.cjs` 从页面量过 `vEdge`，也没有一张截图证明「同一丛草因为背景不同而描边不同」。本轮补 `tests/grassline-contrast-browser.cjs`。
- 如实口径（不计缺口）：
  - 原作的反差纹理是 mesh UV 上的；本仓是 **XZ 平面图 + 顶高的 2.5D 近似**，崖壁取的是它所在格的颜色，没有那套 UV（模块头已注明）。
  - 片子的底色是**地面**的诊断配色；本仓的诊断是把**草卡**染成白→红（`uGLDebug`），地面诊断色走 r55 `?shade=contrasttex`。本轮两张整岛图用的都是默认地面配色（`grassline-island-ink` 直接对「草卡描边」这问），「底色是否一模一样」不在本轮口径里（测试返回值 `island.state` 里记了 `shading.on.contrasttex` 的实际取值）。
  - 外轮廓不是「有/无」两态：`max()` 里还有一条固定 0.8 的叶瓣弧线，`vEdge` 只调制最外层那圈 —— 所以 vEdge≈0 的草卡仍留叶瓣弧线（下面 A 组的 0.855→0.575 就是这个原因）。

## 验证

```
node tests/grassline-contrast-browser.cjs        # PASS（连跑 3 次一致）
node tests/c11-grass-shrub.mjs                   # PASS（contrastDE 17.2 / sameDE 0.08）
node tests/contrast-texture.mjs                  # PASS（quad 13.73→0.112、mixed 13.79→0.08）
```

场景 `index.html?scene=fusion&c11=grassline`：2516 格 / 12 层 / **4491 丛草卡**；烘图 256²、10064 三角、maxH 6、**contrastDE 17.60 vs sameDE 0.16**、bakeMs 260。

1. **逐卡强度分布**（4491 丛，当前机位）：p10 0 / p50 0.0122 / p90 1.0；>0.5 有 **1684** 丛、<0.08 有 **2525** 丛 —— 同一个场景里「背景差大」和「背景同色」两态都大量存在。
2. **不是静态 aEdge**：`aEdge=1` 1055 丛均值 0.391、`aEdge=0` 3436 丛均值 0.311；两者判定不一致 **1930 丛 = 43.0%**。
3. **转镜头**（绕 target 每 45° 一圈，8 档）：相对 180° 变过 **63.6%** 的草卡、强度中位变化 **0.5512**；相邻 45° 之间中位 **0**、p90 0.91（不变的是大多数、变的集中在崖沿那一圈）→ 与 "not too jittery when turning the camera" 一致：变化是**局部的、连续的**，不是整片闪。p90ByYaw 八档恒 1（崖沿那一圈始终高反差）、p50ByYaw 0～0.0122（内陆始终低反差）。
4. **GPU 回读 == JS 孪生**（关键：证明着色器真跑的是这两次采样）：单卡隔离渲染（临时场景只放这一张卡，避免 4491 丛互相遮挡）48 丛，`uGLDebug` 白→红读绿通道反解 `vEdge`，与 CPU 孪生逐卡比：**最大差 0.003 / 平均 0.001**（8bit 量化级）。
5. **真实描边的 A/B（同一张卡，只切 `uGL`）**：
   - **A 组**（静态 `aEdge=1`，但两个采样点同色 → `vEdge=0.001`）：轮廓环（贴白底的 2px 带）暗像素占比 **0.855 → 0.575**、环内平均亮度 **51.7 → 77.6** —— 最外层那圈墨被采样差值抹掉，只剩叶瓣弧线。
   - **B 组**（静态 `aEdge=0`，但背景差大 → `vEdge=0.998`）：环暗像素占比 **0.908 → 1.000**、整窗墨像素 **438 → 593（+35%）**、环平均亮度 **47.8 → 42.2** —— 轮廓由背景差**加粗**出来。
   - 同状态两帧噪声 **0**；两组都是单卡隔离、白底（bg 像素 388/575 证明窗口里确实只有这一张卡）。
6. **0 console error**（favicon 除外）。
