- 可量到的画面特征（原尺寸 600×338 frame-0000）：屋脊、崖棱、单位轮廓外面都有一条深墨线，宽度约 1–2 个像素；岛缘与海面之间还有一圈白亮线（岸线），与墨线不是同一层。

## 判定
有机制，但**画面本身不可证"变粗"**（成片只给了效果，没给前后对照）。原文说的是"为 4K 玩家把描边做粗"，即：描边宽度要跟着**渲染分辨率**走，否则 4K 下同样像素宽的线看起来会变成发丝。所以机制 = 屏幕空间固定宽度的反向外壳描边 × **按渲染高度归一的缩放**。

## 代码落点与差距
- 落点：`src/world/outline.js` · `OutlineLayers.update()`：
  `px = pixelRatio * max(1, drawingBufferHeight / pixelRatio / 1080) * thickness`，`uWidth = 1.4*px`（墨线）/ `3.2*px`（逆光亮边）。
  顶点着色器里 `clip.xy += dir * uWidth * 2.0 / uRes * clip.w`，所以 `uWidth` 的单位就是设备像素，不随物体远近变化。
- 已等价：① 墨线 + 逆光亮边两层反向外壳，宽度与距离无关（片子里远近屋脊的墨线一样粗）；② 宽度以 1080 高为基准按渲染高度放大，4K 下不会变细；③ 分辨率小于 1080 时有下限（`max(1,…)`），不会更细。
- 差距：① 代码里 `thickness` 的 ×2 只有 `view.setDebug('thickoutline')` 这一条入口，**学习面板上并没有「粗描边」勾选框**（旧 note 写"面板「粗描边」再翻倍"与实现不符，已在 data.js 的 note 里改口）；② 描边是几何外壳，交叉处会互相穿插（片子里看不出，因为都是凸形屋脊）；③ 片子里岛缘还有一圈白色岸线，属 `shore.js` 的另一层，不在本模块。
