## 判定

有机制，且是三条：

1. **导航面本身**：人群不是朝格心走，而是朝"面上连续的方向"走——过面/过格边时刻看不出任何朝向突变（片子 0060–0129 过矮脊、0200–0259 绕凸台两段最明显），且路线紧贴可站区域，跨层只经由坡道。
2. **流向在面内连续**：同一股人里不同位置的人朝向略有差异（面内插值），不是"每格一个常量方向"。
3. **通口前视**：过通口时人不是先走到格边中点再拐，而是直接朝向通口后方的点（0130–0199 绕崖边那一格）。

## 代码落点与差距

- 导航面：`src/world/navmesh-flow.js` `navMeshFromLayeredGraph(graph)` —— 由**共享 World 的分层导航图**（`src/world/layerednav.js`，battle 实际用的那张）自动生成，不是手搓的规则地形；`src/badnorth/battle-c02.js#navmesh()` 把同一份 mesh 画成黑线 + 红顶点调试层。
- 接进 battle.js：`src/world/battle-navigation.js` `steerTarget()` 里 `if(this.continuousFlow){…this.flowAim(unit,plan,base)…}`；`flowAim()` 用 `buildVertexField → buildFaceDirs → guardedFlowAt`（顶点距离场的面内梯度 + 鞍点守卫），再与通口前视 `base` 各占一半（偏离超过 `acos(flowAgree=0.5)` 就回退给图），并对整段扫掠做 `discFits`。开关 `continuousFlow` 默认关，可由 URL `?continuousFlow=1` 或 `battle.g3.set('continuousFlow',true)` / 场景能力面板打开（`src/badnorth/battle-g3.js`）。
- 通口前视：`portalAim()`（`src/core/portal-aim.js`）+ 精细门户 `#throughAperture()`，一直是默认路径，不依赖连续流开关。
- 本轮新增的可观测量：`BattleNavigation.flowStats={steer,used,rejected}` 与 `flowSummary()`（polys/verts/links/goals/graphNodes/portals/adopted），让"接上了"变成可读数字而不是口头声明。
- 仍未做到（**不是本片机制缺口，是既有路径共性**）：本岛地面层有 1 个人在起点就没动（`maxRemain 4.928`），但**关掉连续流也一样卡同一个人**，属 `move()/sep` 的既有瓶颈；人群逐帧转向角受间距分离支配，p90 在开/关之间两个方向都测到过，不作判据。
