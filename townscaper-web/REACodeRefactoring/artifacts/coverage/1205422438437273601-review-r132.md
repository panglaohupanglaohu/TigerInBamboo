## 逐帧观察

- 0000–0059：仰视红/洋红墙块 + 淡灰立面，立面上是**深蓝色窗格**（白十字窗棂），底部一块门；镜头从低处抬升，右侧紫灰块体上有整排小窗。月亮圆盘压在左上方。
- 0060–0149：镜头抬起并左移，出现深色屋顶与多栋小屋；门窗仍是「深色面 + 白框」，此时看不清洞内。
- 0150–0199：最近景的一栋（浅灰立面 + 深蓝窗）居中，窗格是白十字 + 深蓝四格，门洞下方有浅色门槛；编辑器 gizmo（绿箭头/蓝锥）叠在画面右侧。
- 0200–0329：绕到岛的另一侧，仍是同一种门窗画法；0320+ 出现斜向白线（模型线框/辅助线）压在门窗上。
- 0330–0389：正面近景（红墙 + 浅灰檐 + 浅灰立面），窗为**深蓝底 + 白十字**，可见窗下浅色窗台；门框是白色双竖边 + 深色门板。

3 倍放大裁切（`r132-f0360-windows.png` / `r132-f0330-windows.png` / `r132-f0190-windows.png`）：
窗内部在**正视角**下基本是一整片深蓝（与「挖洞后看到暗室内」一致，也与「贴一片深蓝板」不可区分），
只有在窗洞一角能看到**一小块比深蓝更亮、偏灰的斜面色块**——这是洞内侧壁/窗台的受光面。
**片子本身没有给一个能让洞深一眼可见的强斜视角**（相机始终大致正对立面），所以「有没有洞深」这件事在原片像素上只能靠这块灰斜面判，
不能靠视差。这条是本轮如实口径。

## 判定

有机制：**模板挖洞（stencil 挖 z-buffer）**，不是给门窗贴片。原片自述 "punch holes in the zbuffer"，
画面里每个门窗后面都有一小块受光的灰斜面（洞内侧壁/窗台），说明洞是**空腔**而不是平面。

## 代码落点与差距

- 落点：`src/render/opening-punch.js`（零厚度平面原型：三趟 pass mask → reset → recess）+
  `src/render/opening-punch-layer.js`（r56 C05·C，**文件头署本片 ID**：把同一机制接到 WorldMesh 真实建筑上，
  `punchGeometry()` 每洞出 1 张 mask 矩形 + 5 面凹洞盒（后墙 / 左右侧壁 / 窗台 / 窗楣），`depth` 默认 0.06 = 洞深）
  + `src/build/buildings.js:198` 的 `openingLog`（240 条：236 窗 + 4 门，带 cell/edge/t/y0/y1/width 与墙边 a/b、外法线 n）
  + `src/world/app.js` 一行挂钩。
- 旧 note 的两条「仍缺」本轮逐条核实：
  1. **「墙体厚度与洞口侧壁，墙是无限薄的面，近景无洞深」→ 过期账**：`punchGeometry` 的 recess 盒就是洞深（depth 0.06，
     后墙 + 两片侧壁 + 窗台 + 窗楣），本仓墙确实是零厚度壳，但洞深由这个盒子提供，不是靠墙本身有厚度。
  2. **「接 buildings.js 主管线（门窗仍走 archedEntry 贴片）」→ 半过期、半真缺口**：`openingLog` 早在 r56 就由 buildings.js 产出、
     `attachOpeningPunch` 也读的是 `view.worldMesh.build.openings`；但 `app.js` 原来是 `if (params.get('punch'))`，
     **默认不接**——全岛门窗在默认场景里都是深色贴片。这是真缺口（wiring），与 r130 的 `UnitShadowBatch.enabled` 同型。
- 本轮改的（机制主线一字未动）：`app.js` 把门窗挖洞层改成**主场景默认开**，`?punch=0` 关档；
  并把注释里「默认全关」的假账改成实际口径（churchDoors / canalBridges 仍默认关）。

## 验证

新测 `tests/opening-punch-main-browser.cjs`（主场景 `index.html?scene=town&grid=quad&seed=3`，判据全部来自 GPU 默认帧缓冲 `readPixels` 读回）：

1. **接线**：`rea.punch.stats()` → `openings 240 / doors 4 / depth 0.06`，与 `build.openings` 的 240（236 窗 + 4 门）逐条对齐；
   `?punch=0` 时 `rea.punch` 不存在（关档有效）。
2. **整岛 A/B（远景 d=9、pitch .45）**：开/关差分 **6402 px**，其中 **5347 px（83.5%）落在 240 个洞口的投影矩形并集内**，
   矩形外 1055 px（贴着洞口边缘的 1px 抗锯齿/斜视退化的窗），**同状态两帧噪声 0 px**。
3. **近景单个窗（cell 183 / edge 0，d=2.2 / pitch .22，窗投影 53×60 px）**：
   关档时窗内 **2244/3158 = 71% 是深色（玻璃板）**；开档时深色 **0 px**、亮灰侧壁 **1312 px（42%）** —— 窗从「暗贴片」变成「亮着的洞内侧壁」。
4. **视差/洞深**：同一窗斜看 dy = 0.10 / 0.22 / 0.40，灰侧壁像素 **1423 → 1711 → 1975**（单调增多）；
   洞内残余暗缝质心横移 **31.2 px**（关档同一量只有 **1.1 px** 的透视漂移）。
   理论量级 `depth·tanθ·scale`（scale = 53.2px / 0.082 世界单位 = 649 px/单位，θ 从 0.10→0.40）= 0.06×(0.4228−0.1003)×649 ≈ **12.6 px**；
   实测 31.2 px 约为理论 2.5 倍 —— 因为暗缝本身只有 10–23 px 宽、且随视角被侧壁挤到一侧，质心被推得更远。**只作方向性证据，不当精确标定。**
5. **0 console error**；`?punch=0` 那趟同样 0 error。

回归：`tests/opening-punch-browser.cjs` PASS（interiorVisibleSharePunch 1 / decal 0、holePixelsError −0.46%、wallDrift 0、repeatDrift 0）；
