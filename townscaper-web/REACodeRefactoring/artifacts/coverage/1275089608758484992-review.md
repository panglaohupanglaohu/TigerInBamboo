## 判定

**有机制，两件：**

1. **教堂高拱龛（church door）**：不是贴在墙面上的贴片门，而是把墙挖开一个跨两层的拱形洞（矩形段 + 半椭圆拱顶），洞口有石框、有厚度（能看到侧壁），洞内墙面是另一种颜色，洞底再放一道小拱门。等价于"带拱顶轮廓的墙体洞口 + 洞内墙面 + 洞底小门"。
2. **竖梯（ladder）**：两根梯梁 + 等距横档，从水面/地面竖直爬到高脚楼底面；梯梁沿竖直方向，横档间距恒定，梯脚落到水面高度。

## 代码落点与差距

- 梯子：`src/core/ladder-profile.js` · `ladderProfile(foot, lip, …)` 已给 rails + rungs（长度按真实 3D 锚点、横档间距、预算上限），`src/world/navlayer.js` 已用它把下层锚点接到上层楼板。**与片中一致，无需新增。**
- 高拱龛：本仓原来只有 `src/build/buildings.js` · `archedEntry()`，那是**贴在墙面外 12mm 的贴片门**（门板 + 一圈拱环），单层高度、无洞、无侧壁。本轮补的是挖洞侧的拱顶支持：`src/render/opening-punch.js` 增加 `rise`（半椭圆拱高）——`planFacade` 解析面积改走 `openingArea()`（矩形段 + 半椭圆段）、`isInsideOpening` 按拱脚线分矩形/半椭圆、`holePixelStats` 像素账同步、渲染侧 `rise>0` 的洞口改用 `THREE.Shape` + `ShapeGeometry` 挡模板（矩形洞口路径不变）。
- **还缺**：① 没有把拱顶洞口接进 `buildings.js`（`archedEntry` 仍是贴片）；② `opening-punch.html` 只有矩形 11 洞的对照栏，没有"跨两层高拱龛"这一栏，所以拱顶只有解析层验证、没有 GPU 读回；③ 洞内墙面与洞底小门（片中蓝色内墙 + 底部拱门 + 三级台阶）没有落点。
