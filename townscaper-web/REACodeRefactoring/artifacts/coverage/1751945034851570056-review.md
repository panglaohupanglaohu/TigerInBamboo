- 原文：Some nice new highlights when the island is backlit. Achieved by simply adding another inverted mesh outline layer that shows up when looking into the sun. And masked by shadows, of course.

## 逐帧观察

- 0000–0100：斜俯机位（约 35°）绕着岛转。浅色石塔、白墙、橙红屋顶、绿草台地；**每条轮廓都有一道细的暖白/奶油色线**贴着剪影外侧，屋顶棱线尤其明显，比深色墨线更粗。
- 0101–0180：镜头转到让太阳落到岛后面（背景仍是纯色天空，看不到太阳本体），silhouette 上的奶油色亮边变**粗且更亮**，尤其在屋顶坡脊、塔的左侧竖棱、台地折边上；背光面本身变暗。
- 0181–0245：继续绕，亮边始终只出现在"迎着太阳的那一侧"，背侧只剩细墨线。
- 0246–0281：正对逆光角度时亮边最明显，草叶、灌木剪影上也带一圈浅色。

## 判定

有机制：**第二层反向外壳（inverted-hull）**，比墨线更宽，只在镜头朝着太阳时出现在剪影的迎光侧，并被阴影/朝下面遮掉。片子明确说"masked by shadows"，画面上表现为：朝下/在影里的轮廓不亮。

## 代码落点与差距

`src/world/outline.js` `OutlineLayers`：同一个几何画两次、只画背面，顶点沿 `aOutline` 在裁剪空间外扩固定像素（ink 1.4px、rim 3.2px，按 1080 高归一），`vRim = into × facing × lit`。

本轮修的真 bug：`into` 原来写 `dot(-uCamDir, -uSun)`，而俯视机位下 `uCamDir.y ≈ -0.58`、`uSun.y ≈ +0.77`，点积**恒为负**——实测四档太阳方位 `into` 分别是 0 / 0 / 0 / 0.069，也就是亮边在这个机位下几乎从不出现（原片恰恰是这个俯角下出现的）。改成按**水平方位**判定：

```glsl
float align = dot(normalize(uCamDir.xz), normalize(uSun.xz));   // 1 = 太阳在岛后面
float into  = smoothstep(0.15, 0.85, clamp(align, 0.0, 1.0));
```

其余保留：`facing`（迎光侧）、`lit`（朝下面算阴影里，近似"masked by shadows"）。

缺（写进 next）：

- 阴影遮罩是"法线朝下程度"近似，没有真去查 shadow map；片子里屋檐投在墙上的影子里确实没有亮边，本仓会有。
- 片子的墨线偏浅（奶油底上的深线），本仓墨线固定 0.85 alpha 深色；亮度关系与片子不完全一致。
- 亮边宽度随焦距的换算沿用 1080 归一，4K 下的绝对值未与原片比对。
