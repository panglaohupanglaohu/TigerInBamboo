## 逐帧观察

调试层由四类元素叠成，全片反复出现、顺序固定：

1. **白色 1px 网格线框**（不规则四边形，格宽 0.6–0.9 不等）。
2. **格角小白点**：每格四角各一颗，相邻格共用的角只画一颗（所以点数明显少于 4×格数）。
3. **格心彩色点**：一颗比角点大的点，**多数是黄**，夹着少量红 / 绿 / 蓝 / 紫。关键在帧 0303–0310、0420–0429：**同一颜色的点沿一条格列排成直直的一串**（黄列、红列各成串），说明颜色不是逐格随机的，而是按某个区域/类别整体上色。
4. **区域边界折线**（红/粉，个别段是紫/蓝）：只走格边、沿不可见区域的轮廓绕行；帧 0260–0299 有一圈很长的红色闭环，中间夹着黄/蓝点。
5. **RGB 三轴移动 gizmo**：帧 0095–0105、0455–0460 在某一格上出现，红/绿/蓝箭头 + 两个半透明方块手柄。
6. 另有整格黑白棋盘高亮（帧 0460–0489），是"候选格集合"的另一种标法。

没有 UI 文字、没有菜单；这是纯渲染调试层的录屏。

## 判定

有机制：一整套网格编辑器调试层（线框 / 角点 / 心点 / 区域边界 / gizmo / 候选格棋盘）。

本仓此前状态（第 53 轮）：白色线框（LineSegments，天然 1px）、红色区域边界（`regionBoundary`）、选中格半透明填充 + 定宽金黄折线、屏幕恒定 RGB gizmo 都已落地。

**缺口就是点标记**：`contour-overlay.js` 的文件头注释里从第 46 轮起就写着「格角上有小白点」，但整个类里没有任何 `Points` —— 注释承诺的东西从来没实现过。格心彩色点同样没有。

## 代码落点与差距

落点：`src/world/contour-overlay.js`（`ContourOverlay`）。

本轮（第 59 轮）新增：

1. **`this.corners`（白点 3px）/ `this.dots`（格心点 5px）** 两个 `THREE.Points`，`sizeAttenuation:false` + `depthTest:false` + `renderOrder 13` → 屏幕恒定尺寸、压在网格线上（对应原片"拉远拉近点还是那几个像素"）。
2. **`#fillDots()`**（在 `refresh()` 里跑）：角点按 `(x,y,z)` 字符串键去重（相邻格共角只留一颗），格心取多边形顶点均值。
3. **格心配色按低频空间分块**：`floor(x/2.2)`、`floor(z/2.2)` 上做 sin 哈希分五档 → 同块同色，相邻格连成片、沿块界排成「同色成列」，黄占 2/3、红/绿/蓝/紫各占 5–14%（对应原片"一片黄里夹几条彩色串"）。
4. **`setDots(on)` / `setDotSize(corner,cell)`** 两个入口，`dotStats` 暴露 `{corners, cells, colors, on}`。

## 仍缺（留给下一轮）

1. **区域边界只按高度层分色为一种红**：原片同一时刻有红、粉、紫、蓝几种不同颜色的边界，是"不同区域各一种色"，本仓 `regions` 是单一 `#e0473c`。
2. **格角白点尺寸未做原片校准**：原片角点比格心点小约一半（现在 3px vs 5px 是估的，没量）。
3. **候选格黑白棋盘**（帧 0460–0489）本仓没有对应层。
