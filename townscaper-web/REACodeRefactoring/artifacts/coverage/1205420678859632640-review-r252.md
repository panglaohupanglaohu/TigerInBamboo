## 判定

有机制：叶纹贴在**球面坐标**上，alpha = f(视角 |N·V|, 叶纹值)，掠射处被 discard，切口沿边压一条墨带。线框帧（0250 起）是调试视图，同时是「冠是低面球 + alpha 镂空」的直接证据。

## 代码落点与差距

- `src/life/leaf-surface.js#leafPattern`（球面 uv：`atan(n.z,n.x)` / `asin(n.y)`，读全城 128² 图集右下 32² 角）+ `#leafCoverage(facing,pattern)`；
- `src/life/vegetation.js:242-258`：`rim = 1-|dot(normal, viewDir)|`，`leafAlpha = leafCoverage(1-rim, pattern)`，`inkBand = 1-leafCoverage(1-rim-.06, pattern)`，`discard` + 切口墨色 `mix(rgb, .12/.13/.10, inkBand*.85)`；
- `src/life/leaf-depth.js`（阴影 caster 同源判据）、`src/life/leaf-impostor.js`（远冠替身）；
- 页面入口：`leaf-surface.html` 的俯仰滑杆 / 图集–旧噪声–整团块三档 / 0250 线框档（r250 补）。

**本轮闭合的缺口 = 「冠 alpha 随视角的定量曲线」**（r250 记为仍缺）：

| 俯仰 | solid 像素 | 覆盖比 atlas/solid | 被咬掉 | 咬边离轮廓深度 p50/p90/max |
| --- | --- | --- | --- | --- |
| 0.55 | 11974 | 0.936 | 6.4% | 0/1/5 px |
| 0.70 | 9836 | 0.935 | 6.5% | 0/1/6 px |
| 0.85 | 7983 | 0.936 | 6.4% | 0/1/10 px |

| 1.30 | 6393 | 0.952 | 4.8% | 0/1/8 px |

- 解析式：叶纹均匀（p̄=0.5）时被咬掉的面积比 = (0.08+0.35·p̄)² = **6.50%**，实测 4.8–7.9%（六档均值 6.4%），覆盖比 **0.921–0.952** vs 解析 0.935 —— 逐档都落在 ±3.5% 内；
- **咬边只贴轮廓**：被咬像素到冠边界的深度 p50 = **0**、p90 ≤ 2px（≈ 抗锯齿带宽），六档一致 → 缺口是「沿掠射轮廓一圈」，不是冠内部挖洞；
- |N·V| 分箱存活率（按投影半径反推 facing）：0.904/0.944/0.939/0.954/0.959/0.952/0.956，中段比掠射端高 0.032；**如实说**这条分箱曲线很平，因为切口只有 0–2px 宽，径向分箱分辨不出亚像素环 —— 能定的定量就是上面的面积比 + 咬边深度分布，别把这条当强曲线用。

**仍属美术近似（不列为机制缺口）**：原作手绘叶簇纹样无源，本地是程序叶纹（同一张共享图集的植物角）；片内冠的叶簇更碎、缺口更深。按 r243/r251 的记法记「如实」，不记「仍缺」。

新测 `tests/leaf-crown-alpha-pitch-browser.cjs` 的做法（可复用）：只留树冠、藏掉墨线外壳、洋红底 → 用「非洋红」判掩膜（不用亮度：solid 档时反向外壳会把冠缘画暗，用亮度会把边缘当背景，实测把 solid 面积压小 7%）；同一像素集内数 `solid∧¬atlas` 得咬边像素，再做 BFS 深度分布。

试错记录（都量完回滚，无代码改动）：
1. 单株隔离（另建只含目标株的 `InstancedMesh`）→ 整片被 discard（覆盖比 0.059/0.000），因为冠材质的 `uLeafCenter` 按原实例写死；回退为「最大连通块」近似（代价：邻株会换人，面积摆幅 1.87×，只作读数不作判据）。
2. 用亮度阈值判掩膜 → solid 档反向外壳把冠缘画暗，solid 反而**小于** atlas（比 1.07–1.09），误判成「叶片 alpha 让冠变大」；改洋红底 + 藏外壳后方向正确（0.92–0.95）。
3. 相邻档原始 XOR 翻转量 → 机位平移主导（4.6 万 px），不能当「视角调制」证据；改为读数、不作断言。
