## 判定

有机制，且是**一处自定义投影矩阵**：

1. 普通透视里 clip.w 来自视图空间 -z，俯视相机的 w 会随世界 y 变化（w 行的 y 系数 ≠ 0）→ 同一根竖线上下端 w 不同 → 屏幕 x 不同 → 竖线收敛；
2. 把 w 行的世界 y 系数按 k 衰减（k=1 时归 0），竖线两端 w 相同 → 屏幕 x 相同 → 竖线笔直平行；而 w 仍随水平距离增长 → 远处照旧变小。
3. 这是**投影矩阵级**的效果（不是相机 FOV、不是正交切换），必须改 `camera.projectionMatrix` 并把深度行一起改写，否则整片会被远裁面切掉。

片内没有暴露参数界面，只交代了结论；原文自己说"不适合 Townscaper"，所以本仓按"可选档（`?mixedPersp=`）"接入，主场景默认关——与原文态度一致。

## 代码落点与差距

- `src/core/mixed-perspective.js`（文件头第 2 行署本片 ID）：
  - `perspectiveMatrix` / `viewMatrix` / `multiply` / `invert`：自带矩阵工具（列主序，与 three 一致）；
  - `withVerticalParallel(vp, k, pivotY)`：**核心**——`m[7] = wy·(1−k)`，`m[15] += k·wy·pivotY`，pivotY 那一行保持不动免得整幅上下平移；
  - `verticalEdge` / `quadWidths` / `compareProjection` / `projectionForRenderer`（P' = M'·V⁻¹，供 three 直接用）。
- `src/world/view-mixed-persp.js`（第 56 批 C05，文件头署本片 ID）：`attachMixedPerspective(view,{k})` 做三件事——
  1. 换掉 `camera.updateProjectionMatrix`（先走原生，k>0 再混），并在 `view.updateCamera` 结尾重刷（混合投影依赖视图矩阵，转镜头就得重算）；
  2. **深度行跟 w' 走**：`mixed[c*4+2] = −P10·mixed[c*4+3]`、`mixed[14] = −P10·mixed[15] + P14`；不改这一行时 `z_ndc = (−P10·w + P14)/w'` 会 >1，整岛被远裁面切掉（模块注释里记了第一版截图"岛面和墙下半截全没了"）；
  3. `fixRay`：混合投影的像素不再对应"过眼点"的射线，`Raycaster.setFromCamera` 会错 → 用 (P'V)⁻¹ 反投影近/远两点重设射线。
- `src/world/view.js:311`（`?mixedPersp=` 装载）与 `view.js:1270`（`pick` 前调 `fixRay`）；倒影是同一相机下 `scale.y=−1` 的镜像网格，投影一换自动同步（`view.js:278–280`）。
- **旧 note 的「主视图 view.js 未接（k=0 默认）、pick/倒影相机矩阵未同步」核实为过期账**（第 46 次同型）：三处接线全在，真缺口是**从没在 index.html 上跑过一次运行验收**——旧账里唯一实测的是 `mixed-perspective.html` 的四块标尺，没有真实城镇、没有拾取、没有倒影。

本轮如实口径（写清不夸）：

- 原版是 Unity 自定义投影 + 镜头移轴管线，**逐像素对齐不可证**（片子里只有一种投影、没有对照帧）；本轮判据是两条可量的事实（竖线横移 0、近大远小仍在），不是"与原版逐像素相同"。
- `k=1` 时近侧几何按 w 缩小被放大，自动取景（`frameTown` 按原生投影算）会让岛底略出画；这是混合投影的必然后果（原片机位也是手动摆的），滚轮/拖拽可调，不改取景代码。
- `fixRay` 起点本轮从"z=−1 反投影点"改成"线上离相机最近点"：前者实测落在离眼点 **8.36** 世界单位处（可能已经在近处柱子内部/背后），后者 0.10。**本夹具 24/24 拾取结果与旧起点完全一致（diff 0）**，属消除隐患的稳健性修补，不改本轮任何结论。
