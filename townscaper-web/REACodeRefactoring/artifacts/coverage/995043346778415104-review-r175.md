- 原文：The pathfinding in some levels does get a bit convoluted

## 逐帧观察

等距俯视一座两级台地岩石小岛（上层草台 + 白屋、崖壁有洞口与外挑岩台、四周浅灰水面），镜头缓慢平移，全片无调试线框、无路点编号、无网格。

- 0000–0019：只有雨丝。台上三支守军（白盔蓝身、紫红菱形盾 / 蓝圆盾 / 橙旗）聚在左上草台。
- 0020–0070：**白色圆点路线**出现。0035 原尺寸：点从守军队列出发，先沿台地横走到崖沿，在沿口**向外抛出一小段弧**、几乎竖直地落到下一层，再沿下层台地横走；另一段从左下海滩沿崖壁上行。点距基本相等，**一个点都不在崖体里**；平地拐角是圆角不是尖折。全片同一时刻能看到**两条**（两个小队各一条）。
- 0071–0090：小队开始行军，主路线点串被"吃掉"——已经走过的段消失，前方未走的段还在（0075：只剩左侧与下台的零散点）。
- 0091–0199：队伍绕过洞口与外挑岩台两度折返（原文说的 "convoluted"）。0150：左台与下台仍有少量残余点，主体已随行进消失。
- 0200–0385：行军继续到下层集结，末段无新预览。

## 判定

**有机制**：移动指令的**路线预览**——导航路线画成等弧长白点串；跨层段从崖沿外抛一段弧再落下（不是节点直连的斜插）；平地拐角圆角；点浮在地表；行进中未走的段留、走过的段消。

与"寻路"本身是两件事：路线怎么算（navgraph）本仓早在；本片问的是**路线怎么画**。

## 代码落点与差距

落点 `src/core/route-preview.js`（文件头署本片 ID）+ 主战场接线 `src/badnorth/battle-c01.js#route/#routeStep`（C01 层 `routePreview`）+ URL 入口 `src/badnorth/battle.js#applyC01Param`（r173 补）。

**核实（先核再动手）**：旧 note 的两条「battle.js `#drawPath` 尚未接入」「预览仍是 2.5s 淡出的一次性点串」**都是过期账** —— `#route()` 覆盖 `b.path.geometry`、`#routeStep()` 每帧 `b.pathT = max(b.pathT, 1.2)`（走完前不退）、按领头人位置逐段 `slice` 裁切、走完才把 `route` 置空交回 battle 的淡出，全都已实现；缺的是**从没在主战场跑过**。

**本轮查出的真缺口（不是过期账）**：接上了但**没生效**——
`landArcs()` 里 `land` 默认 0.55 是死值，而真实导航图相邻节点只有 **0.42–0.47 世界单位**（一格宽）：
落点必然越过终点 → 走的是"段太短，退化成斜落"那条 early-return → **arcs=0，跨层段仍是斜插**，
主战场实测 2 处跨崖共 **6 个点埋在崖体里**（直线 0.55 外抛在 demo 页的合成崖上就不存在这个问题，
所以单页测试 `route-preview-browser.cjs` 一直绿、node 测试也一直绿）。

改法（只动几何模块一处）：`land` 从"死值"改成"上限"，按这一段崖沿之后**还剩多少水平余量**收边
`reach = min(land, 剩余段 × 0.85)`，贝塞尔控制点同样收边到剩余段 1.05 倍；只有余量 < 5% 段长才退化成斜落。
`tests/route-preview.mjs` 同步把"0.4 短段 → arcs 0"的旧断言改成"arcs 1 且落点收边在段内"，另加 `at: 0.95` 的退化用例。

## 如实口径

- 片里同一时刻能同时看到**两条**路线（两个小队各一条），本仓仍只有"当前下令那一队"一条 —— 这是既有设计（`c01.route` 单对象），本片只要求"路线怎么画"，不声称已支持多队并行预览。
- 片里点位更密（约 0.08–0.1 格距），本仓 `spacing=0.12` 是既有常数，未按片重标。
- 相机/配色与原版不同；点径是 `PointsMaterial size 5, sizeAttenuation:false`（屏幕 5px），与片里 2–3px 的点更粗一档。
