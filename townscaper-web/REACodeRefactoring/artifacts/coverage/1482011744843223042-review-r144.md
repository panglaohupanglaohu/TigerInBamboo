## 逐帧观察

- f000–f001：灰模（无着色）先立起来，f002 起换成绿草顶 + 灰白崖面的岛，之后是一整段缓慢转镜（f002–f228）。
- 表面形制（4× 裁切确认）：草面是**一块块明暗略不同的多边形**，块与块之间不是靠颜色硬切换，而是**交界处压一条深色细线**；崖面是**竖向分块的板条**，板条之间同样是一条细线，且细线**断续**（部分段落只有半截，端点有加粗的小结点）。
- 线的粗细（原生 640×640 下量）：约 **1 像素**，抗锯齿后读作 1–2 像素；线是深绿灰色，不是纯黑。
- 不出现线的地方：**天空 / 海面完全干净**；**岛的剪影没有粗描边**（剪影只是表面色对背景的硬边，没有额外墨线）；水面无任何线。
- f229–f230：切到另一座岛的灰模 + 线框调试（两帧），f231 起换成第二座岛（低平、带红顶小屋）继续转镜到 f383。
- 全片只有一件事：**着色法线反差出的一像素线**。没有 UI、没有参数面板、没有第二套机制。

## 判定

有机制：**线源 = 程序化法线图的反差**（不是深度、不是几何轮廓）；线宽 ≈ 1 像素；剪影与海面不出线。

## 代码落点与差距

落点 `src/world/view-c11-normalline.js`（`?c11=normalline`，文件头署本片 ID）：打开 paintnormal（程序化大笔触法线扰动）+ 屏幕空间 outline，把**法线遍的线源换成同一张笔触法线图**（最近邻副本 → 交界在一个像素内跳变），`uDepthMix=0` 只用法线反差，海面片元写平法线。

本轮核出并修掉的**真缺陷**（旧 note 记的「卡美术资产」不是这里的病根）：

1. **开关已经坏了**：`outline-pass.js` 后来把硬编码阈值 `smoothstep(0.55, 0.98, nd)` 换成了 `uNormalThreshold` uniform，`view-c11-normalline.js` 仍按旧字符串 patch 复合着色器 → `?c11=normalline` 直接抛 `composite token missing`。抛错发生在「已经把 outline 打开」之后，于是**几何描边留在天上**：第一次实拍看到云边、天空全是锯齿折线（原片一条都没有）。
   → 改成直接写 `pass.uniforms.uNormalThreshold.value = (0.025, 0.09)`，不碰着色器源码；关档把该 uniform 还原成 (0.55, 0.98)。
2. **关→开再来一遍会二次 patch**：`st.prevFrag` 在第二次打开时已经是 patch 过的源码，再 patch 必抛；实测 `off→on` 复现。→ 原始源码只存一次（`st.origFrag ??=`），且现在根本不再改源码。
3. **线源没限定**：法线遍只排除了「无 normal 属性 / 透明不写深度」的网格，云、天空、远景、树卡都会进法线遍 → 天上出线。→ 法线遍限定为**共享地形材质**（`pass.c11NormalOnly = new Set([view.material])`，另留 `material.userData.c11LineSource` 退出阀）。

仍存的**形态差（非机制缺，如实记录）**：

- 线密度偏高：同一量具下本仓开档 **172.11‰**（关档 91.52‰，即线本身贡献 +80‰），原片三帧 **63.98 / 72.81 / 73.67‰**。根因是本仓地形是逐格台地，**每个台阶/侧面都是一条几何折痕**，都落进法线缓冲；原片地形更平滑，线基本只出现在笔触交界。
- 笔触形状：原片是手绘感的大块多边形；本仓是周期平铺的程序化笔触（`paintScale=4`），块形更规则。
- 世界轴三向投影在轴向切换处仍有接缝（本轮未单独量化，视觉上未见明显直缝）。
