# 精灵受击姿态与逐单位浸血

## 学习承接
先读984813819280191488（大小兵浸血/中断）及969860566322958336（单方向精灵与方向模糊性）的README。本轮承接已看934帧和308帧的学习证据，不重复计数，新增帧0。受击摆动和UV噪声血斑均为本地程序表达，不称为原作图像或动画曲线。

## 实现
此前可选精灵模式忽略stunRemaining与soak，切换后失去受击反馈。现在仍用两套阵营共享材质和既有程序精灵，改用ShaderMaterial按每个对象上传soak，UV内生成血斑，保留透明裁切和色彩输出。onBeforeRender设置uniformsNeedUpdate，避免同材质的伤员把下一位健康单位染红；没有为每名士兵克隆材质。

中断期间以剩余计时生成小幅镜头平面摆动，绕脚底原点旋转，恢复后回到镜头朝向；暂停计时不变所以姿态冻结。Battle传入gore显示选项，关闭只清显示soak，单位真实血量/浸血/中断状态保持。既有朝向翻转、大小兵缩放、池化及切场隐藏均保留。

## 验证
sprite-hit-browser.cjs使用实际UnitSpriteBatch在GPU渲染两名同阵营单位：伤员红色像素19006，健康者0；交换绘制输入顺序结果相同，关闭gore两者均0，材质仍为2。检查脚底原点和中断摆动恢复，双网格真实北境检查暂停、gore往返及切场隐藏。报告sprite-hit-browser.json；截图sprite-hit-{quad,mixed}.png为受控状态比较近景，已查看。combat-profile-browser回归大小兵生成/命中/精灵缩放通过。GPU定量是固定离屏夹具，不是游戏截图像素统计。

## 边界
目前是简单摆动及UV血斑，没有完整逐帧动作集、受击方向动画、精灵阴影或原作美术。大兵专属动作、美术和体型拥挤验收、矛的旋转/接触时刻3D遮挡及格挡推力仍待续。模块保持部分覆盖。未同步游戏副本，未认证TigerMessenger实景。
