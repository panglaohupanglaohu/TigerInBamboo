关键：**没有第二种「装箱」演示**，也没有 UI/参数面板；片子只给画面与一句配文（原文「大块连贯的部分在中间」）。

## 判定

有机制，且是三件事叠在一起：
1. **分片**：把朝上的面合并成一大片（片中那块带洞的中央大块）；
2. **径向按大小排布**：大块放页心、越小的越靠外（不是矩形扫描/方向性排布）；
3. **把 UV 页贴回同一座岛**（棋盘格 / 反差色），且反差色是逐轮迭代出来的连续渐变。

## 代码落点与差距

落点（r56 C11，文件头第一行就署了本片 ID）：`src/core/uv-radial-atlas.js`
- `topMergeCharts`：朝上面（n.y ≥ cos 40°）沿共享边连通成一片、统一竖直 XZ 投影，崖柱脚印自然成洞；片内投影自交退回原分片；
- `radialChartPack`（`src/core/uv-charts.js`，`footprint:'raster'`）：按面积从大到小、从环 0 向外找空位 → 就是原文说的 radial size-sorting；
- `clipIsland`：与片子同构的测试岛（底板 + 3 根崖柱 + 拱洞），写进共享 World、用共享 terrainmesh 出网格；
- `rasterizeChartPage` / `paintCheckerPage` / `meshContrastGraph` + `contrastSimulation` / `paintContrastPage`：UV 页光栅化、棋盘格、三角反差色（1482346496460828674 那半句配文）。

页面：`uv-radial.html`（上 UV 页 512×512 + 下 3D 视图 + 反差模式的三张调试图条，模式 wire/checker/contrast、分片 top/angle、逐片播放）。

**旧 note 的「原UV流程未实现，圆块/矩形演示不计验收」是过期账（第 19 次同型）**：`textures.html?t=radial` 的圆块螺旋与 `engine/spritepack.js` 的矩形 radialPack 只是旧演示，本片真正的流程（分片 → 径向装箱 → 贴回岛）r56 就落在这套模块里，node 测试 `tests/uv-radial-atlas.mjs` 一直绿，**唯独没有 `-browser.cjs`** —— 没人从页面上把这三件事量出来。

造型差（不计缺口，已写进页面提示语）：
- 本仓是「同构测试岛」（110 格陆地 + 3 根崖柱 h=3/5/4 + 拱洞 62），不是原片那座真岛；
- 原片 UV 页里的图块边界是**手绘不规则的**，本仓图块边界由格网三角决定，外围碎块更细碎（322 个连通块 vs 268 片，个别顶面分片在夹点处被投影压成零宽 → 光栅化成两块）；
- 原片的彩色线框是**只给边着色**、面留底色；本仓反差模式是面填色 + 边压暗；
- 逐片放置是本地加的演示（原片是剪辑，没有「一片片出现」的过程证据）。
