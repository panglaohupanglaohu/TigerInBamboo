## 逐帧观察

- 0–99（0.00–2.97s）：海岸边停着几条深色木船。靠岸那条船里塞满了东西：船底一片红（血），上面压着几个发白的人形（尸体/浸血的身体），船的舷侧木纹与血迹都在同一个透视里。镜头沿岛缘缓慢绕行。
- 100–199（3.00–5.94s）：镜头继续绕，船在画面里转了角度。**船内的红与白仍然贴着船板走**——不是屏幕空间的贴片：船体转多少，血迹跟着转多少，没有出现血浮在船外或滑到水里。
- 200–299（6.00–8.97s）：另一侧海岸的两条空船入画（船身干净、只有木色），与那条满血船形成对照，说明血不是全局滤镜而是逐船的附着。
- 300–399（9.00–11.97s）：镜头绕到近侧，岸边地面也有一片暗红（岸上的血），船身随水轻微起伏。
- 400–439（12.00–13.26s）：构图保持，无跳切。

4× 裁切（frame-0150）确认三件事：
1. 血是**大面积浸透**的：整条船底几乎全红，不是几处斑点；
2. 尸体是**白色/浅肤色的人形**压在血上面，随船的姿态一起倾斜；
3. 空船与满血船同框，附着关系是逐船的。

## 判定

**有机制**：血、尸体、箭矢在命中瞬间记录「相对船体的局部锚点」，之后跟船的完整变换（位置 + 朝向 + 起伏/横摇）一起走；船离场时这些附着物要跟着清理。片中能直接证伪「屏幕空间贴片」：镜头绕行时血迹相对船板一像素不滑。

## 代码落点与差距

- `src/core/platform-anchor.js`：`capturePlatformAnchor(matrix, m)` 把命中点存进平台局部空间，`resolvePlatformAnchor()` 再乘回平台当前矩阵；拒绝奇异矩阵。
- `src/badnorth/battle.js`：
  - `#bleed(x, y, z, s, boat)`：命中在船上时 `boat.mesh.updateMatrix()` 后 `boat.stains.push({local: capturePlatformAnchor(...), i: this.blood.count})`；
  - 每帧对 `boat.stains` 重算世界位置写回血迹实例矩阵；
  - 箭命中船时用 `boat.mesh.attach(a.mesh)`（three 的 attach，把箭挂到船节点下，自动保留世界变换）；
  - `this.boats.filter(...)` 离场时连 `group.remove(b.mesh)` 一起清。

**实测（两条浏览器测试，本机 Chrome + swiftshader）**：

```
node tests/boat-corpse-browser.cjs
  quad/mixed 两套网格：drift 2.07e-8、arrowDrift 0、rollChange 0.0322、goreRoundTrip true、deathPoseCaptured true
node tests/boat-anchor-browser.cjs
  quad/mixed：hitHealth 2、drift 4.28e-7、motion 1.075、immediateCapture true、transformedParent true、singularRejected true
```

即：船横摇 0.032rad 后血斑世界位置漂移 1e-8 量级（等于零），箭的漂移为 0；关掉血再开回来（gore 往返）附着关系仍在。

**还缺什么**：
- 片中血是整船浸透、成片连成一片红，本仓是**斑点级**血 decal（几处椭圆），量级差很多；
- 尸体的姿态是原作的死亡姿势，本仓捕获的是命中瞬间的简化姿态（`deathPoseCaptured` 只保证姿态被抓到，不等价）；
- 原文还提到「加些小花」，片里岸边能看到细小花点，本仓没有配套的花点缀（不在本条验收范围，记作缺口）。
