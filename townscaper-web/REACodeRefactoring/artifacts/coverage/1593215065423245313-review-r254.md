# 1593215065423245313 · Making a lil dynamic sprite packer, able to add and remove sprite allotments at runtime

- 帧数 / fps / 时长：164 帧 / 30fps / 5.47s
- 联系表：sheet-00.jpg（0000–0099）、sheet-01.jpg（0100–0163）本轮实看
- 原文：Making a lil dynamic sprite packer, able to add and remove sprite allotments at runtime. I had one of these in Bad North and found it very useful. Here, the sprites are baked live from meshes.

## 逐帧观察

- 0000–0010：棋盘格底图上只有 1 个精灵（十字叶丛 + 一只圆柱），四周空槽。
- 0010–0030：槽位逐格填满到 8–9 格（十字叶、圆球、圆柱、星形小花），每格带绿框定位线。
- 0030–0039：**整板变黑**（批量释放），黑面上已看不到贴图内容，只剩极淡的格缝。
- 0045–0060：从空板重新烘焙，先 3–4 格，再补满整板。
- 0061–0063：又清空一次；0064–0070 再填满；0075–0079 第三次清空；0084–0100 第三次填满 —— 全片就是「填满 → 释放 → 重烘」循环 3 次，正是「运行时增删 allotment」。
- 0100–0140：精灵只剩 1–4 个（释放到最少），绿框跟着缩到那一格。
- 0141–0144：最后 1 个也消失，板面全黑。
- 0144–0163：黑面上**格线隐约可见、无精灵残影**（暗纹理仍在，说明底板/格缝没被清成全透明）。

## 判定

有机制：动态精灵打包器（保留/释放/重排/烘焙）。片子本身只给「整板填满与清空」的节奏，不给 UV 与槽位规则 → 序列里能读出的是生命周期，不是打包算法。

## 代码落点与差距

- `src/life/impostor.js`（8 视角 Baker、整组预留、清 padding、释放）、`src/life/vegetation.js`、`src/world/view-post-extras.js`、`atlas-live.html`。
- 本轮可复算的部分：满板扩容（512→1024 原位 `rt.setSize`）、逐槽搬运、`atlas.repack` 整批重排、两路回滚；释放后的暗残影 `release({residue:true})` ×0.38 压暗。
- 缺：原素材与完整 `SpriteAtlas` 接口 ——【卡点·B 美术资产】。

## 验证

- `node tests/impostor-grow.mjs` → PASS（256→512→1024，rt/texture 身份不变，9 次 blit 序列，maxSize 封顶回滚，GPU 失败复原）。
- `NODE_PATH=… node tests/atlas-live-browser.cjs` → PASS；读回 `atlas-live-browser.json`：`gAlpha0=294780`、`gAlpha1=112132` → **112132/294780 = 0.3804**，与 note 记的 0.3804 倍逐位一致（残影读数可复算）。
- 如实：`impostor-grow.mjs` 自己标 `真实像素对拍 NOT_RUN`，像素级证据由 `atlas-live-browser.cjs`（真 GPU、存活像素逐位一致）承担，不重复计。
