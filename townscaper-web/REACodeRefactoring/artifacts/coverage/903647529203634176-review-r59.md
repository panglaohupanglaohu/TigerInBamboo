## 逐帧观察

- 帧 0–99（0–3.03s）：低俯角俯视村口。蓝方长矛兵成两排在屋前，红/深色敌方从右侧沿路推进，双方接触后短兵相接。血量槽在单位头顶（白条）。
- 帧 100–199：敌方分批上岸、沿路进攻；蓝方维持阵线。地面开始出现红色血迹斑与倒地的尸体，尸体不消失。
- 帧 200–299：战斗集中在村口左侧；血迹逐渐铺成一片，尸体叠在地面上不动。
- 帧 300–399：镜头换成更高的俯角，整条战线可见；红方尸体成片堆积，蓝方仍有成列站立。
- 帧 400–499：红方从右下角再次涌入，被蓝方长矛线挡住；命中处出现白色小 "+4"。
- 帧 500–599：村口地面被血铺满（大面积暗红），蓝方阵列仍完整；零星 "+4"。
- 帧 600–653（18.4–19.98s）：尸横遍野、血泊静止，镜头缓慢外移，画面无 UI、无结算文字、无鼠标指针。

**`dmg-plus4-crop.png`（5× 放大，关键判读）**：同一瞬间有**三个各自独立的 "+4"**，一字不差都是「奶油白填充 + 深褐描边/投影」，字高约等于一个单位身高的 1/3，屏幕正立不倾斜。数字压在**红色矛状命中特效与血雾前面**（不是被特效挡住），三个数字的位置高低错开、互不重叠——说明是"每个被打到的单位各跳一个"，不是合成一个大数。

## 判定

有机制，且本仓已落地（第 53 轮）：`src/badnorth/damage-numbers.js`（`damageValue` 只按真实掉血、`addDamageNumber` 只合并同单位、`stepDamageNumbers` 上浮+淡出）+ `battle.js` 的 `#damageTex/#damagePopup/#updateDamageNumbers`（Sprite、按相机距离定屏幕高度、`depthTest:false`、`toneMapped:false`、renderOrder 32）。

逐条对照原片：

| 原片特征 | 本仓 | 结论 |
| --- | --- | --- |
| 奶油白 + 深色描边 | `DAMAGE_STYLE.fill '#fff6e2'` / `stroke 'rgba(48,24,20,.85)'` | 一致 |
| 屏幕正立、不随单位转 | `THREE.Sprite`（始终朝相机） | 一致 |
| 屏幕高度恒定 | `h = 距离 × 0.021` | 一致 |
| 一单位一刀一条、相邻单位不合并 | `unitId` 不等直接 `continue` | 一致 |
| 压在命中特效前面 | `depthTest:false, depthWrite:false` | **一致（原片确实压在矛特效前面，上一轮"压在建筑上"的记录是把这一点当成了缺陷，本轮纠正）** |

## 代码落点与差距

落点：`src/badnorth/damage-numbers.js` · `src/badnorth/battle.js`（`#updateDamageNumbers`）· `artifacts/coverage/damage-numbers.json`。

本轮未改代码：对照下来 `+4` 这一层的形态、颜色、遮挡顺序与片中一致，没有可自证的改动点。剩下两条是真差距，但需要跨模块决策，留给下一轮：

1. **金色 "+10" 与白色 "+4" 未统一分层**：击杀飘字在 `src/badnorth/squad-hud.js` 里另走一套 DOM/canvas 路径，与这里的 Sprite 池互不知情 → 同一帧同时出现 "+4" 与 "+10" 时字号、描边、上浮速度、遮挡顺序不一致，片中两者是同一套字体与同一层。
2. **无受击方向抖动**：片中三个 "+4" 有明显的高低/左右错开；本仓只按 `y` 上浮 + `merges` 放大，横向恒在单位正上方，密集命中时会叠成一坨。
