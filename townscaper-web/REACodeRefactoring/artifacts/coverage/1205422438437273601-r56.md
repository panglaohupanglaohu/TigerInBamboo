**原文**（2019-12-13）"For doors and windows, I use som stencil buffer shenanigans to punch holes in the zbuffer. I admit it was a bit fiddly to figure out."
**本轮看帧**：sheet-00、01 逐格（0000–0199），配合旧核验全帧记录：门 / 窗处墙在 z-buffer 里被挖掉，后面有厚度的洞口与室内透出，随镜头有视差（窗格相对门框移动）。

**原缺**：原型零厚度、无侧壁，未接主管线。

**本轮做了什么**：新建 `src/render/opening-punch-layer.js`，把同一机制接到 WorldMesh 实际建筑上：
- pass A mask（renderOrder 100）：每个门窗玻璃 / 门板矩形放在墙外 0.014（夹在玻璃 0.012 与窗棂 0.016 之间），depthTest 开、不写色不写深度，stencil Always→Replace 1——只有看得见的洞口像素被标记，前排房子挡住的部分深度测试失败、不会误挖。
- pass B reset（101）：同一矩形、顶点着色器把 z 推到远平面，depthFunc Always + 写深度，stencil Equal 1 → 只在标记像素把 z-buffer 重置为无穷远（= punch holes in the zbuffer）。
- pass C recess（102）：每洞一个开口朝外的盒子（后墙 + 两侧壁 + 窗台 + 窗楣，深 0.06），stencil Equal 1 → 洞里是有厚度的侧壁与暗室内；窗棂在 mask 前面被保留，悬在洞口前。
- 只对主相机且目标带 stencil 的那次渲染可见；主相机渲进无 stencil 的 RT（描边 colorTarget）时，在本帧微任务里把 RT 升级为 depth+stencil（DepthStencilFormat / UnsignedInt248Type）再用——实测开 `fx=outline` 时 upgraded=2 且之后正常。
- 门窗记录：buildings.js opening() 加一行 `openingLog.push(...)`，结果返回 `openings`；worldmesh.js 加一行 `this.build = build`。开关 `index.html?punch=1`（app.js 一行），默认不加载。
