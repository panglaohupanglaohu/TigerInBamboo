## 逐帧观察

沿用 r169/r170 的分段，本轮复看 sheet-03 与近景截图核对「收边 + 等深」：

- **0000–0139**：固定机位环绕。顶面是大块圆角色块（草绿 / 黄绿 / 桃色），边缘柔和、带极淡同色描边；崖面米白，只有细层理线。
- **0140–0253**：抽色只留几何（灰白崖体 + 黄顶小块），崖面出现沿口折线与层理。
- **0254–0299**：颜色回来，机位拉到岛侧。
- **0300–0399**（本轮复看）：近景崖肩。顶面淡绿色块靠到崖肩线上，**沿崖肩外缘有一条窄的深绿描边**，颜色只垂到很浅的一小段就平齐收住（目测 < 崖高 1/6 ≈ 0.1 世界单位量级），崖壁其余处干净、水平层理清楚、深部完全无色。
- **0400–0549**：镜头拉回全岛，色块恢复成大斑，末帧静止。

## 判定

**有机制**，且「controlled」= 三件事同时成立：① 只在崖肩附近；② 只到固定深度（等深线）就齐平收住；③ 深部崖面一点不带。r169 量出 ①③ 与顶面图集，r170 修掉 below 口径；**本轮把 ② 量成世界米**。

## 代码落点与差距

落点：
- `src/terrain/blotch-atlas.js`：`createBlotchAtlasData`（128² 可平铺图集）· `buildBlotchRimField`（崖肩 chamfer 距离场，B 通道 = 崖肩顶面）· `blotchMasks`（rimMask 收边 / bleedMask 等深）· `blotchRimTint` + `BLOTCH_RIM_GLSL`。
- `src/terrain/blotch-tongue-c09.js`：翻崖舌头（`tongueWallMask` / `tongueTopMask` + GLSL）。
- `src/world/view-shading.js`：`?shade=blotchatlas` / `?tongue=1` 接主材质；`setBlotchRim` / `blotchParams`。
- `blotches.html`：图集 / 舌头开关 + 渗漏深度 / 笔触尺度 / 强度滑杆 + 读数。

**本轮修掉的真缺陷（r170 一直读不出等深带的真正原因）**：`BLOTCH_RIM_GLSL` 的 `bleedMask` 少了「bleed>0」这一道闸门。
`smoothstep(x, x*.35, below)` 在 **bleed=0** 时退化成 `smoothstep(0,0,below)` —— `e1−e0 = 0` 的除零区间，GPU 上钳成 1，
于是 **bleed=0 在着色器里等于「无限深」**（CPU 的 `bleed>0 ? … : 0` 正好相反）。这同时解释了 r170 的两个怪现象：
「bleed=0 仍在给崖面上色」和「bleed=0 与 bleed=20 逐像素相同」。修法：`…*step(1e-4, uBlotchRimQ.x)`；
`tests/blotch-atlas.mjs` 增一条 GLSL 文本断言，防止再退化。

**夹具也修了两处（r170 记为「怀疑共享材质」其实不是）**：
1. 探针位置：旧夹具在「格心 → 下格」的 **0.85** 处，rimDist≈0.15 > 0.10 的收边窗 → bleedMask 恒 0；改为沿该线扫到 bleed 覆盖最大的点（本片 World 落在 t=0.90，rimDist 0）。
2. 逐态 uniform **回读**（`blotchParams().bleed`）＋修掉两个坐标口径错：`readRenderTargetPixels` 第 0 行在**下**（投影的屏幕 y 必须翻成 `H−1−py`）、NDC 的 `y=+1` 在屏幕**顶部**（`py=(0.5−v.y*0.5)*H`）。r170 的 wallBand 全 0 就是这两处叠加。

**如实口径（不影响判定，写清以免下次重复踩）**：真实地形上 0.14 世界单位在 480×360 全景里约 2px，逐点采样读不出可信的带宽（`wallBand` 与近景采点只作读数、未进断言，见测试里的 `closeNote`）；等深带的世界米读数由「合成崖肩窄条（真 uniform + 真距离场 + CPU 孪生对照）」给出，真实地形用整帧阶梯与近景 A/B 作证。原片配色（桃/黄绿/米白）与反射仍未对，图集是程序化替身。
