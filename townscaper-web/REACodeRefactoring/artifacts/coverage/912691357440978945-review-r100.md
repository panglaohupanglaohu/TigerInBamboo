## 判定

有机制（战斗天光柱），触发语义已在第 91/93 轮**永久降级**，本轮不动。

本轮的实质产出是**量测工具**：低 α 平台段（0278–0285，α≈0.10）以前两种方法都得不到可信值 ——
阈值计数在这些帧里命中不到柱芯（判 0），v3 的逐帧找柱芯又会漂到旁边的高亮像素上（给出 1.0–1.14，明显偏高）。
「多帧同点斜率法」用**固定像素集 + 逐像素 anchor + PCA 方向**解出平滑曲线，平台段稳定在 0.10–0.13。

## 代码落点与差距

- 新增 `tools/beam-alpha-slope.py`：
  - `--selftest`：合成斜坡（真值 0.10/0.16/0.24/0.34/0.46/0.58/0.70 + JPEG 级噪声 + 有渐变底色），
    斜率法最大误差 **0.001**，同一批数据上 v3 复刻**全部判 0**（最大误差 0.580）——
    这是「为什么要换方法」的机器可复现证据，不是口头结论。
  - 实测 912：`--frames 274-289 --ref 288 --anchor 265`（anchor 取无柱的 0265），
    曲线 0274:-0.06 → 0277:0.00 → **0278–0285 平台 0.09–0.13** → 0286:0.52 → 0287:0.87 → **0288:1.00** → 0289:0.83 → 消失。
    与联系表看到的「平台 → 一帧内跨到亮 → 突灭」逐帧对上。
- 方法边界（写死在脚本 docstring 里）：单靠颜色只能解出 α(t)/α(cal)，绝对值需要一个已知 α 的标定帧
  （`--cal-alpha`）。本轮拿「峰值帧 = 1.0（全不透明）」当标定，且 anchor 必须是无柱帧 ——
  用带柱的最暗帧当 anchor 会把整条曲线压低一个 α（自检里踩过，误差正好等于 anchor 的 α）。
- 差距：① 峰值帧是否真的 α=1.0 没有独立证据，所以上面是「相对 0288=1.0」的口径；
  ② 0270–0277 这 8 帧的 α 在 0.00–0.05 之间，接近噪声底，不给绝对值只给「有/无」；
  ③ 第三机位宽度仍判「当前素材不可测」（第 97/98 轮结论不变）。
