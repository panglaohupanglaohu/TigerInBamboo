## 判定

**有机制**，三件事：

1. **投影 patch（草 / 水）**：花纹是世界坐标（球面方向）的函数，跨格/跨块连续 —— 片里绿面圆点与蓝面团块都在格子边界上不断裂。
2. **手工 UV 岸带（shoreline）**：`u` = 沿岸弧长（决定白点的等距相位）、`v` = 到岸的有符号距离（决定沙滩深浅、白浪线所在层、岸缘暗线）。片里白点严格沿弧长等距、白线严格与岸平行，正是手工 UV 的签名。
3. **高度混合**：原文自述 "some height based blending"；片中沙滩↔草↔水的过渡没有硬边，是窄带渐变。

## 代码落点与差距

- `src/terrain/patch-blend.js`（文件头署本片 ID）
  - `buildPatchField(world)`：在共享 World 上栅格化 `land / SD（有符号距离，陆正水负）/ U（沿岸弧长）/ ground`；岸线来自 `core/shore-loops.js`。
  - `makePatches()`：`water`/`land` = `mapping:'project'`（只用世界 XZ），`shore` = `mapping:'uv'`（u/v），三者各有 `coverage/heightAt/color`；岸带宽度用**世界单位的有符号距离**定义（不是海拔差），故缓坡处不会暴涨。
  - `renderPatches(field, patches, mode)`：`hard` 硬切（对照基线）/ `alpha` 覆盖平均（无缝但糊）/ `height` 前两名按高度差 `smoothstep`（原文做法），并回 `ids`（每个纹素归哪个 patch）与 `soft`（过渡带）。
  - `seamStats/edgeJump/abModes`：边界 ±r 带的梯度 vs 内部梯度、跨 patch 边一像素跳跃、三模式并列。
- `src/world/view-shading.js` 的 `?shade=patchblend`：`shPatchBlend/shShore` 直接进 View 主材质（`uShPB*` 纹理 + uniform），实景里岸带贴着真实 World 岸线画。
- 页面入口（本轮新补）：`patch-blend.html` —— 同一 World 的整岛 patch 图（三种合成切换）+ 世界空间近景窗 + **岸带 UV 展开条**（横 u、纵 v，原片那扇窗口展示的就是这张图集）。
- 本轮补掉的形制差：① 岸带**白浪线**原来一条没有（模块与 GLSL 各补一道判据，两条与岸平行的白线，v = .34/.58）；② 岸带**白点原来是竖条**（`dot < .2` 只按 u 判、v 整带染色）→ 改成 `hypot(du·spacing, (v−.16)·.9) < .075` 的圆点。
- 差距（如实口径，不计缺口）：场景路径只画**陆侧半幅**岸带（`sd ≥ 0`），水侧由水面片自己承担，所以白浪线在实景里落在沙滩内侧而不是水里；世界空间岸带只有 9 纹素宽（res 0.1），实景里读作断续小斑，不像原片那样一整条连续带；本仓是 World XZ 平面投影，原片是球面 UV（`Planet.psd`）；纹理是程序化替身（无手绘草缘/暗紫岸缘两层）。
