## 判定

有机制，而且是本仓的核心机制：**mega texture ↔ 六向光体积 的交替往返**（体积从贴图 gather → 贴图用体积重新照亮 → 再 gather …），外加「约第 3 轮后看不出」。

旧 `note` 的「完整贴图/体积往返反馈仍缺 · 卡点 A 机制未做」核实为**过期账（第 16 次同型）**：
`src/light/megatexture-gi.js` 的 `bakeMegaTextureGI` 就是这条往返 —— `snap('reset')` → 直射写进 mega texture（体积仍全 0）→ 循环里 `gatherVolume()`（命中经 SDF 的 RG 反查 mega texture 纹素）→ `relightTexture()`（`sampleLV` 按法线取体积 → 写回 exitance）。
`src/world/view-c11-megagi.js` 接管 `view.bakeGI`（`?c11=megagi`），`megatexture-gi.html` 有「慢放反弹序列 / 结束慢放」入口，node 测试 `tests/megatexture-gi.mjs` 一直绿。缺的从来不是机制，而是**没人从页面上把这条序列放出来量过**。

## 代码落点与差距

落点：`src/light/megatexture-gi.js`（`bakeMegaTextureGI` / `gatherVolume` / `relightTexture` / `snapshots` / `bounceStats`）·
`src/world/view-c11-megagi.js`（`showStage` / `endStages`）· `megatexture-gi.html`（三张贴图 + 慢放按钮）。

本轮核实出的**两个真缺口**（都在页面/展示层，机制主线一行未改）：

1. **慢放阶段漏关补光**：`showStage` 只关 `ambient / hemi`，本仓还有一盏 `view.fill` 方向光（`setTimeOfDay` 的 `P.fill=0.45`）→ direct 阶段「只有直射、阴影纯黑」在原片是 9.48% 暗像素，本仓只有 **0.63%**，序列少掉前半段。
   改法：`showStage` 一并保存并清零 `view.fill.intensity`，`endStages` 还原（实测 direct 暗像素 0.75%→1.91%，reset 18.0%→35.9%，原片 39.6%）。
2. **「结束慢放」不打断播放循环**：旧 `play()` 是 `for` + 900ms `setTimeout`，没有取消令牌 → 点结束后循环仍每 900ms 覆写 stage（本轮测试第一次跑就被它抢占，`reset` 抓到的是上一阶段的画面）。
   改法：`playToken` 令牌 + 每次迭代校验 + `#end` 里 `playToken++`（实测点结束后 1.4s `stage` 恒为 `null`）。

没有改的（如实口径，不计缺口）：
- 本仓 `reset` 阶段残留极细的高光描边（原片是纯剪影）；`reset` 暗像素 35.9% vs 原片 39.6% 的差主要是取景（本仓整岛更小、背景海面占比更高）。
- 原片 direct 阶段 9.48% 暗像素、本仓 1.91%：本仓台地是逐层实心体素，投影阴影面积本来就比原片那个白色素坯模型小。
- 原片场景是白模建筑群，本仓是地形岛（同一套 GI，不同 World）。
