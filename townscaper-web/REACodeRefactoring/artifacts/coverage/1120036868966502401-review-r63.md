## 逐帧观察
- 0000–0010：全场只有浅灰底 + 白网格，右上有红/绿/蓝 gizmo；0002–0004 出现黄点（格心标记）并迅速增多。
- 0011–0035：白网格线加密到「每格一个不规则四边形」；0022 起建筑体块一个个长出（灰蓝块 + 顶部三角剖分线），格角出现**黑色小方块**（crop0027 放大可见：每个格角一个约 3–4px 的实心黑方块，不是白点）。
- 0040–0065：红色闭合折线沿格边勾出两片区域（crop0075/crop0165 可见红/蓝两条**沿格边**的折线，同一高度上并行走向），gizmo 挂在选中格上（黄绿半透明填充 + 红/蓝箭头）。
- 0070–0089：出现**明暗整格填充**——已放置 tile 的格整格铺成近黑（crop0165 里方块状深色格，格内有 tile 网格），空格仍是浅灰；相邻格因此读起来像棋盘，但成因是「该格有没有东西」，不是按坐标奇偶。
- 0400–0489（sheet-04）：视角推近后，0470–0489 顶部出现**黑白相间的整格棋盘**（相邻格严格反色），并且格上有红/蓝/绿/黄小圆点（逐格状态标记）。

## 判定
有机制。两条仍未落地：
1. **区域边界按「区域 id」稳定配色**：同一条闭合区域在相邻高度层应保持同色。本仓 `ContourOverlay.refresh()` 的 `regions` 颜色取 `(h-1)%6`——按高度层循环，同一片区域换一层就换色（sheet-04 里红线跨层变成蓝线就是这个现象的物理对应）。
2. **候选棋盘按 WFC 逐格候选状态上色**：0470–0489 的棋盘是「已定 / 未定」的逐格状态可视化。本仓 `setCandidates()` 用 `Math.floor(cx/1.4)+Math.floor(cz/1.4)` 的空间奇偶——与候选状态无关，是纯视觉近似。

- 差距：本轮 **未改代码**（90 分钟预算全给了烟雾的 native 化）。两条都具备落地条件：
  - 区域 id：按层做连通分量，再与下一层的分量按格重叠继承 id，`color = palette[id % 6]`；
  - 候选状态：`setCandidates(cells, {domainSize})`，`domainSize===1` → 近黑、中间值分档、等于全集 → 不铺。
