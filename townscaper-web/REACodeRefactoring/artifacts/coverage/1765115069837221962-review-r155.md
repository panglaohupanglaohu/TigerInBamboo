## 判定

**有机制**，而且是原片自述那件事本身：

1. **臂 = 一次真实碰撞查询的递归解析路径**：从树根开始逐层往叶子走，分叉处就多出"手指"；青色是直角折线（先横后竖），指尖落进当前候选框。
2. **黄框 = 当前候选位置**（0141 帧清楚了这一点，前几轮只把它当成"高亮块"）。
3. **"板子越碎 → 手指越多"**：片子里能直接看出 —— 0012–0054（大块空区）臂只有 1–2 根手指且段很长；0185–0246（几十个小孔）臂有 3–5 根手指、段很短、拐角多。
4. 无 3D 视角、无删除、无统计数字。原文标题里的 "recursive tree parsing" 指的就是 ①。

## 代码落点与差距

- `src/core/atlas.js`（文件头第一行即署本片 ID）
  - `allocate()`：显式栈的 first-fit + guillotine 切分，`trace` 逐事件记 `{x,y,w,h,depth,parent,decision}`，`decision ∈ size|branch|used|fit` —— 这就是"递归树解析"的**真实**事件流；
  - `canPlace()`：给定整数坐标的树剪枝碰撞查询（`outside` 事件 = 被包围盒剪掉的子树）；
  - `allocateAt()`：**跨叶放置**（一个槽可以吃掉多片 free 叶），`#handles` 记住一次槽对应的所有叶节点；
  - `recursiveFill()`：REACode `RectBin.recursiveFill` 的移植（深度优先的手臂、缩小的块），同时报 `fingers`（probe 口径）与 `treeFingers`（提交查询真正走到的叶子数）。
- `src/core/atlas-c09.js`（文件头署本片 ID）
  - `armFromTrace(trace, query)`：把 trace 变成手臂折线（父中心→子中心，先横后竖）+ 指尖（叶中心→叶与查询框重叠部分中心），`fingers` = 走到的叶子数、`pruned` = `outside` 数；
  - `placeBottomLeft()`：候选 = 板角 + 已放块角 + 有界随机点，按 (y,x) 排序逐个用 `canPlace` 判、`allocateAt` 落位（**可跨叶**，存活槽不动）；
  - `treeLayers()` / `project3D()`：3D 展开图的数据与正交投影（根在最上、每层按深度往下叠）。
- 页面 `atlas-tree-c09.html`：2D 手臂视图 / 3D 展开视图两态、暂停、单步、自动增删；`#st` 报「本次手指 N（剪掉 M 枝，试了 K 个候选）」。
- 旧 `note` 的「原 3D 树 / 跨叶候选待补」= **过期账**（第 34 次同型）：跨叶走 `allocateAt`，3D 树走 `treeLayers + project3D`，本轮实测两者都在跑（跨叶槽 71/150、3D 27 层）。
- 本轮唯一改码（都是页面入口/探针，不动机制）：`?arm=0` 关手臂档（做像素 A/B）、`window.atlasTree` 增 `project3D` / `leavesInSlot()` / `canvas()`。

画面形制差异（如实）：原片叶框只画"割线"（新裂开处），本页把**每片叶子的边框**都描了，碎片化后画面比原片更密；原片无 3D 段，本页的 3D 展开是给姊妹片 1764958522398146667 的附加视图。这两点都不影响机制判定。
