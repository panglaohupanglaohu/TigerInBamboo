## 片子机制（158 帧，sheet-00/01 全看，0021 原尺寸回看）
- 按左下角 Go! 开始。体积里每一格都有一个小线框字形，表示这一格还没坍缩。字形越大，剩余可能越少。
- 黄色的格是这一步被传播改写的格，黄色成片出现，就是传播波。
- 坍缩完的格换成实体构件，构件跳着出现（最少可能数优先）。
- 建成后机位推近，并绕塔转一圈。表面按层分色：薄荷绿、淡紫、粉。

## 本轮做了什么
- 新建 `src/build/wfc-bitset.js`，规则直接复用 multitile-wfc 的 buildParts / facesCompatible，不另写规则。传播引擎有三档：
  - `array` 基线：Uint8 域，逐个找支持。
  - `bitwise`（对应 794）：域和支持表都是 Uint32 位集，传播时 `dj &= OR sup[d][p]`，可能数用 popcount 计。
  - `cached`：缓存支持并集（供 797 用）。
- 回溯有 `snapshot` / `trail` 两种。
- 选格、随机、回溯的骨架与 solveMultitile 完全一致。AC 不动点唯一，所以各档逐格同解。
- `record` 模式记录每一步事件（本步被改写的格、新的可能数、已定部件）以及回溯事件。`replayState(res,k)` 把事件折算成第 k 步的画面状态。
- 新建 `wfc-bitset.html`（three.js），内容如下：
  - Go! 按钮。
  - 未定格画成线框，框的大小按剩余可能数缩放。
  - 本步被改写的格显示为黄框和黄点。
  - 已定格画成实体：柱细、楼板薄、其余满格，多格拱 / 塔 / 厅整块出现。
  - 逐层分色：薄荷绿 → 淡紫 → 粉。
  - 建成后机位推近并绕塔转。
  - 「每步 ms」可调；填 0 时按解算墙钟实速回放。
  - HUD 显示三档计时和工作量。
- voxel-ghost.html 加了一个指向新页的纠正链接。旧 voxel-ghost.js 保留未动。
