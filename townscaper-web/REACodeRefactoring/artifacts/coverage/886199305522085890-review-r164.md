## 判定

有机制，且是**纯调试可视化**：窄道判据 = 可走图「度 2 且两侧不互通」；点按弧长等距铺在通道中线上、贴地；视觉上 = 世界尺寸的点 + 逐点按视线遮挡淡出。

## 代码落点与差距

- r160 已把判据/淡出抽成 `src/world/passage-overlay.js` + `passages.html`（通用入口，混合格/四方格两套 World）。
- **本轮收掉的唯一剩余**：北境战斗**默认**点径还是固定 7px 屏幕点（近景点距/点径 3.3，显疏）。r160 试翻世界尺寸失败（可读性 40.3→21.1），本轮查明**不是机制问题，是量具问题**：
  - r160 的 `#passagePx()` 按 `px = size·(H/2)·fovK/depth`（`fovK = 1/tan(fov/2)`，本例 ≈2.14）反算 size，
    而 three 的 `sizeAttenuation` 实际是 `gl_PointSize = size·pixelRatio·(H_css/2)/depth`（**没有 fov 因子**），
    所以「按 px 反算 size」把点缩到实际的 1/2.14 → 中位对比度掉到 21.1。
  - 另有一个真限制：`PointsMaterial` 只有**一个全局 size**，抬 size 会把近端的点也钉死，做不到「近端随距离放大、远端保底」。
- 改法：
  - 新增 `src/world/point-floor.js`：`installPointFloor(material,{minPx})` 在顶点着色器末尾逐点 `gl_PointSize = max(gl_PointSize, uPointFloor)`，
    下限按**物理像素**给（`minPx(CSS) × devicePixelRatio`）；`pointPx(size,depth,H,minPx)` 提供与 three 同口径的换算；`customProgramCacheKey` 串上上游键，避免程序缓存串味。
  - `src/badnorth/battle.js`：点材质默认 `sizeAttenuation:true, size:0.13`（= 点距 0.28 的 1/2.15）+ 下限 7 CSS px；新增 `setPassageDots('world'|'screen')` 与 `passageDotPx()`（逐点读近/远点径、被托底比例、深度范围），`passageStats` 每帧带上；`update()` 每帧按 `renderer.getPixelRatio()` 同步下限。
  - `src/badnorth/battle-c02.js`：原 `passageWorld`（切世界尺寸）语义反转成对照开关 `passageScreen`（切回固定 7px），`?c02=passageScreen` 即旧口径；`#passagePx()` 改为直接读 `passageDotPx()`，不再自己反算 size。
  - `src/world/passage-overlay.js`：同样装下限（真在着色器里托底，不再只是读数托底）；`dotPx/measure` 去掉 fovK；`dotWorld` 0.09→0.13（与战斗侧同口径）。
  - `src/ui/scene-capability-panel.js`：开关标签改为「窄道点线（旧·固定 7px 对照）」。
