## 逐帧观察

- **0000–0100**：红砖多层塔群立在浅色地台上，左端粉色塔 / 右端青色塔 / 中间黄色小塔（三色附属体块）。**每一层顶面都是平台**：同一个暖橙面、无脊线、无两面明暗差（frame-0030 的 4× 裁切逐层看得很清楚），临空边一圈**矮护墙 + 浅色压顶**，护墙下**白色腰线**外挑；平台上直接坐烟囱；塔身双扇小窗白框，旁边两道外挂石阶。
- **0100–0200**：塔被编辑加高（右侧加一层、左侧加顶盖），中层向右伸出一块**木面平挑台**；平台边缘的护墙随层数增多。整段没有生物群（"紫点"是树冠，有树干、随楼体增删、不位移）。
- **0200–0300**：塔长到 5 层，出现跨楼木梯、拱形门洞与白门；地台边缘加石砌护岸。顶面仍是平台。
- **0300–0343**：终帧 = 5 层砖塔 + 两段外阶 + 三个彩色附属体块 + 若干树。**全片没有一处坡顶 / 山墙面**。

## 判定

有机制：多层砖塔的**逐层平顶平台 + 临空边矮护墙 + 檐下白腰线 + 平台坐烟囱**。
r200 已撤销「群体寻路」这个前提（原文那句是作者猜测），本轮沿用该结论，不再记作缺口。

## 代码落点与差距

- 落点：`src/build/buildings.js` 的 `buildRoofs()`（按 `world.regions()` 分区，`base = h·L`）+ 新函数 `flatRegionRoof()`。
- r200 的核验结论：`buildRoofs` 只出坡顶/山墙，栏杆只在 `h === 1` 的地面院落收集 → 片内「每层顶面平台 + 临空护墙」在本仓无法表达。
- 本轮实现（`world.flatRoofs`，默认关）：
  - 每格顶面铺**平台板**（`w.poly` 于 `base`，暖橙色 `K.roof/K.roofAlt`，同一 hash 口径）；
  - 沿**临空边**（邻格不在本 region 且不更高，与坡顶檐口同一判据）立一圈**护墙**：`w.beam` 高 `0.062`、厚 `0.05`，顶面再压一条浅色（`K.plaster`）压顶；
  - 护墙下加一道**白腰线**（外挑 `0.03`、高 `0.05`）；
  - 平台上按 hash 34% 概率坐**烟囱**（`K.chimney` + 深色盖），不再走「找坡面 seat」那条路；
  - 只读账：`roofStats.flatRegions / flatCells / flatRimSegments / flatRimLength / flatDeckArea / flatChimneys` 与逐区 `flatTerraces[{h,cells,base,minId,rimSegments,rimLength,deckArea,chimneys,gables,minY,maxY}]`；`gables` 恒 0。
- 页面入口：`src/world/app.js` 的 `?flatroof=1`（写 `world.flatRoofs` + `touch()` + `invalidate()`）；默认档不设该 flag，走原坡顶路径，几何逐顶点不变。
- 为什么用 `beam` 而不是手写四边形：平台护墙/腰线是薄条，手写四边形容易被自身绕序背面剔除（第 56 条坑），`w.beam` 是闭合棱柱，侧视俯视都稳。

## 验证

- `node tests/flat-terraces.mjs` → **PASS**（quad/mixed × town/town/fusion 共 6 组；148 个平台区 / 455 格 / 953 护墙段 / 149 烟囱）：
  - 默认档（未设 `flatRoofs`）与 `flatRoofs:false` 顶点数相同、无 `flatTerraces` 账；
  - 每格「恰好落在 `h·L` 上的水平面面积」== 该格多边形面积（误差 <1e-6）；默认档该量 <0.5（坡顶没有水平整板）；
  - 护墙段数/长度 == 按 `world.neighbor` + `region` 独立重算的露边数与边长和（1e-9）；
