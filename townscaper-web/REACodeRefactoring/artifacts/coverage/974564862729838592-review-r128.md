## 逐帧观察

- **背景**：无贴图的灰紫色地形（白模），整片地面**铺满三角网**（细黑线），崖壁/台地都用同一个网格；右上角有一个方形井口/坑。
- **0000–0059**：白色三角形边角在画面中左，白球带 **RGB 三色轴箭头**（红 +X、绿 +Y、蓝 +Z）压在三角形靠上的一条边上；鼠标光标（手形）就停在球上。
- **0060**：三角形较窄，白球位于三角面上方一点；球在面上的**投影点**（小白点）到三个顶点各连一根**红 / 绿 / 蓝**细线；三个顶点处各有一颗**同色小球**，球径 ∝ 该顶点权重。三角形三条边是**白色**的（与周围黑细线明显不同）。
- **0060–0330**：白球被拖着在三角面上移动；三角形本身也会**拉窄 / 张开**（0060 窄、0200 与 0330 明显更宽、朝向也变了）；球有时压在边上甚至越出边（负权重出现时对应顶点球变小/变暗）。
- **0330–0477**：球仍在三角面附近来回，光标始终压在球上（说明是实时拖拽，不是预渲染动画）；0390+ 球被抬离平面的幅度变大，白色竖直连线变长。

## 判定

**有机制**，且是同一件事的两种拍法：任意朝向平面上的三角形重心坐标。

1. query 点 P 由参数 (u, v, h) 给出：面内 (u,v) + 沿面法线的高度 h → 球可以离开三角面悬在空中；
2. 三个权重 w = (1−u−v, u, v) 直接用**预算好的两条对偶向量**求得（1 次减法 + 每坐标 1 点积 + 离面距离 1 点积）；
3. 投影点 Q = Σ wᵢ·Vᵢ，P→Q 沿法线；顶点球大小 ∝ |wᵢ|，负权重（点在三角形外）变暗；
4. 三角形本身可被拖动变形（第三个顶点沿中线走 → 面积线性变化）。

## 代码落点与差距

- `src/core/spatial.js`：`baryPrep3(a,b,c)`（任意朝向平面，`g_b=(e2×n)/|n|²`、`g_c=(n×e1)/|n|²`，避免 d00·d11−d01² 的抵消；带 `normal` / `distance` / `ops{1,1}` / `degenerate='flag'` 退化回退）、`baryCramer3`（对账用朴素 Cramer）、`baryPoint`、`baryInside`。
- `src/world/bary-gizmo.js`：`gizmoState(tri,{u,v,h,spread})` 纯函数 + `BaryGizmo`（真实共享 World 的一格扇三角上叠 gizmo）。
  **本轮补的（机制主线未动）**：
  1. `attach(canvas)` —— 真指针拖拽：抓白球 → 射线打到三角面反解 (u,v)（球可越出三角形）；抓第三个顶点 → 沿 A–B 中线改 spread；**Shift + 拖球 → 沿法线抬升 h**（轴向拖拽用"射线与轴线最近点"，不是"垂直视线的平面"，后者位移恒 0）；
  2. `params()/state()/triArea()` 三个只读面 + `dragStats{mode,starts,moves,ends,last}` 台账（页面和测试都从这里量，不读日志）；
  3. 三角形三条边改用**细长盒子**画（`LineBasicMaterial` 的 linewidth 在 WebGL 里恒 1px，原片白边比 1px 粗），不再用 1px LineLoop；
  4. `pickGizmoCell` 增加"周边 2 圈最高点最低"的空旷度排序 —— 原来的"离岛心最近的平整格"会贴着塔基，相机和三角形被墙挡住（第一版截图直接是一堵墙）。
- `bary-gizmo.html`：真指针入口 + 拖动时滑杆跟手（否则 headless 低帧率下下一帧会用旧滑杆值把拖出来的参数覆盖回去）+ 背景三角网（`cellWire`，按真实格扇三角画半径 6.5 内的黑细线，`?wire=0` 关）+ 机位钉住（`?dist/?pitch`，世界异步生成后 app 会再 fit 一次相机）+ `?hud=0` 清屏 + 启动竞态修复（iframe 命中缓存时 `onload` 可能先烧掉，补一次启动）。

**如实口径（造型差，不计缺口）**：
1. 本仓地形是真彩色（草地 / 沙滩）+ 旁边有建筑，原片是无贴图灰模 → 配色差一档；
2. 原片三个顶点都能自由拖，本仓只让第三个顶点沿中线拉窄/张开，另两个固定在网格顶点上 → 交互自由度差一档；
3. 原片背景是整片真实导航三角网，本仓画的是同高格半径 6.5 内的扇三角边（视觉等价，不是全岛）。
