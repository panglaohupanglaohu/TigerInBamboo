- 原文：The pathfinding in some levels does get a bit convoluted

## 逐帧观察

等距俯视整座关卡，镜头缓慢平移，地形是一座两级台地的岩石小岛：上层平台长草、中间一栋白色小屋、崖壁上有几处洞口与外挑的岩台，四周围着浅灰水面。

- 0000–0010：无路线。台上守军小队（白盔蓝身、四面**紫红菱形盾**）聚在左侧台地，队旗是品红。图里能看到几条白色点线只是雨丝。
- 0011–0019：底部 HUD 出现三个按钮 **Select / Move / Swap**（Move 高亮成紫底）。
- 0020–0070：画面出现**白色虚线点路线**：从上平台的小队出发，先沿台地横走到崖沿，在沿口**向外抛出一条弧**、贴着崖壁落到下一层，再沿下层台地继续横走到目标点。点与点间距基本相等，弧上密、平地略疏；同一时刻不止一条（两条小队各一条）。
- 0071–0090：路线消失（下达指令后），小队开始沿同一路径下山；崖沿处确实是"先横、再往下一折、再横"。
- 0091–0199：小队分头绕过崖壁上的洞口与外挑岩台，路径两度折返——这就是原文说的 "convoluted"（绕）。
- 0200–0385：镜头继续平移，台上还有第二队（蓝色圆盾）与橙色旗小队；无新路线预览，只有行军。

全程无调试线框、无路点编号、无网格；路线预览只在 Move 模式悬停时出现，是玩家可见的 UI，不是调试可视化。

## 判定

**有机制**：小队移动指令的**路线预览**——把导航路线画成一串等间距白点，跨层处从崖沿外抛一条弧落到下层，平地拐角是圆角。

它与"寻路"本身是两件事：路线怎么算（navgraph 的 Dijkstra + 楼梯）本仓已有；**路线怎么画**是本轮补的。

## 代码落点与差距

新增 `src/core/route-preview.js`：

- `landArcs()`：跨层段（落差 ≥ minStep）换成「沿口 → 外抛弧 → 落点」，弧用二次贝塞尔，起点切线水平、终点切线陡落；崖沿位置由 `at`（数值或回调）给出，导航图有真实楼梯格对时必须传真实位置，否则弧会落在台地中间、自己埋进岩体。
- `roundCorners()`：内部拐点做二次贝塞尔圆角；**陡腿的拐点默认不圆角**（贝塞尔是从拐角内侧切过去的，在凸棱上切进去就是扎进岩壁）。
- `buildRoutePreview()`：`landArcs → roundCorners → samplePath`，复用既有等弧长采样。
- `buriedSamples()`：统计比地表低的点数，用来量"预览点有没有埋进岩体"。

差距（已写进下一轮）：

1. **没接进 `src/badnorth/battle.js` 的 `#drawPath`**。现在那边还是节点直连 + 等弧长撒点，斜穿崖体；接的时候要把导航图楼梯的真实格对位置传进 `at`，否则弧会落错地方。
2. **预览还是 2.5s 淡出的一次性点串**，片子里是 Move 模式悬停时随目标持续刷新的预览。
3. 片子里多条路线同时显示（每队一条），本仓只有当前选中队一条。
