## 逐帧观察

- 0000–0019：纯线框视图，白/浅灰 1px 线是不规则四边格网；几颗黄色小点在格心；0002 起出现红色 1px 闭合折线，只走格边、在格角折弯。
- 0020–0064：一块深色楼板落到网格上；楼板边界出现彩色细线（红 / 紫 / 蓝），仍是 1px、仍在格边上；0028 起有 RGB 三轴 gizmo（红/绿/蓝箭头 + 两个半透明方块手柄）挂在角上，一直不大不小。
- 0065–0149：多栋楼板排开，红线上出现「捏点」（两块只在一角相接时线在顶点断一下），并有一圈黄色粗折线套住被选中的那一格（放大裁切实测约 3px，明显比 1px 的白网格线粗）。
- 0150–0249：镜头绕到侧面后，白网格线在斜面上依旧 1px 不随远近变粗；黄折线的粗细也不随远近变；gizmo 大小同样恒定。
- 0250–0330：俯视，整片红色边界环 + 黄点，gizmo 在画面中部。
- 0331–0499：城市生长起来，网格点仍在建筑上方显示，红色细线跟着可见格集合更新。
- 0500–0702：推到极近（672–702 帧建筑占满画面），彩色小点/线依然只有 1–3px —— 说明这些调试层是**屏幕空间定宽**，不是世界空间几何。

## 判定

**有机制**：格集合 → 沿格边的区域边界（1px 折线，有闭环 / 开放端 / 捏点）；被选中的单格用**约 3px 的金黄闭合折线**套一圈（内部只有很淡的填充）；另有一个屏幕恒定尺寸的 RGB 三轴移动 gizmo。

## 代码落点与差距

- `src/core/region-boundary.js`：格边段 → 按格点串链 → 闭环 / 开放端 / 捏点。
- `src/world/contour-overlay.js`：`regions` 用 `THREE.LineSegments`（硬件 `gl.LINES` → 天然 1px），已与片子的细线一致。
- **本轮补的两件**：
  1. `selectCell()` 除原有半透明填充，再生成一圈**屏幕空间定宽**的金黄折线（每条边一个四边形，顶点着色器把两个端点投影到 NDC、取屏幕法向、按 `uWidth × 2/画布高` 偏移 → 远近都是同一个像素宽）。实测 width 3.5px、`outlineQuads = cell.pts.length`。
  2. `#buildGizmo()`：红 X / 绿 Y / 蓝 Z 三根箭头（线 + 锥头）+ 两个半透明方块手柄；`update(camera,h)` 每帧按 `相机距离 × 0.09` 缩放当地世界尺寸 → 屏幕上大小恒定（近 d=9 时 0.806、远 d=22 时 1.976，比 2.45 ≈ 距离比 2.44）。
- 仍缺：① 片中网格点（格角小白点）没做成独立图层；② 黄点（格心标记）与「黄色竖列」没有；③ 边界线在片中会按区域换色（红 / 紫 / 蓝），本仓只有单色红。
