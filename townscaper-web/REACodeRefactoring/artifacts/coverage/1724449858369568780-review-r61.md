## 判定

有机制：**节点式数据绑定** —— bool 资产 → Select（在 −226.9 / −33.8 两值间选）→ LerpTowards（Speed 20，逐帧逼近不冲过）→ Compose2（拼成 Vector2）→ Event（写回 UI 的位置）。图本身是**可存可载的资产**。

## 代码落点与差距

- `src/core/node-graph-runtime.js`：① 每个节点工厂补 `type` + `params`（可序列化的元数据）；② 新增 `NodeGraph#serialize()`（导出 节点类型/参数/连线/**有状态节点当前值**）与 `NodeGraph.fromJSON()`；③ 新增 `NODE_REGISTRY`（类型名 → 工厂，sink 的运行期回调由 `sinkFn` 注入）；④ `sink` 的"上次值"从闭包挪进 `state.last`，这样序列化能带上、载入后不会把"没变"误判成"变了"；⑤ `buildToggleChain` 增加 `load(json)`。
- `node-graph.html`：新增**连线图**（7 个节点框 + 6 条连线，每帧重画、框里带实时值）+ 导出/载入 JSON 的按钮与文本框。
- 本轮补上的：整张图的序列化/反序列化（含 lerp 当前值，载入后位置不跳回起点）、可视化连线图。
- 仍缺：连线图是**只读**的（不能拖节点/拖线/增删节点），原片是完整节点编辑器；原片面板里的字段名与分组来自其资产，本仓只挑了真正起作用的那条链。
