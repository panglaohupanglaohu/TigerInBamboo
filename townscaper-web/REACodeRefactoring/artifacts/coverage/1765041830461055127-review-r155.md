## 判定

**有机制**，四件事都在片子里：

1. **删除**（"Now supports removing rects too!"）：块会真的消失并留下幽灵框，之后同一位置还能被别的块用掉。
2. **越删越碎**（"the bin space gets quite fragmented"）：0050 之后小孔从个位数涨到几十个，终帧成片。
3. **只能兄弟合并、不能随手整理**（"I've tried to optimize it on the fly but I can't figure out how to when it get sort of interlocked"）：碎掉的孔长期留着，片子从头到尾没有一次"整块重排"的跳变（板子布局只增量变化）。
4. **仍然装得紧**（"Still packs tight though!"）：碎了以后块还是一片连一片，没有大面积空洞。
5. 近侧视角那一团白线 = 按深度叠起的树（3D 树），不是噪声。

## 代码落点与差距

- `src/core/atlas.js`（文件头第二行署本片 ID）
  - `free(rect)`：只认自家 handle（`#handles` WeakMap），**只做兄弟合并**（`p.a && !p.a.used && !p.a.a && !p.b.used && !p.b.a → 置空`），并沿父链闭包自底向上走一遍；不扫全树、不做全局重排 → 正好是"interlocked 就没办法随手整理"这件事；
  - `remove(key)` / `repack()` / `grow()`：key 级删除与显式重排（重排是**手动调用**，不在放置路径上）；
  - `report()` 的 `freeLeaves / largestFree / largestShare` 就是"碎不碎"的读数。
- 页面 `atlas-tree-c09.html`：`?remove=1` / `?removeAt=N` 或 UI 勾「开始删除」，`#st` 报「空闲叶 N/M · 树深 K」。
- 旧 `note` 的「跨叶放置及完整 RectBin 接口仍缺」= **过期账**（第 35 次同型）：跨叶走 `allocateAt`（本轮在姊妹片里实测 71/150 槽跨叶、面积逐槽精确），RectBin 侧的 `shelfPack` 基线、`place` 候选搜索、`repack/grow`、`rects/report` 全在。
- 形制差异（如实）：原片正面视角把树的割线画成**白细线压在块上**，本页画成深色叶框；原片的近侧视角是**同一块板绕相机压到 0°**，本页 3D 视图固定在 yaw 35°/pitch 38° 并把每层按深度抬起来。两者构造同源（都是 `treeLayers` 的节点框按深度叠 + 父子连线），但机位不同。
