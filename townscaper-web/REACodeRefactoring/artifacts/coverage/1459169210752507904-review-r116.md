## 判定

**有机制。** 机制三层：

1. **混合网格**：不规则四边格为主 + 保留下来的三角形（三角带 = 四边格阵列朝向翻转处的过渡带）；
2. **补丁着色**：同一块补丁（四边格朝向完全一致的一片）同色，补丁之间用品红缝分开，三角格填绿，**每个四边格内部画两条对角线**；
3. **周期重铺**：每 40–60 帧清空换种子。

本轮**核实推翻**了第 19 轮 note 里挂着的三条"缺口"：

- 「格心彩色小块语义不可证」→ 3× 放大后看清：格心没有色块，那些"紫/蓝/黄小方块"是**补丁缝折线 + 三角带里的小三角边**；格心只有**对角线 X**（这是我们此前完全没画的一层，本轮补上）。
- 「3D 透视视角」→ 全片所有格子在画面各处尺寸一致、没有任何纵深/遮挡，是**平面正视**（补丁各自旋转 0°/30°/60°），不是透视 3D。
- 「接 world 实景」→ 609 帧里没有任何建筑/地形/水面，只有格子调试视图，原片没有"接实景"这件事。

但**真缺口仍在**：原片每块补丁是**一整块朝向完全一致的刚性方格**（一片几十到上百格），本仓的 quad 是逐格松弛出来的，相邻格轴向差 0–15°。

## 代码落点与差距

- `src/core/grid-wireframe.js` 新增 `patchLayout(grid)` / `cellAxisDeg` / `axisDelta`：
  - 四边格轴向吸附到晶格三族 {0°,30°,60°}（松弛前实测正是 3 个方向、144/164/161 格）；
  - 补丁 = 同族 + 共边的四边格连通块；给出 `patches / cellPatch / families / edgeKinds{inner,patchRim,seam,tri,rim} / maxSpreadDeg / triangleCells`。
- `grid-graph.html` 新增 `?mode=patch`（下拉可切）：按补丁着色 + 品红补丁缝 + 绿填三角格 + **四边格对角线 X**；面板与 `window.gridGraph.stats()` 暴露 `patchCount / largestPatch / maxSpreadDeg / families / patchEdgeKinds / triangleCells / diagonals`。默认 `mode=type` 不变（旧口径回归不破）。
- **差距（仍是 partial 的原因）**：补丁数是 **153 块（最大 34 格）**，原片约 8 块（每块几十格）；逐格轴向抖动 max **14.99°**，原片 0°。根因已定位：`latticeAndMerge` 的三族在 hex 拓扑里是**按格交错**的，逐格松弛又各自拟合正方形，所以"整片刚性"不是画法问题而是**生成器层面的补丁级约束没做**。本轮试过给 `relaxPolygons` 加族向约束（临时的 `constraintFamilies` 开关），实测抖动反而升到 45°（相邻格目标冲突），已回退，未留在代码里。
