## 判定

有机制，且只有一件：**生成管线跑在 job（后台线程）里，主线程往一块共享的静态数组写「时间倍率 / 暂停」，job 内部的 sleep 每片都重新读这块内存并阻塞**（= Burst 里的 Thread.Sleep）。表现就是同一套生成过程被拉成 22.8s 的慢放，分阶段可看 —— 原文自己说 "good enough for visualization and debug"。

**note 里「四轮节奏」是错的（第 23 次同型过期账）**：全片 420 帧 = **一轮** 22.83s + 片头 0.84s 的上一轮尾巴，片内没有第二轮。多轮是页面的可调参数，不是片里的东西。

## 代码落点与差距

- `src/terrain/pipeline-job-c08.js`（r56 C08，文件头署本片 ID）：`runJob`（7 段节奏 + 4 轮循环）、`createJobControl`（**static NativeArray 的浏览器同构** = `SharedArrayBuffer` + `Int32Array` 的 SCALE/PAUSED/ROUND/PARK 四槽）、`makeJobSleep`（每片 ≤16ms 重读倍率与暂停位，`Atomics.wait` 阻塞）、`startJob`（`new Worker(module)` + 时间线）、`stageDurations`。
- `src/terrain/pipeline-job-worker-c08.js`：真 module Worker，收 `buf` 后自建 `Int32Array` 跑 `runJob`。
- `job-c08.html`：2D 画布按阶段重绘（线框 → 抬墙 → 灰模 → 黑剪影 → 分层上色），带倍率滑杆与暂停按钮。
- `tests/pipeline-job-c08.mjs` 一直绿（虚拟时钟下的节奏 / 阶段顺序 / 共享控制块语义）。

**真缺口（本轮修掉的）**：页面上那件事**根本没发生**。`tools/serve.py` 没发 COOP/COEP → `crossOriginIsolated === false` → `SharedArrayBuffer` 在页面里是 `undefined` → `createJobControl` 退到 `copied-busywait`：倍率只在启动时复制一次（滑杆后半程失效）、暂停位压根不读（暂停按钮是死键）。实测改前：`coi:false / sab:'undefined' / mode:'copied-busywait'`。
原 note 把它记成「【卡点·E 环境不具备】本机验不了」—— 实际是**服务器少两个响应头**，不是环境不允许。
