- 原文：Spears are so weird to implement. I can see why most games don't use them

## 逐帧观察

- 0000–0120：夜间滩头，蓝衣守军（盾墙 + 一排白矛头朝右）顶着红衣维京人；矛**压平指向来敌**、矛杆偏粉、矛头白；血量槽在旗子顶上。
- 0120–0249：白矛从守军阵面同时前探（突刺），被刺中的维京人倒地；地面上血斑开始累积。
- 0250–0330：混战。**这一段出现了本轮要验的东西**：被打到的敌人头顶跳出白色「+4」；原尺寸 0300 + 5× 裁切可见三个「+4」几乎同时出现在相邻的三个敌人身上，**各跳各的、没有并成一个 +12**；字是奶油白 + 深色描边，屏幕正立（不随单位朝向旋转），高约 8px（420 画幅）。同一帧里敌群中还有红色放射状血迹。
- 0330–0499：镜头拉远到中景，蓝军两列推进，岸上留血色条带；0460 里出现**金色「+10」**（击杀奖励，与白色「+4」是两套颜色/含义）。
- 0500–0653：推到近景收尾，尸横遍地、血泊扩大，白色小数字仍在零星冒。

## 判定

**有机制**：近战命中 → 被真正打到的那一个单位头顶跳白色「+N」（N ∝ 实际掉血；本仓 1 点血 = 片中的 +4）；不同单位各自一条、不跨单位合并；屏幕正立、屏幕定高。击杀另有金色「+10」（本轮不改，`squad-hud.js` 已有）。

## 代码落点与差距

- 新增 `src/badnorth/damage-numbers.js`（纯逻辑）：`damageValue(hpBefore,hpAfter,per=4)` 只按**真实掉血**算（没掉血返回 0，打死那一刀照样给）、`addDamageNumber()` **只合并同一 unitId**（不同单位不合并）、`stepDamageNumbers()` 0.9s 升 0.55 / 后 55% 淡出、`DAMAGE_STYLE` 奶油白 `#fff6e2` + 深色描边。
- `src/badnorth/battle.js`：`#hit()` 里记 `hpBefore`/`hpAfter` 再取 `damageValue`，只有 >0 才 `#damagePopup(u,value)`；新增 `#damageTex()`（按文本缓存 CanvasTexture 2× DPR）、`#updateDamageNumbers(dt)`（Sprite 逐帧按**相机距离**缩放，屏上恒 ~15px；合并次数越多字号略大）；单位加 `uid`，开局清空；`damageStats` 给出 `spawned/live/lastValue/lastUnit/merged` 供验收读数。
- 仍缺：① 片里「+4」是贴着每个单位的屏幕位置，镜头极近时会被建筑压住（本仓 depthTest:false，一律画在最前）；② 数字没有随受击方向轻微抖动；③ 金色「+10」与白色「+4」还没有共用一套「伤害/战报」分层（分别在 squad-hud.js 与 battle.js）。
