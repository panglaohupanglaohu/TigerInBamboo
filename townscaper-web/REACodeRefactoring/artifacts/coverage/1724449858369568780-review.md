## 逐帧观察

- 界面是 Unity 编辑器：左边 Scene 视图（青色底），右上 Inspector，正中一个白色 **Toggle** 按钮和一块写着 **Moving!** 的白色横条。
- **0000–0010（0–0.42s）**：Condition 是 ☐（false），FloatSelectNode 的 Output = **226.9**（取 On False = −226.9 的绝对值口径），FloatLerpTowardsNode 的 Target/Output 都是 226.9；"Moving!" 停在下方（y ≈ 226.9）。
- **0011（0.45s）**：Condition 变成 **✓**（true），FloatSelectNode 的 Output 立刻跳成 **−33.8**，但 FloatLerpTowardsNode 的 Output 还停在 226.9 —— **选值立刻变、位置慢慢走**，这是整段最关键的一帧。
- **0012–0069（0.48–3.0s）**：Lerp 的 Output 一帧帧往下走（226.9 → 200 → 150 → 100 → 60 → 40 → …），Speed 恒为 20；"Moving!" 同步向上滑。
- **0070（3.0s）**：Output = −33.59433，还没到 −33.8；Vector2ComposeNode 的 In 1 = −33.59、Output 显示 (X −5, Y −33.59)。"Moving!" 已经滑到上方。
- **0071–0133（3.1–5.8s）**：Output 收敛到 −33.8 后不再变，画面静止；Vector2EventNode 一直写着 `Runtime Only → RectTransform.anchoredPosition`，目标对象是 Moving 的 RectTransform。
- 全程 X 一直是 **−5**（In 0 取自 Moving 的 anchoredPos.x，没有被改）。

## 判定

机制读得很全：**bool 资产 → FloatSelectNode（在 −226.9 / −33.8 之间选）→ FloatLerpTowardsNode（Speed 20，每秒最多走 20 个单位，到点即停、不回弹）→ Vector2ComposeNode（X 取 −5、Y 取上面那路）→ Vector2EventNode 的 UnityEvent 写回 `RectTransform.anchoredPosition`**。它是"节点式数据绑定"，不是简单 tween：每一站都是独立节点，值可以随时被别的节点读走（Inspector 上实时显示）。

## 代码落点与差距

- 新增 `src/core/node-graph-runtime.js`：
  - `NodeGraph`：端口 + 有向连边，求值按**拓扑序**（先算上游再取它的 out；本轮第一版是"统一搬一遍再求值"，读到的是上一帧的值，select 永远慢一拍，测试逮住后改掉），有环/自环/端口不存在都直接抛错；
  - 节点与原片一一对应：`boolSource`（ScriptableObject bool）、`select`（FloatSelectNode）、`lerpTowards({speed})`（FloatLerpTowardsNode，每 tick 最多走 speed·dt、到点精确停住）、`compose2`（Vector2ComposeNode）、`sink(fn)`（UnityEvent，只在值真变了才回调）；
  - `buildToggleChain()` 把这条链按截图里的默认值（−226.9 / −33.8 / speed 20 / x −5）装好。
- 新增 `node-graph.html`：左边是场景（Toggle + 会滑的 "Moving!"），右边是仿 Unity Inspector 的实时数值面板（节点名、On False/On True、Condition、Target/Speed/Output、In 0/In 1、UnityEvent 目标、sink 回调次数）。
- 差距：原片是 Unity 的 ScriptableObject 资产 + 序列化组件，本地是纯 JS 运行时，**没有编辑器/序列化**；节点图没有可视化连线编辑器（只有 Inspector 式读数）；UnityEvent 的 `Runtime Only` 持久化模式没有对应物。
