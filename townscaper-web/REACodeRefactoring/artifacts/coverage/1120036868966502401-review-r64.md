## 逐帧观察

- **0000–0003**：俯视一块平板上的不规则四边形网格，白色**1px** 网格线铺满，格角有小点。
- **0004–0008**：出现区域边界折线：一块台地被**红**线勾住，旁边另一区**粉/洋红**；0007 起又多一条**蓝**线沿另一片边界。三条线各走各的格边，不交叉、不同高。
- **0009–0019**：网格整体抬升，红/粉/蓝仍在同一片区域上 → 区域**没有换色**。
- **0020–0069**：中间升起一块深 navy 的整片区域（顶面仍是同一套格线），红/粉线绕在它外沿，蓝线在更低一级台地上；期间有黄色/红色/绿色/蓝色的**逐格彩点**沿格心排布。
- **0070–0079**：切到候选阶段：深色区域上出现**逐格黑白棋盘**（白格 / 深格相间，整格铺满、三角格按三角），棋盘随求解逐格翻色。
- **0080–0099 / 0400–0434**：回到近景，只剩网格线与少量彩点。
- **0435–0450**：红/粉区域边界重新出现，同一片台地跨帧保持同一颜色；0450 起彩色点（红/绿/蓝/黄）成串。
- **0470–0489**：黑白棋盘整片出现（白块明显、与深色底相间），0480 之后棋盘逐格减少 → 就是「候选格按 domain 收缩、定下来的格不再铺」。

## 判定

**有机制**：不规则四边形网格上的「区域边界 + 候选格」调试层。三条机制：
1. 区域边界沿格边，颜色跟**区域身份**走（同一片台地长高不换色，分裂才出现新色）；
2. 候选格整格黑白棋盘，翻色对应求解推进（domain 收缩）；
3. 格角/格心有彩色标记点（原尺寸 2.5 倍裁切确认格角是**黑色小方块**，不是白点）。

## 代码落点与差距

- 新增 `src/core/region-ids.js`：`regionComponentIds(cells, topAt)` —— 每层集合 {top ≥ h} 求**层内**水平连通分量，
  分量向上继承父 id；一个父分裂成多个孩子时，最大那个继承父 id、其余拿新 id；合并则拿新 id。纯函数、无 three 依赖。
- `src/world/contour-overlay.js`：`refresh()` 的颜色由 `palette[(h-1)%6]`（按高度层循环）改成 `palette[(regionId-1)%6]`；
  `regionStats` 每层多带 `regions:[{id,segments,color}]`；`this.regionIds` 暴露整张 id 表供探针读。
- `setCandidates(list,{domains})`：黑白不再按空间奇偶，改读**逐格 domain 大小**（`ds<2` 的格不再是候选、直接不铺）；
  `candidateStats.mode` 记录 `'domain'` / `'spatial'`，另带 `converged` 与 `domainSizes` 直方图。
- 仍缺：① `setCandidates` 的 domains 还没接 `wfc.js` 的真实 `trace` 快照（本轮只用夹具验了代码路径）；
  ② 格角点本仓是白色 3px，原片是**黑色小方块**；③ 区域边界线宽未做屏幕空间恒定。
