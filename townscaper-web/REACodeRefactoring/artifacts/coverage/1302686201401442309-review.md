## 判定

**有机制（它是 bug 的现场，等于给出了验收条件）：**

1. 翻折的块（有向面积为负的 patch）在松弛时塌成一条缝 → 现象是"深色皱褶 / 一团乱线"；
2. 为了和邻居对齐，翻折块的顶点被插值拉开，非翻折的邻块被迫拉长去补缺口 → 现象是"横跨几个块范围的巨块 / 长条形格子"。

对我们来说这不是要实现的效果，而是**两个必须被量出来的失败模式**：翻折数 > 0、以及单格被拉伸到远超自身点阵足迹。

## 代码落点与差距

- `src/core/infinite.js`：块/簇各自松弛、**外圈钉住**（`buildInfinite` 的 patch/cluster 松弛都只动内部点），块边界上两侧版本恒等，所以不会出现翻折；`verify()` 原本只统计 `flipped`（有向面积 ≤ 0）与块边界 `seam`，**第二个症状量不到**——这正是片中最显眼的"巨块拉伸"，此前是验收盲区。
- 本轮补：`verify()` 增加以**本格原始点阵**（同 mode 的 `'raw'` 版本）为基准的拉伸/收缩度量——`maxStretch / minShrink / maxEdgeStretch / minEdgeShrink / stretched / shrunk / stretchLimit / worst`。归一化到自身 footprint 而不是块内中位数，因为合并格本来就比邻格大，中位数基准会把合规大格误判成拉伸。`grids.html` 状态行同步显示"拉伸最大 1.83× 最小 0.46×（相对原始点阵，超 2× 的 0 格）"。
- 实测（`passes: 60`，即页面默认）：19 块 / 24 簇 / 3946 格，翻折 0、非法 0、块边界最大表示差 3.7e-15、拉伸最大 1.83×、最小 0.46×，没有任何一格超过 2×。即本仓实现把片中两种症状都避开了。
- **还缺**：松弛 60 遍时仍有 14 格收缩到 0.46×（画面表现为局部小格偏碎），属正常松弛而非翻折，但要彻底像原作那样"看不出接缝"还需要按面积反推的松弛权重（把每格面积拉回点阵面积），当前只在验收层量出来、没有回灌到松弛过程。
