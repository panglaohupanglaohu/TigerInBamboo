## 判定

有机制，而且是**纯纹理机制**：一张 equirect 世界贴图 + 岸缘五层（陆侧暗带 / 海侧浅浪线 / 沙滩 / 两色草 / 1px 海岸线）贴到球面上。
note 里「【卡点·C 算法未公开】…只能近似」**过期**：`src/sphere/worldmap-shore.js`（文件头就署了本片 ID）恰好就是这三件事，且 `src/sphere/worldmap.js` 用 **3D 单位方向**采 fbm3（不是 lon/lat 噪声）——正是原片「极点不撕裂、经度无接缝」的原因。

## 代码落点与差距

- `src/sphere/worldmap.js`：`buildWorldMap`（3D 噪声海陆 + 1px coast）、`worldMapColors`（r55 四角色）、`poleStretch`、`mode:'uv'`（2D 反例）、`worldMapTexel`、`WORLDMAP_GLSL`。
- `src/sphere/worldmap-shore.js`：`shoreDistance`（球面度量有向距离场，经向 ×cos(lat)、双向 chamfer 两轮、经度回绕）、`worldMapShoreColors`（rim 暗带 / 3 道 wave / sand 月牙 / grass·grass2 两色）。
- `src/sphere/worldmap-material.js`：`worldMapTexture({shore:true})` + `attachWorldMap`（按片元方向查表、顶面取贴图、墙面保留瓦色）。
- 页面入口：`planet.html?map=1&stage=maptest&shore=1`（「贴图测试」球 = 原片那颗光滑星球；`shore=0` 或省略 = r55 基线）。

**本轮查出的真缺陷（已修）**：`worldMapTexture` 的 `DataTexture` 没标 `colorSpace`。r160 里 DataTexture 默认 `NoColorSpace`（当线性数据处理），而渲染器输出是 sRGB → 整颗星球被「线性→sRGB」再提亮一次：海 (92,158,161) 渲成灰蓝、草变粉绿，与原片的高饱和绿/青差一大截（首版截图整颗星球发白）。补 `tex.colorSpace = THREE.SRGBColorSpace` 后海/草的渲染色回到贴图作者值附近。

**仍存在的形制差（如实口径，不计入缺口）**：
- 贴图 1024×512；原片近景（f0200–0241）在同样取景下本仓约 **4–5 屏幕像素/纹素**，看得见方格与线性插值的糊边，原片是更长笔触的手绘感 → 换 2048×1024 烘焙 ≈ 2.1s（1024 是 0.56s），本轮**没有**加默认分辨率，只在证据里记账。
- 原片的沙滩沿大部分岸线成一圈细带 + 零星深色卵石点；本仓沙滩由 `fbm3(beach) > 0.6` 门控，只占 **25.9%** 岸线（原片更像 60%+），也没有卵石点。
- 原片暗带更宽、边缘更「毛」；本仓 `rim = 0.035 rad`、边缘靠 fbm3 抖动，视觉上更窄更硬。
