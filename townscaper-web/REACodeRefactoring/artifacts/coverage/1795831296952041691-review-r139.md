## 判定

**有机制**：一条沿河加权的简化导航图 —— 河格之间连边、边价按方向分档（顺流便宜、逆流贵），高差优先于「离河口几步」这种几何启发；平床/封闭河段用开挖顺序定方向，判不出就保持中性。画面里「绿→黄→橙」的渐变与红色区域编号就是这棵树的调试可视化（原片同样只在指针附近铺色带）。

## 代码落点与差距

- `src/world/navgraph.js#buildNav`：`riverDirection()`（高差 → `riverNetwork.parent` → `riverFlow.flowTo` → 河口步数）、`edgeCost()`（`RIVER_DOWN=0.3` / `RIVER_UP=0.65` / `SLOPE_COST=1.25` / `STAIR_COST=1.8`）、`flowSource` 读数。
- 同一模块的完整接口：`findNavPath` / `riverRouteStats`（speedup / detour / upDownRatio）/ `simplifyNav`（junction graph）。
- 球面层：`buildNav(..., { metric: 弦长, slopeStep: 1 })`，页面 `planet-rivers-c09.html?nav=auto` 就是这条路（`metric=chord`、河格顺流 0.3）。
- 平面层：`river-nav.html`（混合/四边形两套网格，绿色箭头=顺流、灰线=方向未知）。

**核实结论（本轮最值钱的一条）**：旧 note 的「原球面/复杂汇流与完整接口仍缺」是**过期账（第 18 次同型）**——
① 球面早就有 `metric` 弦长这条路（r56 C09-B 加的参数，`planet-rivers-c09.html` 一直在用）；

## 如实口径（造型/参数差，不计缺口）

1. 边价 `0.3 / 0.65 / 1.25 / 1.8` 是**本仓本地参数**，不是原作速度数值；原片没有任何可测的角色往返，倍率不可反推。
2. 原片是平面连续高度场的单条河谷；本仓球面页是逐格台地 + 硬侧壁，河谷更密（409 河格 / 29 汇流格 vs 原片一条主河 + 两三条支流）。
3. 球面页树线用「到达时间」着的绿→黄→橙渐变（只铺前 35% 时间，原片同样只看到指针附近），不是逐边按顺/逆分色。
4. `simplifyNav` 在球面上压缩比只有 0.988（缓坡直走让绝大多数格度数≠2），平面网格上是 0.03–0.35 —— 简化图这件事是另一条片（1582293326815862786）的口径，本条只要求接口一致。
