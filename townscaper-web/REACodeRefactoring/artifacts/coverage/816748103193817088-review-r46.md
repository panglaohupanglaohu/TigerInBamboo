## 判定
有机制：流场直接定义在导航面上（面内连续），群体沿连续流向流动；坡道是导航面的一部分，所以上下坡连续（"so it depends" = 取决于导航面，而不是格子）。

## 代码落点与差距
- 重构版此前：`src/badnorth/flowfield.js` 格心多源 Dijkstra（parent 指针 = 下一格），单位朝下一格中心 / 通口走；GAP-PRIORITIES 记「连续导航面内流动 / 群体流体运动 / 坡高」缺。
- 新 `src/world/navmesh-flow.js`：
  - `buildNavMesh` 凸多边形导航面 + 邻接；`navMeshFromTerraces` 台地 + 坡道（顶点共享，坡与上下平台天然连通，崖不进面）；
  - `buildVertexField` 顶点多源 Dijkstra（面内两两顶点连边，近似测地距离），目标 = 圆；
  - `flowAt` 所在面顶点距离的最小二乘平面梯度取反 → 面内 / 过边连续流向；
  - `stepCrowd` 流向 × 速度 + 空间哈希分离 + 加速度平滑；`moveOnMesh` 跨边进邻面、边界沿边滑；高度 = 面平面插值。
- 新页面 `navmesh-flow.html`：3 队 × 100 人，点地面给所选队下目标。
- 缺：还没接到 Bad North 战斗的 `battle.js`（那里仍用格心流场 + 通口前视）；导航面是演示用台地生成器，未从共享 World 的分层导航自动生成；无避障预测（ORCA 类）。
