## 逐帧观察（全片复核，本轮重看三张联系表）

- **0000–0019**：彩色小镇全景（青绿天空、红/橙屋顶、蓝塔、绿墙），相机缓移，表面是干净的程序化配色。
- **0020–0028**：深色窗口自右侧滑入，带标题栏与关闭按钮。
- **0029–0065**：窗口展开为 PS 风格查看器，标题栏 `TownColor.png @ 200% (Layer 0, RGB/8)`，中央是**整张游戏贴图图集**（灰阶墙格/屋顶格/窗格 + 右下角一小块彩色格），底部 `200%`。
- **0066–0177**：粗蓝画笔在图上连写 S 形大字，涂满图集中部与下部的灰阶墙格，彩色格基本未动；窗口外的镇子被挡住。
- **0178–0206**：窗口右移滑出，小镇露出——**墙面已经开始变蓝**（涂鸦纹在每栋房子上重复出现）。
- **0207–0278**：整城所有建筑墙面/部分屋顶统一成那张蓝色涂鸦，相机环绕展示。关键证据：**只在一张图上画，全城所有面一起变** → 共用总贴图，不是逐面材质。

## 判定

**有机制**：游戏建筑表面共用**一张总贴图**（`TownColor.png`），运行时替换/重载这张图 = 整城换肤；这也是作者说"最宽泛意义上的 moddable"的技术前提（不改模型、不改材质槽，改一张 PNG）。

## 代码落点与差距

**核实结论：上一版证据写的"本仓走逐面调色板顶点色、无共享 surface 图集、无热替换"已过期**（r102 blobshadow、r103 architecture.html 之后的第四次同类误判）。真实落点是 r56 C07 批次：

- `src/core/town-skin.js` —— `SKIN_SLOTS`（8×8 色格去掉右下 2×2 植物角 = 60 格）、`buildSkinAtlas()`（128² 总图集，每格细线纹但**格均色 = 底板色**，所以换肤前后整体亮度一致）、`buildSkinMips()`（每格独立 box 滤波，不跨格渗色）、`skinAttributes()`（底色 → 色格 + 光照比）、`scribble()`（那笔蓝涂鸦，只涂墙格、不碰植物角）、`cellMean()`。
- `src/world/town-skin-layer.js` —— `TownSkinLayer`：给主网格写 `aC07Cell/aC07Ratio` 顶点属性、注入 `SKIN_VERT/FRAG`，`refresh()` 在 `worldMesh.rebuild` 后**立刻**补属性（晚一帧就整帧缺属性 → 全黑）；热替换三条通道 `scribble()` / `paint(fn)` / `loadImage(url|Blob|File)` + `toPNG()` 导出，还有拖 PNG 进窗口的 `#dropTarget`；`set(on)` 时把 `view.vegetation.leafSurface` 也指向同一张图（植物读同图那个 32² 角）。
- `src/world/view-c07.js` —— 开关 `?c07=townskin` / `view.c07.set('townskin', on)`，`view.render` 每帧 `skin.refresh()` 并写 `stats`。

差距：**无**（机制层）。片子里 PS 窗口那一层是"编辑器 UI"，不是游戏机制；机制是"一张图 → 全城"。
