## 逐帧观察（本轮复核段）

- 0100–0119：镜头对着左侧台地，蓝甲守军在旗前列阵；多数兵**没有明显示意动作**，只有少数几根偏粉的浅色细线从人堆里斜着伸出
  —— 斜举约 40°，线端一点白（矛头）。这批人附近的敌人还在海上，说明**待机就是斜举**。
- 0120–0159（crop-0120 原尺寸）：红船靠岸，前排矛兵的杆已经压平、指向来敌，形成一排放射线；杆色偏粉（`#e2a59c`），头是白锥。
  之前几轮把这排线记成「粉红放射状命中特效」，本轮再看仍是**整排压平的矛杆**，不是独立命中特效。
- 0160–0199：接战，个别单位被击中后僵住（`stunUnit`），矛停在半途；地面开始出现血点。
- 0300（crop-0300）：右下三名红方倒在地上、周围是红色喷溅；中下部有一排斜插的浅色杆，杆端白头。
  此处没有「独立于矛之外的粉色命中细线」—— 画面里所有细线都能对上某根矛。
- 0200–0299 / 0300–0653：第 60 轮与第 102 轮已逐段核过（含末段 `+4` 与 `+10` 飘字、尸体、僵直恢复），本轮不重复。

## 判定

有机制，且是**四层**：① 待机斜举 40° / 刺出压平 / 收矛线性抬回；② 架矛（敌人未到身前整排压平指向来敌，杆长前探 0.38）；
③ 固定轴伸出胶囊的连续命中判定（一刺一命中集，同一目标不重复）；④ 每次真实掉血在**被打中的那一个**单位头顶跳 `+4`、击杀另跳金色 `+10`。

本轮把第 44 轮记的最后一条「伤害数字与刺击命中集是两处实现未联动」收掉：现在 `battle.js` 的 thrust 分支先拿
`stepSpearThrust` 返回的 `hits`，再 `for (…) this.#hit(target, u)` —— 掉血、飘字、命中计数全部从同一个数组派生，
并把联动结果写成可读度量（下一节）。

## 代码落点与差距

- 姿态：`src/badnorth/battle.js` 的矛实例矩阵 `e.set(-pitch, angle, 0, 'YXZ')`，`idlePitch = 40°`，
  `u.thrust`/`braced` 时为 0，`u.spearRecovery` 时按 `1-remaining/duration` 线性抬回；`mSpear` 杆色偏粉、`mSpearTip` 白锥在杆端。
- 命中：`src/core/spear-thrust.js`（`beginSpearThrust` / `stepSpearThrust`，固定轴、逐帧连续接触、`hit` Set 去重）。
- **本轮改码**：`battle.js` thrust 分支原来是一行 `for (const target of stepSpearThrust(...)) this.#hit(...)`，
  虽已同源但**没有任何可观测的联动度量**，验收无法对数。现在同一帧内记录
  `damageStats.{hitSet, thrustFrames, lastThrustHits, lastThrustPopups, lastThrustKills}`：
  `lastThrust*` 每帧重写（没命中就是 0），`hitSet` 只累加真命中。
- **差距**：无（本片记录的三项缺口全部闭合）。持矛的完整动作谱与格挡推力属于另片/另组，不在本条。
