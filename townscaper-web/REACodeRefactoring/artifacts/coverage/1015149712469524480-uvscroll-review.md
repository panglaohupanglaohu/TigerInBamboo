## 逐帧观察

- 0–100 帧（sheet-00）：演示用**棋盘纹理**代替噪声（为了肉眼能看见 UV 在动）。草地上一个白色小屋，屋顶冒出一条**斜向右上**的棋盘带；棋盘方块在带内是倾斜的平行四边形，说明采样坐标被按流向旋转过。
- 100–200 帧（sheet-01）：相机绕到岛的左侧并抬高，棋盘带仍是一条连续斜带；同一帧里不同方片的棋盘**相位各不相同**（有的格里黑块靠左上、有的靠右下），方块大小也随方片缩放变化。带的中段出现轻微"断开"——相邻方片相位不连续，正是逐方片独立滚动留下的缝。
- 200–260 帧（sheet-02）：机位转到接近俯视，棋盘带变成一片竖直柱；柱底的棋盘格最密（方片小），往上格子边长变大。画面右侧还有一小片淡棋盘（第二个发射源/低权重粒子）。
- 260–330 帧（sheet-03）：转到正面，柱体正面看是宽窄不一的棋盘块堆叠，方块之间有明显位移错位，没有出现整体平移的同相位格子。
- 330–451 帧（sheet-04）：回到起步机位附近，棋盘带重新变斜；末帧与 0 帧角度接近但相位已经换过（同一个方片里的黑白位置不同），符合"随机正/反滚动"。

## 判定

有机制：**每个方片只做一次纹理采样，但 UV 沿烟流随机正/反滚动**。
片子用棋盘纹理会话就是为此：如果 UV 不动，整条带会是一块连续、可识别的大棋盘（blob 可辨认）；实际上每片相位各自漂移、方向可正可反，所以大图案被打碎成"多层流动"的观感。
可确认的是"逐片独立 + 双向滚动 + 沿流向旋转"；**不能**从画面反推每片一帧内的 GPU 采样指令条数（原文是"per quad 一次采样"，但那是作者的实现口径，不等于本仓的逐片元取样）。

## 代码落点与差距

- 模块：`src/life/smoke.js`：每实例 `aDir`（±1）、`aFlow`（按当前相机把粒子实际速度投影到屏幕后归一化，滚动坐标沿它旋转）、`aAge`；fragment 里 `uv += flow * dir * time * speed` 后 `texture2D(uNoise/uChecker, uv, bias)`。`setSampling({scroll, mip})` 独立关断。
- 实验页：`smoke.html`；页眉开关「UV前后滚动 / 年龄mip偏移 / 棋盘方片 / 黑底遮 / 浅色遮 / 混合网格」。
- 做到：真正可平铺的 64² 棋盘 DataTexture（自动生成 mip），替换掉原来"texture2D 之后 floor 出解析格"的旧调试路径——旧路径绕过 mip，压根看不到过滤变化；正/反方向与冻结对照都能在线切换。
- 缺：`aFlow` 是本帧风/上升速度的近似投影，不是原作的三维流体轨迹，所以片子那种"整条柱体共同弯曲"的层流感只能局部近似；两次透明 pass 的粒子相交仍是近似，做不到真体积。
