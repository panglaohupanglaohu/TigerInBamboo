## 判定

有机制：不规则四边形格上的 marching squares / 格线可视化。分三层：

1. **格线** = 逐格顶面边 + 跨层竖边（贴面），2px 定宽，交点画白点；
2. **候选棋盘** = 逐格（或逐三角）双色块，落在该格所在层；
3. **区域/选择** = 编辑平面上的 2px 折线 + 单格三角标记，**不跟层**。

## 代码落点与差距

- `src/world/view.js` `refreshGridGeometry()` / `setGridSurface(on)` / `setGridWidth(halfPx)`：① 逐格 `world.top` 顶面边、② 相邻更低时落角柱竖边、③ 贴面档 `depthTest=true` —— 与 frame-0165 / 0385 / 0470 三处观察一致；`gridWidth` 默认 1（半宽）→ 总宽 2px，与上文 460 宽实测 2px 对齐。
- `src/world/contour-overlay.js` `setCandidatesLayered` / `setCandidatesFromTrace(...,{layered,ground})`：分层候选块，与 sheet-04 帧 470–490 的高层台顶棋盘一致。
- **本轮结论（关缺口）**：r72 遗留的"贴面档下区域边界/选择环是否跟层"→ **原片就是不跟层**（frame-0260 / 0445 硬证据），不需要改代码，该缺口关闭。
- 仍缺：
  1. 候选块/区域线全部 `depthTest:false`，而原片这些调试层**是吃遮挡的**（frame-0260 红线被块切断、frame-0445 彩框右下角被切）→ 本仓会透穿前方几何。要改需同时给 `mesh/regions/regionThickMat/candidates` 加 depth 开关并回归 4 个 assembly 测试。
  2. 本仓真实岛 2748 段（736 格）vs 原片 5116 段 —— 段数差来自岛体格数不同，不是实现差；若要保证密度一致需按帧内"每格边段数"比，本轮未做。
