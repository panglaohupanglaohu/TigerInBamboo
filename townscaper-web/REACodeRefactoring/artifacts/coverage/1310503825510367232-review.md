## 逐帧观察

- 0000–0019：小岛静止，正面偏俯视。一条彩色排屋（红/黄/绿/橙屋顶）沿一条折线栈道排成 L 角，右端一座白色灯楼（红瓦尖顶）、左端一座红身塔。水面有倒影。
- 0020–0049：镜头绕岛转，约 0028 起岛体转到斜角，看到排屋的两面墙同时入画，栈道折角正对镜头。
- 0050–0099：继续旋转，从 L 角内侧转出去，灯楼从左移到右侧；全程竖边（塔身、墙角、栏杆立柱）**一直是竖直的**，没有随旋转倾倒。
- 0100–0149：转过 180°，看到排屋背面和栈道另一段，灯楼移到画面左侧。
- 0150–0199：回到与 0000 近似同机位的侧视角，收尾。整段是一个 360° 转台，没有编辑操作、没有 UI。

关键点在于：转台本身不是重点，"竖线直不直"才是。原尺寸 frame-0035 里灯楼的左右两条竖向棱、以及后排房子的墙角线，彼此平行且与画面竖轴平行；而按常规透视，俯视相机下的竖线应当随高度向内收（越靠下越窄），实际没有。

## 判定

**有机制**：自定义投影。不是"正交投影"（正交的话远近不会变小），也不是普通透视（普通透视竖线会收）。它是二者混合——远处仍然变小（透视的 w 参与），但竖线的屏幕 x 不随高度变化。

数学上就是：`w = -z_view` 里含有世界上方向 y 的分量（w 行的 y 系数 = −r₂₁，r₂₁ 是相机前向的 y 分量；俯视时 ≠ 0），所以同一根竖线上下端点拿到不同 w → 屏幕 x 不同 → 竖线收敛。把 w 行的 y 系数衰减到 0，竖线两端 w 相同 → 屏幕 x 相同 → 竖线笔直平行；w 仍随水平距离增长 → 远处照旧变小。

原文自己说"not a good fit for Townscaper"，所以这条原先记成 `ref`（相机参考）。但机制本身是独立、可判、可测的，属于"能承载"，按 C 路径补了实现。

## 代码落点与差距

- 新增 `src/core/mixed-perspective.js`：列主序矩阵工具（perspective / lookAt view / multiply / invert）、核心 `withVerticalParallel(viewProjection, k, pivotY)`（衰减 w 行 y 系数，pivotY 那一行原样保住，避免整幅画面上下漂移）、诊断函数 `projectPoint` / `verticalEdge`（竖线两端屏幕 x 偏差 driftNdc）/ `quadWidths`（竖直面板上沿相对下沿的收窄率）、渲染器接口 `projectionForRenderer`（P′ = M′·V⁻¹，可直接塞进 three 的 `camera.projectionMatrix`）。
- 新增实验页 `mixed-perspective.html`：左右两栏，左普通透视（k=0）、右混合透视（可 0→1 连续调），场景是四块**同尺寸标尺**（宽 2.0 / 高 2.6，底边同在 y=0.1，只有 z = 7 / 2 / −4 / −10 不同）。数字全部从帧缓冲按颜色逐行量（不是解析值），同时并排给出解析预测用来对账。
- 差距：主视图 `src/world/view.js` 仍是 `THREE.PerspectiveCamera(30, …)`，**没有**接这个投影（默认 k=0 才安全，接进主视图要一并改 pick/raycast 与水面倒影的相机矩阵，本轮没做）。原版是 Unity 侧的自定义投影 + 移轴混合，逐像素匹配没做。

## 验证

```
node tests/mixed-perspective.mjs
→ PASS mixed perspective: verticals straight (drift<1e-9) at 5 placements x k grid,
  depth shrink preserved, pivot row pinned, P'=M'V⁻¹ exact

NODE_PATH=/tmp/pw-shim:… node tests/mixed-perspective-browser.cjs
→ PASS k=1 竖边横移 0px / 上下沿等宽, k=0 与普通透视逐值相同, 近大远小保留, k 单调
  stock: probes 4, maxAbsSpreadPct 8.05%, maxAbsCenterShiftPx 16.5px, widths [87,69,56,47]
  mixed: probes 4, maxAbsSpreadPct 0.00%, maxAbsCenterShiftPx 0.0px, widths [88,70,57,47]
  k 扫描 0→1: spread 8.05 → 5.68 → 4.60 → 2.13 → 0.00（单调递减）
```

像素级结论：k=1 时四块面板的上沿与下沿**逐行同宽、竖边横移 0px**，同时远处仍比近处窄（88→47），正是原文那两句话。截图 `artifacts/coverage/mixed-perspective-k1-stock.png` / `-k1-mixed.png` 已用 ViewImage 看过：左边是斜边的平行四边形，右边是方正的矩形。

坑：`THREE.ColorManagement` 默认把 Material 颜色 sRGB→linear 转换，读写回缓冲后 RGB 全对不上（背景 0x101e26 读成 1,3,5），按颜色找面板会一个都找不到，页面里必须关掉色彩管理（量像素的实验室专用）。
