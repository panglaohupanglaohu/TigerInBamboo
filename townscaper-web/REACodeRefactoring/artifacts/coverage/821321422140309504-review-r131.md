## 判定

有机制，且只有一件事：**单位脚下的接触软影**（灰模地面无贴图、无明暗渐变，能看出来的"暗斑"只可能是脚下那块影子）。
其余内容（选点框 / 路径点 / 挥砍 / 血 / 尸体）本仓 `src/badnorth/battle*.js` 早已有并有更早轮次的验收，不是本片新增。

  → 默认战斗一片软盘都不画。已改：`battle.js` 构造里默认开，`?unitShadows=0` 才关。
- **第 130 轮留下的最后一层（本轮已收）**：没在画面上确认盘子可见。原因是机位（`dist 3/pitch 1.0` 钻进云层、`dist 5/pitch 0.42` 钻进台地侧壁）
  与被测对象选错（取了「同伴最多」的单位，它在台地中段，相机正好塞进实心柱侧壁）。
  本轮三条一起改：① 120ms 定时器钉 `target/distance/pitch`（r127 做法，app 会在世界异步生成后再 fit 一次相机）；
  ② 冻时间轴（`v.render = () => orig(0)`），否则同状态两帧差分 2 万 px，暗盘信号被植被摆动淹没；
  ③ 目标改取**楼层最高**的单位（台地顶层上方没有植被和侧壁），`distance 4.0 / pitch 1.25` 俯视。
- 顺带排掉第 130 轮记下的真实风险：「台地是实心柱，形变后的渲染面可能高于 `floor*L+0.008` 把盘埋掉」——
