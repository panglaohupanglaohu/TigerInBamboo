## 逐帧观察

- **0000–0019**：深灰底，地面是一张**不规则四边形线框网格**（格子大小不一、角点歪斜，"funky grid"）。画面中心偏上只有一小团红色多面体碎块，逐帧变大、开始沿格面延伸；相机在缓慢环绕（底网整体在转）。
- **0020–0059**：红块连成**低矮的脊**，沿格面向两侧爬，脊上出现第一处可以看穿的**拱洞**（0029 / 0039 明显）；红色实体表面叠着更深的**三角剖分线**，线的交点都落在底层网格的格边上，没有落到格心。
- **0060–0099**：脊拉长成一条带弯折的**梁**，末端展成一块**薄板**；板的边缘平直、随格边走，板底不是同一高度（能看出台阶）。
- **0100–0199**：整片蔓延成一大块，出现**竖直墙面 + 悬空板 + 多处拱洞**；相机继续环绕，右侧那块板与主体之间留出一个方形的洞（0100 原尺寸可数清墙面三角剖分顺着格边斜切）。全片只有红色，没有第二种配色，也没有 UI 文字。
- **0200–0299**：形态展开成**多层台地**：板面高低错落、每块板底下垂的竖墙高度不同，拱洞变成两三个连通的通道；底面阶梯在 0220 原尺寸帧里能一格格数出来（同一块板分成 2–3 个层高）。
- **0300–0352**：末段分化成若干**互不连通的方块/梁**（0352 原尺寸：中间一个大环、左侧带台阶的厚板、右侧两块独立梁），形态不再生长，只继续转镜；颜色和线框规则不变，末尾无文字/无切换。

## 判定

有机制：**不规则四边形网格上的三维等值面生长**。三条可直接核的判据：① 等值面的交点只出现在**格边**上（不是格心、也不是连续曲面）；② 同一格内部有两种切分（面歧义）且没有裂缝 → 相邻格共享的交点必须焊接成同一个顶点；③ 底面沿格子**阶梯化**（板底多次落在不同层高）。原文的「next up is turning this into mixed initiative WFC」是下一步计划，不在本片。

## 代码落点与差距

- 落点（r56 C06，`src/core/marching-cubes.js` 文件头就署了本片 ID）：
  `marchIrregular(cells,{levels,value,iso,levelHeight,yOf})` —— 每格 × 每层是一个不规则棱柱，对体的每个面「从外面看逆时针」走一圈，外→内记「进」、内→外记「出」，
  每段连续内部角点给出一条「进→出」线段（面歧义一律「内部角点分开」→ 共享面两侧结论相同 → 水密），线段首尾相接成环后扇形三角化；
  交点按「顶点 id + 层」做边键**全局焊接**，插值在规范顺序下做。**不需要 256 情形硬编码表**（按面走一圈与查表等价）。
  `growthOrder()` 是片子里的生长序（从一个角点沿共享角点偏水平蔓延成脊/桥），`meshVolume()` 验法向朝外，`quadRegionGrid()` 对应姊妹片 1120036868966502401 的「区域 → 挤出厚板」。
  页面 `marching-cubes.html?mode=cubes|slab`（`?t=` 定进度、`?still=1` 停转镜、`?edges=0` 关表面三角线）。
- 本轮真改的两处（都不改机制）：
  1. 页面加**几何探针** `window.marchReview.mesh()`（等值面顶点/索引 + 本网格格角 xz + 各层 y）与 `vertices/cellsTouched/levels` 读数 —— 原来只吐三角数与体积，测试无法逐点对账「面只在格边上」；
  2. 页面加**表面三角边线层**（`?edges=0` 关）：片子实体表面一直是「红面 + 更深的剖分线」，之前页面只有平色块，形制对不上（r117 的「有没有 / 像不像」两问）。
  3. 模块加 `vertexKinds`（1=格边真实交点 / 0=环扇形三角化补的中心点）与 `fanCenters` 计数：长环扇形三角化会补一个内部中心点，
     它本来就不在格边上，不区分开就量不出「交点全在格边上」（第一版没区分 → 726 个顶点被判成偏离，最大偏离 0.385）。
- 差距（如实口径，不记机制缺口）：原片左侧有一个**编译/光标 gizmo**（0100 帧左中那个红方框 + 绿箭头，是编辑器光标），本仓页面没有；
  造型上本仓的生长场是本地确定性程序（`growthOrder` 的 seed/upBias），团块比原片更胖，原片的生长手法未公开 —— 属造型/编辑器差，不是机制缺。
