## 逐帧观察

## 判定

有机制：补丁级方形子点阵（每块补丁各自一个正交基），补丁之间共用一条折线边界，
只有边界上极少数格退化成三角。r230 已把"补丁内正方形"做对（角偏差 p50/p90 = 0.00°）。

本轮新读数（frame-0160 原尺寸）：片中**缝格里没有反号格**，缝基本是"两块直接共边"，
不是 r229/r231 假设的"整圈三角过渡带"。这削弱了上一轮写进 next 的"重划三角过渡带"前提 ——
把缝格改成三角并不必然消掉反号，见下。

## 代码落点与差距

- 落点：`src/core/grid.js#unshearPatches`（换基 + 整块等比收缩）+ `grid-graph.html?square=1`。
- 现档（与 r231 逐位相同）：补丁 6 块 / applied 1 / **flips 35** / scale 0.886 / maxMove 3.9295 /
  roundErr 0；页面 `squareInfo` 与 488 四边格 / 200 三角格 / seam 367 三项都正常。
- 仍缺：缝上 **35 格反向**（缩到 0.886 也压不掉）。
- 第 232 轮试了三条路，**全部用读数否掉、代码已回滚**（试错账写在 `grid.js` 文件末）：
  1. 共用顶点两侧平摊（各补丁提案取均值，替代"大补丁独占"）→ 反向 **35 → 50**。
     两侧私有点仍钉在各自方格上，中间那圈落在谁也不认的位置，两侧一起坏。
  2. 换基前把"带共用顶点的四边格"沿对角线退化成三角 → 反向 **35 → 63**
     （四边格 1331→1140、三角 242→624）。两个顶点都在缝上的过渡三角照样折。
  3. ①②合用 → **73**；②且不做等比收缩 → **89**。
- 结论（写进下一轮）：缺口不在"格形"，而在"共享顶点表本身无解"——
  两条正交基不一致时，同一个顶点无法同时属于两块的方格。要收口必须让缝上顶点
  **不属于任一块的方格**（独立过渡顶点表 / 按补丁边界重排顶点），或承认缝格是"略歪的四边格"
  并把判据从"反号=缺陷"改成"|面积|>阈值"（后者是口径放宽，不走）。
