# 实际发船进场走廊预留

实际发船由仅终点盒扩展为整条直线进场扫掠盒预留：终点分开但航线交叉也拒绝。双网格各6次实际发船、15对进场盒无交，交叉/平行走廊逻辑通过。旧504帧不重计，172/285；地形岸礁碰撞、动态避让与原完整规划仍缺。

复用974325184525201409既有504帧全核记录与landing-plan-review.md，未增加学习计数。原README只证明自制盒测试，不能证明原走廊策略。本次工程规则：船保持固定水平朝向沿from→stop直线行驶14单位；将原保守终点盒半长.74沿该方向扫掠，中心移至stop+dir*7，半长7.74，半宽.26。对这种固定朝向的直线段，扫掠体本身就是此长盒；SAT拒绝与既有船预留走廊相交的候选。出场沿同一直线，故预留到船从列表移除才释放。

逻辑明确构造终点不交但进场交叉的两艘船，终点测试false、走廊测试true；平行相距2单位走廊不交。浏览器两网格固定随机连续6次真实Battle发船，各6艘船/90单位，15对终点和走廊盒都无交，无页面异常，两截图已看。仍是几何静态预留，不是基于到达时间的调度，会保守拒绝不同时间使用同走廊；不检查地形/岸礁，不证明全种子吞吐或复杂旋转航线。原版/.workbuddy只读，未同步TigerMessenger。
