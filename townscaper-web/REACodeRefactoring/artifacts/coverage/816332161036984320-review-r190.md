## 判定

有机制：Unity「Trajectory Calculator」= 同一 `Start Speed`/`Drag` 下按整排角度画带阻力弹道，并把
「打中某个格点该用的出射方向」预先解成**逐格点查找表**（白点 = 格点，白线 = 该格点的低弧出射方向，够不着的格点只剩点）。
本项目落点 `src/core/trajectory-fan.js` + `trajectory-fan.html`，r56 已实现线性阻力解析解、等弧长切线采样与 `launchGrid()`。

旧 note 挂的三条缺口本轮逐条核实：

1. **「缺场景碰撞截断（片子弧碰到体块就断）」→ 撤销。** 全片（177 帧、两页联系表 + 0040 右半 3× 裁切）场景里没有
   任何实体块：只有地面线、点阵与 Inspector 面板；弧线终止的原因只有「落地」与「出视口」。按「片中没拍到的机制不记缺口」
   的纪律（r127 先例），这条不是本片的缺口，本轮不加碰撞截断，也不冒充已实现。
2. **「二次阻力档」→ 真缺口，本轮落地**，但**片内不可判**（下面是量出来的，不是猜的）：把二次档 `k` 拟合到与线性档
   同 45° 射程后（7.99 / 0.83 线性 ↔ 7.99 / 0.15 二次，射程 3.870 对 3.870），两条轨迹最大高度差 **0.0731 单位 =
   1.89% 射程**、顶点 1.244 vs 1.197（−3.8%）。片中扇面横向约 390px、1 单位 ≈ 43px 时 1.89% 射程 ≈ **2px**，
   小于划线长度 25px 且低于 JPEG 压缩噪声 → 不能从画面判档，故页面给**两档可选**而不是硬选一种。
3. **「Inspector 第三行读不到」→ 已过期。** 4× 裁切确认第三行确实存在、被面板下沿裁掉只剩字符顶部（`G…`），
   逐帧都读不出完整标签；但 `Gravity` 滑杆 r56 就已在页面上（弹道扇面离不开 g，且 45° 解析射程对照一直挂着 g）。

## 代码落点与差距

- `src/core/trajectory-fan.js`
  - 新增 `DRAG_MODELS = ['linear','quadratic']` + `checkModel()`；
  - 新增 RK4 积分器 `quadStep()`/`quadMarch()`（落地按最后一段 y 线性回插，落点精确贴 `groundY`）；
  - `throwArc({ dragModel })`：linear 走原解析解（逐位不变，多了 `dragModel:'linear'` 字段），quadratic 走 RK4 并返回末速度；
  - `heightAtX({ dragModel })`：二次档按 `x(t)` 单调性积分到目标 x 再回插；`quadMaxReach()`（带缓存）先否掉够不着的点；
  - `solveLaunch({ dragModel })` / `launchGrid({ dragModel })`：同一「扫 + 二分低弧解」流程，二次档扫描步 2°、够不着的格点直接 null。
- `trajectory-fan.html`：新增 `#model` 档位下拉 + `?model=quadratic` 入口；读数行出 `模型 / 射程上界`，`fanPage.setModel()/fan()`
  探针；说明栏补第 190 轮那一条（两档都在 + 1.89% 不可判）。
- 如实口径（不是缺口但没对齐）：本仓 `drag` 是「dv/dt = −k·v」的 k，与原版 Unity `Drag` 标量不是同一量纲（页面 Default 0.83 是
  沿用旧页的对照取值，不是从片里反解出来的）；投影/字色/点阵色未按片重标；白划线长度 25px 用世界单位 0.55 近似。
