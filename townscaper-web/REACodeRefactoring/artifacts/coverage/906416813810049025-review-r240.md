新测 `tests/cave-light-pixel-browser.cjs`：

1. `index.html?scene=badnorth&bncaves=3&cavelight=1` → 冻时间轴（`view.render = () => orig(0)`）→ 关植被 + 摘 `#hud`；

3. 三张：**开 → 关 → 再开**，每次 `world.caveLight` 换档 + `worldMesh.invalidate()`（缓存按几何 hash，不显式失效不重烘），

## 判定：**仍 partial**（账不动，done 212 / partial 36）

拍到了开关差分，但**画面证明的是另一件事**：ViewImage 实看 `cave-light-on.png` / `cave-light-off.png` ——
相机在洞口外的台地上沿洞轴看，挡住视线的是一整面**外部岩壁**，开档时这面墙整片变暗（48% 像素全变），
而不是「洞口一圈亮、洞内深处沉下去」。即 `caveShadeAt` 只按「y 落在 (floor·L,(floor+2)·L) 带内 + 到洞轴横向 ≤ 半宽」判洞内，
**不看面朝向、也不看是否被洞顶遮挡** —— 洞外朝外的岩壁只要落进这条带里就被当成洞内一起压暗。

这正是 r239 写进 `next[1]` 的那条预判（「遮挡可见性：站在台面上俯视时压暗会连带把洞口边缘的岩壁压暗」），
本轮**用像素账证实了它**，并且它已经足以让「像素级 A/B」这张图证不出片子里的那一层。

## 落点与差距

- 落点：`src/light/cave-light.js`（`caveShadeAt`）+ `src/world/worldmesh.js`（bake 后 `applyCaveLight`）；
