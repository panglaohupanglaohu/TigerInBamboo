## 逐帧观察

- 0000–0100：俯视一座 Bad North 的岛。地面是浅灰褐色台地，台地上沿、院落内部、外圈水面边缘**各有一道贴地的亮白细线**，线互相平行、间距基本相等，在平地上闭合成圈，遇到建筑基脚就绕开。塔楼顶上有几面蓝底横幅（装饰件，不是单位）。镜头几乎不动（0–10 帧平均灰度差 1.93）。
- 0100–0200：镜头开始缓慢环绕，亮线**跟着几何一起动**（说明线是世界空间画在地面上的，不是屏幕叠加的 HUD）。0107 之后左下出现一片浅蓝水面高光，是水面反射/材质变化，不是新元素。
- 0200–0400：继续环绕，主堡四周能数出 4 圈嵌套线；线条在建筑转角和台地拐角处是**小切角/圆弧**，不是直角硬折。这一段的切角形态和 marching squares 在格子标量场上取等值线的倒角一致。
- 0400–0550：绕到背面。线从台地边缘顺着台阶立面往下，再沿下层平地绕行；同一块平地上的线不与建筑轮廓重合，而是**固定内缩量**的平行线。

## 判定

**有机制**：距离场的等值线（iso-distance contours）。

判据三条：
1. 线是等距的、互相平行的多重闭环 —— 只有"到某个边界的距离"这种标量场才会产生等距嵌套线；流向/继承场（902069261304287232 那条）画出来是分叉的树，不闭合。
2. 线贴地但**不与几何轮廓重合**，有固定内缩量 —— 是等值线，不是墙脚轮廓高光。
3. 平地上闭环、遇建筑绕行、顺台阶下行 —— 距离是在可走面上算的（把建筑/水面当障碍）。

原文只有"Distances this time"，没写做法，所以"等间距是人工挑的层级、距离在可走面上传播"是按画面反推的，不是原文结论。

## 代码落点与差距

新建 `src/core/distance-isolines.js`：

- `distanceField(mask,{w,h})`：四周补一圈「外面」，用 Felzenszwalb–Huttenlocher 分离式 EDT 求**精确欧氏距离变换**（到最近不可走格/岛外的格心距离），带双线性 `at(x,y)` 采样。
- `isoContours(field,{levels})`：marching squares，16 例查表 + 鞍点（5/10）按四角均值定向；端点按 1e-4 量化键缝合成长折线，输出 `segments / paths / closed / openEnds`。阻塞格按距离 0 参与插值，线才会贴着障碍/岸线闭合（代价：level 接近 1 时线会往障碍格里压最多半格）。
- `evenLevels(max,spacing)`：片子里是等间距层级，不是按数据分布取分位。

实验页 `distances.html`：左=同一份距离场热图（深=靠边、浅=岛心），右=等值线（实线闭环 / 虚线开放段），带间距滑杆与「参考片配色（浅地白线）」开关，几何不随配色变。

**缺什么**：
1. 片子是**3D 多层地形**：距离在带台阶的 nav 面上传播，等值线还要贴台阶立面（现在的实现是单层 2D 格）。
2. 建筑的占地是任意多边形（片子里有圆角/城堡轮廓），实验页用的是矩形块。
3. 没接进 `battle.js` 的调试层（`view.flowDebug` 旁边再加一个 `distDebug`），因为这条片子是空岛、没有单位，接了也没有对照画面。
4. 层级间距在片子里是否等距只能目测（约 0.7–0.8 格），没法定量。
