## 逐帧观察

- 全片是一段**慢速环绕**（约 200°），无生成过程、无 UI 文字；frame-0120 左下角有白色圆形笔刷光标 —— 是实时操作录屏。
- 三处"怪"从头到尾都在：
  1. **屋顶与铺地齐平**：近处几栋房子墙全没了，只剩屋顶和一道山墙尖露在广场地面上（frame-0000 中景三栋最明显）；
  2. **台地悬在房子上方**：中部台地外沿向右伸出一条**悬空的檐**（frame-0000 右上方那块大板），檐下压着房子，房顶只从檐口下面探出一条；
  3. **崖面挂草舌**：台地边缘草皮顺崖壁下垂一段（`terrainmesh.js` 已有，本轮未动）。
- 关键细节（本轮新增判读）：被吞的墙**不是干净的一条切线** —— 屋顶与地面交接处还留一条比岩石深的**细暗带**（墙裙/勒脚），而且它只在**屋顶还悬在头顶**的那些面上；整栋被埋的柱子崖面上什么都没有。这就是「墙裙残留 + 悬檐联动」在 640px 下的可读形式（细到 1–2px，只能靠"有/没有"判定，量不出厚度）。

## 判定

有机制：**抬地形时把不超过新地面的建筑层换成岩石、保留其上的层**；崖面上留一圈墙裙，且只出现在屋顶仍悬出的面上（檐下墙皮躲过了刷地）。

## 代码落点与差距

- 已有（r56 起）：`src/core/terrain-burial.js` 的 `buryColumn()` / `raiseGround()` / `burialReport()`（peeking / blanketed / swallowedLevels）、`terrain-stages.html` 的「地表抬升吞建筑」栏。
- 本轮补齐（原登记的两条剩余缺口）：
  1. **墙裙残留** `cliffSkirt(world)`：每份 World 一份掩埋台账（`buryColumn` 记录 `{height, swallowed, kept, wall}`），
     只对「台账里有记录」×「`top > ground` 且顶上仍是建筑（只剩屋顶）」×「这一面露在崖上（邻格地面更低 / 网格开边）」的
     交集出面：`ground-0.34 … ground` 的一条带，内缩 `0.08` 层 —— 内缩是因为墙皮在格内、不在格边，刷地只吃掉格心那一坨。
  2. **悬檐联动** `notches`：同一张面从 `ground` 往上压 `EAVE_SHADOW=0.45` 层、再缩进 `EAVE_SETBACK=0.17`（合计 0.25），
     与墙裙**一一对应**（`bands.length === notches.length`、同 cell 同 face），屋檐挑得比墙裙深 —— 这就是"联动"的可检验形式。
     画在建筑盒之后（第二遍），压在墙头上；整栋被埋的列 `notches = 0`。
- 页面上：`#bury` 画布按格深度顺序画墙裙（`#7a705f`）与檐下暗带（`rgba(0,0,0,.24)`），读数栏加「崖面墙裙 N 面 · 檐下缺口 N 处（联动）」，
  `window.terrainStages.skirt()` 暴露 `{faces, bands, notches, linked, painted{skirtFaces,eaveNotches,roofs}, depth, inset, setback}`。
- 差距：片子里的墙裙是**贴图上的细暗线**，本地是几何薄带（0.34 层），只取到"有/没有"与位置；材料/笔触等价不在本片范围内。
