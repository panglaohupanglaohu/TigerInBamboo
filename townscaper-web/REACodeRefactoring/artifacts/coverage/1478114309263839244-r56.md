## 原缺（r53 / r55）
r55 G5 已有 uv-charts（法线夹角分片 + 径向排布 + 三角栅格占用）、uv-bake（UV 页进共享 Atlas、逐像素烘焙）、uv-bake.html，但在 generateTerrain 的台阶岛上中心片只占 4%，"中间一大块"不明显；没有 UV 页线框调试视图、模型线框、逐片放置动画，棋盘是世界空间的（不能看出各片 UV 方向）。

## 本轮做了什么
- 新 `src/core/uv-radial-atlas.js`：
  - `clipIsland(world)`：与片子同构的测试岛写进共享 World（底板 1 层 + 3 根 3–6 层崖柱 + 拱洞：柱边一格 1–2 层挖空、上面实心），网格走共享 terrainmesh + shapeTerrain。
  - `topMergeCharts`：朝上面（n.y ≥ cos50°）沿共享边连通成片、统一竖直投影（不受"离种子法线 ≤40°"限制，缓坡也并进来；片内自交则退回原分片），其余三角走 r55 `buildCharts`。中心片 = 底板，崖柱脚印成洞。
  - `chartHoles`（Euler 计洞）、`radialSpearman`（面积名次 vs 离心距离）、`rasterizeChartPage`（UV 页逐像素记三角号 + 重心）、`paintCheckerPage`（UV 空间棋盘）、`dilatePage`（gutter，alpha 128 标记）。
- 新页 `uv-radial.html`：上 = UV 页（灰蓝底 + 深色三角线框，`?step=` / 播放按钮按 radialChartPack 名次逐片加入），下 = 同一座岛 three 模型（线框 / UV 棋盘格 / 反差纹理三模式），分片可切「朝上面合并 / 法线夹角（r55）」。
- 判断：在片子同构岛上，r55 的 buildCharts 本身也能把平底板分成一片（30.9%），所以 r55 的"4%"主要是测试岛形状（台阶多）造成的，不是算法缺陷；topMerge 对缓坡/形变顶面有用，在本岛上不改变中心片大小。如实记录。

## 测试
`tests/uv-radial-atlas.mjs`：测试岛确定性、拱洞下空上实；每三角恰好一片、朝上片竖直投影不翻面；0 重叠；最大片在正中且是底板、占 30.9%（>25%）、带洞；Spearman −0.62（<−0.5）；中心片不小于 r55 分片最大片；generateTerrain 四边形岛也能跑（0 重叠、最大片居中）；UV 页覆盖、棋盘两色、gutter；参数拒绝。回归 `tests/uv-charts.mjs`、`tests/uv-bake.mjs` 通过。
