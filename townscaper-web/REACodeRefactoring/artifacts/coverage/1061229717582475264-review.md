## 逐帧观察
- 0000–0019：画布上是两条竖向装饰带，铺满视口，条纹细节大到一个图元占半屏。
- 0020–0050：镜头拉远，两条带缩成画布中央的小方块，四周空；读得出"这是两块独立的面板"。
- 0051–0120：再推近，**三条**竖向面板并排（每条一整块装饰带），中间的朝向/缩放与两侧不同；变换读数 2497.9。
- 0121–0169：三条并排稳定，横向条纹与卷草在三条上的接缝位置不同 → 并排看时不再是一条无限重复的带。
- 0170–0230：镜头继续推近到只看得见一条带的局部，图案变成大三角 + 卷草。
- 0231–0331：保持在这个近景，缓慢平移；末帧仍是同一张贴图放大后的局部。

## 判定
有机制：**同一张贴图，用几套不同设置（朝向、格宽/缩放）拼成多条面板**，让相邻面板的重复起点错开，从而"打破重复"；用的还是同一张纹理。

## 代码落点与差距
- `textures.html` deco 页签第 3 个子模式「+ 几种设置」本轮重写成**三条并排装饰带**（朝向 7/3/1、格宽 36/44/52），与片子的三条并排构图对齐。
- `src/core/mirror-uv.js` 的 `orientUV` 提供 8 种朝向；页面里 `decoPanel()` 用 `orientation>=4` 加一次额外镜像，等价于模块口径。
- 仍缺：片子里的贴图是真实的巴洛克 UI 图集（沿边可拉伸的九宫格），本页只有程序化 48px 图元；三条带目前是固定三套参数，没有做成可保存的"装饰套件"。
