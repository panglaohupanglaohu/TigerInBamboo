## 代码落点与差距

落点：`src/light/bake.js`（`AO_MODES` / `bakeLighting({aoMode:'directional'})` / `FACE_TINT` / `OCCL_TINT_W`）、`src/world/worldmesh.js#setBakeLighting`、`src/world/view.js setDebug('bakedonly')`、`src/world/view-c04.js SSAOPass`、页面 `ao-stages.html`（五档 + `?baked=1` + `aoStageReport()` + 本轮新增 `aoTintAxisReport()`）。

r235 留的那一条（⑤与③只差 41px）本轮查清并改掉，**根因不是量级，是着色项挂错了对象**：

1. 旧实现只按「**遮挡来自哪一侧**」着色，`mix = min(1, occl*1.5)`，开空墙面上 `occl=0` → 色偏被压成 0，只有凹处有一点颜色。而片⑤是**整面墙按朝向分冷暖**（0002 整片灰 / 0004 整片粉紫），与遮挡无关。
2. 改为「主项 = 法线朝向色（`FACE_TINT`，逐轴），次项 = 遮挡侧色（`DIR_TINT`×`OCCL_TINT_W=0.35`，只在真有遮挡时叠）」；AO 项仍是 `1−strength·occl`，与朝向色相乘。
3. 量级按片内像素账标定：标称 ±36% 时本仓 mean\|Δ(R−B)\| **14.31 级 = 10.7% 亮度**、\|Δ\|≥8 占比 **76.2%**（片内 11.5% / 71.9%）。旧 `DIR_TINT` ±3–6% 在 8bit/ACES 下就是被抹平的那一档。
4. 轴符号按本页机位标定（相机在 +X+Z 一侧：法线朝屏幕左的是 **−X / +Z** → 暖，朝右的是 **+X / −Z** → 冷）。标定办法：把单轴临时染成蓝（`FACE_TINT[a]=[0.2,0.35,3]`）拍图目视，两次（+X / +Z）定出左右，之后复原常量。与片内「左暖右冷」同向。

**如实记两条口径问题（都是本轮量出来的，不是猜的）：**

- r235 的像素账**没摘 UI**：`#hud`（143 个开关面板）与底部进度条压在画布上，元素截图会一并拍进去（右半屏白底文字面板直接把 R−B 与高频抬起来）。本轮验收前先 `visibility:hidden` 掉 `#hud/#learnpanel/#toast/#helpcard` 与非 canvas 的 body 子元素，再拍。摘 UI 后 r235 那组阶梯差从 484295px 落到 224058px（仍是逐级可见）。
- r235 计划的「左半 R−B − 右半 R−B」这**条读数在本仓不成立**：第③档（无方向色）左右半屏基线就差 **17.3 级**（左半屏橙屋顶多、右半屏铺地多），把墙色染成哑光灰后仍差 17.3 级 —— 是场景构图差，不是色偏。故冷暖账改走**逐轴顶点口径**（`aoTintAxisReport`，按法线主轴分组读顶点色 R−B），并保留像素 Δ 分布做量级校验。
