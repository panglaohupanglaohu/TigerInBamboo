## 逐帧观察

- **0000–0099**：一座多层的岛/小镇，红紫色调的光从侧上方打过来，镜头极慢地环绕（7.6 秒只转了很小的角度）。能看出来的是**没有硬折边的黑线**：台地侧壁、屋顶斜面之间是渐变过渡，转角处有一圈柔和的暗边而不是一条刀切的分界。
- **0100–0199**：继续环绕；0105–0108 拉远露出整片地基与几缕白色烟，随后回到近景。同一座模型、同一套光，明暗关系不变。
- **0200–0255**：仍是这一座岛的环绕，结尾**没有任何字幕、AB 对照、开关或参数**，画面直接结束。

片子里没有出现「硬法线 / 平滑法线」的对照画面，也没有 UI 数字，所以系数只能靠观感反推。

## 判定

有机制：**几何统一生成平滑法线，最终光照里再和硬法线按系数混**。片中可见的证据是「面片之间有柔和渐变、但转角仍有清晰形体」——全平滑会显得像塑料软糖、全硬会每一面一个色块，片子是两者之间。

## 代码落点与差距

- `src/world/view.js:99` `this.normMix = { value: 0.8 }`（1 = 全平滑，0 = 全硬），`view.js:126` 挂到材质 uniforms。
- `view.js:152-153`：`onBeforeCompile` 里用屏幕空间导数求面法线
  `vec3 hardN = normalize(cross(dFdx(-vViewPosition), dFdy(-vViewPosition)))`，
  再 `normal = normalize(mix(hardN, normal, uNormMix))` —— 就是原文那句「smooth normals + blend between smooth and hard in the final lighting」的同一套做法。
- `view.js:577` `case 'hardnormal'`：开 = 0.8（混合），关 = 1.0（纯平滑），可现场对照。

差距：
1. 原作是 2D 精灵渲染，硬法线来自精灵法线图的 alpha/导数；我们是 3D 网格用 dFdx/dFdy 现算，语义等价、来源不同；
2. 片子里看不出混合系数的具体值，0.8 是按观感定的；
3. 片中没有对照画面，无法逐帧验证系数变化。
