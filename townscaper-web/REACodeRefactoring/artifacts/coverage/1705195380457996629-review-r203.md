## 逐帧观察

- **0000–0019**：固定俯视偏斜机位，浅绿岛体 + 高灰白岩柱群；草面与岩壁交界的**上棱**有一条细暗带（frame-0012 原尺寸可见：左上崖顶、前方崖顶各一条，宽度约 2–3 个草格像素），岩壁面本身没有暗带。
- **0020–0099**：相机绕岛小幅转动（0001–0010 之间完成主要转向），暗带始终**贴着草崖边**、随视角重投；房基（右侧黄顶小屋）墙脚也有一条短暗带 —— 就是"檐下"那一侧。
- **0100–0207**：换岛继续环绕，暗带依旧只出现在草地-崖缘交界与建筑墙脚，平草面、平台内部保持干净。
- **0208–0299**：镜头拉远收尾，暗带随尺度变细，但位置不变（不糊到平台中央）。

## 判定

有机制：**纹理式（高度图）地表阴影，投射高度与 z 测试高度解耦**。门槛高 → 只有局部凸起（草崖棱、屋脊）够格投影，影子落点被压到"草崖边 + 檐下"；门槛降到 0 就回到上一版"太 3D"的满地影子。UV 边界伪影作者自述"很轻、可能不用修"，不记缺口。

## 代码落点与差距

- `src/light/surface-shadow.js#bakeSurfaceShadow`：`castHeight`（谁有资格投影）与 `zBias`（射线深度比较）两个独立旋钮；`surfaceHeightsFromWorld` 在真实 World 顶面采样，建筑顶面加 `roofRise` → 屋檐能投影、屋顶自身不收自己的抬升；`bakeFloorShadow` 给洞/悬挑下地面烘第二张图；`surfaceShadowStats` 输出落点份额（崖缘/檐下/别处）。
- `src/world/view.js` + `view-shading.js`：`?shade=surfaceshadow` 走 `receivers:'all'`（顶面 + 洞内），默认强度 0 不干扰既有体素阴影。
- 本轮差距只剩**页面入口**：`surface-shadows.html` 原来只暴露 castHeight/zBias/strength，接收面固定 `top`（洞内进不来）、瓦檐抬升与落点统计都读不到，且提示语仍写"屋檐、洞内尚未覆盖"（过期）。本轮补：瓦檐抬升滑杆、接收面下拉（顶面 / 顶面＋洞内）、落点统计行（崖缘/檐下/别处/洞内像素）、提示语改成"已覆盖/未覆盖"的真实划分。
