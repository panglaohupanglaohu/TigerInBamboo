## 判定

**有机制**：一个 Unity 开发用「弹道计算器」——给定标量 Start Speed 与 Drag，从同一起点按一整排发射角各积分一条带阻力的弹道，用点状曲线画出，并在等弧长位置插白色短划线表示该处速度方向；改 Speed/Drag 即时重绘。

不是美术展示片：画面里两个参数被反复改写、扇面跟着变，属于工具在工作。

## 代码落点与差距

- 新增 `src/core/trajectory-fan.js`：`throwArc()`（线性阻尼解析解 + 二分求落地时刻）、`sampleTicks()`（等弧长重采样、返回单位切线）、`trajectoryFan()`（整排角度的扇面）、`defaultAngles()`、`analyticRange()`。
- 新增 `trajectory-fan.html`：深底 + 白点阵 + 青点弧 + 白切线划线，Speed / Drag / 划线间距三个滑杆，读数栏给 arcs / 划线数 / 最大射程 / 最高点 / 无阻力解析射程对照。
- 原有 `src/core/ballistic-table.js` + `ballistics.html` 只做**无阻力**、按代价挑角度的定点射表（页面上原本就写着「没有复现原 Inspector 表达式/阻力」）——这条片子正好补的就是那一层，两者并存：射表管「打哪个目标用几度」，扇面管「这套参数能打多远、弹道长什么样」。

**缺什么**：

1. 片中弧碰到建筑/坡体就断（Unity 场景里有碰撞体），本仓只按地面 y=0 收尾，没有场景截断；
2. Inspector 第三行参数被窗口截断，读不到，没有猜（可能是重力或时间步）；
3. 线性阻尼是选择：片子里只看得出「有阻力」，分不出线性还是二次，未实现二次阻力档；
4. 没有把扇面接进 `ballistics.html` 的实际射表（两套角度口径不同：射表解 10°–80° 的定点最优角，扇面是固定角度排布）。
