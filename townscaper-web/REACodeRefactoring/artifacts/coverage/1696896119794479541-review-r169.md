- 原文：On the other hand, I've always wanted to make a game in the Art Nouveau style. This might be a good fit. Look how neat and controlled the grass blotches bleed over the cliff edges.

## 逐帧观察

- **0000–0139**：固定机位缓慢环绕的「新艺术」小岛（青灰底、米白崖面、桃色岩层、黄屋顶塔楼）。顶面是**大块圆角色块**（草绿 / 黄绿 / 桃色），色块边缘柔和、带极淡的同色描边；崖面是米白，只有细层理线。此段看不到跨崖色块。
- **0140–0253**：镜头下压、色块整体抽掉，画面只剩灰白崖体 + 黄顶小块（几何读图段），崖面出现沿口折线与层理；0230–0253 顶部又出现薄薄一层草色。
- **0254–0299**：颜色回来，机位拉到岛侧，顶面重新出现黄绿大色块。
- **0300–0469**：**本片关键段**（近景崖肩）。米白崖壁上方是一整片桃色/米黄顶面；0350 原尺寸可见：顶面桃色斑**越过崖肩**继续往下一点点，形成一条比周围更深的窄带，色块内部有柔和的同色波纹，外缘有一圈很细的深色描边；崖壁本身仍是米白，色只垂到很浅的深度就平齐收住，深部完全没有色。0455 的 3× 裁切里草绿斑沿崖肩走成一条「舌头」状，边缘深线清楚，更下方的崖面干净。
- **0470–0549**：镜头拉回全岛，色块恢复成大斑，末帧静止。

## 判定

**有机制**：顶面大笔触图集（可平铺周期噪声）→ 崖肩距离场决定「顶面色块在崖肩前收住」→ 崖面只在沿口下方很浅的一段内延续同一色块（等深收口）→ 另一路「舌头」把顶面色块按图集强度翻过崖肩，长度随强度变化、末端带细深描边。片中「controlled」= 只在崖边、只到固定深度、不渗到深部崖面。

## 代码落点与差距

- `src/terrain/blotch-atlas.js`（文件头署本片 ID）：`createBlotchAtlasData` / `sampleBlotchAtlas`（128² 可平铺图集）· `buildBlotchRimField`（共享 World 崖肩 chamfer 距离场，G 通道=本格顶面高）· `blotchMasks`（rimMask 顶面收边 / bleedMask 崖面等深收口）· `blotchRimTint` + `BLOTCH_RIM_GLSL`（CPU 与 GLSL 同式）。
- `src/terrain/blotch-tongue-c09.js`（r56 C09，署本片 ID）：`tongueAmount` / `tongueWallMask` / `tongueTopMask` + `BLOTCH_TONGUE_GLSL`（顶面带 + 崖面舌头 + `col*.55` 深描边 + `fwidth` 抗锯齿等深线）。
- `src/world/view-shading.js`：`?shade=blotchatlas` 键 + `?tongue=1`，图上到 View 主材质；本轮新增只读 `setBlotchRim()` / `blotchParams()`（运行时可调 scale/strength/bleed/streak/density/swirl/segments）。
- 页面：`blotches.html` 原来页脚写「原作 atlas、受控跨崖采样、配色及反射尚未复现」、只有旧噪声档 → 本轮补「图集笔触＋受控渗漏」「翻崖舌头」两个开关 + 渗漏深度 / 笔触尺度 / 强度三个滑杆 + 参数读数。

**仍缺（本轮未证实）**：渗漏的**世界深度**在画面上没量出来 —— 合成竖带/竖直探针上「bleed 0 vs 0.14 vs 0.30」的差值恒为 0（见下），而 CPU 孪生在同一位置给出 0.115 / 0.265 的带高；说明「等深收口」这一层目前只有 CPU + node 层的证据，缺一次可信的 GPU 剖面读数。原片的**配色**（桃/黄绿/米白）与**反射**仍未对；图集是程序化替身。

## 验证

- `node tests/blotch-tongue.mjs` **PASS**（新增）：强度 0..1 覆盖、`reach == depth·amt` 逐档 ±0.02、平顶/沿口以上/弱斑不上色、顶面带比例 `topReach/depth=0.58`、真实 World 285 格里 147 个崖肩格有舌头且内部格 0、GLSL uniform 齐全。
- `node tests/blotch-atlas.mjs` **PASS**（回归）：图集覆盖 0.41 / 行内穿越 6、249 个崖肩格、编辑后重建、等深收口、GLSL 名不冲突。
- `tests/blotch-atlas-rim-browser.cjs`（本轮新增，**当前 FAIL**）：主场景同机位 A/B `offOn 18168 px`、`onTongue 19222 px`、`noise 0`、顶面 6×6 面片 `atlas on vs off` 着色 **10.0%**、图集尺度 `.09 → .045` 扫描线边界 `6 → 0`（更大笔触）——这些成立；**等深带三条断言全 0**：竖直探针 8 档（dy .03/.08/.13/.18/.25/.40/.60/.90）在 bleed 0/0.14/0.30 下亮度差 0，舌头档同样为 0。
- 自查出的口径坑（写进测试注释）：① readPixels 第 0 行在下；② 行均值是 0..1 亮度，阈值 1 级 = 1/255（第一版写成 `>1` 恒不触发）；③ 崖面上的 streak/steep 明暗是**常驻项**（与 bleed 无关），拿「图集关」当基准会把常驻项读成渗漏（第一版读出 0.9 深度）；④ 探针 RT 清屏 alpha=1，按均值会被背景稀释 100 倍。

## 结论

该条**保持 partial**：机制与「顶面色块 / 笔触更大更少 / 崖肩收边」在运行时可验，但「受控跨崖渗漏到固定深度」缺一次可信的 GPU 读数，不能算收口。下轮从这里接：先在竖直探针上把 `uBlotchRimQ.x`（bleed）与 `uBlotchRimP.y`（topSpan）的实际取值打印出来，确认 shader 里 `below = G·topSpan − y` 是否落在预期的 (0, 0.14)。
