## 逐帧观察

- 0–60 帧（sheet-00 前六行）：深灰地面，地面本身是**不规则多边形网**（弯边、大小不一的四边形，像松弛过的 Voronoi），不是方格。画面正中只有一小撮白色块体，每帧增加 1–2 块，位置沿不规则格向外铺，说明是逐格求解而非整片重算。48–62 帧出现过一次绿色高亮（一部分格被染色），持续 2–3 帧后恢复白色。
- 60–140 帧（sheet-00 末两行 + sheet-01）：块体长成一座带塔的高台建筑群，轮廓明显随不规则格走 —— 外墙是折线/弧线而不是直角网格线；屋顶沿各格顶面各自倾斜。绿色高亮每隔 8–14 帧扫过一片格（每次位置不同），像在标出刚被改判/刚求解的格。
- 140–300 帧（sheet-01 末行、sheet-02 全部）：主体结构基本不再变化，只有相机缓慢绕行和绿色高亮的游走；同一块建筑在 60 帧里保持同一形态，说明已经是稳定解而非每帧重生。
- 300–380 帧（sheet-03 前八行）：绿色高亮越来越频繁地覆盖整片网格线（frame-0303 原尺寸可见：整个建筑被绿色线框套住，底部还有一道红色弧），像是切到边/接口调试视图；建筑本身仍未改变。
- 380–395 帧（sheet-03 末两行）：机位压得很低（近地平），能看到地面网格的弯曲边与建筑底座贴合。

## 判定

有机制，而且是本片的核心：**在任意多边形（不规则四边）半边网格上跑 WFC**。
证据是"块体边界与地面弯边严格贴合"——方格格子不可能长出这种弧状外墙；同时 0–60 帧的增量铺开说明求解是按格推进的（interactive speed），而不是离线算完再逐块播放。
"Next up is to make it deterministic"这句是**未来时**：片子里没有出现"固定种子跑两次结果一致"的对照，所以片子本身只能证明"能跑"，不能证明"确定性"。

## 代码落点与差距

- 模块：`src/core/wfc.js`（任意多边形半边 socket 约束、稳定顺序求解、迭代回溯、固定约束与预算）。
- 实验页：`wfc.html`（复选框「混合网格」「四边形切四三角种子」、按钮「求解 / 固定首格全1接口 / 改中间一格并局部修复 / 枚举已固定格周边 / 清除约束」）。
- 做到：`quad` 206 格、`mixed` 147 格均能求解；正序/倒序输入同一解；回溯 0；改一格后局部修复只动 0 格/范围 0 格；5.6ms。
- 缺：**尚未实现四子格联合模块约束**，因此只是"格集求解器"，不等于原作那种整栋建筑的多格 tile；片中的绿色线框调试视图本仓只有等价物（`wfc-quad.png` 里以格填色 + 边点表示），没有逐帧扫过的绿线动画；红色弧标（片里底部那道）没有对应实现。
