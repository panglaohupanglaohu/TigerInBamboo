`src/terrain/field-pattern.js`（文件头署本片 ID）+ `src/core/meshwriter.js` 的 `fieldFrame` + `src/terrain/terrainmesh.js:187`（`fieldAngle = hash01(c.id*19+5)*π`，只给非河道露岩顶面）+ `src/world/view.js:241`（`if (uFields > 0.5) diffuseColor.rgb *= fieldTone(vField)`）+ `fields.html` 全部 r56 就在 —— **机制侧不缺**，缺的是「四段显示顺序」这个页面入口和「格块读得出来」的运行验收。

## 代码落点与差距

落点：`src/terrain/field-pattern.js`（`fieldToneStripes` / `fieldTonePlots`）、`src/world/view.js`（`uFields`）、`src/core/meshwriter.js`（`aField`）、`fields.html`。

**本轮补（页面入口 + 量具，机制零改动）**

1. `fields.html` 增加 `?stage=`（`fields` / `lit` / `unlit` / `shape`）与下拉框 —— 片内 4 段顺序第一次在页面上能逐段摆出来：`shape` 走 `MeshBasicMaterial(#000)` 换掉**地形网格**材质（不动水面，这样「剪影 vs 光照」整帧差分正好圈出岛）。**如实口径**：树、灌丛、瀑布是独立几何/材质层，换地形材质时仍是原色 —— 原片剪影是整岛含附属物全黑（`islands-c09.html?stage=silhouette` 用 `scene.overrideMaterial` 才有那个效果），本轮没把这一层做全。，`unlit` 走既有 `setDebug('textureonly')`，`lit`/`fields` 走 `uFields=0/1`。
2. 页面同时关掉 HUD 与灌丛叠层（原片顶面是裸田纹；灌丛会把条纹压成绿斑），并把 `#plots` 画布 id 冲突（原来复选框与画布同 id）修掉 —— 复选框改 `#plotsOn`。
3. `window.fieldReview.report()` 逐三角反解每格的田纹坐标系（`u = x·c + z·s`，由两个顶点的 Δ 解 (c,s)），返回格数/方向直方图/周期像素/格心屏幕坐标；`project()` 自己乘相机矩阵（页面里没有 THREE 便利方法）。

**仍缺（本轮实测，不是过期账）**

- 屏幕观感与原片差距大：本仓实景是**带树、灌丛、河、云、瀑布的地形场景**，顶面大量是草绿而不是片中的裸浅黄；田纹开/关整帧差分 44043 px / 岛掩码 215937 px（20%），但沿格 u 轴 64 px 取样线上主频占比只有 **1–3%**（p50 0.02），开田纹信号幅度只升 **1.14×**（p50）—— 即「条纹在屏幕上远没有片中那么读得出来」。
  该量具本身也不干净（64 px 取样会跨到邻格/崖边），所以这一条按「观感差距」记，不当作精确比值。
- 原片条纹是宽而软边的**带**（周期/岛宽 ≈3%、占空比接近 1:1），本仓是 0.18 幅度的**细线**；改宽度/对比度会破 `fieldToneStripes` 的「uFields==1 逐字节保留」承诺，属于要动默认值的活，本轮没动。
