## 逐帧观察

- 0000–0079：俯视一片浅灰地面 + 白色不规则格线（三角/四边混合网）。左上一块红色闭合折线开始出现（3 帧内成型），中间有几颗黄点，右上一个 RGB 三袖 gizmo（红/绿/蓝箭头 + 半透明方块手柄）。
- 0080–0159：出现深色岛体（黑灰多面体），格线压在其上仍清晰；红色折线贴着格边走、只走格边不穿格，端点处会「捏」在一起。
- 0160–0239：红折线扩展成多环，颜色开始分家（红 / 粉 / 紫 / 蓝各一段），同色段沿同一层走。
- 0240–0319：镜头推近到岛体一侧，红色折线整段贴在台地边缘；格角上的黄点沿格边排成串。
- 0320–0399：候选阶段——大片格被**整格**铺成白色，形成棋盘式斑块（黑格与白格交替），同时红/粉/蓝折线仍在。
- 0400–0479：棋盘铺满，格线几乎被白格盖住；随后逐格翻色（有的白格变黑）。
- 0480–0599：棋盘退去，只剩几颗彩色点心点与几段折线；0400+ 起岛体上出现灰色斜网格（岛体自身的面）。
- 0600–0702：镜头贴近岛体斜面，调试线基本消失，只剩格线。

线宽量化（frame-0470，460×460）：偏红像素 195 个，**水平 run 中位 2px**（p25 2 / p75 5 / max 15）。p75=5 是斜线沿像素台阶走的合并 run，单段横截面就是 2px。折算：2px / 460 宽 = 0.43% 视宽；本仓 1440 宽下 `LineBasicMaterial` 恒 1 设备像素 = 0.07% 视宽，细了 6 倍。

## 判定

有机制：网格调试层 = 白色格线框 + 沿格边的彩色区域边界（按跨层连通分量上色）+ 格角/格心点 + 整格候选填充 + 屏幕恒定的 RGB gizmo；线宽是**屏幕定宽**，不随远近变。

## 代码落点与差距

- 落点：`src/world/contour-overlay.js`（`ContourOverlay`：`regions` 区域边界、`candidates` 候选填充、`corners`/`dots` 点、`outlineMat` 定宽选中环、`gizmo`）、`src/core/region-ids.js`、`src/core/region-boundary.js`。
- 本轮改码（区域边界屏幕定宽 2px）：新增 `THICK_COLOR_VERT/FRAG` 与 `regionsThick` 四边形网格 —— 每条边界段一个 quad（`aSide/aPosA/aPosB/aColor`），复用选中环那套「投影两端点取屏幕法向」的外扩，半宽 `uWidth` px。默认 `regionWidth=1` → 总宽 2px（对齐原片 2px/460）。原 1px `LineSegments` 保留在中间当硬芯（不删，其他测试读它的 `color` 属性）。新增 `setRegionWidth(px)`。
- 仍缺：① `setCandidates` 的逐格 domain 仍由夹具喂，没接 `wfc.js` 的 `solveWFC(..., {traceLimit})` 快照；② 白色格线框（`view.gridLines`）还是 1px，原片格线更粗一点（本轮只改了彩色区域边界）。
