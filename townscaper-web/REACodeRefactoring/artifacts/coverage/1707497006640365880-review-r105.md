## 逐帧观察（本轮重看，按联系表页码）

- 0000–0039：全景俯视小岛，5–6 个台地/塔块，顶面外沿一圈鲑橙带；相机几乎不动，带子形状逐帧恒定 → 静态着色，不是粒子。
- 0040–0046：空帧 / 近黑过渡（采集中断），非画面内容。
- 0047–0099：第二机位环绕，橙斑转到侧面可见；**同一台地不同边的带宽差很明显**（内侧一条 14–20px，紧邻一条 4–6px），同一条边上从头到尾不变，到下个三角才换档。
- 0100–0199：继续环绕的中景，带子宽度分档清晰；台顶中心始终留浅米色窄带，**没有任何一格是整面橙**。
- 0200–0299：换岛（新种子），带子仍在台地边，宽窄分档一致；0229 后再换一台地。
- 0300–0339：镜头下降，宽景变成塔群。
- 0340–0499：低角度贴近塔身，橙带在每层塔身下沿成条；顶面被压缩，带宽在此视角不可直接量（俯角太小）。
- 0500–0599：回到全景 + 换岛，带子仍是「沿台地边、逐边换档、沿边恒定」。

## 判定

有机制，且机制已实现：**每个顶面三角一个带宽倍率**（`aBand`），同一边恒定、相邻三角换档 —— 与 0047–0099 看到的「边界两侧各自恒定、边界本身是直锯齿」一一对应。

本轮把 r101 留下的两个卡点分别处理：

1. **「P90 只有原片 ~60%，但机位不可比」** → 本轮建了同机位标定，结论是**这条差距是机位造成的假象**（详见下节）。
2. **「`splitCells` 三角化边缘那圈带子走向未对照」** → 全仓 `grep splitCells` **零命中**（`src/`、`tests/`、`tools/` 都没有），这条是过期名词（同 r102 的 blobshadow 教训）。真实三角化是 `terrainmesh.js` 的 `triC(ctr, ring[i], ring[j])` 扇 + `w.edgeTri=[ce, 角落?0:ce, ce]`；本轮用线框渲染（`view.material.wireframe=true`，`artifacts/coverage/shrub-band-wire-r105.png`，ViewImage 看过）确认：带子的外沿落在**三角扇的外圈顶点**（崖沿处 `aEdge=0`），不是沿格轴走 —— 与原片 0150 帧里「带子贴着三角斜边」一致。

## 代码落点与差距

- `src/terrain/shrub-band.js`：`SHRUB_BAND = {min:0.70, max:1.36}`，`shrubBandMul(cellId, edge, level)`。
- `src/core/meshwriter.js:216`：`aBand` 写属性（三顶点同值）。
- `src/terrain/terrainmesh.js:236`：`w.bandTri = bandOn && ce >= 0 ? shrubBandMul(...) : 1`。
- `src/terrain/shrub-texture.js:41`：`width = uShrubStyle.x * (band * (.55+.9*bfbm) * mix(.5,1,cover))`，运行时 `uShrubStyle.x = 0.12`（`view.shrubStyle.value.x` 实测，不是文件里的 0.50 默认值）。
- **常数未改**：同机位复测下 P90 差 11%（20px vs 18px），小于原片自身帧间 P90 跨度（14–26px = 1.86×）。若按「格 ≈ 58px」的另一种读法反推，需要把带宽放大 4×，那会让每个台顶被橙色铺满 —— 而 6 张联系表里**没有任何一格整面橙**，该读法自相矛盾，故不采纳。
