## 逐帧观察

**1707490932017279035（257 帧）**

- 帧 0–99：高空俯视一座台地岛。顶面是灰橄榄绿，**沿台地边缘一圈鲑橙/粉橙色的窄带**，带宽随崖高变（崖高的地方带更宽），外缘是一串小圆齿。崖面本身是浅桃色、带极淡的竖向条纹。水面深青绿，无倒影。
- 帧 100–199：机位压低贴到崖面，崖壁占满画面。**崖壁明显分层**：顶缘一条橙带 → 下接浅桃色崖壁 → 崖脚一条米白浅带（沙/浪）→ 水面。橙带在这一段最宽，约占崖高的 8–12%。
- 帧 200–256：机位拉到岛的侧后方，台地边缘的橙带连成一条不断的带，跟着轮廓弯折，中间有几处被崖口的凸角切断。

**1707497006640365880（600 帧，同族）**

- 帧 0–47 / 218–228 / 332–339 / 500–507 / 550–559：每隔一段出现**整片纯黑的岛屿剪影**（生成中/未着色状态），随后立刻恢复彩色 → 这是"又一个在生成"的实录，不是渲染错误。

- 帧 550–599：台地摊平成一大片粉褐色高原，边缘是密集小圆齿的扇贝边，橙带与高原顶面几乎连成一片。

## 判定

有机制（100% 贴图、无几何、无广告牌），且本仓已实现：`src/terrain/shrub-texture.js` 的 `shrubApply()` + `terrainmesh.js` 给顶面每顶点写 `aEdge`（到崖边归一并按崖高缩放）。第 53 轮修掉 `ChunkRouter` 不代理 `edgeTri` 的 bug 后，带子终于能画出来了（scaledShare 0.163）。

**但厚度与饱和度仍明显不匹配**（本轮实测，不是复述旧结论）：

| | 原片 | 本仓（默认 width 0.36） |
| --- | --- | --- |
| 带宽 | 约占崖高 8–12%，每层台地都有一条 | **一条淡粉细线**，肉眼几乎是发丝 |
| 颜色 | 饱和鲑橙（S≈110–150） | 被 `uShrubColor` 与基底草地混成浅粉，S 明显更低 |
| 外缘 | 密集小圆齿（扇贝边） | 齿形可见但频率偏低 |
| 倒影 | — | 水面倒影里没有灌木暖色 |

## 代码落点与差距

落点：`src/terrain/shrub-texture.js`（`shrubApply` 的 `width`/`rag`/`rim`/`lit`）· `src/terrain/terrainmesh.js`（`aEdge` 写入）· `src/world/view.js`（`setShrubStyle`，已限幅 width ≤ 0.6）。

本轮**未改代码**：参数的"对不对"必须靠与原片同机位同构图比对才能定，而本仓没有片中那个"阶梯台地锥"的场景（`?scene=terrain` 是普通岛）。已做的准备：

- 用 `view.setShrubStyle({width})` 扫了 0.36 / 0.48 / 0.60 三档并各存截图（`shrub-sweep-*.png`），确认**加宽能把带子拉到明显可见**（0.60 时台地边缘出现成片橙团），但 `coverage` 的低频门控会让带子断成一坨坨，与原片"连续带 + 扇贝边"仍不同构 —— 单改 width 解决不了，下一轮要同时改 `coverage` 门控（0.62 → 更高）与齿频（`bn(w.xz*23)` → 更高频）。

仍缺（写进 next）：

1. 带宽 + 连续性（width 与 coverage 要一起调，不能只调一个）；
2. 颜色饱和度：`uShrubColor` #e8876a 在 `mix(base, shrub, body)` 里被草地底色抬亮，需要提高 `body` 覆盖或加深色值；
3. 外缘齿频；
4. 倒影缺暖色（水面那一路完全没有灌木项）。
