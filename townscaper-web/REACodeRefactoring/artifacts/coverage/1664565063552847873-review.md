## 逐帧观察

全片一条静止机位（略推近），一座低矮岩台/小丘上叠着**假彩色（plasma 色带）场**，没有 UI、没有文字：

- **f0000–0017**：色带满幅：左侧品红/洋红塌成一片，中部黄→绿，右下青，台上还有两处亮白斑（场值最高处）。
  小丘轮廓被色带整体包住 —— 说明不是在给地形上色，而是**一张覆盖整屏的场被假彩色映射**。
- **f0018–0049**：绿/黄交界线缓慢横移，青斑（右下）往左上收缩；品红区域整体略微变淡。
  同一帧内色带是**连续**的（没有等高线台阶），说明场是 16F/32F 这类连续量，不是 8 位贴图。
- **f0050–0079**：画面推近（小丘变大），黄绿交界沿小丘轮廓弯折 —— 色带跟着地形起伏走，
  即场是**投在几何表面**上采样的，不是全屏平板。
- **f0080–0116**：品红从右上角再次渗入，黄色带变窄；末帧（0116）红黄斑集中在画面中下偏右，
  青只在左下角残留。全程没有闪烁/色块跳变（16F 精度不够时会出现的那种断层没出现）。

结论：片内是**一个随时间被平流输运的连续标量场，假彩色铺在岩台表面**，没有别的机制
（原文也只讲 float render target + 跨平台 + 回喂 CPU 这三件担心）。

## 判定

**有机制**：shader 流体（场平流 + 假彩色可视化）。片内能证明的只有"连续场在动"，
证明不了目标格式到底是 16F 还是 32F（色带连续只排除了 8 位）。

## 代码落点与差距

| 片内这件事 | 本仓现状 |
| --- | --- |
| 32F/16F 渲染目标能力 | `src/world/float-probe.js` + `float.html`：真 WebGL 读写 16F/32F、负值/HDR 回读、linear/nearest 过滤都有读数 |
| 场平流（片内一直在动的东西） | `src/core/float-advect.js#advect/advectionQuality/storageRoundTrip`：半浮/浮点/unorm 三种存储模拟 + f32/f16/u8/nearest 四档对照 |
| **假彩色铺在岩台表面** | **没有落点** —— `float.html` 是数值读数页（`#rows`/`#gpurows` 表格），不是把场画到几何上的可视化页 |
| 回喂 CPU | `storageRoundTrip` + GPU→CPU 读回在 `float.html` 里测过，数值层面通了 |

真缺口就一条、而且是**形制**不是算法：缺一张"把平流场按色带铺到真实 World 顶面/岩壁上"的实验页
（片内 117 帧全是这幅画）。所以这条保持 partial —— 机制在，画面没有。
