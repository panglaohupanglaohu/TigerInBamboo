要点：三类线不是随手画的——黑线始终贴着岛的外轮廓与崖壁折角，红线始终沿**格边**走并在格点转折（模块/格边界），蓝线只出现在**池岸那一小段**（材质边界：水与陆在台地上相接处）。原片整段没有出现「顶点乱飞」的形变，符合「顶点只在同级/更低级之间拉」。

## 判定

**有机制**：边按类型分级（黑=硬 / 红=模块-格边界 / 蓝=材质边界），顶点只被同级或更高级邻居拉、且只沿适配的边走。

本仓核实（先核再动手）：
- `src/terrain/shape.js` 文件头第 5–7 行就署本条 ID 与原文；`shapeTerrain(world,{mode,hardEdges,materials})` 的 `rank()` 返回 `pinned > cliff-top > cliff-foot > material > free` 五档，`curveStep` 只沿**同级边**取两邻居（`edgeOrd[ed[q]] !== k` 直接跳过），材质线单独走 `matStep` 且只沿材质边、只被材质或更硬点拉 —— 正是原文那句「equal or lower order, only along the appropriate edges」。
- 旧 note 的「原模块/材质三角网语义仍缺」「卡点·A 机制未做」核实为**过期账（第 43 次同型）**：三类的机制与 node 测试（`tests/edge-hierarchy-modes.mjs`，含蓝色材质边那一段）都在；真缺的是**页面上从没画过这三类边** —— `hierarchy.html` 只有一条约束边（黑）与一条青色对照线，页脚还写着「模块/材质三角网边界仍待补」。
- 因此判 **A**（页面入口 + 运行验收），不是缺机制。

## 代码落点与差距

- `src/terrain/shape.js`：机制本体，本轮**零改动**（`rank()` / `pinned` / cliff-top·cliff-foot / `materials` 全沿用）。
- `hierarchy.html`：
  - 新增「边类型着色」开关 `#clsOn`（默认开）、切面选择 `#clsSlice`（1–10）、读数 `#clsOut`（三类段数 + 逐切面表）、「材质边界近景」按钮 `#focusMat`；
  - 新增 `riverMaterialPairs()`（蓝色输入：同高度相邻格 `world.river` 归属不同 → 显式顶点对）、`edgeClass()`（钉住 > 崖顶/崖脚 > 材质 > 自由）、`classTable()`（逐切面去重计数）、`buildClasses()`（三色 `LineSegments`，`depthTest:false` + `renderOrder:101`）；
  - **分类用单独一份 `shapeTerrain(...,{materials})`**，不写进 `view.worldMesh.shapeOptions` → 主网格渲染与 r166 的三档读数逐字不变；
  - 探针 `window.hierarchyClasses`：`counts / slice / table / materials / hard / colors / segments / shape / visible / setVisible / setSlice`。
- 差距（如实写在页面上，不记成缺口）：原片分类的是**原始模块/材质三角网的边**，本仓只有格边，三类是格边上的近似；页脚已改成这个口径，不再声称「原作保形完成」。
