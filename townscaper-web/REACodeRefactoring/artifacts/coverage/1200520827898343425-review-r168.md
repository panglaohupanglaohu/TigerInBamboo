## 判定

**有机制**：色槽（slot）→ 体素色索引 → 调色板查表。

- 改的是一个**色槽**，不是某几栋建筑：四步里每一步都作用于「所有用该槽的墙」（散布在整座岛不同高度，bbox 分别为 x[22,228]y[72,224] / x[67,225]y[28,241] / x[46,235]y[94,238] / x[16,212]y[138,235]）；
- 改动是**单帧一次性**（10 fps 下 ≤0.1 s），没有渐变、没有逐栋补间；
- 未改的槽（屋顶橙、上层其它墙色）在同一步里**逐像素不变**；
- 相机缓慢环绕、无建造动画 → 片子讲的是「调色板后端」而不是「建造」。

## 代码落点与差距

落点（早已在，机制与本片同一件事）：
- `src/core/palette.js`：`PALETTES`（town/pastel/dusk 各 15 槽）、`withPaletteColors`（私有化 + 槽数/#rrggbb 校验）、`blendWallPalettes`（本地可选 HSL 过渡）；

核实旧 note「PNG/完整原接口与持久化仍待补」（先核再动手，不照抄）：
- **PNG 已在**：`src/core/palette-image.js`（像素↔行色、`encodePaletteImage`、`pixelsDigest`、`changedSlots`）+ `src/world/palette-png.js`（fetch no-store 轮询、摘要变了才解码、下行=色槽）+ `app.js:515` `?palettePng=`；`palettes/Palette.png` 是 16×2 RGB8（121 B）。**但本片自己的页面 `wall-palette.html` 从来没接过**，页脚还写着「PNG热更新及配色存档尚未实现」。

## 如实口径（不是缺口，是差异）

- 本仓调色板是 JS 常量 + 18 号槽下标，原版把 `Palette.png` 当资源文件；本轮的 PNG 通路是同一机制的本地替身（16×2 图 = 上行参考/下行墙色）。
- 原片注释提到的「1.5 s 渐变 / 最短色相」在本片**看不到**（四次都是单帧硬切），`blendWallPalettes` 属本仓可选扩展，不声称是原公式。
- 反弹光让单槽改色对邻近几何有 ≤0.33 的间接影响；原片是否有同样耦合无从判断。
- 整岛重建有 4692 px 像素地板（同色换对象也发生），因此「改色像素差」只能作同代重建内的相对量。
