## 六条逐项结论

### 1. 山体材质与低端设备预算

来源：[Oskar，2024-05-02](https://x.com/OskSta/status/1786014232594485497)。证据文件：`1786014232594485497-author.json`、同 ID 下 contact sheet 与 samples。

**A 作者事实。** 作者说山体纹理难处理，山体需要光照与法线，但担心其纹理混合技术在低端设备上难以承担这部分成本。“normals”未具体说明法线贴图格式、每像素混合层数或着色管线；也不是发布了“山体应关闭光照”的一般结论。

**B 实看。** 0–1.26秒显示草地与曲流后面的浅色山脊；1.92–4.47秒视角变化后可见连续山脊和孤立岩峰，浅米灰、白色块纹理沿坡面拉成长短不同的笔触，坡脚接绿草色带；5.10–6.99秒显示另一侧山脊。画面保留几何轮廓线和大面积明暗色块。无法仅凭这组旋转采样判定光源是否移动、白色是否有雪的语义，或法线如何参与纹理混合。

**C 项目建议。** 固定已认可 r17 山形，先以低频岩色域、坡脚草岩边界和有限亮面增加材质层次；不把白块自动解释成雪，也不把阴影烘死为某个太阳方向。对低端档先比较“几何法线统一照明 + 颜色/高度权重混合”与“多层法线贴图混合”的 GPU 成本和昼夜一致性。统一照明只算一次是候选结构，是否比现状快须实测，不能由原帖推导预算数字。

### 2. 河流图：连续河岸，不等于水文生成证据

来源：[Oskar，2024-04-27](https://x.com/OskSta/status/1784276757266231419)。这是**静图**，作者表示继续测试纹理，希望把此项目的河流做好。

**A 作者事实。** 原文没有给出河流求解、UV、流速、侵蚀或分叉处理算法。

**B 实看。** 一条浅蓝弯曲水带从左下较宽水域延向上部并多次回弯；可见浅色岸边、零星灰褐石块、陆侧深绿色边缘色块。内弯与外弯的色带宽度有变化，岸边没有表现为沿屏幕方向的一条直纹。不能由单图判断是否真实顺流动画、河流是否全局连通、窄颈是否有精确碰撞，或所有弯段属于同一水文流域。

**C 项目建议。** 把河网拓扑、可通行河口与岸线外观分开。水边条带使用几何岸线驱动的纵向/横向坐标，草地仍可采用面域投影。河宽不能只靠一张纹理假装扩大；近岸模型、可登陆口及桥下净空仍由最终几何决定。本帖不能作为已经实现分叉河网的证据；后文给出的分叉处理是本项目设计。

### 3. 球面纹理测试：有接合表现，无具体算法披露

**A 作者事实。** 原文只宣布一次纹理测试，没有解释技术。

**B 实看。** 0–3.96秒看到不同朝向的绿色陆块/蓝色水域球体；4.62–7.20秒放大到岸边，可见沿弯曲边界排列的浅色细线、水侧波纹状笔触、陆侧较深绿带与较浅草地色块。不能从球体旋转得出它在重新生成，也不能从线的形状断言这是流体模拟或某种投影公式。

**C 项目建议。** 验收应同时包含球体远景和岸边近景，防止小视口把拼接错位隐藏掉。不要用全球 XZ 投影解决整个球面：它在背面/高倾斜区域会重叠或退化。球面材质需要局部图表及显式接缝策略，且要检查转到极区和背面的密度。

### 4. 无缝 patch 混合与手工岸线 UV

### 5. 100% 纹理的边缘小灌木：必须带父帖语境

### 6. 大笔触不污染重要边界

来源：[Oskar，2023-08-30](https://x.com/OskSta/status/1696864977171189980)。

**A 作者事实。** 作者说一次较大重构后可以使用更大的斑块笔触，且不再越过重要边界造成混乱；同时指出展示的样子并非最终想要的风格。没有披露其边界约束算法。

**B 实看。** 0–1.44秒整岛草地/土色为较大色斑，悬崖是浅色直立面；2.88–4.32秒近景中顶面绿色色斑在崖缘收束，房屋白墙和黄屋顶仍有独立色块。5.76–15.84秒不同岛形/朝向的样本继续显示地表斑块与崖面的区分。不能仅靠采样证明每一条重要边界都无渗色，且该调试美术不是目标图的指定色板。

**C 项目建议。** 先定义“哪些边界必须保持”，再扩大笔触。草/岩、水/岸、建筑/地面等使用语义域隔离；同材质内部可以大尺度混合，硬边界两侧不共享无约束的颜色扩散。图集 mip 与边缘 padding 也必须按域生成，否则原分辨率不渗色、远处仍会串色。

## 自动岸线与河岸 UV：项目方案，非作者算法

### 输入与输出合同

输入为**最终已批准的三角网格**、材质域、拓扑邻接、河网/岸线语义及版本。岸线取真实水陆接口或有定义的水位交线，不从截图颜色提取，也不只按 Y 阈值猜河岸；球面采用场景实际海面和当地向上方向。记录 `surfaceRevision、topologyVersion、seed、chartVersion、textureMetricScale`。同一地形版本和配置应产生稳定 chart ID 与切口，避免每次编辑材质随机跳变。

输出包括每顶点/角点的 `chartId、uvBank、uvSurface、signedBankDistance、materialDomain、blendWeights`，每条共享边的兼容约束、纹理周期、接缝位置，以及反转/重叠/拉伸报告。需要 UV 接缝时复制顶点的属性槽，不移开三维位置，不打断碰撞或网格共享边的几何身份。此工具不改山体、河网流向或导航结构。

### 1. 岸线图提取与规则化

从半边邻接提取水陆分界，按稳定端点 ID 建立有向边图，记录哪侧是陆地。端点、度数不为2的交汇点、瀑布/桥头等人工锁点、材质切换点成为分段节点。度为2的连续边串组成普通岸线 chart；独立湖岸/岛岸为闭环。河流中心线只辅助流向与河段身份，纹理岸带直接跟随左右岸边界，避免大弯时内外岸被强行等长配对。

用几何误差和曲率控制重采样，锁点位置不变。很窄的回头弯存在两个空间上接近却拓扑不同的岸段，最近距离查询须限制在所属河段/岸线邻域；不能让相邻河段夺取 UV。岸带相交或宽度超过局部有效半径时，应缩窄或切 chart，不能继续无条件向外偏移。

### 2. 纵向弧长和横向距离

沿岸累计最终曲面的弧长 `s`。岸外条带每点计算从所属岸线出发的有符号曲面距离 `d`，陆侧为正；近岸平坦段可用局部切平面近似，坡折/球面或较宽带用三角网格上的距离传播并保留来源岸段。简单候选坐标为：

```text
u = (s + chartPhase) / repeatLengthMetres
v = d / repeatWidthMetres + shorelineRow
```

这里纵横尺度都是米，纹理重复密度不会随河宽改变。另算 `q = d / localBandWidth` 仅用于岸带混合遮罩；不要把 q 直接当全部细节纹理的 v，否则宽岸与窄岸的沙粒/笔触大小不同。沙岸、水波、陆侧灌木可以各有稳定的尺度与偏移，仍共享同一岸线语义。

最近岸点给出的 s/d 只作为初始化：强凹弯、距离场中轴与多岸等距处会不连续。检测这些区域，将 chart 切成可参数化的窄条，或在保持岸线/端口约束下求局部平滑参数场。可采用约束调和参数化再按拉伸能量优化；它只是候选数值方法，不保证任意凹边界无翻转，失败时继续切 chart，不能把失败写成成功。

### 3. 分叉、合流与河口

每条入/出河段有自己的纵向坐标，交汇处使用专门 junction chart。保持各岸端口的位置、方向、单位纹理密度及横向零位；junction 内以无强方向的底色/细节和受限权重连接相邻条带，再逐渐恢复沿岸方向。若求解到一个可行的局部二维展开，可将边界 UV 作为约束优化，仍需检查面积/翻转。

不能简单把所有分支都从 u=0 重启后相加；这会造成交点重影和相位断裂。对于周期纹理，可为图节点求整数周期相位，使普通接头连续；当闭合图的长度约束不相容，允许指定接缝或专用交汇混合，报告它。河网流速/动画相位与岸纹理 u 分开存储，岸纹理连续不代表流体守恒或导航合法。

### 4. 闭环与切口

闭环岸线选择稳定、低可见度的切口，长度 L 对周期长度有两种处理：一是选择整数重复次数 N，使实际周期 L/N 在允许的密度误差内；二是保持指定世界密度，在切口设有限宽混合。N 不可取0，也不能为闭合而无限缩放短环。

切口两侧可以出现相差整数周期的 UV，但采样结果、混合权重和法线切线必须相容。检查的不只是 UV 数值相等，还包括纹理 wrap 后的相位、梯度和 mip 行为。短环容不下一个正常笔触时使用单独的小环图样或降级为无方向材质，并将降级记录在报告中。

### 5. 球面处理

在球面上，基准方向取局部径向/真实地表法线，岸线切向投影到当地切平面；沿边平行输运切向框架，避免每点与固定世界轴叉乘导致极区突然翻转。最终有起伏地形的距离仍沿地表计量，不能把全局经纬度或球面大圆长当成所有山坡的精确距离。

闭环平行输运可累积旋转，球面也不能拥有处处无奇点的单一全局切向坐标。工具必须有显式 chart 切口/极区策略，允许在低显著处吸收或分布闭环旋转，并报告方向扭转量。近对跖、极区、长岸线、跨球面 patch 的样例必须单独验收。低起伏面域可使用立方体/局部投影 chart；多向投影是可选方案，有额外采样成本，不自动作为低端默认。

### 6. 无缝 patch 混合与大笔触边界

草地/水体表面坐标和岸线 UV 同时存在，由带有语义许可的权重混合。令 `a_i` 是合法域 mask、`h_i` 是同一标定范围的纹理高度、`b_i` 是域优先偏置，可以试验 `w_i = normalize(a_i * max(0, h_i + b_i - threshold))`。分母接近0时回退到所属主域，不输出NaN或黑洞。高度混合权重的候选公式是项目推断；原帖未给出公式。

硬边界的另一侧先用语义 mask 严格禁止采样贡献；软边界内再按曲面距离渐变。大笔触应在允许跨越的邻接图内生成/扩散，不能穿过水岸、建筑接缝或指定硬边。全局噪声仍可用于低频变化，但它不能绕过域 mask。两邻接 patch 共享边上的权重和采样相位要同时匹配。

图集打包按 chart/语义域生成各 mip 的扩边，gutter 宽度随最大采样 footprint 预算制定；相邻 atlas 区块即使颜色相近也不能当作合法 padding。需要切线空间法线贴图时，先将不同 chart 的法线转换到共同空间再混合；不得直接混合方向不同的切线法线 RGB。本轮不假设必须上法线贴图，低端可先保留网格法线照明。

### 7. 自动细分与拉伸验收

对每个三角形在其自身切平面建立世界二维边矩阵，与 UV 边矩阵计算 Jacobian。先把 UV 缩放到统一目标世界密度，再记录奇异值 `sigmaMax/sigmaMin`（各向异性）、面积比、定向行列式和最小面积。世界三角形退化先报告，不能归咎 UV。各 chart 定向基准必须一致，不能因为背面法线方向不同而误判翻转。

拒绝未授权的 UV 反转/零面积、同一 chart 内不应存在的面重叠、共享边相位不相容；拉伸阈值和像素密度容差由小样实际设定。本研究没有测出既有项目阈值，不能编造通过率。超过阈值时先切短 chart、收窄高曲率条带或增加**属性采样/显示网格局部细分**；若需要新增几何顶点，只在原三角形面内插值，保护 r17 轮廓与导航网格，禁止借 UV 修正偷偷改山形。

检查 chart 输出有限数值后，再用高对比棋盘/岸线箭头/米刻度实机观察；均匀单色会掩盖畸变。图集接缝、图表重叠和纹理实际 wrap 都必须检查，不能仅通过“所有uv落在0..1”测试。

## 最小实验与交付门槛

本节是完整能力的验证计划；下文“已实现的隔离小样”只覆盖其中一部分 CPU 检查，**完整计划尚未执行，没有 runtime 验收分数**。后续固定地形、相机、光照与纹理尺寸，并保留当前手工/投影版对照。

| 样例 | 故障必须被捕获 | 可验证结果 |
|---|---|---|
| 直岸、S弯、极窄发夹弯 | UV反向、最近岸跳支、内弯叠片 | 沿岸箭头不倒转；密度、最大拉伸、问题三角ID可查 |
| Y分叉、三岔、宽河口 | 接头相位冲突、重复叠色、方向突变 | 每端口有坐标与权重合同；无解接缝显式列出 |
| 湖岸、孤岛、很短闭环 | 闭环断裂、周期数0、过量缩放 | wrap相位一致或有限混合；密度偏差报告 |
| 球面极区、跨chart、长闭环 | 全局XZ退化、切向翻转、输运扭转 | 框架有限、切口稳定、背面密度与正面同量级 |
| 草岩硬边、河岸软边、大笔触 | 笔触越界、mip串色、混合分母0 | 近景和远景都不侵入受保护域；全部权重有限 |
| 局部地形编辑/撤回 | stale UV、全图相位随机跳变 | 版本失配不发布；相同输入确定性重建；撤回恢复 |

CPU输出：有限属性、退化/翻转/重叠数量、每chart密度与Jacobian统计、接缝数量和误差、闭环相位残差、局部重算范围。GPU输出：同分辨率远近景/球面多方向截图、实际 draw call、纹理采样预算、CPU重建时间和GPU帧时；写清设备、浏览器、视口、纹理分辨率、热身与采样时长。不能以没有 shader 错误代替视觉或性能达标。

## 既有代码差距与已实现的隔离小样

实际读取 `src/procgen/planet/terrainPatchBlendingV10.js:33` 的 `shorelineManualUv(direction,height)`：u 是 `atan2(z,x)/(2π)+0.5` 经度，v 是经高度缩放再 clamp 的值。函数注释称沿球面岸线距离，但实现没有输入真实岸线、累计弧长或横向岸距，因此不能计为自动岸线展开，也不是本报告方案已接入。此轮没有修改该文件。

本批新增 [AUTO_UV_PROTOTYPE.mjs](AUTO_UV_PROTOTYPE.mjs) 与 [test_auto_uv.mjs](test_auto_uv.mjs)，导出 `buildAutomaticShoreUV`。输入有序不分叉岸线、带状三维顶点和三角索引；输出复制后的顶点、UV、三角形、源顶点映射和报告。实现范围：

- 平面岸线按三维折线段累计弧长，横向值为当地法向叉乘岸线切向的有符号距离；支持弯岸，没有使用经度代替岸线长度。
- 精确球面输入按相邻点间小于π的大圆弧计算沿岸距离，球面带宽按球面角距计量，使用当地径向构建左右方向；不支持起伏球面地表的精确测地线。
- 闭环跨切口三角形复制低u端顶点并增加一圈弧长，保持三维位置相同，避免整圈反向插值。`closureTexturePhase` 保留周期不能整除周长时的剩余相位；顶点分割解决插值，不自动保证图案相位无缝。
- 分叉输入、重复内部岸点、最近岸等距歧义、离开声明平面/球面、零长或近对跖段、退化三角形、UV折叠均显式失败。凸角/凹角中轴附近可能有等距歧义，这个最小版本要求拆短patch或收窄岸带，不假装已完成圆角/junction解算。
- 没有实现完整雅可比优化、图集/mip生成、任意自交/UV全局重叠检查、局部增量重建、着色器或运行时集成。复杂岸线不能因这个小样通过就直接发布。

2026-10-06实际运行4项 Node 测试，4通过、0失败：①90度弯岸的累计弧长与左右符号；②12段闭环岸带的接缝复制、三维位置保持与插值跨度；③精确球面1/4大圆的长度、横向角距与符号；④分叉、重复零长、无效尺度/非有限值、非平面/离球面、退化三角形与等距歧义拒绝。闭环验证顶点取各折线段中部，未把顶角中轴歧义掩盖成已解决。

执行命令：`node --test artifacts/research/oskar-series-20261006/test_auto_uv.mjs`。本机使用桌面依赖包中的 Node 执行，未新增第三方依赖。源码只有向量数学，输入不变更；没有接入主游戏、替换山体或渲染材质。

## 可并入顾问 Skill 的决策规则

1. 见到岸线/河岸定向纹理时，先查作者明确说的是投影还是手工 UV；2024-04-19为投影草/水 + 手工岸线，自动化算法属于本项目扩展。
2. 纹理边缘灌木与实体树冠分开决定；2023-09-28的100%纹理结论只指父帖那些小灌木。
3. 大笔触先有语义边界和 mip 隔离，再谈噪声尺度；作者展示结果不等于公开其具体边界算法。
4. 山体照明、颜色混合和法线贴图分别列预算；低端担忧不能泛化成一律无光照。
5. 球面 UV 必须报告 chart/极区/闭环与密度策略；没有一种全局平面坐标可以替代这些处理。
6. 所有无缝、低端流畅、自动展开成功的结论都要有本项目测试和实际画面；五段60时刻抽样与一张静图不能升级成完整视频或完整引擎实现证据。
