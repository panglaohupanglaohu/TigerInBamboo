# 圣城蓝夜 · 第一轮候选

实际交付：独立 Godot 检视工程 `project/project.godot`（运行后空格切换）、同镜头 `original-day.png` / `blue-night.png`、Blender 环境副本 `terrain-blue-night-v1.blend`。查看 `index.html` 可拖动比较。

## 这轮做了什么

- 原 `buildOdysseyCitadel` + `HIGHLAND_TOWNSCAPER_TOWN_SPEC`，固定构建种子20260808、WFC种子37。保持978格占用及原中央地标组件顶点/变换；没有重排街巷。
- WFC 在独立浏览器模块副本调节权重：露台×2、hip×1.4、gable×0.7。露台角色122→170，整体313格选型发生变化；不是新增313栋建筑，也不是只在一栋上修改。求解结果哈希由5a8616a8变为881da723；2436条有向共享边兼容检查、确定性及错误模块反例通过。完整不规则角模块与几何接缝仍待做。
- Blender后台实际导入原地形独立GLB，仅改变原山面和对应高光副本。主山面92个顶点改变，272个低处/近城顶点保护；地基和水岸低于5或距中心33以内不动。没有在Blender重建建筑。植被这轮保留，抬山后植物贴地需要下一轮检查。
- Godot实际渲染，固定相机(38,38,70)看向(0,20,0)、FOV48。导出图1280×960；记录中的窗口物理大小与内容渲染尺寸分开。夜景使用一盏带阴影方向光、两盏无阴影暖点光；窗材质复用两种暖色。

## 重要边界

这是原工厂的独立局部坐标检视，不是原Web完整世界截图；原版也经过同一套Godot基础材质适配。源程序云/体积光/高光无法直接由GLB复原，两边统一隐藏相应辅助层，不能把导出图当作原Web像素基线。原水系位置保留，但动态倒影尚未实现或验收。未实现本工程角色移动和通行碰撞；未部署到活动游戏。

当前画面与目标仍有明显差距：山体需要更细的峭壁层次和远近分层，建筑纵深、暖光分布仍需继续调整。Godot单帧绘制调用约数千，仍偏高；渲染计数不是性能通过证据。禁止把本轮标为完整圣城复刻或全部四轮完成。

## 下一轮具体动作

1. 在当前Blender候选上细化远处峭壁折面，校核抬山后植物贴地，保护近城地基/入口/水岸。
2. 使用已保存的WFC按格角色清单检查露台边界、转角、共脊屋顶；用出现的具体反例修规则，不以色彩遮住穿插。若需要修改生产源接口，独立验证后再挂回主工程。
3. 在同镜头继续调整Godot冷暖比例，给原水面做明确可验证的小片区反射；记录适用视角和开销。
4. 合并/实例化静态检视网格，补入口真实通行，再决定是否部署。

## 复现

`tools/export.mjs` 读取8765原项目模块，在独立浏览器中选择WFC角色，导出到本目录；不改生产模块。`tools/check_wfc.mjs` 独立重求解与邻接检查。`tools/terrain.py` 仅操作本目录地形GLB。Godot运行本工程并传 `-- --capture` 保存对照图。首轮失败/过曝检视图保存在 initial-*，不是最终图。
