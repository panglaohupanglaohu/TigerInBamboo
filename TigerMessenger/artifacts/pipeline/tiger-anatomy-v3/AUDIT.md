## 动画必须保留的节点

精确父级、原本地矩阵、GLB 节点索引见 `animation-contract.json`。原动态结构是 Group 链，不是骨骼蒙皮：

- `n0` 虎根：scale .4，+Y 上、+Z 头、-Z 尾，脚底 local Y=0。
- `n1` 身体：原 Y=1.6392；`n8` 头挂在身体下，local (0,.72,2.42)。
- `n52/n59/n66/n73` 为四腿，全部是虎根的直接子级，不能合并进 body。前两腿 Z=1.55、后两腿 Z=-1.55，髋 Y=1.5592。
- `n27` 尾根挂 body；`n28/n31/n34/n37/n40/n43/n46/n49` 是连续八关节链。原轴沿各自 +Y。
- root 的 `three_userData` 仅存 tailRoot/tailSegs 的 nodeRef；head/body/legs 为 JS 闭包变量，并没有可直接解析的 parts 字典。新增完整 role contract 是必要的，不要假定它们已经有士兵式 parts 元数据。

原 GLB 有 0 个 animation clip、0 个 skin。源 JS 中步态按对角腿 ±.28 rad 绕 X 摆动；饮水直接写 head RX=.95u、Y=.72-.55u、Z=2.42-.5u，并写 body RX=.1u；尾根及八链每帧直接写 X/Z。**新的厚颈、后腿、下垂尾 rest 即使静态正确，也会被原动画绝对值覆盖。** 保留节点身份与层级，允许建立新的候选 rest 数据；后续 adapter 要以候选 rest 叠加动画或显式重定向，而非把原绝对式机械照搬。脚底贴地、步态穿插、低头饮水需要候选专门验证。

## 原世界放置与回接边界

`src/world/moebiusSwamp.js:2115` 创建带 roam 的虎，加入 swampZone 并保存 `userData.tiger`；圈缘半径37.4、速度2.6，石阶到饮水区；`2797` 每帧调用虎 update。`createMoebiusSwampPlacement` 将 inner Y=-40，默认 wrapper scale=.5；虎自身 scale=.4 继续保留。世界运行时处理球面下沉、进坑跳下相见、踏水跟随（本地Y=25.15）与灯谜。

Godot 既有独立 `assets/originals/moebiusTiger.glb`，也有嵌入 `assets/world-source/original-world-v1.glb` 的原虎：路径 `moebius-swamp-placement / moebius-swamp-zone / moebius-cyber-ink-tiger`。后者当前节点索引5814/5815/6241，这条链没有 three_node_id；独立资产 n0 等 ID 不能直接套用到整个世界。只替换独立资产预览不会自动改变原世界里的虎。候选验收后应按 placement 路径与持久身份挂接，并保持 wrapper/球面放置不变。

这份审计没有宣布 JS 行为已移植 Godot，也没有把静态 GLB 导入当成动画完成。
