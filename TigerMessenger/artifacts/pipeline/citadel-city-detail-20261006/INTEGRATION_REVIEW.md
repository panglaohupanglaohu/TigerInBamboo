# 城市细节候选接入审阅

2026-10-06，独立只读。读取 `targetCityDetailCandidate.js`、`targetNewCityMain.js`、`targetOldCityWaterfall.js`。图像依据为已实际查看的批准 `target-v3-landmarks.png` 与 r21 的 colour-flow-clouds、facing-layout 两张实机图。尚未看到本轮细节工厂接入后的实机画面，**不评分，不把CPU结构当美术效果**。本次没有改运行时。

## 接入顺序与比较条件

山形保持当前认可版本；两城建筑、瀑布作为可撤回候选。主场景中旧版建筑和比例代理的可见性应明确切换，不要与新工厂叠绘。保留原雕塑木马；候选关闭/销毁后恢复切换前可见性。新工厂目前是手工确定性几何，不是可编辑完整Townscaper/WFC建筑系统。

建议页面提供同机位的三状态：原布局、仅新城细节、细节加瀑布；另可关闭云来查入口与承托。保持r21同灯光/海色/山色，避免换光把模型变化掩盖。先留全景，再拍新城正前和侧后、旧城瀑布侧前与水脚近景。

## 朝向及尺度：需要直接检验的锚点

新城工厂局部+Z是入口，candidate固定castle-local位置[74,12,33]、yaw −55°。其入口朝向为约[-0.819,0,0.574]，确实向中央海湾偏左，符合r21对向代理方向。按源码转换：

- 拱门前入口约[68.51,13.20,36.84]，应从海湾看见洞口而非侧墙。
- 四级短梯底约[63.38,12,40.43]；它只爬1.2m到厅地面，**不等于目标中的长中轴上城阶梯**。
- 穹顶金尖最高约castle y36.50（平台12+本体24.5），需实图与后山轮廓比较；目标是蓝穹顶作为新城主角，后山仅略高，不修改山去迁就新工厂。
- 外翼屋顶总宽约29.05m，比此前32m代理台更窄。用投影包围框记录新城屏幕宽/高、穹顶对山脊的可见高度，不只看本地米数。不能把目标参考画面的30%等粗估直接作为不同镜头下的硬尺。

旧城主建筑在本候选中尚未重建；瀑布朝向是岸线survey选择25°—75°之一，不是自动绑定旧城+45°。应显示最终yaw和落点，并确认它位于旧城面湾前缘、供水侧在城内。水向海落正确不意味着它与旧城立面关系正确。

## 承托和通道：当前审计缺口

1. `newCity.supportSamples`只采floorY=0脚印角点，且最大gap不能揭示严重负gap（埋地）。接入页至少列misses、最大正gap、最小负gap，并采中心/边中点；现场观察楼翼与阶梯是否穿草台或悬空。候选不能因有report就默认通过。
2. sampler默认只找 `citadel-oskar-grid-mountain-surface`。接入时显式传当前真正可见的冻结terrainMeshes，核对geometry UUID/positionVersion；不要采到隐藏旧山。当前sampler本身没有验证所有祖先visible。
3. 工厂拱门是实际开口，报告宽4.1m、矩形净高3.3m。但穿堂底面、后出口和前接路仍需实际射线/胶囊检查；代码没有将此建筑接入玩家walkable/collider。不能把through:true当已可行走。
4. 新城短梯到广场的跨台路线未建；目标的重要中轴长梯必须在后续建筑/路径阶段明确端点、高差和承托。旧城瀑布供水渠也未连接。不要靠云或地面同色遮掉这两个断口。

## 瀑布：实际落点较细，但仍有必须看清的风险

- survey先测5横向列的干岸脚、海面及水下地形，拒绝落在陆上的水脚；下落水幕底行又逐顶点投到实际海mesh。这比随意填一个平面水位可靠，但仍是抽样，不是全体积无碰撞证明。
- 新支墩仅每段4脚点；采样不足会跳过该段。必须显示9段中实际建成数和缺段，不能留下供水墙悬空后仍只报built:true。
- **扩散水圈目前没有按曲海投影。** candidate.update只重新定位 `target-waterfall-impact-white-foam`，`target-waterfall-expanding-impact-ripples`仍在工厂的平面y=-dropHeight。近景/低视角应重点检查圆环是否穿水或漂浮。源码waterfall水幕前后两层端点也各自采样，不要只拿中心海高代表整个瀑布。
- 这里采的是CPU海面三角，未同步海shader波形和depth offset。此前海岸泡沫已有depthWrite/polygonOffset遮挡经验，应读取本场景实际海材质后检查，不能先调高白度掩盖。截图须看得见落水接触，且不穿岩。
- update每帧更新两层水幕全部position并重算法线；foam随动画位置重复查询海面，六位小数cache可能持续增加键。先查固定foam世界XZ是否真的随旋转/缩放不变；若变化则做限定缓存/预采样。报告真实update耗时和内存，不能仅凭“6个主pass draw”称轻量。

## 遮挡与目标差距

r21色块已比r18清楚，但旧实景建筑与山体关系仍不是目标城市，比例代理只能证明朝向大体对。新工厂具备暖石灰门厅、蓝翼楼、红瓦顶和蓝穹顶，方向上适合目标；实际是否被岩壁、树冠或云遮住还需GPU图。

- 新城正门、蓝穹顶、长梯轴线三者应同屏可辨；r21入口旁薄云容易叠在台面上，接入图要先关云确认结构，再开云看是否遮门。
- 目标旧城是暖色多样、红瓦顶的密集坡城及细高塔。当前只加新城与瀑布仍没有补齐旧城街廓/共墙/屋顶邻接；不能称“两城已经按目标完成”。
- 新城已有单独窗框、压顶和拱石，需看全景是否读成几块清楚色体，近景不要退回密砖纹写实。目标的模块关联比增加小装饰更重要。
- 瀑布应成为旧城立面下方的窄竖向亮点，宽9m是否合适依接入图判断，不能挡住整面崖或变成无来源的独立水坝。三孔出水是工厂设计，不是目标精确复刻证明。

## 本轮应保存的最小证据

固定镜头全景/新城正面/新城侧后/瀑布水脚；前后自然更新的时间与水幕、泡沫数据（用户不要求录视频，不必录）。记录源地表版本、最终朝向和屏幕框、支撑miss/gap上下界、缺支墩、海端残差、GL/page错误、开启和销毁后的资源/可见性变化。关闭候选应恢复原版；反复挂载已有handle的策略也要注明目前不支持不同options自动重建，避免以旧handle误称新参数已生效。

有本轮实机后再按目标独立审图；承托和编译通过只是必要条件，不能兑换美术分或95%相似度。
