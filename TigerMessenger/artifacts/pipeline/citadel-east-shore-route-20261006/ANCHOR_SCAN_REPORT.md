# 接头可行域扫描与第二批实构候选

仍未安装；未修改地形、生产release或全球线。先扫描真实生产三线，而不是继续试已知超坡接头。扫描红u=.56..6507，步长.00025；蓝/中心采用与现接头一致的u差并分别读取真实曲线。可行性仅为三线原切向径向坡度≤4%，不含净空。

## 扫描结果

- 近端可行带约红u .6485–.6505，最多仅增加5.68m原红线替换长度。
- .604–.6485之间本批没有同时满足三线4%的样本。
- 更早可行带本批覆盖 .56–.604，最靠近原接头的 .604 已增加120.81m原红线影响；.602增加125.98m。
- .604实际castle点约[150.805,-166.138,46.279]，已在目标地形chart的低侧/域外。不能沿用正面最高高度场，直接断言此处船/车或山体净空通过。

原34m控制柄版最紧弯实际位于castle约[87.86,-34.05,94.11]（东侧绕广场转南弧处），并非只在全球接头。缩短控制柄没有解决：它把紧曲率移到其它曲段。由此不能靠接头通过4%便宣称路线可建。

这些候选在东段的中心到近干岩距离约6m，说明贴岸意图有实际位移，但代价是小半径及保护台侵入。未把这个数字与前报告“廊背到岩脚”混为同一口径，也没有把25m门槛放宽。

## 为什么没有新增切崖field

当前不足不是单纯无功能坡脚：保护台包络筛查仍有命中，且车道自身最小半径先失败。对这种路线生成切面会把错误几何固化，甚至侵入广场/城台。本轮没有授权自己削这些保护面，没有造轨道槽。

低侧source段的chart向下首交高度会与球面另一层混淆，因此本批wet/cuts只保留为筛查诊断，不能升级为完整三维土体/海面碰撞结论。它们也不是通过理由；曲率失败已经独立否决。前批载货表面OBB零交叉仍不能推翻内部侵土结果。

所有输入、实际原切线/坐标、候选世界Bezier序列与逐米点在anchor-scan.json / scanned-candidates.json。候选依然default-off、accepted=false、installed=false。

可复现：`node tools/pipeline/scan_target_east_shore_anchors.mjs`；`EAST_SCAN_ONLY=1 node tools/pipeline/audit_target_east_shore_route.mjs`。本批没有找到能联合通过的方案，亦不证明任意重新布局都无解。后续若继续，应重新分配东侧整段外绕弧的切线/转弯半径，而不是继续平移原弧或剪受保护台地；额外原线影响至少约121m这一扫描证据必须保留。
