# A 方案实际候选：未通过，禁止安装

已实现独立默认关闭 `createEastLoadedCliffCandidate`，生产、正式 release、全球线均未修改。它接收真实双线 world curve、castleMatrix、公共 Mesh 三角和真实海面 callback，从完整载货棱柱投影生成海侧开放切域，切到海面下3m，不是轨心沟槽。仅允许 x60..108/z54..105 的新城外坡区域；不改旧城。原 source .59 及约157m额外全球线影响保持显式。

## 两次实际结果及失败根因

第一次仅保护真实公共三角及35cm边缘，虽然蓝线土体清空、红线只剩9个表面姿态/4个内部点，但**原1.7m网格邻点下降拉斜承托三角**，实际铺装脚点最大失去30.44m支撑。因此这个版本被拒绝，没有把少量碰撞当进步完成。

最终候选给实际三角边追加2.8m网格承托保护（约2.39m格对角线+35cm承托余量，不是新椭圆）。真实公共表面2949个贴地脚点复测：全部承托高度保持，最大落差0。原有网格位置只在副本中改，公共 Mesh 未变。

但保护后的有限联合检查仍失败：

|检查|红线|蓝线|
|---|---:|---:|
|最小采样曲率半径|32.203m|28.197m|
|最大径向坡度|3.282%|3.447%|
|载货 OBB 与真实山面接触姿态|20|10|
|实际闭合山体内部采样点|96|10|

剩余红线内部点 x78.64..88.15/z72.66..91.12，蓝线 x85.75..88.29/z79.57..86.12。它们沿广场实际承托邻接网格，不在此前东侧裸坡外段。**不能为了清这30个姿态取消承托保护，也不能称其证明整个几何无解**：现有粗网格顶点下拉方法需要2.8m保护圈，限制比实际物体宽。下一步若仍采用该路线，应在实际铺装外边做受限重网格，保留原铺装承托边作为硬约束，再重建直崖侧面；不是继续加切深或削保护台。当前模块是这种重网格前的明确失败候选。

## 断面已实际查看

`loaded-cliff-sections.png` 为真实 CPU mesh 前后采样，不是概念图或 GPU：z64/70裸坡已显著退回；z80/90受保护顶台保持，但格宽控制的斜侧面仍延伸进列车棱柱。z98外围只降海侧坡脚。图中的地面落差为 castle-local Y，不能当作径向挖深或视觉评分。

该字段不输出隧道土盖，也不把原顶部铺装变成浮板；未通过时不允许安装。默认off本身为高度恒等函数，放弃副本即可完整回退。

## 水面证据纠正

实际 ocean world scale=[1,1,1]，vertex shader最大局部径向波幅 .045+.022=.067m。当前最终1.5m姿态采样中，**扩张包络底面**（up=-.6，不是最低实车顶点）最小静态余量红.09059m、蓝.10816m，比.067m上界分别多.02359/.04116m。当前两线静态湿点0，但原额外工程储备.3m仍未过（红74/蓝63个足点）。不能把.3m称为真实波幅，也不能据旧5cm数值宣称永久无解。

这仍不是动态完整车体证明：需实际最低车辆几何、放置frame、波浪相位与更密连续路径核对；本轮只给保守扩张棱柱有限采样，并保留 `actualVehicleGeometryWaveCollisionVerified=false`。
