# 月牙绕月湖 · 生产模块 r1

用户要求月围绕湖心转。仅修改 `src/world/moonOrb.js`；布局、四松资产及原古松本轮不改。Root负责在正式 garden 完成地面承托后调用 `lake.moonOrb.setOrbitObstacles([lake.ancientPine,...garden.trees])`。

月牙实际绕湖局部XZ=(0,0)移动，周期180秒，半径7.46768036米，初始XZ保持[-6.225,4.125]，实体半径3.4米、厚度、色彩和月海不变。位置使用首个update的绝对时间差计算，帧率不改变轨道速度。面向观察者的偏航、光晕背离方向和水面反光均使用当前运动位置。

## 树冠净空决策

CPU量测原古松+四株新增松，固定5.6米高/7.47米轨道会穿树冠。20米外轨仍有枝冠，而且严重偏离现景。Root明确批准保留轨道和尺寸，在经过高冠时平缓抬升，随后回到5.6米基准。

`setOrbitObstacles`对已实际承托的树几何转回湖局部坐标，去重筛选顶点，预计算360个角采样；月体包围球+0.22米边距，加入呼吸幅度余量。循环膨胀与同窗口平均建立连续高度包络，逐帧只计算三角函数和表插值，无逐帧raycast/几何扫描。周期接缝连续。

CPU当前5树解析落根结果：11056个有效去重顶点；包络最低5.6米、最高15.7867米，另有±0.22米呼吸。正式地面承托后数值以运行时report为准。group.userData.moonOrbit及返回orbitReport提供参数与量测。

这是有限顶点和角采样的近似净空，不是连续三角面碰撞证明。原小树林仍可自然遮月，本模块不挪树、不关闭深度遮挡。

## 实际验证

`orbit-probe.mjs`实际调用生产moon工厂、原古松与四伴松：

- 周期XZ、不同步长同时间位置一致；
- 球面父节点平移/旋转/缩放绑定一致；
- 光晕与反光使用当前月位置；
- 每0.25秒最大位移0.1803米，无瞬移；
- 全周期每0.5秒扫描实际树顶点，月体包围球最小顶点间隙0.3094米；不等于三角内部连续碰撞验收。

语法和diff检查通过。JEV真实调用见 `jev-r1.json`；输入仅紧凑文字。GPU、正式场景树体绑定与玩家观察需要Root继续验收，未冒充已看。
