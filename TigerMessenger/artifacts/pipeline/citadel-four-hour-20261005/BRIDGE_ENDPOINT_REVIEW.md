# r26 桥末端独立碰撞复核

依据：`r26-wide-arches-target-front-plants-terrain.png` 与同名 JSON。PNG 已查看，以下结论由 JSON 的实际面和高度计算得出。本次只增加本报告与 `check_bridge_endpoint.mjs`，未修改 candidate、地形、桥或阶梯运行代码。

## 结论与可实施端点

当前 4 拱桥末跨确实穿入蓝房实体墙。应取消直接通向主门的末端。推荐保留前 3 个控制点，将 **4.4 m 宽主桥结束于 castle-local `[51,12,39]`**，再由 **2.4 m 宽、5.5461 m 长短连接台** 侧接 surveyed stair 的第 14 号 tread（零起始编号）中心：

```js
bridgePath = [
  [-32.23116164579317, 17.3, 3.7674098192195498],
  [-10, 16, 24],
  [23, 14.8, 33],
  [51, 12, 39],
];
bridgeWidth = 4.4;
sideConnector = [
  [51, 12, 39],
  [54.46119159252616, 11.820296716518753, 43.33355061510956],
];
sideConnectorWidth = 2.4;
```

坐标全部已经是 castle-local XYZ，不能再次套新城 `[74,12,33]` / yaw -55° 变换。控制点使用折线（polyline）；未经检查的 Catmull-Rom 会改变包络。

主桥 + 短连接台按完整宽度计算，与 6 栋沿坡房完整檐口 footprint、所有主建筑 footprint 的交叠面积均为 0。最近房檐平面距离 **0.281473 m**。最大主桥坡度 **9.7780%**；连接台坡度 **3.2402%**。这些指标针对踏面包络；新栏杆的外伸应控制在 0.15 m 内，连接口处必须移除相交护栏。

连接后沿现有 surveyed 上层步行带前往 `mainApproach [63.383789506014665,12,40.43355061510956]`，中心线路程约 **9.3820 m**，再经既有约 **6.26 m** 正门阶台到 `mainEntry [68.51168130326376,13.2,36.84296212355201]`。该上层路线与房屋墙体交叠为 0。

## r26 原路线的实际碰撞

r26 JSON 的 `bridge.walkSurfaces` 末跨 `bay-bridge-walking-deck-3` 与 `new-city-stair-house-0--1` 相交：

| 检查体 | XZ 交叠面积 | 交叠范围桥面 Y | 房体 Y |
|---|---:|---|---|
| 完整房檐/基础包络 | 14.158845 m² | 13.545074–13.785717 | 11.291972–22.041972 |
| authored 实体墙盒 | 11.608442 m² | 13.557409–13.773382 | 11.941972–18.541972 |

墙体与桥板、步行头部区间均相交，因此并非画面投影巧合或仅檐口相触。`supportValidated=true` 和通船采样 true 不包含这项建筑碰撞。

原桥还与主厅地板、正门阶台/landing 相交；这些部分有意承托行走，不能直接当实体障碍。主厅整体 footprint 交叠 1.485903 m²，但其中包含真实门洞，因此本报告不将这项包络相交冒称墙体碰撞。

## 接台须做的局部收口

推荐路径没有跨越下降阶梯而形成独立低净空桥洞，但短连接台会与 surveyed tread **12–17** 的上层边缘重叠，构成接台区域。交叠区域最大绝对高差依序为 **0.0109 / 0.0576 / 0.0704 / 0.0833 / 0.0960 / 0.1851 m**；不能简单叠放两张面后声称无缝。应将连接台与这几块踏面的相交多边形统一三角化，做短坡/阶缘收口，保留通向第 18 阶的正常下降。不要把第 17 阶整块抬高造成新高坎。

新加的阶梯栏杆应在这个相交范围留出侧向入口，随后沿接台外边界补栏杆。报告数据没有新增栏杆的实际几何包络；不能把栏杆通行验收写为已通过。

曾检查“4.4 m 主桥直接折向 `[47.5,12.1,46]` 再进入上层带”的方案。虽然能绕开房屋，却跨压下方下降阶梯，产生低净空冲突，故不推荐。绕房另一侧直接接最上层 tread 的 4.4 m 方案又会穿过既有正门阶台体积。以上推荐的收窄短连接台避免了这两类情况。

## 方法、复算与边界

脚本不导入 bridge/stair runtime factory。对 actual `walkSurfaces.corners` 按实际中心线 4 三角面分别做凸多边形裁剪，并以重心插值取得交叠位置的桥面 Y；桥板厚度 0.42 m，步行净空检查高度 2.4 m。新路线用独立 miter 条带构造。房檐取 `authored.footprints`，实体墙取 `authored.houses.position/size`；两者均用报告的新城位置/yaw 变换。主厅门洞的 gross footprint 只记待窄相位核验。

复算：

```sh
node artifacts/pipeline/citadel-four-hour-20261005/check_bridge_endpoint.mjs
```

脚本含原路线实体墙碰撞存在、新建议完整宽度建筑包络无碰撞、无独立下降阶梯低净空交叠的断言。低净空筛选将差高 <=0.3 m 的近水平相交列为需收口的接台，而不是独立桥下通道；具体接台高差已逐项披露。

**尚未完成新的地形/桥墩/海面/通船或 GPU 验收。** `[51,12,39]` 是新侧台位置，原 r26 的桥墩采样不能证明这里被地形承托；第 14 阶端点高度确实来自已采样 JSON。集成后须重新地形采样、重建并审计桥跨/桥墩，检测新增栏杆与接台，复拍目标机位。桥按 maxSpan 36 重建后拱数也需从实际 report 重新读取，不能沿用原 4 拱数字。

## 后续授权实施：连接台与栏杆开口

只读复核完成后，主线程另行授权实施。已新增 `src/world/citadel/targetBridgeStairConnector.js`，并只修改其授权的 `targetNewCityStairRoute.js`、`targetCityBayBridge.js` 栏杆接口及相关测试；未修改 candidate 或地形。

```js
const connector = createTargetBridgeStairConnector({
  stairReport: surveyed.report,
  dock: [51, 12, 39],
  treadIndex: 14,
  width: 2.4,
  dockTangent: [28, 6], // bridge final segment XZ direction
  groundHeightAt: (x, z) => castleLocalYOrNull,
});
root.add(connector.group); // identity castle-local
surveyed.setSideOpeningFootprints(connector.sideOpeningFootprints);
const bridge = createTargetCityBayBridge({
  // other bridge arguments ...
  sideOpeningFootprints: connector.sideOpeningFootprints,
});
```

`groundHeightAt` 只读，必须返回有限 castle-local Y 或 null。`stairReport` 使用真实 `createTargetNewCityStairRoute(...).report`。`setSideOpeningFootprints` 可重复调用，传 `[]` 恢复阶梯两侧栏杆，不动任何踏面。桥开口是构造参数，在批处理前裁剪 curb、扶手、立柱，留出 0.35 m 几何余量。

接台模型从原条带中裁掉真实踏面宽度与 `ds + 0.012` 矩形，得到 6 个凸面单元，边界顶点贴相应阶面；原第 17 阶及全部踏面没有被抬高。完整交叠面积为 0。为避免名义缓坡在细长三角形上形成陡面，内部顶点按其行进射线到真实阶边的高度插值：**实际三角面最大坡度 20.1438%**，名义中心线坡度仍为 3.2402%，两者不得混用。

短台两侧细栏杆位于净步行宽之外，轴线外移 0.10 m、半径 0.042 m，最外伸 0.142 m；桥端和阶梯入口没有横向栏杆。`report.railSegments`、`walkSurfaces`、`seamPoints`、`support.penetrationSamples` 提供审计数据。采样为每单元顶点、边中点和质心，有限采样通过不等于连续承托验证。

CPU 测试 **15/15**：连接台 5 项、桥 7 项、原 surveyed stairs 3 项。包括真实 r26 接台几何不侵占踏面、不修改原阶高、最大三角面坡度、缺失/穿出地面不得通过、资源只释放一次、阶梯开口可恢复、实际批处理桥栏杆/curb 的跨通口射线检查。

仍需 GPU 集成核验：新桥尾与短台的交界拓扑、全路径导航、精细房檐/窗饰净距、栏杆接头、实际地形承托与新桥拱采样。没有声明 GPU 验收通过。

## 六栋沿坡房的基座初评（只读，后续实施建议）

r26 JSON 的基座高度是房屋 `position.y - footprint.floorY`；可见高度依地形遮挡而变，不能把全部基座高度当成截图中外露高度。

| 房屋 ID 后缀 | 房身高 | 总基座高 | 四角地形下的最大外露量 |
|---|---:|---:|---:|
| 0--1 | 6.60 | 0.650 | 0.138 |
| 0-1 | 7.10 | 1.575 | 1.455 |
| 1--1（玫瑰色） | 5.50 | 22.261 | 22.141 |
| 1-1 | 6.00 | 0.650 | 0.143 |
| 2--1 | 4.80 | 3.606 | 3.486 |
| 2-1 | 5.30 | 8.027 | 7.907 |

玫瑰色房 `1--1` 四角 castle-local 地形 Y 为 7.043、10.252、1.983、-11.809，房身地板 Y 为 10.332。它横跨陡崖，用最深角点延长整块矩形基座；四角承托采样为 true 不能证明这种 22 m 长墙符合目标。`2-1` 截图表现为明显浅色石柱，8.03 m 基座甚至高于其 5.3 m 房身。目标图中相近位置是连贯的分层挡墙、房屋下层与拱廊，当前缺少层次和结构解释。

建议按 `1--1`、`2-1`、`2--1` 的顺序细化。保留固定 r17 地形和现有通路，不直接降低房屋：上坡角会被埋。先在原 footprint 内按地面轮廓分段生成承托墙，每约 2.8–3.2 m 设置一道浅石带，墙脚随实测坡面下降；统一石色，降低现有大块基座与上部墙之间的突兀色差。高度超过一层的外露段可做真实浅拱龛：几何凹入原墙面 0.18–0.25 m、保留实体后墙，不能用黑平面冒充贯通拱洞。真正贯通承托拱须另做地形空隙、承重墩和入口验证，不能在被山岩填满处开假通道。

所有新增外挑框、墙带、窗台应限制在现有房檐 footprint 内。现基础宽/深为房身 +0.32 m，檐口为 +0.50 m，单侧仅剩 0.09 m；因此外凸装饰建议 <=0.06 m，主要细节向内凹。贴地绿植可以打断基座长直线，但应位于采样确认的外侧地面小斑块，避开 stair/connector walkSurfaces 及桥侧入口，不用密植掩盖承托问题。当前房门标记 `publicInterior:false`，若未增加真实门洞/室内，不应把立面装饰报告为可通行入口。
