# 湖沼近景黑碎面与遮挡：只读诊断

2026-10-07。已查看用户截图 `codex-clipboard-b7eb94b5-79a3-4cde-8d79-6e96ae8db4c2.png`，阅读真实工厂并运行默认 seed 7711 / scale .5 的 CPU 对象审计。**本代理没有控制浏览器、没有修改源码。主代理已恢复正常 GPU 访问；不再沿用“安全阻塞”。**

## 当前证据能说明什么

- 截图左上近景有大片绿/褐平面和薄片，黑部呈局部三角面、含细碎透孔；左/中景被近物与密集竖向物件遮挡。凭此可以确认玩家看到的空间阅读失败，不能凭颜色确定对象归属。
- 主代理实测约 12–14 FPS、9400–9900 draw calls，近期 warn 未见 shader error。这不能证明 shader 无几何/深度缺陷，也不能把全部帧耗时归因于一个轮廓 shader。
- **代码与 CPU 已排除一个容易误诊的来源：** `moebiusSwamp.js:1055` 的 `buildCanopyCeiling` 虽有12片巨叶与共面叶脉，但生产调用在1487行注释，默认真实 factory 中 `swamp-canopy-ceiling` 不存在。不要修这段死代码后声称截图已修。
- `swampGregVisuals` 的新 `greg-lake-outline` 实际11件：9个坑沿封闭冠簇、中央冠簇、世界树干。它没有挂到 `v2-entry-fronds`、`v2-world-tree-leaflets`、`v2-bank-ferns` 或旧平面落叶。新 shader 没有飞白噪声 discard，只有距离淡出。
- 旧 `v2-central-crown-ink`、`v2-rim-crown-ink`、`v2-bark-line` 已在实际 factory 隐藏；不能把这三项的源码存在误作重复绘制证据。
- 默认湖沼仍有 **617个可见 outline 对象，其中107个源是双面或严格平面**：湖沼直接孩子19、发光花瓣80、鸟翼8。它们属于旧 `toon.addOutline`；审计见 `leaf-audit.json`。这是风险和工作量清单，不是107项均有视觉缺陷的证明。

## 原因优先级

### 高优先：定位有“飞白”透孔的旧反壳

`assets/toon.js:130` 对源几何共享一份 BackSide 壳，法线外推厚度带哈希扰动，fragment 用 `floor(vBrushPos*36)` 随机丢弃少量片元。截图黑面中的细碎孔洞与该视觉特征一致。可能是相机进入封闭网格/反壳内部、源几何被替换后壳仍持旧几何，或者近距离与其它薄片相交显出大片背面。**尚未拿到截图中对象ID，故只是优先假说。**

最小验证由主代理在当前机位命中该片对象：记录 UUID、name、祖先、geometry/material、isOutline children、source/shell geometry是否同一对象。只临时隐藏这个源对象的旧壳，保留叶子本体和所有其它渲染。黑孔面消失而正常绿面保留才确认来源；之后恢复临时状态或实施同样窄修正。

### 中优先：新反壳在相机进入闭合冠体时显示内面

新反壳是 subpixel 外扩的 BackSide，也不是通用内部观察轮廓。相机若进入冠体，其背面可以大面积可见。新壳透明/不写深度，但会测深度；这些设置本身不能防止内景面。它的11件开销也不是9400–9900 draw calls的主要数量来源。

验证应保持同机位，**只切换11个 `greg-lake-outline` 可见性**。不要先切 `gregLakeVisuals=0` 整套，因为那会同时改材料并恢复旧壳，无法隔离回归。若黑色细碎透孔不变，则新outline不是这处黑面主因。

### 有限风险：平面叶背面与共面细线

旧双面叶＋BackSide壳不是必然在背面填黑：正常一致法线、正缩放且深度正确时，壳常被叶片遮住。必须检查真正叶片变形、几何替换、负尺度/面方向后再下结论。`v2-world-tree-leaflets` 与新入口 fronds 本身没有反壳，无法凭“双面”二字解释黑色飞白。

生产禁用的大叶主脉确有共面风险，但与当前截图不能建立运行时因果。现有新 bark lines 是材质内部图案，无第二共面网格；旧 `v2-bark-line` 已隐藏。

## 最小修复顺序

1. 拿当前截图大叶命中对象身份；确认是否实际属于 `moebius-swamp-zone`。颜色/局部放大可能来自相邻水晶城对象，不能删除整个湖沼树冠试错。
2. 若是旧平面叶反壳：仅移除该类叶的反壳；保留双面本色。需要边界时用叶的边界轮廓或受限 shader 线，勿将 EdgesGeometry 的内部三角全画出来。不要扩大到角色/建筑全局 `addOutline`。
3. 若是源/壳几何失配：源几何替换时同步重建/退休对应壳，补 geometry identity/轮廓 bounds 回归；不要只让黑材质透明来掩盖。
4. 若是相机进入新冠体：针对近相机冠体控制反壳可见性，或使行走/观景空间不穿冠体；先验证，不改全局相机 near 值“裁掉问题”。
5. 视觉遮挡另验：三层路线各取入口、人眼高度中段、下岸回望，保护到世界树/船坞/下一层的视线。近叶退到通路边缘或减小局部冠幅，保留植物实际根部与身份，不是把镜头抬到天上。
6. 性能需采整场可见对象/材质与 CPU/GPU时长。先降低确证重复壳与零碎静态提交；不能仅凭11件outline承诺从13FPS恢复到60FPS。

## 验收

同一当前相机、时刻、天气记录 A/B，再左右小幅绕视确认黑面不复现。真实shader无错误只是必要条件；还需黑面消失、叶片前后正确、没有穿冠、三层目标可读。CPU数据用于确认归属与副作用，不替代以上GPU观察。
