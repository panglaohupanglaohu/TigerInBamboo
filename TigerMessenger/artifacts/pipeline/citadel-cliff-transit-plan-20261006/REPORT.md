# 中央下层铁路：可运行断面诊断，当前失败不安装

接口：`createTargetCliffTransitPlan({castleMatrix, bridgeReport, bridgeRoot, sampleTerrain, sampleSea, drop=6, bankControls})`。输入地面/海面采样函数使用castle坐标并返回height/number/null；桥root必须已拥有真实世界变换。输出 `worldCurve` 和 `report`；不会添加模型、修改轨道或接受方案。

运行 `node tools/pipeline/survey_target_cliff_transit.mjs` 可重现；其读取r47实际桥路径，以当前桥工厂重建真实拱券/柱/板几何，在真实castle世界矩阵下检测。土地来自当前retreat后作者高度函数，尚不是新GPU最终三角射线。新增单测3项通过。

## 已测实质问题

下层沿现步行桥路径下移5/6/7m，各95断面，两列车包络轨心间距4.1m、车宽3.44m、侧余量各.6m，总净宽8.74m，长度6.98m，高3.022m加顶部.6m。现上桥宽4.4m；这不表示下层结构能承托8.74m宽交通带。

实际桥三角与车辆有向包络相交lane站数分别175/110/80。底部9点地形相交站39/40/42；均无缺海面或浸水。相交率不是精确车身碰撞率，但已足以否决照搬。原路径约27°与4.77°折点必须圆顺。世界径向重力下最大纵坡约.34，不能拿castle-local低坡度冒充轨道平缓。

所以 `accepted=false`、`installed=false`、`status=failed-diagnostic`。没有把失败候选接入电车。

## 下一模块边界

下层应保留中央桥在画面上的对应关系，但使用独立世界径向高程线；调整实际柱/拱的支承方式使两个列车包络贯通，再与两岸外崖线连接。原桥整体简单下降不可行。旧城端不向山内挖隧道，水槽海侧外挑，列车在水帘后干燥开敞廊通过；需要新水槽出唇/水帘实体与轨体包络检查。两岸的真实路线由splice模块统一选分支，当前 `bankCandidates` 仅端点占位或调用者提供的候选，不声称完成。

断面全数据在sections.json，含每站world/local/up、两车体中心、桥命中名称、9个地表/海面高度和失败原因。还缺连续车体扫掠、货载完整高度、实际最终网格支持、两岸承托、车辆运行与GPU视觉验证。

## 第二候选：独立径向高程及圆顺

已继续实现 `mode:'radial'`，按实际上层桥沿程允许半径最小值选下层world radius=173.9052m；海面+预留船孔/桥底要求最小165.7m，两界有可行区间。保持原上桥不动，采用centripetal曲线圆顺原角点并投至该球面。90断面最大世界纵坡0.000023，已消除简单localY下移的34%坡度。中心线对上桥XZ投影最大偏离1.9243m，在原4.4m宽上桥投影内；下层双轨整体仍宽8.74m，必须独立设计宽度和承托，不能据中心线通过说桥已容纳两车。

真实现桥柱/拱实体仍有95个lane站相交，必须重构下层贯通拱；地形冲突38个lane站集中在两岸入口，旧端最初约11站及新端末段。不是中央海上沉水：海面缺失0、浸水0。两岸要向各自外崖展开连接，不能沿这条内缩端线挖旧城隧道。此候选依然failed-diagnostic，但轨面高程及中央投影已有可用解；global splice和桥实体仍未修改。测试增加至4项通过。

## 门槛修正与有限两岸搜索

默认铁路门槛已统一为maxGrade=.04、minCurveRadius=25；当前径向中央线实际最小采样半径31.768，通过该单项。急弯负例、缺失/非有限水面、不可逆矩阵与无效路径均有拒绝测试。bodyProjectionCovered显式false，不能以中心线在上桥投影内代替车体净宽通过。

新增 `findTargetCliffBankCandidates`，仅产生外接短段候选，每岸49个控制偏移，以世界等径弧每1m及9个宽/长包络底点检验不入土、不浸水；不改全球轨道。实际新城侧找到有限清空短段，旧城49项全部被山体拒绝，因此旧侧保持无方案，未开隧道也未伪造通过。新端候选还没验与中央线接角、旧桥实体、新支承和全球线连接，不能直接使用。结果在bank-candidates.json。此搜索不是完整寻路器，失败不证明一切外崖路线不存在，只说明当前有限短段集合不可用。单测现7项通过。
