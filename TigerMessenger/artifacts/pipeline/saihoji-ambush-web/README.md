# 苔庭蓝盔隐蔽与伏击

本批只修改 Web 传统战船兵的时序。两船共 50 名蓝盔沿原航程抵达，短暂整理后移至真实松冠下；掩护不足会阻塞，不隐藏或删除人物冒充成功。全员隐蔽后，必须由真实舰队扫描范围、鲲实际升起与舰队锁定共同触发伏击，随后恢复原弓箭/投枪/绳索战斗。重甲空降仍由舰队实际受击触发。

- 运行文件：`src/world/saihojiAmbush.js`、`src/world/saihojiPhalanx.js`；根代理另外负责 `src/scenes/saihojiGarden.js` 的提前到达舰队揭示门控，以及真实松树和掩护点。
- 可观察入口：`__tm.messenger.landmarks.saihojiPhalanx.root.userData.saihojiAmbush`，含 `state` 与最多 16 条 `events`。
- 掩护接口：`leviathanGroup.userData.saihojiCoverPoints`，每项含 `id`、固定岛面 `anchor`、`localPoint`、指定 `pine`、真实冠底 `clearance`。原圣城红守军仍为红色；初始登陆船与原蓝方补给船显式使用蓝色。
- 复验：`rtk proxy node tools/pipeline/test_saihoji_ambush_web.mjs`。独立浏览器打开实际 8931 页面，调用真实 Garden 和 Battle 更新器，保留人物身份。

## 诊断边界

测试人为控制舰队位置：提前停在扫描范围内直到全体隐蔽；在隐蔽状态切换瞬间移远，验证 10 秒等待没有射箭；再移近，观察真实升鲸和锁定触发。没有直接写入发现标志、鲸升高值、伏击状态或重甲状态。不是自然全游戏舰队巡航回放。

验证了完整更新链的阶段、50 名角色可见性/颜色/身份、驻定朝向、掩护点冠底与实际可见装备顶高的余量，以及不会把尚在赴松路上的兵随鲸升起。冠净空扣除掩护点抬高 .04 岛面局部单位；它是驻定截面的保守高度检查，不是树干、横枝、装备互相穿插或风动全周期的逐三角检测。

保留原战船到岸后的 cohort 放置，未实现甲板逐人下船动画、完整树间寻路、25 人登船调度，也未修改 Godot。伏击后原 `patrolSoldier` 会回到鲸侧北翼地表阵地，原绳索队也回到地表；新松下位置到这套旧阵地之间的高度衔接尚未完成运动连续性验收，不能把阶段通过当成无跳变。后续如果改变松树几何、岛面布局或人物装备，应重新运行净空与流程检查。

最终证据见 `latest.json` 指向的版本；旧中间运行保留，其中 sourceStable=false 的记录不作为最终版本验收。
