# 书店石板路回接

用户指出静态渲染有石板路、网页游戏没有。核实第三轮 Blender 的四块 `Entrance path` 是场景根对象，不在建筑层级内；前批只导出了建筑与窗框，遗漏石径。

本批从保存的第三轮 Blender 副本独立导出四块磨角石板，保留平面位置、宽度、间距和交错旋转。只在临时评估网格校正向内的面朝向，不保存回源文件。新增数据约 15 KB、176 三角形，四块合并一次绘制。

运行时石板顶面随实际山丘网格和原书店土坡调整，保留薄石板厚度。碰撞沿用连续地面，不生成四道会卡脚的独立竖直碰撞墙。只有新版书店启用；旧版参考仍可保留。已在用户应用内当前游戏预览确认石径显示。

代码入口：`tools/originals/export_bookshop_path.py`、`src/assets/bookshopPath.js`。石板数据：`assets/models/optimized/bookshopPathData.js`。导出来源及原文件不变证据：`export.json`。

验证脚本：`tools/test_bookshop_path.mjs`，已通过。捕获约定：1280×800 真实玩家镜头；在同一个同步渲染段仅切换石径可见性做前后对照，随后真实 W 行走与 R 交信。固定视口并非整场景性能达标声明，Chrome 软件渲染不作设备帧率基准。

结果：`web-report.json`；四块石板顶面均可从上方命中，位于山丘表面上方约 0.427/0.099/0.078/0.068 米（第一块还由原土坡承托，故高于山丘）。实际行走与落地、R 章节 0→1 通过，无页面错误。固定场景绘制 2997→2998，三角形 375394→375570。`web-path-before.png` / `web-path-after.png` 是同场景同玩家镜头，仅路面开关不同，主代理已逐张查看；`web-path-gameplay.png` 保留实际 HUD 与交互后的画面。

适用边界：这是默认书店位置的贴地适配；地图编辑器搬迁书店或改地形后的再次贴地刷新不在本次检查范围。Godot 原石板使用双面材质，因此没有 Web 单面显示的同类消失，但源面朝向缺陷仍应保留记录。

本批并发分工：主代理负责网页石径；Godot 书店协作任务负责两阶材质，并核实原生石径。文件范围分离，原模型和前台未保存 Blender 不被覆盖。

并行的 Godot 材质已通过真实场景及前后对照，证据在相邻 `bookshop-materials/`；主代理已查看。Web 旧书店的拓扑回归、招牌编辑与回退也复测通过。
