# 能力如何作用于选中目标

状态（2026-11-06）：已完成实景命中、合批来源范围与只读高亮；尚未完成目标绑定的可执行算法节点。移动/旋转面板不是本阶段核心，下一步以“目标 + 算法 + 作用部位/区域 + 候选”闭环为优先。不要把选中、来源登记、整体可见性开关写成目标算法已执行。

## 前端流程

选中实景对象后，生命/植被能力区显示“可用于此目标的能力”，每项带真实来源缩略图、输入输出、作用范围和可执行状态。用户选择作用于整棵、树冠、叶片，或以此物件为锚点的一片地表；无适配器的能力显示缺口，不伪装可运行。加入后节点明确标出目标名称与作用范围，不依赖一个会随着下一次点击而改变的全局selected变量。

执行从不可变基线提取目标部位，在独立候选中运行，预览只覆盖约定部位；保留树干、根部、邻近植物/建筑等锁定内容。比较、采用/放弃、对象历史、草稿保存/恢复、过期定稿拒绝必须一起接通。选中下一件物体不能重定向已绑定节点。

## 节点最小契约（待实现，不是当前API）

- capabilityRef：真实库模块/导出函数、来源记录、已校验revision。
- targetRef：scene ID、对象ID、对象revision、输入部位或区域mask；运行时mesh UUID不作跨版本身份。
- inputs：由适配器提供的几何/材质通道、变换、实际地表采样与邻域约束。所需输入不齐即阻塞。
- params/seed：明确白名单与范围，可复现；不接受任意脚本。
- locks：保留部位/对象ID；writeSet列出允许输出的精确部分。
- output：候选补丁、来源/算法revision、基线指纹、检查结果，不直接修改已定稿版本。

## 实际来源与输入区别

1. REACodeRefactoring/src/life/vegetation.js 的 Vegetation.refresh(world, shape, {yards,paths}, seed) 从World格子/地形形状重建落点、草、灌木、树等；这是地表/区域输入，不是接收任意tree Mesh的单棵编辑器。不能把选中树ID传进去就运行整湖refresh。若能力是“树周边补地被”，必须显式派生邻域mask并提供真实莫里斯岸坡采样；不能拿湖上体素World冒充岸坡。
2. src/core/canopy.js 的 buildCanopy(blobs,{resolution,passes,hardStiff,softStiff}) 输出树冠几何，实际stats.extraction为surface-nets。输入是blob集合；现有莫里斯悬铃树为分枝/叶片卡片，不能未经转换就调用，也不能把新团块树冠当默认风格升级。只有适配器与用户明确选择树冠候选时才可接入。
3. src/life/leaf-surface.js 的 makeLeafSurface/LEAF_SURFACE_GLSL 是纹理/uniform/着色器通道能力。莫里斯树使用自己的叶片材质与贴图，需目标叶片材质通道适配；不能改共享合批material导致所有树一起变。

“树冠”、“区域落点”、“叶片着色”、“impostor远景”等是不同输入/输出域。能力扫描只登记来源；可执行状态还取决于目标类型、输入通道、适配器与局部写入契约。

## 已有基础与剩余实现

scene-objects.js/bindBatchedObjectOwners已能从面命中回溯plant顶点区间；下一步需保留目标基线position/normal/UV/index及材质通道、真实地表上下文，并以每物件revision追踪。此信息尚未进入Source快照/recipe/场景版本，不得提交一个只有文字目标、没有targetRef的对象改造请求。

先做一条具有真实输入适配、局部输出和完整版本闭环的能力，再扩展算法库；不要默认选中哪棵树就开放所有植被算法。保持已认可莫里斯造型，转换/替换只做候选，用户采用前不改原场景。

## 验证门槛

- 兼容目标显示可用，不兼容目标/缺失适配器拒绝；来源revision真实。
- 两个对象先后选择，节点仍作用于原绑定目标。
- 运行后只有writeSet中目标部位变更；其他合批区间、材质、建筑和锁定内容指纹一致。
- 同seed/参数结果可复现；过期对象revision、失效区域或基线冲突均保留用户版本并拒绝直接应用。
- 候选放弃/执行失败/配额失败无数据损失；采用后对象撤销/重做、草稿重载、版本恢复、定稿/固定游戏加载均可复现。
- 本契约未跑通前，UI只能称“候选/待适配”，不能把全局参数预览称作对象算法执行。
