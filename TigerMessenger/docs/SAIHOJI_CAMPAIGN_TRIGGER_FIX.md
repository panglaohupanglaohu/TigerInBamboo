# 苔庭主线与盟军触发修复

2026-09-10，用户反馈：完成前序任务、使用两位英雄能力后，鲲已升空、机队到场，却看不到传统士兵。截图主线仍在第三章，离诱敌信号点 28 m，按钮不可用。

## 已确认的代码问题

- 救援主线、英雄能力与原士兵出兵状态机没有接线。两个英雄技能只暂时抑制机队吸食；送出信号也只推进章节并提供保护。
- 原士兵链由独立鼓声任务决定出发，不等玩家完成结盟，因此可能提前推进，或被其他任务状态阻挡。
- Garden 旧门控只检查 `landing`；士兵控制器不存在时反而允许鲲升空。
- 可选圣城 V3 后端分支会省略原苔庭士兵控制器。完整故事与实验样片不能互相替代。

这些是代码确认的缺口；没有用户当时运行状态快照，不能断言具体是哪一分支造成截图。

## 修复契约

`rescueCampaign` 在初始化、章节变化及更新时同步 `battle.setCampaignProgress({chapter, started})`。该接口只授权原航程，不直接生成士兵，不重置正在进行的战斗或攻城。

- 结盟前：不提前发船，也不提前揭示鲲。
- 结盟完成（chapter 2）：沿原运兵航线出发，登陆后进入松下隐蔽。
- 两位英雄技能保留原保护功能，不代替诱敌信号。
- 玩家在信号点 9 m 范围内步行按 R，完成信号（chapter 3）。同时满足士兵已隐蔽、真实舰队扫描和鲲升空，才允许伏击。
- 士兵控制器缺失时不允许鲲先行升空。
- 主线面板显示准备出航、航行、登陆、隐蔽和伏击状态。
- 原存档章节键不变，不要求重做前序任务。刷新后由已保存章节授权同一原航程。
- 重甲兵仍需舰队实际受击才能部署，不能仅因信号或鲲升空刷出。
