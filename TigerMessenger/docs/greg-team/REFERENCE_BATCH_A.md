## 逐条证据

### 1. 1887140576526491902

- 来源：[原帖](https://x.com/ShedworksGreg/status/1887140576526491902)。作者文字为空。GIF 转 MP4；本轮看到 0、0.5、1 秒共 3 个样本，API 未给有效时长。
- **画面观察：** 驾驶视角向前穿过近白地面，左右有深黑/灰机械或遗迹体块；近景飞行器中央红色带状物提供运动方向，远处仍能辨出拱形和立柱。深色块集中在边缘，中央地面细节少；近景主体与远处地标没有同等密度。
- **本项目推断：** 湖沼入口与水道中央应维持连续低细节空间；根部、设备与高对比线集中到两旁。白鲸轮廓周围不能有同明度、同密度的碎石和粒子。
- **待验证：** 无文字确认此具体版本或日期；运动平滑度、速度和时间循环不从 3 张图推断。

### 2. 1853866288071704780

- 来源：[原帖](https://x.com/ShedworksGreg/status/1853866288071704780)。原文短语：“Gliding and clambering”。视频 6.371 秒；0–6 秒共 13 个样本。
- **画面观察：** 0–1.5 秒，粉红岩壁与紫色背阴间，角色从窄台向另一处边沿移动，红色球状效果包裹角色；2–4 秒为相近峡谷的外部俯视滑行；4.5–6 秒角色攀在明亮青绿藤叶带上。植物主要贴附可攀崖面，不是在所有空隙平均填满；台顶呈清晰浅暖色，侧壁偏暗，植被与石体色相分离。
- **本项目推断：** 三层岸台各保留一块读得清的落脚面；连接根桥/藤梯应在画面中有起点、末端与承托。青绿植物可提示可达边缘，但不遮住踏面。入口图至少让下一落脚点可见。
- **待验证：** Sable 的具体攀爬碰撞或着色实现不公开于本帖；本项目不能因为画出藤梯就声称已可攀。

### 3. 1851648957224534135

- 来源：[原帖](https://x.com/ShedworksGreg/status/1851648957224534135)。
- **作者陈述（意译）：** Greg 回顾这是最初广泛传播的 Sable GIF，改变了团队发展的轨迹；其中人物还是 T 字姿态在沙丘上起伏，但已概括创作目标。视频 3.15 秒；0–2.5 秒共 6 个样本。
- **画面观察：** 浅黄沙丘、灰白天空、单一红色尾迹；飞行器穿过低起伏地形，粉色高柱只占小块背景。地面有稀疏笔触，主要面积仍是平色；机体下方影子与轮廓支持离地高度判断。画面方向靠尾迹和沙丘曲线成立，精细角色动画尚未完备。
- **本项目推断：** 湖沼目标图先用岸台、水面、主树、白鲸构成一个读得懂的画面；不先加百万叶片。鲸的投影/水中剪影和岸边接触线用于尺度，虎保持辨识度。
- **待验证：** 不将原型中的 T 字姿态和粗糙角色作为最终质量标准；参考的是空间清楚的优先级。

### 4. 1850109738383544750

- 来源：[原帖](https://x.com/ShedworksGreg/status/1850109738383544750)。视频 7.05 秒；0–6.5 秒共 14 个样本。
- **作者陈述（意译）：** 早期车辆很快、难控制，后来因玩家操作困难、世界显小、场景加载与碰撞问题而减速。
- **画面观察：** 车辆在浅黄沙丘上快速变换位置；天空大面积浅青。远景巨石、拱桥、细高地标之间有大段空隙。白色泡状尾迹明确指示轨迹，投影把机体与地面联系起来。地面零星草石并未挡住地平线。
- **本项目推断：** 湖沼尺度不能只靠放大主树。三层之间的步行时长、显露顺序与安全停留点需要共同决定；目标图先画连续路线和可停处。不可用一次高速飞越俯视来代替正常玩家抵达过程。
- **待验证：** 这条能支持“速度影响空间尺度”的作者论述，但不能导出本项目某个固定移动速度数值。

### 5. 1849085705915449413

- 来源：[原帖](https://x.com/ShedworksGreg/status/1849085705915449413)。作者标注 Sable pitch build 片段。视频 10.35 秒；0–10 秒共 21 个样本，2 张 sheet。
- **画面观察：** 固定正面机位，暖红峡壁围住蓝绿色台阶/门框；前方人物背对镜头，中央粉色面具形门是最高识别节点。0–2 秒门闭合；约 2.5–5.5 秒左右门片分开，显露更深、更冷的通道；6–10 秒开放后的深处仍清楚。近景人物、阶梯、门、深通道形成连续尺度。
- **本项目推断：** 湖沼上岸不应直接“一览无余”或始终被树干遮挡。窄入口先框住白鲸水域的一角，转弯后显露主树与修船岸；用色块和实体边缘组织显露，避免用强体积光替代空间。
- **待验证：** 这是 pitch 原型，不等于成品材质规则；高饱和红蓝并非湖沼必须照搬的色板。

## Rollerdrome 作者规则：单列，不能冒称 Sable 实现

已实际读取 [Dekerle 2022 完整问答](https://www.gamedeveloper.com/art/deep-dive-rollerdrome-art-direction-q-a) 的美术规则与色彩段，以及 [Roll7 AMA](https://www.reddit.com/r/Games/comments/x8zxpb/were_roll7_developers_behind_rollerdrome_ask_us/) 中 Paul Rabbitte 对风格与高速可读性的答复。

**作者陈述概要：** Rollerdrome 为色块和阴影设置恒定屏幕宽度轮廓，以平色、线和少量斑点表达材料；远处减细节，每环境以四至五个主色及变体组织；繁简对比、色值分离服务高速可读性。AMA 将法比漫画的适量细节和高速清楚联系起来。这些是 Roll7 的规则。本组 Sable 媒体可见大块色面、不同距离层级和投影，但不足以证明两款游戏采用同一着色方法。

## 湖沼目标图的硬性画面准则（本项目提案）

1. **不改成沙漠。** 保留用户蓝绿密林、白鲸、虎、修船/原住民故事；Sable 提供空间与线色关系，不能把所有参照的粉沙黄沙配色搬进湖沼。
2. **一个可以读懂的总空间。** 宽幅总览同时看见三层岸台和至少两段连接，不把台地画成互不相干的漂浮环。主树偏离画面中心，具有根—干—冠和疏密间隙；它可以宏大，但不能是一根把水面一分为二的直立巨柱。
3. **白鲸是水域尺度参照。** 主鲸在中景完整或大部分可辨，周围有完整水面呼吸区；不可用发光粒子盖住轮廓。虎在近侧承托明确的干岸，修船工作点靠一侧岸线且有干燥作业面。不要把它们变成互不相干的“装饰小人”。
4. **繁茂靠有机层叠而非满屏噪声。** 近景叶片/树根可更密；中景让出水道与台面；远景合并为几层蓝绿轮廓。每处复杂根群旁都留一块大色面。
5. **空间先于描边。** 将目标图缩至宽 320 px，仍应分得出上、中、下岸及主树、鲸、水域。再看大图，才读到树皮、叶脉、修船绳索等选择性细节。
6. **用四张相关镜头验同一地理。** 总览/入口上岸、转折中岸、近水下岸、水下生态；各图岸线、主树、码头关系一致。水下不是新增楼层，树冠也不能因目标图画得漂亮就称可达楼层。

### 语义色板及面积建议

以下 HEX 是湖沼候选设计值，不是从作者原始项目中提取的参数，也不是已获用户批准。面积是总览构图建议，不是现网统计。

| 色族/功能 | HEX | 建议面积 |
|---|---|---:|
| 深蓝墨线与前景阴部 | `#17445E` / `#163E56` | 10% |
| 水面与水下色域 | `#46B5C1` / `#164967` | 32% |
| 林冠/湿地叶片 | `#298C94` / `#53AFA6` | 27% |
| 石岸/树干的中冷色 | `#75A7B1` / `#287C91` | 18% |
| 浅色路径/白鲸 | `#9CC4BA` / `#D7E7CD` | 10% |
| 花/小灯/修船强调色 | `#D6A9C2` / `#EAD4AC` | 合计≤3% |

不能使白鲸、岸面、灯、大片体积光都处在同一个最亮档；白鲸与可走面为稳定亮部，小灯只是局部强调。蓝绿也需要明度和冷暖细分，不能一键染成同一青色。

### 线条、距离和阴影

- **外轮廓：** 主树、鲸、岸台、近叶的外缘连续清楚；以深蓝墨代替大面积死黑。总览不能把每片远叶描成同粗黑边。
- **结构线：** 岩层、根节、树皮纵线、踏面接缝用于说明构造，密度低于外轮廓。侧壁和台顶用不同色块支持高度判断，不靠随机多边形明暗。
- **细节线：** 叶脉、稀疏点刻、木板纤维只在近景停留区。远处先去细节，再简化结构，主体剪影最后保留。任何像素阈值需在游戏实景移动中标定，不能从目标图反推作者数值。
- **阴影分色：** 叶/树使用较深蓝绿面，石岸用蓝灰阴面，避免全物体同黑色乘法压暗；踏面与墙面保持有色硬分界，水下允许有限深度渐变。不硬套 Rollerdrome 的“绝无渐变”到用户湖沼。

### 验收与回退边界

目标图交付只是方案，不等于接入、CPU 测试或 GPU 验收。本组未修改工厂、球面变换或尺度。后续实施必须沿真实默认调用链接入、保护当前虎/鲸/船动画与路径。

实景验收：固定同镜头/同时间做无细线和有细线两版；按实际玩家速度从上岸下行中岸再到水边，记录下一步落脚点是否持续清楚、鲸是否被主干长期遮住、远线是否抖成黑噪声；另放完整船/鲸循环检查净空。静帧不能替代这些检查。方案未实现时无需代码回退；新代码仍需保留源快照及局部开关。
