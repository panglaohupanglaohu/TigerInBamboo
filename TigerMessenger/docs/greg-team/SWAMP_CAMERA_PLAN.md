# 湖沼专用镜头方案（2026-10-10）

提案：视觉规则 + 镜头与操控角色（学习 Antoine Dekerle、Paul Rabbitte / Rollerdrome 方法的代理，不是本人）
评估：Greg / 组长代理
状态：**方案已评估，未实施**。

## 1. 现状（读代码得出）
- 第三人称镜头跟在信使朝向（`player.forward`）的正后方，默认距离 7.5，高度随距离缩放。被墙挡住时沿视线往回拉，最近 2.0（`src/core/camera.js`，已回退到验收过的版本）。
- `cameraRig.setFollowProfile({yaw,height})` 已有接口，可以给某个区域加偏航和抬高，不用改主逻辑。
- WSAD 相对镜头：W = 画面前方（`src/player/controller.js`）。坑缘步道上有转向辅助 `swampWalkwaySteer.js`，还有防掉落护栏。
- 湖沼内坐标（inner）缩放 0.5，1 个 inner 单位 = 0.5 world。
  - 坑缘步道：r 35.5–46.8（加宽后），顶面 y≈40。
  - 坑内：r<35.5。
  - 信使身高约 1.66 world。
- 问题：
  - 树干和扇叶树冠密集，7.5 的镜头常被树叶挡住。
  - 在弧形步道上，镜头跟着朝向走，会切过坑的弦线，画面掠过整片坑。
  - 唯一处理遮挡的办法是把镜头往前拉，曾因此钻进信使身体（已禁止）。

## 2. 提案
### 2.1 分区与参数（world 单位）
| 区域（inner 坐标判定） | 距离 | 额外抬高 | 俯视约 | 偏航 |
|---|---|---|---|---|
| 坑缘步道 r 35–47.8，y 38–44 | 5.0 | +0.8 | 28° | 沿步道切线跟随（见 2.2），向坑外侧偏 12°，让湖面进画 |
| 坑内台阶 / 岸台 r<35.5，y 4–40 | 4.5 | +1.2 | 35° | 跟随朝向（不加切线） |
| 湖沼外 | 默认 7.5 | 0 | 默认 | 默认 |

- 区域之间用 0.8 秒平滑过渡（按到边界的距离做 smoothstep），不跳变。
- 骑乘任何载具、第一人称、特写时，湖沼镜头不生效。

### 2.2 沿步道跟随
- 在坑缘步道上，当前进方向与步道切线的夹角在 55° 以内（和转向辅助同一规则）时，镜头的"身后方向"取步道切线方向，与朝向按 70% / 30% 混合。
- 走弧线时，镜头沿着路绕，不会切过坑。
- 明显朝内或朝外走（下台阶、出坑）时，不改偏航。
- 镜头仍只在信使身后，不会自动绕到侧面或正前方（硬性规则 1）。

### 2.3 遮挡：遮挡物半透明，镜头不前推
- 树冠扇叶、树干、林下植物的着色器各加一个"视线胶囊"：从镜头到信使胸口的线段，半径 0.9 world。
- 胶囊内的片元用棋盘抖动丢掉 70%，看起来像半透明。不排序、不改透明队列，也不多加绘制调用。
- 只有岩壁、坑壁这类实心物体，仍按原规则把镜头往回拉，最近 2.0，且绝不进入角色身体（硬性规则 2）。

### 2.4 操控
- WSAD 不变，仍相对镜头。镜头在步道上沿切线跟随后，按 W 就等于"沿路往前"。
- A/D 在步道宽度内左右挪；转向辅助的回中拉力已经减弱，护栏兜底。

### 2.5 开关与回退
- `?swampCam=0` 关闭整个湖沼镜头，`?swampCamFade=0` 只关遮挡半透明。
- 改动集中在新文件 `src/world/swampCameraProfile.js`，加上 `camera.js` 里的一个小钩子：在 `followProfile` 之外再加距离覆盖。

### 2.6 验收（必须真实键盘操作；离线图、CPU 模拟不算）
1. 坑缘步道顺时针、逆时针各走一整圈：
   - 信使始终在画面里，被挡超过 0.5 秒的次数为 0；
   - 不按转向键时，镜头偏航变化不超过 30°/秒；
   - W 始终沿路前进。
2. 从入口下台阶到中岸，再回到坑缘：镜头过渡平滑，没有穿墙。
3. 在坑缘步道上停下，用右键拖拽环视，松手后回弹正常。
4. 上下飞艇、泡泡舱、船时，镜头不受湖沼设置影响，一次 F 只做一件事。
5. 帧时：记录湖沼内开、关两种情况的平均帧时。
6. 美术总监在固定机位下，把默认参数和新参数各渲染一张，和目标图并排对比。

## 3. 组长评估（Greg）
**结论：方向同意，分两步实施。**参数暂定，以美术总监的机位并排对比来定稿。

1. **同意的理由**
   - 方案直接针对用户反馈的三件事：镜头太远看不清信使、走起来方向偏、被树挡。
   - 它不重复上次"自动绕镜头"的错误：偏航只沿路，不绕到人前。
   - 遮挡处理改为"让物体让路"，而不是"镜头让路"，符合 Sable 式"遮挡—再显露"，地标不会因为镜头前推而丢失。
2. **必须注意**
   - **扇叶是实例化共享材质**：不能整批调透明，否则所有树一起变淡，必须用 2.3 的胶囊抖动，只影响视线上的那几片。
   - **切线跟随会和"转身下台阶"冲突**：必须保留 55° 门槛，超过就把偏航交还给玩家。
   - **"进湖沼就拉到最近"只采纳一半**：距离确实要拉近（7.5 → 5 / 4.5），但不拉到最近。拉到最近会失去湖面和地标，弯道上也更晕。
3. **实施顺序**
   - 第一步：距离、抬高、切线跟随。风险低，可以先让用户试。
   - 第二步：视线胶囊半透明，涉及多个着色器。
   - 每步都在 `docs/PROJECT_HANDOFF.md` 记录"已实测 / 未实测"。
4. **依赖**
   - 美术总监先定 5 个固定机位：入口、坑缘步道（信使身后）、中岸、湖心、虎台阶，并出以真实渲染为底稿的目标图。
   - 镜头参数用这些机位验证。
