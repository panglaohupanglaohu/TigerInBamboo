## 2. 用户两张图真正显示的变化

用户的平色/加线对照与演讲 **07:22–09:57** 的同场景叠加过程一致。不是给最终画面套一个黑边滤镜。

本次关键帧核对：07:28 平色中轮廓仍靠色块分离；07:43 投影加强人与帐篷接地；08:10 远岩与天空更接近而近处对比保留；08:44 线把前景板材、物体边界和远岩分层读出来；09:20 远处线淡化、近景线仍清楚。**湖沼要按这五个中间状态做 A/B，不能只展示最终一张美图。**

项目验收应保存完全相同相机、曝光、时间、分辨率的五张图：

1. 纯色体量：确认地标轮廓和每层台地本身成立。
2. 明暗与接触：确认角色脚、平台侧面、船入水的位置读得清。
3. 分层距离色：确认最远出口和下层水面仍可辨认。
4. 主线与次线：确认线路表达结构，没有把三角网格全画出来。
5. 远线衰减：确认远景不黑团、不闪烁、不突然跳出。

## 3. 三类线稿如何转为可施工方案

以下为 **本项目建议的实现方案**；演讲没有提供完整 shader、采样核、缓冲区布局或性能数值。

### A. 外轮廓与真实遮挡边

先保留当前湖沼局部实现的可回退边界，避免改变全世界渲染。`src/world/swampGregVisuals.js` 的反向壳是工程折中，**不能标成 Sable 的三线实现已完成**。它适合封闭的大树冠和岩石外形，但不能可靠表达同一物体内部接缝；薄片、透明水面也不能直接套壳。

若下一轮升级为屏幕空间方案：湖沼独立深度/线语义 pass，仅对不透明、已选择对象写入。深度不连续用于遮挡轮廓；可选的法线差用于少数锐利结构，但阈值需按屏幕占比和对象角色控制。不得描绘每个低模三角面。透明水面采用独立岸线，不写入不透明深度边缘缓冲。

建议参数结构（试验起点，不是 Greg 的数值）：

```js
const lineProfile = {
  outerCssPx: 0.85,
  structureCssPx: 0.6,
  detailCssPx: 0.4,
  fadeStartWorld: 32,
  fadeEndWorld: 85,
};
const alpha = 1 - smoothstep(fadeStartWorld, fadeEndWorld, viewDistance);
```

这些值已经或可能出现在并行视觉样机里，但是否适合实际湖沼仍须近中远动态验证。CSS 像素与 framebuffer 像素必须显式换算；DPR 1/2 下不应线宽翻倍。远景先淡出刻痕，再淡出内部结构线，地标外轮廓最后淡出，不能把全部线一刀切。

### B. 手工可控的结构线

为模型建立 `outlineClass` / `lineMask` 语义：主轮廓、结构接缝、材质刻痕、无描线。材质颜色和线语义分开存，避免换色板改变线的位置。台阶踏面边、码头承重转角、树根分叉可以明确标记；水面三角形、树叶随机面、看不到的背面不描线。

如用顶点属性或 ID mask，边界两侧须允许不同属性，必要时在语义边拆顶点；不能直接把平滑共享顶点当离散面 ID 插值，否则边界会漂移。这是我们的实现推导，不是演讲披露的内部缓冲区。

验收：换三套色板后同一结构线位置不变；昼夜变化不把岩石细线变成大黑面；角色高速移动经过树冠时，线不盖住身体。

### C. 与色块分离的材质线纹

为岩层/树皮/遗迹提供独立单通道 mask。基础颜色保持大色块，线纹仅在 mask 阈值附近出现。UV 或局部坐标固定于物体，禁止逐帧随机噪声。宽度使用导数抗锯齿，并根据投影尺寸减少刻痕；模型缩放时，应保持纹理实际尺度，而非连同噪声一起拉伸。

推荐先做三个小资产对照：一段 8m 岩壁、一根主树根、一块平台铺装。每类只采用一组受控笔触，不叠加屏幕噪点、法线噪声和几何噪声。保留原始干净版本以便回退。

## 4. 色彩 Profile：把变化做成系统

不要混淆两个游戏的规则：Rollerdrome 强调其自身的平色/少色规则；Sable 这场演讲明确演示距离渐变与昼夜色彩过渡。湖沼可以使用渐变，关键是它解释空间而非把全画面染成同一层雾。

`src/world/swampGregVisuals.js` 当前语义色板是项目月夜方向，并非从 Sable 吸色得到。建议集中配置：

```js
{
  id: 'lake-upper-dusk',
  base: {water, stone, foliage, bark, path, accent},
  shadow: {color, strength},
  distance: {near, far, colorNear, colorFar},
  lines: {outer, structure, detail, fadeStart, fadeEnd},
  transitionSeconds: 2.5
}
```

Profile 根据真实玩家在湖沼局部坐标中的层级与时间插值，层边界有滞回，不让站在界线的玩家看到色板来回跳。转场时间 2.5s 是待测试建议值。层级变化优先微调水、阴影、植被关系；保留同一条路径的语义颜色，不能上层黄色可走、下层黄色变危险。

必要调试视图：关闭所有线、仅主线、仅材质线、灰阶、层级 ID、可走面 ID。生产界面不展示 shader 参数。

## 5. 多层湖沼：先尺度，再景观

演讲中的“底层方向＋表层节奏”可转为湖沼的纵向组织，而不是照搬沙丘。

`src/scenes/messenger/loadMoebius.js` 真实放置参数为 `swampScale = 0.5`，湖沼另有球面朝向与 lift。**表格必须注明 inner-local / world 尺度；局部 y 不等于世界竖直高程。** `src/world/swampSpatialPlan.js` 的本轮样机已有三处侧岸平台与阶梯连接，可作为测量对象，不能把其全部 inner Y 当玩家世界米数。

空间组应为每层交付以下字段：`id / 局部高程 / 相对坑口落差 / 水面净高 / 台地有效宽 / 上下连接 / 正向可见地标 / 回望地标 / 生态带 / 居住用途`。图上放人物、船、树根三种尺度参照，而非只标一个巨大的圆。

抵达样区的四个镜头应沿真实通路拍摄：

- A 坑口：看到主要水面和一个下层地标，知道目的地在下方。
- B 下行：部分遮挡地标，但下一落脚面和路径边仍连续可读。
- C 中层平台：地标再次出现，尺度明显变大，能看到后续入口。
- D 近岸抵达：看到可以实际使用的台阶、系泊点或入口；回望能认出刚经过的中层。

遮挡来自既有地形或经过碰撞验证的树根，不得靠把主地标随相机隐藏。不能用视觉上像台阶、实际上没有可走面的装饰通道。`swampGround.js` 的真实射线采样与台阶网格必须用来验证，不能只采理论曲面高度。

## 6. 生态和居住：规则要能回答“为什么在这里”

演讲对分布条件的启发，落实成下面的湖沼约束，均为项目推断：

| 规则 | 数据条件 | 可见结果 | 拒绝情况 |
|---|---|---|---|
| 水边生长 | 距真实水线、坡度、基质 | 低矮成簇湿生植物，有连续露水面 | 植物穿过水面悬空，或覆盖整条岸路 |
| 根系承托 | 主干连接、实际落地、支撑面 | 根从树体连续到岸/岩，不是随机触手 | 根凭空终止；可走根缺碰撞 |
| 高处栖居 | 水位上方、可达台地、维护路线 | 小范围干地和生活设施 | 房屋无出入口、门开向悬崖 |
| 遗迹再利用 | 原结构厚度、排水、可用入口 | 旧构造和少量后来加建可区分 | 将古老误做成满屏裂纹与碎片 |
| 动物导引 | 真实路线附近安全节点 | 少量活动提示停靠/可探索点 | 强行移动虎或鲸破坏剧情，或诱导玩家落水 |
| 内容密度 | 地标视锥、道路宽度、空水面比例 | 远景有留白，近岸有生活细节 | 每一层同密度复制同一树/屋 |
