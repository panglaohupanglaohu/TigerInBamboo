# Greg team · 有机通行：已施工的净空规则

2026-10-07。研究角色学习 Niklas “El Huervo” Åkerblad / Ultros 的公开方法，不是作者本人。责任范围：新 `src/world/swampGregLivingPaths.js`、对应测试、本报告；未改原虎、鲸、船动作及空间主路线。

## 学习证据与项目转译

已阅读 [PlayStation 官方开发者访谈，2024-02-12](https://blog.playstation.com/?p=389260) 和 [导演 Mårten Brüggemann 问答，2024-02-05](https://www.pushsquare.com/features/interview-how-castlevania-studio-ghibli-inspired-the-action-gardening-of-ultros)。作者介绍植物各自有生长规则，种植可产生平台和替代路线；自然不是纯装饰，学习植物的行为会改变探索。美术来源包含 Mœbius、Haeckel 等多种影响。没有取得 Ultros 的植物算法源码，也没有据此宣称复刻其玩法。

对本湖沼的推断：植物先必须回答“根在哪、冠占哪里、它引导玩家去哪里”。已读组长空间审计与 Sable 逐段报告，后者为634条字幕及32关键帧的研究证据，我没有完整观看演讲。Sable 25:21–25:56 的遮挡/再显现和 Ultros 植物组织路线相结合，在本次转为 **既有可达路线之外的生态导向与视线保护**；不加无碰撞根桥，不承诺已做植物成长、播种或循环玩法。

## 实际场地审查

- 新路径三层 inner Y 为34.8、30.8、26.8；默认缩放.5，对应坑缘落差2.6、4.6、6.6 world unit。路径实宽4local=2world。
- 主树新根 `v2-floor-root` 位于innerY约10–13，末端半径约8local；在水下床附近，和三层侧岸没有真实可走连接。不能把它包装成上层根桥。
- 原11株左右的坑缘树另有 `v2-rim-bowed-root`，正式岸路工序可能使其变形以接地。这些现有根的实际包围体纳入保护；不是凭树位置随意画禁种圆。
- 原虎沿8块入口大阶行走，且有坑缘巡游。这里只保护这8块入口阶几何及头部净空，未更改其故事路线；不声称整个坑缘巡游AI已重新验证。
- 修船固定泊位 `dock` 与 `barge` 从实际对象几何取范围，保留工猴换桅和蜥蜴送水。
- 出航船不是静态摆件。原代码 `sailPos` 从角度1.1/半径16，行至.3/22，再继续到.35/31；护送鲸在船侧或泊位绕游。因此保护整个出航走廊，不仅保护生成时船的当前位置。

## 已实施接口

```js
const guard = createSwampLivingPathConstraints(inner);
const decision = guard.inspectPlant({
  position: [x, y, z], // inner-local 根部
  radius,             // 包住完整根、茎、冠的水平半径
  height,             // 从根到最高叶/穗的高度
});
const report = auditSwampLivingPlants(inner, records);
```

无路径时返回null，由调用方跳过依赖这条路线的种植。无效/非有限尺寸直接拒绝。模块没有渲染对象、更新循环或额外draw。

|约束|实现数值/范围|目的|
|---|---|---|
|真实路径净宽|route中心两侧各2.15local，再加完整植物半径|保留整个2world通路及.075world边缘缓冲；禁止用窄中心线当完整通路|
|头部净空|踏面下.2local至上4local|植物高冠即便根在更低处也不能悬过玩家头顶|
|入口虎道|实际8阶几何包围，外扩.15local并加4local头高|不覆盖原剧情入口|
|维修作业|真实dock/barge各子网格并集，外扩.75local|保留既有工作位，不搬船/工人|
|现有根|逐根真实geometry局部范围，外扩.1local|新植物不穿过既有树根|
|船与鲸通道|97节点折线，水平半宽8local，innerY20至当前水路+6|保守覆盖航行、桨、侧游与破水；只限新增种植，不改动画|
|主树地标视线|三平台中心上3.2local眼高到主树innerY≥48，线束半宽1.1local|允许低植被，拒绝遮住树干识别带的高植被|

包围体先将每个原geometry的8个角乘 `inverse(inner.matrixWorld) × mesh.matrixWorld` 后合并；InstancedMesh逐instance矩阵处理。**不把世界轴对齐盒转回inner**，避免球面旋转使保护域无端放大。根与修船保护为保守局部包围，可能少种几株；不是精密碰撞替代。

生态组原先拟在4local宽平台的外lip种植；这个设计会吃掉已承诺的通路净宽。协商后取消所有平台lip候选，移到路径外实际旧岩架，并以真实5点承托验收根盘。生态组完成三种低矮形体；本组不再重复添加导向大植物，避免无必要draw和轮廓拥挤。

## 验证与状态

`tests/world/swampGregLivingPaths.test.mjs` **5/5通过**，使用默认seed7711湖沼工厂，正式半径160/缩放.5放置与-30°转向：

1. 全路线每段五处、左右路缘与中心共超过1000候选均拒绝侵占通路；高于路面2local的冠也拒绝。
2. 实际8虎阶、修船/筏、现有根及97个水路节点均正确保护。
3. 三层地标视线拒绝高挡物，允许落在视线下方的低叶簇。
4. 审核不改变任何actor UUID、位置、朝向、显隐，不添加场景对象。
5. 最终wrapper再次任意平移、旋转、uniform scale后，全部保护域及3125候选的通过/拒绝结果保持一致。

生态组已调用此接口；其66株种植是否通过以生态集成测试及主代理总验收为准。当前没有GPU同机位检查、实操步行、夜间动态遮挡或连续船鲸碰撞回放；CPU净空不等于这些已通过。视线检测只保护新增植物的几何包络，不证明原场景视线绝无遮挡。

## 剩余可执行项

- P0 集成：生态安装必须在 `installSwampSpatialPlan` 之后；三种植物完整冠半径/高度进入guard，在真实根盘接地后再提交实例。无新植物可通行的注册。
- P1 视觉验收：入口→上岸→中岸→下岸及回程，检查植物能帮助辨识层级，同时脚面、主树和下一平台仍可见；与视觉组“无描线/主线/完整线”三状态交叉。
- P1 动态验收：完整26秒出航周期与虎下降周期，检查净空走廊足够且原有枝根未干扰动画；如失败只调整新增种植，保留故事锚点。
- P2 真正活路径玩法：若后续授权根系生长通行，先做带状态的可走根实体、连续踏面、径向ground注册、成长完成前禁入，再增加播种/养护；本轮不以装饰代替这项功能。

回退：移除生态/设施对guard的调用可恢复其原候选规则，但不建议用于正式场景；保留空间 `gregLakeSpatial=0` 与生态独立开关，由主代理统一接入。该模块本身没有场景副作用。
