## 1. 从参考图提取的空间规则

用户图中主色不是灰绿或奶油色：大树与背景是深蓝、青蓝，植被中景用蓝绿区分，鲸背与水线是高亮青色，鲸头和叶舟是浅黄绿，少量粉红生物/花芯提供暖色。以下是目视设计分析，不是作者讲解或精确吸色。

1. **大色块先于纹理。** 左侧巨大树干是完整的暗蓝体量；右侧几簇宽大叶片构成可辨认的前后遮挡。细线丰富，但不会把整棵树变成一排同宽竖杆。
2. **水线承担场景剖面。** 图中水线分开水上人物/叶舟和水下鲸体/鱼/植物；水下蓝色更深，前景鲸体仍清楚。游戏无需照搬一张固定剖面镜头，但必须保住水面、入水深度及三层岸路的关系。
3. **白鲸是亮色主体。** 背景及近岸枝叶不应和鲸头同亮；维修船、孩子、虎是活动线索，不能为构图直接删除。
4. **茂密不等于均匀堵满。** 宽叶、弯曲分叉、近景细节应集中在边缘框景；入口到水面的视窗和安静水面需要保留。
5. **深度来自多种差异。** 前景结构线清楚，中景叶脉较少，后景用蓝色体量和较弱线对比；单独把所有物体刷成同一个灰绿色无法表达层次。

GDC 记录中直接相关的学习段落是 06:02–10:04（平色、接触、距离色与线淡出）、10:05–12:18（色彩配置）、13:03–16:40（可控线纹/不完美）、21:01–25:56（群落条件与地标遮挡/再显现）。下文参数均为项目试验起点，不是 Greg 的源码或数值。

## 3. 已确定的问题及精确代码落点

### P0：棕榈叶被当树干和露根重建

`moebiusSwamp.js:837` 的 `buildRimPalm` 子节点是“1 根干＋6–8 片 Plane 叶”。`:2155` 又把这些棕榈加入 `towerTrees`，用于共同球面贴合，这个用途本身合理。

但 `swampV2Art.js:191` 对 `towerTrees` 每个对象的 `children.slice(0,6)` 无条件重建为 Cylinder；`:357` 对 `slice(6,12)` 无条件重建为 Tube 根。因此“叶片序号”被误读成“六段树干/六条树根”。

**真实工厂 A/B 复核：关闭 V2 时，2 棵 rim-palm 分别有 1 干＋6 叶 / 1 干＋8 叶；默认开启后，每棵前5片叶成为 Cylinder（加原干共6个），其余1片 / 3片叶成为 Tube 假根。** 此外每棵还生成两份 count=0 的空实例叶冠，它们也被同一 slice 误改名为根；因此节点数是3 / 5个 `v2-rim-bowed-root`，其中真正非空假根是1 / 3个。这是确定的语义错误，不必等待视频才能识别。但本阶段遵循先学习，未改生产代码。

最小修复应按 `swamp-towering-tree` 类型或明确 `trunk/root/leaf` 元数据执行专属改形。棕榈只共用球面贴合，保留真实叶片。不能通过改根的可见性把错误圆柱藏起来就算完成。

### P1：灰绿色统一覆盖压掉了蓝绿空间层级

`swampGregVisuals.js:5` 当前色板：wall `#6e9193`、bark `#739187`、foliage `#7da294`、foliageShade `#507e7c`、water `#75adb2`，石/路分别 `#b5bcb0` / `#d3d1b8`。这些低饱和相近色覆盖大面积壁、根、树冠和路径。

`flatMaterial()` 新建 MeshBasicMaterial，保留 side 但不保留 vertexColors、原 shader 和原面区语义。实例树冠只按 `i%4` 在两种绿间切换；V2 的顶点暗面因此消失。墙只乘以 .70/.86/1 三个高度亮度档，并不等于前中后景分色。所有被换材质 fog=false，未实现相机距离色、层级 profile 或统一过渡。

明确区分覆盖前后：V2 岩壁的高频裂纹/苔藓 shader（`:260`）在默认 Greg pass 中被覆盖，**不是默认画面当前全部灰绿的直接活跃 shader**。关闭 Greg 时它才重新成为该墙的有效材质。

### P1：漏管资产与后期覆盖使调色没有单一权威

| 资产 | 当前最终来源 | 问题 |
|---|---|---|
| 中央树干/枝根、rim 命名枝根 | Greg bark | 灰绿覆盖，但无统一近远层 |
| 每棵高树前六段无名干 | V2 `P.bark=#809d9e` + V2 bark shader | 不在 Greg name 白名单内，换 Greg 色板不覆盖 |
| 中央 3024 个尖叶实例 `v2-world-tree-leaflets` | V2/P 颜色＋顶点面区 | 不在 Greg foliage 白名单，冠团和细叶由两套色板控制 |
| rim 树冠 lobes | Greg 两色＋新屏幕壳 | 丢失原先顶点明暗；株距和主干比例没改变 |
| 岩架/石阶两侧 cheeks/湖底草石 | 多处 P 或固定 hex | 一次全色板替换不能收拢它们 |
| 最外圈 promenade | `finishSwampV2Art():462` 的 P.stone | 后装配会把它保留为偏白石路 |
| 66 株 Greg 小植物 | 构建时烘入 Greg 顶点色 | 需要重建或明确更新颜色，不随材质 profile 自动变色 |

建议建立局部 `visualRole + depthBand + lineClass` 清单，按角色统一所有本地材质。避免又新增一层 name 正则补丁，或为了统一湖沼而全局修改 `MOEBIUS_PALETTE`（会牵连水晶城/叹息之门）。

### P1：高干环墙与过密小细节没有构图层级

`buildToweringTree():884` 计算 h=(40..58)×LEAF_HEIGHT_MUL(2)=80..116 local，即 40..58 world，主干六段。`:1318` 均分整圈约 10–12 个位置，排除入口后再加棕榈；变化主要是少量角度随机。V2 换圆润截面、换冠，却没有重新建立入口—主树—鲸之间的主次轮廓。

V2 还保留中央 126 冠团/3024 尖叶实例，各 rim 冠改 7 个 lobes。instancing 降低 draw，不等于屏幕细节密度下降。参考图里的宽叶、树干分叉应先做成几组明确体量，不再用数千个同尺度细叶补“茂密”。

还存在误判风险：原 `buildCanopyCeiling()` 在 `moebiusSwamp.js:1487` 已注释，不能把遮挡归咎于这个未调用的顶棚。具名 `swamp-vine-*` / 跨树藤已被 V2 隐藏，但无名壁挂藤和塔树内部 coils 仍存在，不能说所有藤已删。

## 4. 黑面与水线风险：确认机制，不伪称已复现截图

1. **薄片套闭合物体反壳。** `moebiusSwamp.js:107 part()` 默认对全部几何加 `addOutline`，包括鸟翼、飘叶、部分花瓣。`assets/toon.js:addOutline` 是不透明 BackSide 黑壳，几何沿法线外扩；在薄片背面可形成整片墨面，并非只有边缘。V2 修过巨花 petal 并隐藏其旧壳，但不能推断其他薄片均安全。修复应先列薄片语义清单，改叶缘/主脉 mask 或显式曲线，禁止给开放薄片统一套壳。
2. **透明水面保留旧不透明壳。** `createWaterSurface():178` 双面透明 Circle 上仍调用 `addOutline(water,.014)`；Greg 只换 water color，未清理这个旧壳。从水下看存在整面背壳遮蔽风险，应做水上/水下对照。V2 已隐藏旧 wall/floor/tread 壳，不能把这些已隐藏对象算作仍绘制的黑面原因。
3. **两套墨色及衰减共存。** 新 Greg 屏幕壳是 `#263e49`、.85 CSS px、32–85 world 淡出；旧壳是全局暖黑 `#211e19` 与几何单位厚度，无距离 LOD。CPU 默认工厂可见子树里仍有 **617 个 outline mesh**（包括船和角色），不是“全部已换成 11 个新轮廓”。本轮没有 GPU 编译或透明排序验证。
4. **相互交叠/近裁切与半透明排序。** 新壳的 BackSide + transparent + depthWrite=false 仍须在交叠冠团、极近相机、DPR1/2 动态检查。代码已正确采用实例非均匀缩放的 cofactor 法线变换，不能把它误报成“没处理 instance normal”。
5. **水盘和盆壁横截面不一致。** 水面 r=33、水体上口32.5；V2 壁在 Y=25 的理论半径为 13+(25−10)×.7=23.5（加不超过约1.25的横向扰动）。水盘明显延伸到岸壁外，不只是 .01 级 z-fighting。它还与城市/global 海壳、剧情出航相邻，需根代理按完整装配审计；不能本轮擅自缩湖/移船/移鲸。

## 5. 蓝绿分层的最小材质方案（待视频学习后定稿）

下面是本项目建议色，不是从作者代码获取，也不是已上线效果。先做固定机位无纹理色块，再决定细线。

| 空间角色 | 试验色 | 作用与约束 |
|---|---|---|
| 深水/最深凹口 | `#164967` | 深蓝底，保留鲸/鱼轮廓；不扩成整屏黑幕 |
| 远壁/远林 | `#245F7E` | 蓝体量，减细纹对比，与前景青绿拉开 |
| 中景主干/分叉 | `#287C91` | 保留主树连续轮廓及受光大面 |
| 中景宽叶 | `#298C94` | 冷青绿，不和树干同明度同饱和 |
| 近岸叶亮面 | `#53AFA6` | 限定在框景和可达节点，不平均全冠提亮 |
| 水面 | `#46B5C1` | 一条稳定清楚的水位基准 |
| 鲸头/叶舟亮色 | 保留叙事材质；候选 `#D5E6B5` | 明亮焦点，需单独核对水上/水下关系 |
| 小暖色点缀 | `#D6A9C2` | 花芯/垂挂生物，低面积占比 |
| 结构线 | `#17445E` | 彩色墨线，远线先淡出；不用纯黑铺面 |

不建议按相机距离直接把所有对象染同色。先给确定的地形/林带配置静态 depthBand；之后仅对远景做温和、连续的色差收敛，近岸路径语义不变。水下衰减应按水下深度与视线段区分，不能简单令“低 Y 的任何物体都蓝化”。

## 7. 预算与责任

**CPU 工厂快照**：2011 个 visible Mesh，其中 617 个标记 outline；材质槽计数 MeshBasic1819 / Shader11 / MeshToon138 / MeshStandard43（多材质使槽数不等于 Mesh 数）。Greg 报告 changedMeshes323、outlineDraws11。这些是工厂、无 frustum 视锥裁剪的对象数，包含 count=0 的空 InstancedMesh，不是正式页 GPU draw 数。

工程预算建议：

- R1/R2 **净增 draw=0、净增实体=0**。换材质与修误改无需堆对象；实例色按语义更新，不生成逐叶材质。
