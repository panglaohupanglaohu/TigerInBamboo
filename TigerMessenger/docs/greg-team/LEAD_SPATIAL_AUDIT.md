# Greg team / 湖沼空间审计与施工方案

2026-10-07；角色：基于 Gregorios Kythreotis / Daniel Fineberg 公开方法的研究代理，非本人。本文件先记录默认代码与 CPU 几何；没有 GPU 或实际游戏通行验收。

## 学习证据与范围

已读 [Sable 作者访谈，2019-05-22](https://www.cookandbecker.com/en/article/170/sable-exploration-through-line-art.html)：Greg 讲稀疏环境突出导航地标、建筑如何表达生活及引导；Daniel 提醒多源观察与生活史。不是把每处都做成沙漠。本轮已重新核对 [GDC 2022 官方摘要](https://www.gdcvault.com/play/1027721/The-Art-of-Sable-Imperfection)：小团队限制、手作二维观感与三维可读性；本人未完整观看视频，不将摘要当算法讲义。视频成员的逐段证据另交。

用户两张 Sable 画面对照的直接观察：大色块和远景遗迹的位置基本一致，第二张补了帐篷、地表和山层的选择性细线与颗粒。练习应先保证不描线也能看懂入口、近中远；再加主轮廓、接触线与材料少数痕迹；不描三角网格全部边、不把远景挤成黑墙。此为本项目判断，不是该视频的逐字技术断言。

## 正式默认调用链（已读代码）

`loadMoebiusDistrict → crystalV7Round=3 → V9=5 → V10=15`；`placeMoebiusSwampAndSky → createCatalogObject(moebiusSwamp, seed7711, scale .5) → createMoebiusSwampPlacement → createMoebiusSwampZone → applySwampV2Art(round50)`。V2 只有 `swampV2=0` 才关闭。随后 `installCrystalV7Shores`、`finishCrystalV9Scene/finishSwampV2Art`、`relocateCrystalCore`。

实际星球半径 **160 world unit**，不是旧注释40。inner.y=-40，wrapper缩放0.5，仅一次；坑缘wrapper半径160−24+8.2=144.2。最终绕峡谷中心轴-30°，不能用旋转前位置做入口图。

独立默认工厂 CPU 构建实测（2026-10-07，不是正式全场景）：wrapper最终位置 **[-67.612237,-112.275553,-60.136724]**；cityLocal角坐标 **[.282487,-.070718]**。局部点世界坐标必须通过 `wrapper × translate(0,-40,0)`，世界径向高度不能简单当全局Y。

## 当前尺度、层级及问题

下表H为相对坑缘切平面的高度，H=(localY−40)×.5；单位是world unit，未声称真实米制标定。

|层/对象|当前数值|空间用途与限制|
|---|---|---|

|碗口|local r34，world约直径34；V2有约±.625world岸线变化|入口角.5，开口半宽.25rad；洞口和实际阶梯必须相连|
|入口|8块主体×3小踏步；local r37→25，中心Y39.4→21.9|主阶水平进深6、下降8.75world，整体很陡；顶小步非同一高度。第3块中心小踏步Y34.8|
|三层岩架装饰|local Y約25.96–37.50|只渲染，无行走注册；不能称三层可玩湖沼|

|主树|根部localY10，干高58local=29world|树干锚点local[-8,39,-7]，主树冠分支tip Y60–78，再叠叶簇；可作为方向地标，树冠尚非可达居住层|
|维修船|local[-6.455,25.02,12.423]|水面劳动节点；船头朝湖心，工人换桅、蜥蜴送水，不能搬去干台破坏动作|

当前是多层**可见生态**，尚不是多层**可达聚落**。先造一段成立的侧岸连接，不能宣称整湖已导航贯通。

## 本轮授权施工：侧岸三层样区

提案并实施范围为新 `src/world/swampSpatialPlan.js` 与V2末尾调用。保留虎的8块原阶与巡游、水中鲸及船队行为。

- 第3大阶中央踏步(localY34.8)侧接上岸；上岸Y34.8(H−2.6)。从入口可见主树和下层终点。
- 中岸Y30.8(H−4.6)：自然观察停留台，连接上层的缓阶设真实顶面，避免用花丛暗示不存在的道路。
- 下岸Y26.8(H−6.6)：高出湖面.9world的停留台，供观察鲸和水下生态，暂不直接对接维修船或做水上居住。
- 每层主通道宽4local=2world；连接均为真实实心几何、加入ground sampler。保护入口虎主线，偏向负角度岸边，避开维修区theta2.05与古树根。
- 中/下层不是随意新增房屋；第一批先用观测/泊靠尺度设施验证生活逻辑，新增居民和任务需下一批故事设计。

到达节奏：水晶城桥→可辨识环岸→原阶入口→侧接上岸俯看→缓阶中岸观察→下岸近水停留→原路返回。第一轮保留单一明确退路；沿岸通路不得引导跳水才能回城。

## 本轮施工与CPU验收（冻结交付）

已接入 V2 正式工厂末尾 `installSwampSpatialPlan`，新增入口侧接、三层台地、两段各32级缓阶、8块入岩承托石梁、3根不挡路的矮标。所有76个静态石构件合成 **1个vertex-color draw mesh**，路标为 **1个InstancedMesh**；本空间模块共2个draw mesh（实际渲染调用次数仍需GPU测量）。合批保留逻辑构件名称与三角区段，ground sampler指向真实批次顶面。回退比较参数 `gregLakeSpatial=0`。

实际测试 `tests/world/swampSpatialPlan.test.mjs` **3/3通过**：

- 默认seed7711工厂保留8块原入口、虎、护送鲸与维修船锚点；三层实际H为-2.6/-4.6/-6.6，新下层高于湖面.9world。
- 从原第3大阶中央踏步起，到末端近水台：每.1world采样，中央及左右各.45world三条线，超过1500点，均命中top-facing真实几何（与径向up点积>.8）；脚面误差<.14world。runtime全湖ground sampler同点返回同层，不能靠顶层最高命中混过。
- 实际 `buildMoebiusCrystalMetropolis` 固定V7布局＋`installCrystalV7Shores`＋正式`relocateCrystalCore(-30°)` 构建中，原main.js“先采V7岸，再采湖沼”的顺序在全部路线节点 **0个错层抢占**。此测试不含完整铁路/全世界加载；V7桥岸真实工厂与旋转已覆盖。

与视觉模块联测此前7/7通过；新增实际V7优先级测试后共8项，主代理再跑最终批次。未进行GPU实景、角色步行或物理回程验收，因此“几何采样成立”不等于“玩家操作验收”。
