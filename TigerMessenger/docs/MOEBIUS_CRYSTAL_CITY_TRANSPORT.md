## 收敛与验收顺序

1. 测量：读取实际加载车船的局部包络、轨道曲线、当地水面与湖底。区分艇体、装饰和运动部件；记录船舶水线。
2. 定位：在现有线路上寻找可停站段，将 A/B/C 映射到真实球面坐标。若与塔群偏差过大，先调整换乘步道方案，不凭透视图挪轨。
3. 通行：检查连续曲线的车体扫掠空间、桥下高度、航道宽度、船舶回转区、水深；余量属于本游戏设计参数，不能冒称行业认证值。未测项目明确标为待测。
4. 白模：仅在尺寸核查后制作站台、桥跨、码头和连接通路，先跑通一处母塔换乘，再复用到两侧。
5. 美术与接入：对照认可目标做晶体、支撑和灯光，接入 8931 原游戏并同步 Godot；分别验证步行、停站上下车、进出港和昼夜可读性。

交付证据：同机位全景、站港近景、真实通行记录和问题清单。当前仅完成方案与源代码核查，桥下净空、水深、转弯半径和换乘玩法尚未验收。

### 水面几何的新问题

湖 API 水位半径固定为 136，但实际湖水网格在样本处半径约 126.55–135.91。工厂使用只有中心与外缘的 CircleGeometry 三角扇：虽然顶点贴球面，径向大三角形中部仍形成弦面下陷。全球海面另沿峡谷下降，不能统一当成固定半径 160 的水壳。

因此测量采用全球水面与当地湖面实际网格中较高的交点；不能只读 sea.surfaceR。下一批必须先将湖盘改成带径向分段的球面网格，并让水面查询与渲染使用同一高程，再复测桥高。当前结果是现状诊断，不是修复后的通航证明。

### 必要修正的优先级

1. 修复湖盘径向细分与水位查询一致性；重新测量岸线与塔基，不先增加港口。
2. 从有足够水深的连通水域选择三港，避开已定位低桥；主航道不能直接沿全部轨道投影布置。
3. 用完整船体/船桨扫掠验证桥墩、岸线与建筑，新增船道后再测其实际转弯半径。目前没有水晶城实际船道，不能编造该数值。
4. 定位站台、停站逻辑和步行接驳，再回接新站港。电车已测半径不等于完成停站或人行验收。

范围限制：水深只包含 planet-surface 底床；不包含额外礁石、建筑、桥墩的横向碰撞。桥高是径向中心线采样，未遍历整个船体宽度。尚未修复水面、搬轨、创建三港或同步新的 Godot 几何；候选美术图仍未获用户审定。

## 母塔单港：找到通过初步运动检查的近岸航线

沿母塔扫描 240 个方位/距离点，岸点距离扩至 8/16/24，得到 27 个初选泊位。加入船体范围水位变化、实际船体碰撞后，对最近三处稳定水面候选进一步验证。最终选定 radius=16、bearing=11；世界单位水深 9.486，船体范围水面变化 0.00815。

选择 startBearingIndex=11、headingSign=-1 的弧形进港线：25 个位置 × 4 个划桨姿态（60/75/90/105）共 100 次实际网格交叉检查通过。最小曲率半径约 12.285；港内暂定速度 3.5，对应转向速率约 0.285 rad/s，小于 boatRide.js 现有 1.45 rad/s。另一条虽无碰撞但曲率半径仅 0.372 的掉头候选不采用。有限离散采样不能替代整段连续扫掠和真实驾驶验收。

落点与控制点保存：assets/models/optimized/moebius-city/mother-port-layout.json；对应草图 mother-port-navigation.svg。

岸上连接的重要更正：原岸点搜索越过母塔，落在塔后，岸点到塔后平台的中心线虽通过，也不能作为船到塔的连接。必须在临港侧安排上层落脚平台及高差连接，不得直接画直线穿过塔身。选定船头朝向的登船侧向外海，需安排相应侧的靠泊台，再通过上层通路接塔前；先验证码头与船桨不相交。
