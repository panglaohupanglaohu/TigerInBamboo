# 新城围墙与背面喷泉：Oskar 方法顾问施工评审

日期：2026-10-07。范围：用户新认可三视图对应的新城，研究与布局评审；本文件未改生产代码。顾问基于公开研究，不是 Oskar 本人。截图为设计目标，不能当现有实景。

## 目标图观察与当前差距

目标有四个连续层次：前方铁路与雕像/木马广场 → 主阶梯和穹顶 → 围绕穹顶的低层住宅及侧门 → 背面带喷泉的围墙花园。建筑不是前后等距的对称盒阵；相邻住宅共同围出院落，墙的转角由方塔收束，前方主阶梯保留大开口。后院喷泉是用户明确要求的固定地标。

现有 `targetNewCityMain.js` 有十个庭院屋位、真实前后拱口和小后院，尚无新城喷泉工厂。全 src 的 fountain 结果来自 `navonaPlaza.js` 的旧双喷泉，不能把它们误称新城背面喷泉。背面应在本次施工中明确恢复/建立喷泉，保留独立身份。

## 事实坐标与不可混用的坐标系

`targetNewCityPlacement.js` 原点仍为 castle 局部 `[74,12,33]`，yaw −55°，实际 up 按星球径向计算。生产 `targetCityDetailCandidate.js` 用 `expanded-1`，主殿几何 XZ 为作者尺寸的 1.1 倍，Y 在 1.2 阈值以上乘 1.2；不是整个 group 简单 scale。新墙/喷泉只施加一次相同 placement matrix。

下表使用**形变后的新城局部 XZ**，不是 castle XZ：

|---|---|---|
| 主殿后门 | z −8.58；净宽约 5.5 | 保持真开口，无门板/城墙塞入 |
| 后院地面 | x ±4.73，z −19.25 至 −11.77 | 复用 `rear-court-stone-floor`，不悬空另盖平盘 |

## 可以立即实施的布局合同（项目建议，非作者参数）

1. 保留主殿、木马、雕像、铁路和现有主步行接点。庭院住宅围绕穹顶分为左右两簇，后排向外让出后门与喷泉院落；保持十屋稳定 ID，换位置/朝向，不把旧屋留在隐藏层里叠新屋。
2. 后院喷泉可在 `[0,-15.51]`，外池半径 1.25–1.35 world，水面以下实心基座，顶点都由实际后院地板支撑。两侧各保留≥1.8 world 绕池路，北出口与南后门连续。现植物 x±3.135、z约−13.75/−17.6 位于绕池路线，应退到侧边或减少。水池不能注册成平地，取消“后门到北门直线穿池”式路径。
3. 外墙初始候选可取后方 z≈−23、两侧 x≈±24，再折向前侧门。它们是待测点位，不是已证明有地基的施工坐标。分段沿真实地面高程递升，缺承托则局部收回/换转角；不抬高巨型石裙去填山谷。
4. 主阶梯宽 6.82 的前方轴带始终留空。侧门位置由正式 `publicFootprints` 与城墙中心线交点求得；门洞净宽至少现路线宽＋两侧 .35 world，净高取真实角色高度并保留≥3 world 候选目标，不凭概念图画死位置。门顶墙使用真实挤出拱洞，不用黑色平面冒充。
5. 建议围墙墙身 0.8–1.1 world 厚，高约3.0–4.2，转角塔宽约3.4–4.2；塔和墙低于穹顶。下宽上窄、实体压顶、少量块缝/缺角表达厚重。先做后墙＋两角塔＋后门；验收后连侧墙，再补住宅中间层。上述均为本项目候选尺寸，需要当前人物及地基验证。
6. 草地成连续庭院斑块，灌木在墙脚、转角和住宅基部成簇；不要用密树遮蔽喷泉、城门或主殿。屋顶暖橙、灰白墙、蓝穹顶作为主次，复用 `TARGET_ARCHITECTURE_PALETTE`，不用全新独立色板破坏既有城群。

## 复用点与接入风险

- `targetNewCityMain`：现屋体/屋顶/白框窗、真实 archWall、rearCourt 支撑采样、footprints 与释放句柄；修改住宅计划前保留稳定 ID。
- `targetNewCityPlacement`：唯一径向城群刚性变换来源。
- `targetCityDetailCandidate`：实际 `newLocalSurface`、surveyed 步道与桥接、公有面 footprints，适合在公有通道确定后加入围墙保护检查。生产旧 stair 工厂只保留名字以 `new-city-stair-house-` 开头的孩子；不要往该组加新墙后又被 caller 静默移除。
- `targetNewCityStairs`：已有九点/密网地基、真实三角 public solid intersection、住宅链接规则，可复用约束模式；旧 authored route 不是最终 surveyed 路线，不能仅据它避让新城墙。
- `newCityPublicSupport`：当前 publicName 为名称白名单，新建绕泉路或门道若名称不同，需要明确注册；同时喷泉池不可加入可步行支撑。
- `targetStreetDressing.protectRoutes`：最终布局再跑植被避路，不能只在旧路线注册前调用一次。
- 避免拷贝 `integratedFrontGate` 作为新城墙：那是港口与水门专用坐标、海拔、旧布局，简单复用整组会错位。

## 来源分层

**作者/算法作者已陈述，沿用既有研究：** [WFC 原作者仓库](https://github.com/mxgmn/WaveFunctionCollapse)说明局部约束传播及应用；[Oskar 2021 双网格原帖](https://x.com/OskSta/status/1448248658865049605)区分玩法与表现网格。详见本项目 `OSKAR_GAME_SYSTEMS_DEEP_STUDY.md`、`OSKAR_DEEP_RESEARCH_STATUS.md` 的覆盖范围。这里没有新增完整视频观看，也没有作者私有引擎源码。

**画面观察：** 本次用户目标图的后院喷泉、外围墙、转角方塔、密疏街区与前方开放广场。

**项目推断：** 本次先手工确定环院和门洞，约束后再接模块；WFC 不是把固定门道/主轴堵住后再“随机修复”的办法。给定数值是工程候选，不称 Oskar 官方尺寸。

**待验证：** 两侧/后方候选墙线地基、喷泉院落与主殿的真实可达性、运行时遮挡和整场性能。此前守军 `mainHallReachable=false` 尚在，不得因加了门洞就改称整城连通。

## 最小验收

- 对新墙基以≤.5 world 步距、墙宽两侧和中心采实际支撑；遇缺失不得默默填高裙。墙/屋与 final public 面、实际车辆扫掠做碰撞检查。
- 由主殿后门，经两侧绕池，再到后门，各以角色宽度采多条真实面射线；水池内不应返回可步行地面。
- 喷泉中心、池半径、原雕像/木马/铁路锚点建立几何不变量；支持开启/关闭本次模块并正确释放私有材质/几何。
- 同一生产配置，俯视、正视、木马侧视、后院四视角；正午与傍晚检查墙厚、地基、喷泉可见性。CPU 通过不替代这组 GPU 验收。
