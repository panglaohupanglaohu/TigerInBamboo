# 苔庭网页：翻身触发与性能修复（2026-09-20）

本轮对象是 `http://localhost:8931/TigerMessenger/` 原 Three.js 游戏，不把浏览器说成 Godot。认可模型、松林、装备和战斗角色保留。

## 已定位的根因

- 鲲胜利翻身原先等待机队离开、终扫、再次离开，同时要求士兵已经抵达圣城。玩家在苔庭收尾看不到。
- 每个士兵采样地面时递归搜索整个场景中的鲲；鲲升空后连静止岸地缓存也失效。
- 地面采样逐个扫描网格全部三角形，没有空间索引。
- 罗马士兵刚体部件关闭了视锥裁剪，画外圣城驻军仍逐件绘制。
- 性能面板误读后处理最后一道的1次提交，且平均帧时忽略超过250毫秒的慢帧。

## 性能实现与实测

1. 固定地形和移动鲲背分开查询；仅固定地形缓存。鲲背按当前变换持续采样。
2. 为刚体地形建立局部三角形AABB树；旋转和位移只转换射线。顶点版本变化重建索引，复杂材质组、蒙皮、实例、自定义raycast等回退原查询。
3. 恢复刚体罗马装备/士兵/梯子的正常视锥裁剪，保留动画与阴影。实例和蒙皮不套用此策略。
4. 整帧统计全部渲染步骤；活动慢帧计入均值。避免把最终全屏三角形的次数当作战场次数。

同一冻结帧，绘制7,581→4,755，减少37.3%，两图像素差0。60帧CPU采样中groundHeightAt累计11,839.62→67.60毫秒。地面最近命中1,906项对照通过，误差0，包含移动/非均匀缩放、单双面、索引/非索引、材质组/范围与缓存版本。

自动性能场景是1100×850、DPR1、真实8931场景，使用诊断剧情/舰队位置进入战斗；软件GPU下平均帧时437.7→359.9毫秒。软件GPU数值不能冒充用户硬件FPS。默认硬件Chrome路径180秒未完成初始化，已关闭，不承诺60FPS。
