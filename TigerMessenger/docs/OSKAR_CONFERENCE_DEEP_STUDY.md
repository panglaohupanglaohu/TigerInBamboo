## 可靠技术支点

EPC 既有官方说明支持“手工模块与WFC组合岛屿”；Organic 既有官方说明列出 MC 与 WFC。它们不能单独证明模块数量、具体网格松弛公式、植被实现或云算法。本轮没有获得能进一步确认这些细节的讲义。

独立核查了 WFC 算法作者仓库。其 README 描述观测、传播和矛盾，并专门记录 Bad North 使用偏向保持已生成区域可导航的启发式。这是**附加策略**，不等于局部邻接本身保证全局连通。该仓库也提醒有些规则虽容易满足，却不足以形成丰富的全局结构。[算法作者资料](https://github.com/mxgmn/WaveFunctionCollapse)

本轮实际读到 `Model.cs` 的候选集合、支持计数、传播栈和带权熵缓存：选定状态后禁止其他状态，失去相邻支持的状态继续被禁止。当前实现有 Entropy/MRV/Scanline 选择，并接受seed与迭代上限。注意 `Run` 达到有限limit也可能返回true；项目移植时应额外检查是否所有单元已定值，不能把该返回值直接解释为完整生成。**这是 Gumin 开源实现，不是 Oskar 私有源码。**[Model.cs](https://raw.githubusercontent.com/mxgmn/WaveFunctionCollapse/master/Model.cs)

本轮另读 `SimpleTiledModel.cs` 的前部：从XML读取模块、权重与子集，按对称类型展开旋转/镜像。它说明“模块原型”和“有朝向的候选状态”应区别管理；并不证明 Bad North 使用相同文件格式。[SimpleTiledModel.cs](https://raw.githubusercontent.com/mxgmn/WaveFunctionCollapse/master/SimpleTiledModel.cs)

## 给 TigerMessenger 的工程方案（顾问设计，非作者架构复刻）

### 1. 明确三层输入

- **场景约束层**：球面局部坐标、铁路扫掠体、港口上城路线、城基及门洞固定。先形成不可占据区域和必须连通的路径图。
- **模块语义层**：每块记录海陆、台面高程、崖壁朝向、允许通道出口与最低宽度。可旋转状态由原型生成；禁止把海蚀底脚直接接到草坡顶端。
- **表现层**：将求解结果变成手工几何、MC/MT表面或混合资产。平滑、岩色、草、树和云分别处理；每一层都读取同一最终变换和最终地表。

这三层能让“模块合法”与“玩家能走”和“视觉好看”分别验收。不能用shader描线模拟缺失的岩台，也不能用雾隐藏断面。

### 2. 小范围横向拓扑试验

既有研究快照中的海柱求解是6个纵向角色、12模块、3条合法链；之后虽加入了独立海蚀几何helper，这并不自动成为横向WFC。本轮没有重新审计全部最新代码，以上是研究历史，不冒充当前全库状态。

下一次升级先做一个离线试验块：三个横向单元、两个高度带，包含海水、湿脚、海崖、岩肩、鞍部、碎顶。每条共享边同时核对几何边界和语义。用穷举或小seed集输出所有不同拓扑，让美术先选出可读的组合，再扩到大区域。保留现有已认可岩体，试验未通过不替换主场景。

### 3. 解算结果必须带失败原因

建议返回 `solved / contradiction / budget_exhausted`，另附未定单元数、删减候选数、传播次数、seed、模块版本、首个矛盾位置。不能用一颗随机孤柱填补所有失败；交通邻域失败时恢复上一个合法结果。固定单元在求解初始化阶段就锁定，避免先放山再删除侵轨物件。

### 4. 连通与形变是两道门

模块连接通过后，基于真实出口图跑港口—城门—步桥可达性；网格形变后再次测通行宽度和车辆净空。球面上每个单元都用局部法线，跨单元比较前统一到相同坐标系。使用界面误差和最大可接受位移限制形变，避免统一冻结导致细长尖刺，也避免无约束平滑侵入固定建筑。

### 5. 植被、云与配色的研究边界

本批大会资料不足以复原作者树草shader或云渲染。后续作者公开实验由主代理另做证据核实，不应在本文件中编造归属。项目可把坡度、湿度、岩台承托与禁区作为共同生态场；连续草块和成簇低丛是项目美术方案。云实例应使用最终山面和一致坐标系，必须实际近景可见而非仅统计active。

配色也不能由演讲题目推出一张“官方Oskar色板”。项目沿用户认可的蓝灰岩、灰绿植被及伊斯坦布尔方向，先锁定同光照的明度层级，再比较色彩；具体数值属于项目目标，不署成作者算法。
