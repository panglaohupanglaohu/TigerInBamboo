# 双工坊接手 Guide

适用：场景工坊、学习工坊及本地 Source/候选管线。用户授权每两小时测试优化，持续到用户暂停/取消。2026-11-04 建立；旧四小时窗口已结束，本授权是新的周期工作。任何接手 LLM 从本文件继续，不依赖聊天记忆。

## 接手顺序

1. 读 `../AGENTS.md`、`PROJECT_HANDOFF.md` 最新段、本 Guide、`WORKSHOP_TEST.md`、`WORKSHOP_LOG.md`，学习接入任务再读 `pipelineLearningGuide.md` 与 `pipelineLearningTest.md`。需要项目全局改动时读 PLAN/TODOS/game-progress。
2. `git status --short` 确认并行改动；不能回滚别人未提交文件。原版 `townscaper-web/REACode`、`.workbuddy` 不动，不重复开展其他自动任务的视频学习。
3. 查最新测试目录 summary.json/browser.json。历史 PASS 不能充当本轮 PASS；缺少证据记 NOT_RUN，依赖缺失记 BLOCKED。
4. 执行统一测试入口，按矩阵补测试；选择风险最高的已复现问题修复，重测受影响项，追加日志和交接。不能只写计划。

## 入口与真实架构

- `http://localhost:8931/TigerMessenger/`：默认干净游戏与遥控；不要把编辑菜单再叠回游戏。
- `http://localhost:8931/TigerMessenger/pipeline.html`：场景工坊；顶部切学习工坊，`#learning` 可直达。
- 8931 当前是 `backend.main:app` 的 uvicorn，不是仓库根 http.server。backend/main.py 必须在 frontend `/` 兜底前挂载 `/TigerMessenger`、`/townscaper-web/REACodeRefactoring`、`/REA-agent/gifs`。不要更换域名/端口来“找回”用户存档。
- `src/scene-authoring/studio.js`：配方、撤销链、节点操作、游戏消息接口；`pipeline-model.js`：能力 ID 与参数白名单；scanner：只解析声明 JSON，不 eval。
- `learning-progress.js`：与三视图共用API校验快照，先构造成功再提交；失败保留旧资料并标stale。`learning-cache.js`以独立IndexedDB单槽保存最后成功学习快照，最多1.5MiB，重新校验后供离线重载使用；不访问或清理场景localStorage，不能代替定稿/历史版本存储。
- `learning-workshop.js`：通过同源learning-snapshot API与受限解析器读取原库七文件，不执行原库脚本。学习与场景操作同一recipe，切页保留iframe；60秒内复用，手动刷新更新整份资料。
- `workbench.js`：原编辑器 DOM 迁到父工坊，保留原事件和浅蓝图标栏；`experiment-session.js`：编码、实际 settings、recipe 同步保存/比较/恢复/定稿约束；`store.js`：不可变版本与定稿指针。
- `pipeline-bridge.js`：仅同源父窗口固定消息命令；不能接受任意代码。
- `pipeline-execution.js` 和 tools/scene-authoring/{run_pipeline,candidates}.mjs：仅确定性参数候选，完整配方遇缺失执行器必须拒绝；不是 AI 场景生成器。
- 8933 Source 桥只允许固定游戏 Origin 的 health/requests；8932 是独立 DSH 原型。Source 收件成功不等于 Worker 执行成功。

## 用户场景保护

用户已恢复湖上 Townscaper 建筑群，以此为基准，禁止自动初始化山地或重建场景。所有自动测试使用新 Playwright context，不调用 persistent profile，不碰用户浏览器 localStorage。测试中定稿仅作用测试上下文，不能代表用户验收。几何生成进入隔离候选，不能直接写游戏 World。已定稿版本不得随新版 pipeline 自动改变。

保存三类内容：开发配方、场景实验（编码+实际参数+配方+目标）、固定定稿。版本恢复前必须备份；存储失败不能误报成功；当前实景不同于所选版本时不得定稿。对象/区域锁尚未完整实现，现阶段保护整场几何，不能宣称支持局部锁。

## 每两小时执行协议

1. 查最新聊天、时间、日志和服务身份；不创建重复服务或重复调度。
2. 运行 `python3 TigerMessenger/tools/scene-authoring/test_workshops.py`（仓库根）。浏览器依赖见 TEST 文档。每次生成唯一 UTC 目录。
3. 浏览器测试失败先辨别产品缺陷、断线/资源不足或测试定位错误；保存原始失败，不把失败日志覆盖成成功。修复后新建证据目录。
4. 对照 TEST 矩阵检查脚本未覆盖项；每轮至少补最紧要的缺项或修一个已复现缺陷。没有合理收益则记录“无实现变更”及依据，不能为满足频次重写稳定功能。
5. 实际检查截图，观察和数值验证分别记录。模型/玩法/画面没验证就保留缺口，不以 JEV 或 HTTP200 代替验收。
6. 用 tools/jev/evaluate.py 提交不含凭据/图片/完整聊天的紧凑文本，保存输出或失败；JEV 只辅助分类。
7. 追加 WORKSHOP_LOG：时间、基线、发现、修改文件、命令、结果、证据、残余风险、下一动作。更新 PROJECT_HANDOFF 简要索引。
8. 常规不变状态安静；实质故障、重要完成或需要用户动作才通知。不得自动提交/发布。

## DSH 接手注意

安装在 `~/.local/share/tigermessenger-superagent`，源码 `source-6337fc823ce2`，固定提交6337fc823ce20251c8de8085948165c81aaa701e；旧 prototype 只有.git不可使用。项目内 dsh-local/upstream.patch、manifest、install_extension.py 保留可重放扩展。不得重新 clone/装依赖而覆盖工作。

先 `check_dsh.py --output <独立报告>`，不要输出 dsh.log（有bootstrap认证信息）。最后已验证独立profile零可路由模型，executor暂停，后来原生服务不可达；每次重新诊断，不照抄旧状态。配置模型应通过明确授权的本地配置，不从旧聊天或其他profile拷key。恢复executor前必须识别并排除 DIAGNOSTIC 测试请求；自动测试不提交真实模型任务。

## 自动任务与跨模型

本轮创建 heartbeat `automation-2`，名称“双工坊每两小时测试与优化”，间隔两小时。其他学习与归档automation保持不动。调度由桌面应用执行；Guide和测试脚本不等于系统已实现自动更换LLM。任何模型接手按以上流程继续；额度/凭据等阻塞记录后推进独立事项，不编造运行。用户暂停时用automation_update暂停此ID，取消时删除；不要重新创建副本。

## 场景能力库分类（2026-11-04）
左侧按地形、建筑、水、光、世界、生命、烟火、载具、战斗、基础与工具十个入口组织，默认只展示所选场景层。生命分天气/植被/动物；载具分船/飞行器/车。每层分“场景能力”与默认折叠的“待适配方法”，搜索跨层匹配并展开匹配方法。库原lane/group保存在provenance不改写；分类只是场景用途视图，不代表来源或执行升级。未知记录进入“基础与工具/来源待归类”，不能自动当生成器。capability-library.js集中定义分类及视图；新能力先补归类规则和真实源测试，不再追加无分类长列表。管线生命/烟火/载具节点标父层。撤销移除新增节点时检查选择器与inspector同步。

## 学习进度面板的可读性
进度卡只展开当前批次、摘要、更新时间和三个主来源链接；大批证据入口、历史完成、后续缺口分三组默认折叠。摘要最多三行，完整说明可单独展开；刷新保留三组展开状态，原库所有记录及来源链接仍可访问。不要把持续增长的源链接/任务全文重新铺到首屏。L08验证桌面滚回顶部后资料页签仍在首屏、证据展开可见及刷新保留状态；移动端用单列折叠组。

缓存适配器资源规则：同步IDB open拒绝必须进入与异步失败相同的finish清理，不能留deadline；已超时的version upgrade应abort，迟到成功只关闭连接，不发起事务；读取结果须等transaction complete才发布。可控时钟生命周期测试验证这些条件，不能仅凭界面仍可读就认为没有资源泄露。

## 场景分类必须驱动中央管线（2026-11-05用户再次纠正）
不只对左栏折叠分类：中央有按实际配方顺序编号的场景层导航和分层轨道，生命并列天气/植被/动物、烟火并列火/烟、载具并列船/飞行器/车。连续同层节点归在一条轨道，不能为视觉整齐改写旧配方顺序；若用户显式跨层重排导致同层不连续，则显示多个连续段，保持真实顺序。
选左侧场景层/中央层导航联动当前节点与参数，选中层滚到管线内部顶部，不滚动整页。新能力插在该层最后节点之后，无此层时追加，可撤销；学习工坊加入也用同规则。静态场景槽即使待适配也应直接展示状态，不把船/飞行器/车藏进底层方法。扫描出的底层方法留在折叠方法区，来源扫描另折叠，分类标题显示10类而非全部方法数量。搜索包括层名/子类/原来源字段。
收紧大标题，实景紧接管线，原编辑/版本菜单放在实景之后；顶部两工坊导航保持可达，原浅蓝图标栏和事件保留。管线箭头表示配方顺序，不表示已有生成依赖执行。入口CSS/模块已加scene-layers-r2版本，当前UI不能沿用旧的横向14卡片长队设计。

## 学习媒体预览（2026-11-05用户要求）
视频与笔记采用缩略图卡片：本地learn/thumbs/<帖子ID>.jpg，内容标题取现有title/name/笔记首句/原文，项目主题状态可读，ID作辅助。管线与能力的方法行也必须显示同帖缩略图。learning-video-card.js共用来源URL/缺图/无关联提示；lazy/async图像不算观看学习，不重生成或复制原视频。仅扩展笔记后保留一个原播放入口，不再加同功能播放按钮。缩略图不是模型改造结果或执行验收。

## 按钮职责与当前入口（2026-11-05）
实时能力只由“应用实时能力”执行；移除相同操作的“当前实验”。“对照原始参数”仅用于参数对照，随后可再次应用管线。进入编辑/游玩检验放在实景上方，移除版本区重复编辑入口及迁入编辑器的“返回玩家视角”。保留原建造模式开关，它控制建造交互状态。
“保存场景草稿”是完整实验的唯一保存入口，通过 tm.experiment.save-current 调用共用 session.save：保存当前实际 World、实际参数、配方与目标并做编码检查，绝不先应用配方覆盖手工调整。移除“保存实验快照”和“验证并保存当前”；编码检查通过仍不代表通行/性能验收。“保存管线配方”和原“保存菜单”范围不同，分别保留；“撤销管线/重做管线”与“撤销建造/重做建造”明确独立历史。
“草稿与定稿”打开并定位本页已有版本面板，不能另开 dev 游戏冒充版本入口。未连接时保存明确失败，不应产生空版本。S15隔离浏览器验证手调昼夜与配方不同仍按实际状态保存、只新增一个版本、重复按钮消失及本页版本定位；这不代表用户场景定稿或全部编辑操作验收。

草稿存储失败的验收边界：S16先在隔离浏览器经版本面板建立测试定稿，再只在游戏iframe中对版本键注入配额错误，验证失败提示、World/实际参数/配方及所有既有存储不变，恢复后显式重试仅新增一版。真实用户空间不足时不得自动清理旧版本、覆盖定稿或清空浏览器；提供导出/用户主动处理空间后重试。测试不能把编码检查成功显示成保存成功。

## 固定版本运行入口的验收边界
版本面板打开的是同源浏览器存档中的明确sceneVersion ID，游戏应读取该条World与实际settings，优先于本机工作区；缺失ID必须显示“固定版本加载失败”并明确当前工作区回退，不得标为固定版本成功。新窗口测试只能使用同一隔离context，不访问用户profile。S17在工作区写入不同有效场景模式编码作为标记，核对真实按钮、新游戏实际World/settings、缺失ID提示及版本记录不变，finally还原测试工作区；不是新造地形。
当前固定范围是场景数据与参数。代码、资源与依赖尚未封成不可变发布包，sceneVersion链接还依赖同源浏览器存储，不能宣称跨设备可用或已冻结代码/资源。模块更新后的真正重现性、用户通行/性能和玩法验收分别保留缺口。

## 启动卡顿的取证与修复顺序
先执行整套回归，再单独运行 tools/scene-authoring/profile_workshop_startup.mjs。保留原始CPU profile与汇总；通过CDP NavigationStart单调时间对齐父文档最长五项longtask，查看longTaskStacks，而不只看全程累计热点。累计云层采样时间高不代表它是最长连续阻塞；CPU采样有开销，CAPTURED不代表性能通过。
当前取证指向多个同步构建阶段：水晶V9/V10收尾、山体study、湖岸所有权/花园、湖沼构建等。优化优先拆分已定位的同步步骤、保留调用顺序并验证完整几何/材质/参数一致性，不能为缩短启动直接删模型、关掉已认可场景或改用户湖上建筑。先确认相关世界模块所有权与未提交改动；缺少保真证据时继续补证而非盲改生成算法。旧学习缓存/刷新超时和启动切页卡顿的根因分别保持状态，不能自动合并。

## 实景选择物件（2026-11-06，替代悬铃树专用按钮区）
主入口是实景上方“场景对象 → 在实景中选择物件”。开启后在画布单击实体表面，按当前相机射线的最近有效命中选择，拖动不选择；保持当前镜头并画局部有向高亮，右侧显示实际名称/类型。“定位选中对象”才重新取景，“返回整个场景”取消选择。名称目录默认折叠，按运行时记录动态生成并可搜索，不再有固定四树按钮或悬铃树专用标题。
合批植物按材质mesh保留原plant的顶点区间，face.a命中回溯真实悬铃树/柏树/蜀葵对象；目录来自当前植物集合而不是前端硬编码数量。其他可见mesh只读注册为运行时网格；InstancedMesh按instanceId区分且边界带实例矩阵。没有语义拆分的建筑/地形仍显示“体素合并网格（只读）”，不能冒充已分离单栋建筑。运行时UUID型ID不是跨版本稳定编辑ID。
选择模式阻止体素笔刷，暂停整场景apply/原始参数对照并隐藏建造面板；编辑/游玩先退出对象选择。当前只接选择、高亮和定位，移动/旋转/造型/叶色及对象修改保存尚未接通，选择不写配方/存档或定稿，不以网格只读选择冒充完整对象编辑器。
重要：植物几何已合批，逻辑Group无渲染mesh。边界在工厂合批前以局部mesh数据保留；bindBatchedObjectOwners用WeakMap保存合批来源区间而不改变任何原几何/材质。后续对象变换仍需基线buffer/候选、撤销、版本恢复和定稿契约，不能只移动空Group。其他物件的语义归属逐类接入，点击只能证明命中对象，不能证明独立编辑能力。
