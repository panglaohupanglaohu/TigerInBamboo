# 原作保真重构：当前执行依据

用户已明确纠正：原有模型经过认真设计，应使用 Blender 整理、优化和重构这些原作，不能换成另一套新设计。本文件取代前期指南中“用新模型逐步替换世界”的方向。

## 原作与前期实验

原作来源是 src/assets、src/world、src/player、程序生成模块和它们的实际调用参数。前期 `art/TigerMessenger-kit.blend`、`assets/kit` 与紧凑 Godot 关卡保留为历史实验，停止扩展；它们不代表原作优化成果。新邮筒已从 Web 主线移除。

## 当前状态的准确含义

- `assets/models/originals/source-ledger.json`：全部 src JS 的依赖、导出入口、代码哈希和阅读状态。自动索引不等于完整人工审计。
- `assets/models/originals/代码覆盖清单.md`：95 个直接创建几何的文件；还需按依赖追踪目录之外的组合件和变体。
- `assets/models/originals/catalog.json`：现有地图资产目录的 72 项定义。
- `*.source.json`：调用原模型工厂得到的原始顶点、索引、法线、UV、材质、贴图、层级与运行时引用快照。随机项使用固定种子，不能代表所有种子和所有场景变体。
- `*.blend`：从这些数据导入的原作编辑档案。不是重设计，也不等于已经完成优化。
- `*.import-report.json`：节点数量、顶点导入误差和未支持项目。

完整世界中的圣城、地形、湖沼和其他大型组装体不能仅靠 72 项目录覆盖。代码阅读与场景实例覆盖要继续补齐，不能把目录导入率当成全模型完成率。

## Blender 导入边界

坐标由 Three.js Y 向上转为 Blender Z 向上，同时转换节点局部变换；不改变原作比例。保留原有拆件层级、基础色和招牌贴图，原始数据还会嵌入 .blend 内的 SOURCE_ORIGINAL.json 文本。

原有飞白描边是顶点外扩加片元丢弃的运行时着色器，不能直接等同于一层黑网格。当前 Blender 档案保留描边网格但隐藏预览，避免共面黑壳覆盖模型。Toon/PBR、透明、粒子、实例和程序动画的表现需要后续单独适配，导入报告必须明确列出缺口。原始 Web 仍是视觉判断基准。

## 每个模型的推进顺序

1. 阅读工厂、材质、动画驱动、场景调用和可编辑参数，记录不可改动的设计特征。
2. 保存原始快照与固定机位截图。
3. 在 Blender 副本中处理重复数据、法线、拓扑、UV、碰撞代理和层级；不全局盲目减面，不合并动画关节，不改颜色和比例。
4. 比较顶点/三角形、包围盒、材质与 UV；凡改变可见表面的修改必须有同机位前后对照。
5. 导出并接回原有模型的调用位置，验证动画、文字编辑、WFC 拼装和实际碰撞。
6. 完成后才标记“已回接/已验收”。

书店的保留项已从代码确认：砖红主体、维多利亚八角凸窗、奶白柱与三角门廊、两级台阶、土坡连接、黑底金边斜招牌与可编辑两行店名。其原作 Blender 档案为 `assets/models/originals/bookshop.blend`。

## 工具

在 TigerMessenger 目录执行：

```sh
python3 tools/originals/audit_sources.py
node tools/originals/capture.mjs bookshop
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/originals/import_blender.py -- bookshop
```

capture 依赖仓库已有 Playwright、本机 Chrome 和 8765 端口的仓库根目录 HTTP 服务。原始 .source.json 已存在时保留原文件，避免把后来修改覆盖为“原作”。import_all.py 跳过已有 .blend，保护编辑中的档案。单项 import_blender.py 会重建该项导入文件，手工修改前应另存工作副本。
