# 旧港落地与岸线接回：执行方案

本方案来自 `tools/pipeline/audit_old_harbor_grade.mjs` 对实际 common-frame 游戏的测量；不是已合入结果。报告：`artifacts/pipeline/citadel-old-harbor-grade/report.json`。

## 已确认

当前 pier-deck 四角高出解析海面 19.229、19.985、21.523、22.270 米。原初始化函数主动将港口抬到山顶，渔船再单独放回海面，因此码头与船分离是结构性结果。

只降港口、继续使用城堡统一 up，会使 7.2 米长码头两端离水差约 3 米。港口必须按自己所在地的径向 up 放平，保留原码头 X 方向投影后的朝向。不能通过拉长桩脚或抬全球海水修复。

## 已淘汰的早期测量候选

在城堡共同基准局部坐标 `[-72,-12.719889484735347,44]` 放置原港口组，采用报告中的完整 matrix。四角解析水面净高均 0.7 米；原主山四角竖直探测没有命中。`[-74,-13.194327794541039,52]` 也空出，但距旧城更远，保留为备选。`[-80,-15.949105627451843,58]` 被原地形侵入约 5.5–8.7 米，拒绝。

这里只验证四角和解析水位，尚未验证实际细分海面、波浪、码头全覆盖、船头转弯或完整通路，不应据此直接切默认。

## 当前构建期候选（2026-09-13）

实际入口：`?citadelCommonFrame=1&citadelOldHarbor=1`。原先只测主山四角不足：旧西侧山翼和海岸封口挡住码头与船，早期 [-72,...,44] 被淘汰。扩展 9 个位置、加入西山/封口与船槽代理探点后，选用 `[-60,-7.873131251723464,52]`，港口 X 方向取原港 -Z 投影到自身切面，让船朝向开阔海湾。详见 `expanded-clearance.json` 与 `seaward-clearance.json`；所选位置 8 个点未命中岸壁，实际机位到码头/船的射线首先命中原港或原船，截图可见。

`oldHarborOceanGrade.js` 已在 snapOldHarborToSeaCove 构建期接入此候选；四角解析净高 0.7 米，原船基点净高 0.1 米，中心到码头中心 9.482 米。loadTraffic 原来会在场景加载后把该船从旧港解出并强制送到远处巡航 u=.08（约离码头 176 米），候选模式保留该原船在泊位；其余海面巡逻船不变。实际 F 键上下船通过，原对象保留、两组搬运兵保留。但原物流控制器目前并未连接，不能宣称自动装满出航/返回已通过。

同工程 Godot：`--common-frame --old-harbor-grade`，原港 GLB 用同一份实际运行快照，old_harbor_grade_adapter 替换可见原港，确认一个甲板、一个原战船、世界矩阵一致。这里只回接模型和位置，原生物流与岸边台阶仍未完成；默认布局未切换。

## 下一批实施顺序

1. 在 `snapOldHarborToSeaCove` 构建期加入共同基准候选的新港口 pose，发生在 Navona/兵阵/boatRide 建立引用之前；原港组、起重机、搬运兵、箱货、大树及松树使用原对象。
2. 重新计算渔船真实停泊海面和船与栈桥的距离，核对 boatRide 的停泊矩阵、巡回路径及返回状态；不能只挪可见网格。
3. 世界碰撞点用旧港逆矩阵→新港矩阵变换，验证原物件可交互；确认后续布置不再次覆盖 pose。
4. 从新码头后沿接防御岸门/转折阶梯到旧城原既有岸边入口。沿山势布置台阶，不横穿旧建筑；以真实旧城入口世界矩阵确定上端，不猜测作者坐标。原城门→旋梯→顶层路线保留。
5. 检查码头、台阶全宽、树根平台和船体的地形覆盖；确有侵入才局部让出山体。渔船保持原模型和原运行引用。
6. 同一游戏页面导出最终港口几何/pose/新连接路线，并同步 Godot，同场景检查携行士兵登岸上楼和返回。保留默认旧版本，直到候选完整通过。
7. 同一相机与已认可目标图对照，再决定是否开启共同基准默认布局；不把测量报告当作新港已交付。
