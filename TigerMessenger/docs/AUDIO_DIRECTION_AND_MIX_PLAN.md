# TigerMessenger 场景音乐与克制音效方案

更新：2026-09-10。目标：所在场景的音乐清楚，重要动作听得见，苔庭仍有安静的空间。

## 当前状态

本文件是音效设计及接入标准。`assets/audio/audio-plan.v1.json` 列出 12 类、22 个候选声音及初始限流参数；目前没有生成声音文件，也没有把这些新增音效接入游戏。现有音乐保留。Web 音乐归属修复已落地：13 项异步逻辑检查、真实 8931 页面 11 项诊断检查通过，页面无异常。测试使用真实 HTMLAudio 音乐文件、媒体时钟与上下车回调，诊断控制位置和战斗意图；不等于完整自然乘车或听感验收。Godot 尚未同步。当前切换先停止旧曲再淡入新曲；下文交叉淡化属于后续听感优化目标。

验证记录：`artifacts/pipeline/bgm-scene-web/2026-09-09T21-38-24.362Z/report.json`。

## 音乐归属

- 同一时刻只有一个主音乐归属。允许切换时短暂交叉淡化，不允许几个场景长期叠放。
- 玩家乘坐有轨电车时，以电车音乐为主。远处苔庭的战斗可以继续运行，但不能抢占或叠加电车音乐。
- 下车后根据玩家实际所在区域、距离和正在发生的剧情重新选择。不能简单恢复上车之前所有歌曲。
- 苔庭内才允许相应战斗音乐取得归属；离开听觉范围后退出。场景已经加载、战斗仍在更新，都不等于玩家应该听到它。
- 异步播放、旧淡出回调不能把已经失去归属的音乐重新打开。保留浏览器首次操作解锁、静音和音量设置。
- 切换淡化约 0.8–1.5 秒作为试听起点，边界用滞回避免来回切歌；这不是行业统一数值。

## 第一批音效：共享声音家族，少而清楚

| 对象 | 声音与触发 | 克制方式 |
| --- | --- | --- |
| 短剑兵 | 实际挥击的一声短促破风；命中按木盾、护甲材质反馈 | 不给每次摆臂配音，受击反馈优先于挥空 |
| 长矛兵 | 实际出手的木杆、空气声；命中共用材质声音 | 不把长矛做成金属长鸣，飞行全程不持续鸣叫 |
| 弓箭兵 | 放箭瞬间短弓弦声，三个轻微变化 | 齐射只保留近处代表声音，不让每根箭占一个持续声源 |
| 重甲兵 | 实际能量放射的短电击声；护甲受击 | 不夹带音乐或过长爆炸尾音 |
| bubblePod、scoutAircraft、合并后的 gatePod | 共用轻型悬浮声音家族，用轻微音高与运动包络区分 | 优先听所乘或最近的一艘，不按每个型号编号新增循环 |
| gateHauler、SOCCO 运兵艇 | 共用重型引擎声音家族，随接近和离开变化 | 与轻型引擎合计最多两个循环；舱门声留到第二批按需增加 |
| 飞行器火炮 | 发射时清楚、短促的重音 | 最多一个强发射声同时出现，不连续轰鸣覆盖整个战场 |
| 莫比斯吸取 | 启动提示一次，随后一个舰队级吸取循环 | 不给每架飞机各叠一层吸取；停止吸取即收尾 |
| 鲲鲸吞 | 明确起止的有机吸气声，成为这个动作的听觉重点 | 只在能力真正触发时播放，避免永久低频轰鸣 |

第一批不增加成群脚步、每个盾牌的晃动声、士兵喊话或新的界面提示音。松林与静池可以安静；不为苔庭自动增加瀑布环境声。

## 苔庭伏击的听觉节奏

1. 平静：所在区域音乐、轻薄自然环境；留出空白。
2. 登陆：短暂出现运兵艇和少量动作声，随后收住。
3. 隐藏：士兵藏入松林后保持安静，不能反复播放入场或武器声。
4. 发现：舰队实际发现鲲、开始吸取时，启动提示只响一次。
5. 伏击：近处弓弦、武器命中和能量攻击有层次地出现。以真实事件触发，不能每帧重复播放。
6. 鲲反抗：鲸吞获得短暂重点；可以尝试将音乐和低优先级引擎降低 3–5 dB，再平滑恢复，须试听避免音量抽动。
7. 结束：吸取和引擎循环随状态停止，区域音乐按剧情回归；重置不会留下旧声源。

## 初始混音与数量预算

以下均是本项目的保守试验值，需要实际试听调整，不是业界统一标准。

| 类别 | 同时发声上限 |
| --- | ---: |
| 主音乐 | 1，交叉淡化期间最多 2 |
| 近处武器、命中与能力等前景音效 | 6 |
| 飞行器引擎循环 | 2 |
| 舰队吸取循环 | 1 |
| 环境底声 | 1 |
| 已有界面音 | 2 |
| 非音乐总量 | 12 |

类别、事件和总量上限同时生效。高优先级的玩家危险、关键能力和近处命中可以挤掉远处引擎或普通挥击；远处低优先级事件可以不播放。不能把所有被拒绝声音排队补播。

以玩家身体位置决定区域归属和远近，以视角方向辅助左右定位，避免绕球镜头意外听到另一片区域。每个世界声音必须提供来源位置。距离值按游戏真实尺度试听，不直接照搬现实米数。短声音用少量变体避免机械重复，但不随机到改变武器身份。

## 工程接入

Web 使用统一的音乐、动作、载具、环境及界面音量分组。复用已有解锁和静音入口；解码后的声音缓存复用。事件提交声音类型、来源编号、位置和战斗状态；管理器执行距离、冷却、优先级、类别与总量限制。循环按状态进入启动、退出停止，销毁、切场景及重置必须释放。声音只观察战斗事件，不能反过来改变空降或伏击规则。

Godot 后续使用对应音频总线与空间播放器，以同一声音清单和触发语义接入。单节点的 `max_polyphony` 不是全游戏预算，需要全局管理。隐藏一个节点不会自动让其声音停止。浏览器导出还要核对播放模式：Godot 的 Sample 模式不支持音频总线效果，不能把原生版的效果设置直接当成 Web 已生效。

## 交付顺序与验收

- 先修复并验证音乐归属：苔庭战斗中上电车、驶离、远处下车、返回，以及迟到的播放结果。区分逻辑检测与实际听感。
- 再从弓弦、木盾命中、轻型悬浮、吸取启动、鲲鲸吞各取一个样本试听，确认整体声音语言后才补齐 22 个候选文件。
- 首次接入只覆盖一个实际伏击回合。音效必须对应真的放箭、命中、吸取和能力状态，不能只在调试按钮里可听。
- 在相同音乐音量下比较关闭/开启音效的实际战斗，分别用耳机和电脑扬声器听。既要辨认动作，也要能继续感受音乐与苔庭的安静。
- 用大量士兵和飞行器验证声源峰值受限；检查离开、死亡、撤军和重置后无残留循环。自动化统计通过不代表听感已验收。
- 清单分别记录：候选生成、试听通过、Web 接入、Godot 接入、真实战斗验收。禁止用已导出代替已交付。

## 判断依据

[Wwise 官方：优先级建议](https://www.audiokinetic.com/fr/public-library/2024.1.8_8898/?id=priority_tips_and_best_practices&source=Help)说明声音优先级与音乐实例限制的注意点；因此这里用类别及优先级管理，并给音乐切换留出交叉淡化余量。

[FMOD 官方支持：实例上限与拒绝重复实例](https://qa.fmod.com/t/parameter-sheet-correct-method-to-call/22936/7)及[实例限制机制](https://qa.fmod.com/t/how-do-max-instances-work/13576)支持为重复、循环声音设置上限。上述 12 声源预算与具体音量是本游戏的设计选择。

[Godot 官方：音频总线](https://docs.godotengine.org/en/stable/tutorials/audio/audio_buses.html)与[空间音频播放器](https://docs.godotengine.org/en/stable/classes/class_audiostreamplayer3d.html)提供分组、空间衰减与平台限制的工程依据。采用这些原则不要求本项目安装 Wwise 或 FMOD。
