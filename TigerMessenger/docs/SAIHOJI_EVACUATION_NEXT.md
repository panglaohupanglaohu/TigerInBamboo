# 苔庭驻军转乘现有战船：下一步候选

状态更新：乘员身份接口及配对预约模块已实现，真实苔庭登船路径尚未通过，未启用自动接返。现有干地候选实测 15 人中 0 人通过：电车原下车点附近 8m 无干地；不能继续把该点当步行终点，更不能用裸球面或超时瞬移兜底。

## 容量与可行性

`assets/warshipV6.js` 有 26 个船员展示位；`world/warshipCrewContinuity.js` 明确限定 **25 个战斗/乘客位（0–24）+ 1 个留守船员位（25）**，不能把第 26 位拿给撤离士兵。伤员每人也占一位，护送者另占一位；尚未登船的原乘员必须保留预约，不能按当前空着的模型算余量。

若现场确为三艘可用波次船、原名单 25+25+9，则总乘客容量 75，原乘员全生还时余 16 位，足够接回 15 名驻军；首选第三船接返，前两船保持原身份。必须读取实际 `waves`，不能假定第三船必然存在。只有两艘且原 50 人生还时没有空位：让现有船完成一次真实往返接第二批，第一批在安全岸上候船；全部人员离岛前不放行翻身。死亡释放名册占位，倒地伤员不释放。

## 最小接口改动

1. **乘员名册：扩展 `bindWarshipCohort`，不要重绑整船。** 增加按 UID 的 `reservePassenger(actor)` / `releaseReservation(uid)` / `commitBoarding(uid, proof)`；按 seat 映射 actor、装备和 manifest。目前 `manifest.push(shipkeeper)` 在 9 人船中数组下标为 9、实际 seat 为 25，直接 `soldiers.push` 会把第十人映射到船长条目；必须先改成固定座位表或 Map。新增人保留 UID、role、伤势、盾损与装备引用；一 UID 只能属于一艘船的有效预约。旧 garrison 记录保留来源身份，但完成接返后停止独立移动/重复战斗更新。新乘员在真正到座前不能置 `embarked` 或隐藏。

2. **真实上船队列：接入现有 `createBoardingGate`。** `saihojiPhalanx.js` 目前 `boardT` 到时批量 `crewContinuity.embark()`，只是身份/显示切换，没有逐人登船。候选应改为 `dry-approach → queue → gangplank → deck → seat`；健康者可用 `romanShipCarryPose` 收武器，但该接口不负责搬伤员。每船一条队列，过板期间锁停船；`boardingGate` 本身允许多 occupant，需要队列控制单人或一个护送组合准入。排队未完成、伤员未落位、过板占用、跳板未收起均禁止返航；门的 `canSail` 不能单独替代乘客清点。

3. **连接到实测岸点，不连接 tramHome。** 使用 `warshipWaterRoutes.dock()` 的 `shorePoint`、跳板铰链和甲板支持，验证“驻军当前位置→干地集合点→板→舱内座位”连续路线。`citadel/boardingRoute.js` 依赖城堡坐标、码头数据和已量测泊位，不能直接当苔庭已验证路线；抽取支持采样后重新验证三艘船的泊位、船间距与进出航线。补给波次目前按 `index % SHIP_COUNT` 复用两条导航，第三船的独立泊位不能凭余座推定可用。

4. **伤员接返：新增受保护的 assisted boarding 状态。** 当前 `setStage` / `embark` 明确拒绝 `downed`，不能通过清空 downed/dead 绕过。复用 `garrisonRetreat.patient / escortedBy` 身份配对，新增搬运和甲板安置状态：护送者和伤员一起预约两个位置；原伤员对象保持可见并连续移动，实际跨板后在船上有受伤姿态。现有尾随 .65m 的点位移动不是搬运动作验收；原板宽 .34m，不应并排双人通行，必须验证单列搀扶/背负的模型净空。船员展示 API 只有 embarked/weaponStored 与麻醉坐姿，不能把伤员自动替换成健康划桨者；需保留受伤演员在获验的座位/甲板支撑点，并关闭该位重复船员模型。护送者受伤/死亡时重新分配，原伤员位置不跳变。

## 接入闸门

先以同一真实场景候选验证：25+25+9 船组接 15 人；容量不足拒绝/真实往返；健康者、倒地者、护送者死亡；途中撤销/重试；所有 UID 无重复、伤势不变、船长位未占用。逐帧检查干地/跳板/甲板支撑、步长连续、身体装备净空、船停稳、同一角色模型与船员显示无重影。完成后才让离岛门认可 `commitBoarding` 的物理凭据，并同时要求船体清出鲲覆盖区。没有合格路线或伤员安置点时报告阻塞，不能先隐藏角色来通过翻身门。


## 已实现接口的边界（仍不代表物理接返已接入）

乘员模块已有固定座位、预约/回滚、真实演员查询、登船凭据提交和幂等 `dispose()`；停用后所有旧 API 拒绝操作，不能抢回新控制器的名额。任务永久移除/reset 必须先 dispose，以释放身份登记。

**辅助伤员下船尚未实现。** `setStage(seat, 'ashore')` 仍拒绝 `downed`；旧批量 `disembark()` 也不会改变已辅助登船的伤员。不能清除伤势或调用普通下船来绕过，后续必须新增验证过的“船上伤员位置→甲板→跳板→干地”护送动作及提交接口。在该路径完成前，伤员保持原演员、原伤势和船上归属，不能宣称返岸安置完成。

`manifest` 是 26 位稀疏数组，船长始终位于 25。已有仓库消费者使用 `filter` 或读取明确占用索引，未找到对稀疏项不设防的 `for...of entry` 消费；后续新增循环须 `if (!entry) continue`，或先 `filter(Boolean)`。
