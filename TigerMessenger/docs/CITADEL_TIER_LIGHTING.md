# 高山圣城分层布光接入

## 当前状态（2026-09-13）

仅启用已有 common-frame + old-harbor 候选时生效。原游戏入口仍是 8931，不跳转 Godot；同工程的 citadel_world 场景在 --common-frame --old-harbor-grade 下同步。完整场景仍未达到认可目标。

## 本轮修改

- 旧城原网页只有 1 盏真实点光，Godot 原预览为 4 盏且集中下城。候选统一为旧城 3 盏、新城 3 盏，不新增阴影灯。
- 旧城按照下城、中层、上层三处聚落布光；第二轮抬高中上层聚合光源，避免贴近屋顶形成局部白斑。
- 新城保留主门与广场暖光，将原大范围 PointLight 冷填光改为岸门暖光，适当收敛广场热点。场景原有冷色环境照明继续保留。
- Godot 旧灯组存档朝向落后于旧城旋转，直接使用旧灯组局部坐标曾造成约 7–11m 偏差。现使用原游戏导出的实际世界灯位，实测最大误差 0.0000171m。
- 不改变建筑几何、角色、行军路线和战斗对象引用；既有窗光材质色相及白天恢复逻辑保留。

## 源与同步

- Web 源：src/world/citadel/tierLighting.js；由 messengerIsland 在旧港候选建立后接入。运行时跟随 P.timeOfDay。
- 原始旧灯组 update 继续驱动原灯头及光晕，候选在其后更新三盏聚合照明；新灯组同样保留已有灯头亮暗更新。
- tools/pipeline/test_city_tier_lighting.mjs 使用同一机位，先以模块拦截禁用新布光得到实际改前画面，再正常加载得到改后；输出 godot/data/citadel-tier-lighting.json。
- Godot citadel_window_lights.gd 在候选中读取该清单，校准各灯能量；--legacy-city-lighting 仅用于重现改前对照。
- Godot 测试与截屏脚本依次启动并退出，不并行打开多个 Godot。

## 验证与限度

- 两端夜间旧城/新城各 3 盏亮灯；白天全部关闭。Godot 1012 项窗光材质状态匹配；默认原窗光循环回归通过。
- Web 原城堡几何前后相同：2225 个 mesh、985584 顶点、198099 个索引项。全世界实际绘制数会随远处动画/可见性略变，因此不以逐帧绘制次数完全相等作为正确性条件。
- 浏览器整场景短测每侧 44 个 rAF 间隔，前后中位数均约 33.3ms、P95 均约 50ms。这不是独立 GPU 耗时，不证明所有设备性能达标；点光从 Web 的 4 盏增到 6 盏确实增加着色工作。
- 本轮几何没有改动，不把布光检查算作重新完成整场战斗/运输测试。

## 后续整体工作

继续目标图中的临水建筑连续层次、真实可落脚的山坡植被、港口装卸/群体战斗接入。灯具可见形体、远景灯窗密度和整体色调还需随最终建筑继续校准。不得将分层照明或单条通路通过作为整体圣城交付。
