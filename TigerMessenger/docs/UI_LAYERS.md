# 界面分层规范（UI Layers）

实现：`src/ui/uiLayers.js`（`main.js` 启动最早调用 `installUiLayers()`）。

## 参考的业界做法

- **玩家 HUD 与开发工具分离**：Unreal 的 Shipping 包去掉控制台 / stat 面板，Unity 的 Development Build 才有调试 UI；发布版只留玩家界面。
- **开发工具集中在一个入口**：引擎编辑器、Dear ImGui 一类的调试菜单都是一个主菜单 / 工具栏，按需打开窗口，不是常驻铺满屏幕。
- **监控（stat fps / profiler）单独开关**：和编辑工具分开，默认关闭。
- **HUD 安全区**：玩家 HUD 固定在屏幕边角，底部操作条始终可见；进入“建造模式”时（模拟城市、Townscaper、各类关卡编辑器），信息面板让位，操作提示不让位。

## 三类

| 类别 | 发布版 | 本地开发 | 成员 |
|---|---|---|---|
| **玩家（提示 · 操控）** | 显示 | 显示 | 任务面板 + 小地图（左上）、罗盘 + 救援主线（右上）、Toast（上中）、操作提示条 + 遥控（下中）、触屏摇杆、交互提示（E / F）、对话（阿狸、公主）、加载进度、开场 |
| **编辑** | 隐藏 | 默认关闭，右下「🛠 编辑」或 F1 打开，一次只开一组 | 见下表 |
| **监控** | 隐藏 | 默认关闭，F2 | 帧率探针 `#tm-perf-probe`、体素 AO 探针、莫西斯湖 / 月亮湖 / 城区实时审计、WFC 失败面板 |

## 规则

1. 新面板必须登记：把它的 id 加进 `EDIT_GROUPS`（某个编辑分组）或 `MONITOR_SELECTORS`；玩家面板加进 `PLAY_SELECTORS` 做记录。未登记的面板视为玩家界面，会出现在发布版。
2. 玩家 HUD 只用这几个区域：左上、右上、上中、下中、屏幕中央的上下文提示。底部操作条 `#controls-dock` 的层级高于所有编辑面板。
3. 构建分组打开时，左上任务栈和右上救援主线让位；操作提示条、罗盘、Toast 不让位。建城工具条和面板抬到操作条上方。
4. 发布判定：非本地域名（GitHub Pages 等）或 `?release=1` 为发布版；`?dev=1` 可在公网临时打开开发工具做评审。
5. 状态（打开的分组、监控开关）存本机 `localStorage`（`tm-ui-layers-v1`）；`?editor=build` 可直接打开某组。
6. 关闭构建分组会自动结束 Townscaper 建造并恢复玩家视角。

## 以后

现在发布版是“隐藏”编辑和监控；它们的代码仍在包里。等编辑期结束，可以在打包时按同一张分组表把编辑模块剔除（tree-shake / 条件导入），进一步减小包体。
