## 一次合改的执行顺序

1. **冻结问题表**：完成岗点、动作、正常战斗及完整路线的缺口检查；发现的问题归入C01—C09，区分已复现与待验证。
2. **统一空间**：集中修改港口—平台—广场—主堡承托、台阶、净空和比例；确定同一份布局、路线与岗位数据。
3. **统一人物逻辑**：在确定的空间上调整分层布岗、巡逻避让、携行/攻击姿态、战斗触发与退出；避免重复刷兵。
4. **统一环境接口**：按最终路线调整绿植、灯具、镜头、音乐和上下船接口；不扩展船模专项。
5. **统一交付**：接入8931原游戏并同步同一Godot工程，重跑五项检查，提供目标/实景整体对照与失败项。代码内部可以按依赖分步修改，但作为一个整合批次验收，不把每次修补另算一轮。

## 统一修改和复验原则

1. 完成岗点、动作及正常战斗入口的缺口检查，把结果直接追加到上述编号，不开启新的局部轮次。
2. 先统一调整地形承托、港口平台/阶梯和路线，再做必要的持械姿态、岗点、群体调度、镜头与灯光修正。
3. Web与Godot使用同一布局/路线描述；保留原资产、角色和战斗身份，不通过隐藏障碍或替换成小模型获得通过。
4. 改完统一重走五种检查；提供目标/实景全景、正常游玩证据和仍失败的编号。全部目标未满足前不计为圣城完成。
