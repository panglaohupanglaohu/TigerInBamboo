# TigerMessenger：优化与工程指南

> 用户已纠正美术方向：保留并重构全部原作，停止扩展新建模型。当前执行依据是 [原作保真重构](原作保真重构.md)。本文的新资产包及紧凑 Godot 内容仅作为前期实验记录。

本轮把原 Web 世界接上了六章救援主线，修复一组球面运动与地形问题，并建立了可编辑的 Blender 资产和可运行的 Godot 工程。故事依据本机 `/Users/panglaohu/Downloads/index.html`：父亲借信使身份，联合阿喀琉斯和奥德休斯争取时间，接回红狐与湖沼之虎。

## 1. 从这里开始验收

| 入口 | 用途 |
|---|---|
| `Start-Web.command` | 完整原有世界 + 本轮优化；浏览器访问本机 8766 端口 |
| `Play-Godot.command` | 导入资源后运行 Godot 救援关卡 |
| `Open-Godot.command` | 打开 Godot 编辑器，按 F6/F5 运行场景/项目 |
| `art/TigerMessenger-kit.blend` | Blender 可编辑模型原文件 |
| `assets/kit/contact-sheet.png` | 模型总览 |

在 Finder 双击这些入口。Web 服务的终端窗口需要保持开启，结束时 Ctrl+C。也可在项目目录执行 `python3 -m http.server 8766 --bind 127.0.0.1`，访问 `http://127.0.0.1:8766/`。不要以 file:// 直接打开 HTML。

### Web 验收顺序

1. 开始游戏后在书店附近出生，右侧出现「家书 · 救援主线」。靠近目标到 9 米以内按 **R**，也可点击面板按钮。
2. 依序经过书店、叹息之门、苔庭、红狐、湖沼之虎、高山圣城。面板显示方向和直线距离；距离不是沿道路的导航长度。
3. 结盟后 **1** 提供 12 秒掩护，**2** 提供 22 秒佯动，共用 35 秒冷却。苔庭剧情自动争取 90 秒。机队吸食状态会真实暂停，已有采食过程转入撤离。
4. 救出后红狐、虎虎随行。**E** 仍用于原来的四封支线委托。WASD 行走，Space 跳跃，F 使用现有载具；湖沼救援和圣城抵达允许乘坐载具交互。
5. 刷新保留章节进度。面板底部「重新开始家书主线」只删除主线进度，不清空地图编辑与画面设置。
6. 山坡和被轨道切削的区域检查脚底是否贴地；按住跳跃不应连续自动起跳；切出窗口后松开按键再返回，不应继续自行移动。

Web 存储键为 `tm.rescue.campaign.v1`，保存章节与救援标志，不是完整世界快照。刷新后回到出生区，已救角色重新跟随。`?spawn=legacy` 可回到原出生方式。已有地图存档和特殊 `?tour=` 模式可能改变目标可达性，主线优先在完整默认世界验收。

### Godot 验收顺序

WASD 行走，Shift 加速，Space 跳跃，鼠标右键拖动转向，滚轮缩放，R 交互，1/2 使用能力，M 静音。沿浅色石路走完六个目标，观察球面上下方向、落地、建筑阻挡和相机避障。完成后仍可探索。

Godot 当前是半径 32 的紧凑关卡，用于把物理、模型、WFC 数据和剧情串起来；Web 星球半径仍是 160。Godot 尚未迁移原 Web 的全部城堡、地图编辑器、载具系统和动物 AI，原生版章节目前不跨运行保存。不要把它理解为完整世界已经一键转换。

## 2. 本轮改动及其原因

| 问题 | 实现 |
|---|---|
| 山坡视觉与碰撞不一致 | 原先使用解析高度，轨道切削只修改了显示网格；现在直接采样最终三角网格，碰撞追随切削后的形状 |
| 障碍推挤改变球面半径 | 在切平面推离障碍后恢复径向高度，并排除对跖点误碰撞 |
| 低帧率下移动跨越过大 | 单帧运动拆成最大 1/120 秒的物理子步 |
| 长按空格连续跳、窗口失焦后卡键 | 跳跃使用按下边沿；失焦、隐藏和进入输入框时释放按键 |
| NPC 提示在球体另一侧方向错误 | 提示沿当前位置径向上方抬升 |
| 花丛绘制提交过多 | 静态绣球花按现有材质合并，保留几何、颜色与轮廓 |
| 每帧遍历整棵场景树找更新对象 | 缓存目标节点，场景变化或定期检查时刷新 |
| 主线与四封送信任务脱节 | 新增独立六章救援状态机，复用真实地点与原有动物 |
| 行走缺少反馈 | 复用 Web Audio 上下文，按行走距离合成脚步；空中、载具和静音时不播放 |
| 缺少 DCC/原生工程流程 | Blender 源文件 → GLB / Web 顶点数据 → Godot；共享章节与现有 WFC 输出 |

Web 的照明体系和大部分美术风格沿用现有工程。Godot 配置了方向光、环境填充、阴影和雾，并用实机截图调整曝光。当前新模型是低面数基础资产，后续可以在同一源文件里精修。

## 3. Blender：如何修改一个模型

包内有 house、bookshop、tower、gate、pine、fox、tiger、aircraft、messenger、postbox 共 10 个模型。源文件按展示网格摆放；导出时自动把选定模型移回局部原点。拱门中间是真实空洞，飞机机翼使用有厚度网格。

1. 打开 `art/TigerMessenger-kit.blend`，在 Outliner 选中例如 **house**。
2. Tab 进入编辑模式修改顶点；保留对象名称。调色通过 Principled BSDF 的 Base Color。
3. 保存 .blend。当前输出定位为静态、平面着色、基础材质模型，不包含骨骼动画或完整贴图烘焙。
4. 在 TigerMessenger 目录执行：

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background art/TigerMessenger-kit.blend --python tools/export_asset.py -- house
node tools/export_godot_data.mjs
```

第一个命令同时更新 `assets/kit/house.glb` 和 `assets/kit/meshes.json`；第二个同步 GLB、剧情和 WFC 数据到 Godot。刷新浏览器或重新运行 Godot 即可检查。Web 当前实际接入的是任务邮筒；其他模型供原生关卡使用，尚未批量替换已有 Web 城镇。

`tools/build_assets.py` 用来从程序重新生成整个资产包，会覆盖生成目标，包括 .blend。手工精修后请使用 `export_asset.py` 导出单个模型，避免重新生成抹掉修改。

坐标约定：Blender 米制 Z 向上，导出使用 glTF / Web 的 Y 向上。根节点原点放在地面接触处。外观网格与碰撞形状分开设计：房屋用简单盒体，门用两根立柱，地形使用同一份三角网格。角色、移动载具不要直接用复杂凹面网格作动态碰撞体。

## 4. Godot：从哪几处学习

- `godot/scripts/player.gd`：CharacterBody3D、球心重力、切平面行走、跳跃、SpringArm3D 镜头避障。
- `godot/scripts/world.gd`：球面地形、网格碰撞、资产摆放、剧情交互、音效、机队与随行角色。
- `godot/data/chapters.json`：从 Web 纯数据状态机导出的六章文本。
- `godot/data/town.json`：已有 WFC 求解器生成的城镇结构。
- `godot/project.godot`：主场景、Compatibility 渲染及窗口设置。

球面角色的上方是 `position.normalized()`，重力与之相反。移动方向需要投影到这个法线的切平面。地形碰撞由实际显示网格生成，修改高程时同时重建网格和碰撞，不能只改其中一份。

目前 world.gd 把关卡组装放在一个脚本里，便于观察流程。扩大原生世界前，适合先拆成 PlanetTerrain、Campaign、Settlement、Fleet 四类场景，再逐个迁移现有区域，并为每一区域保留可通行路线的测试。

## 5. WFC 的位置与边界

保留原有 `solveTownSelection` 和城镇版本锁定逻辑，默认 custom 世界没有被替换。Godot 的导出过程调用同一个实际求解器，以 seed 20260906 生成 20 个占用单元，hash 为 cce72379，并将结果映射为原生房屋和塔楼。它共享生成数据，但尚未完整移植 Web 的所有模块拼接外观。

WFC 负责相邻模块约束和组合；它本身不会保证任务点间存在行走路径。本轮原生关卡使用明确的连续主路并让建筑避开主路。进一步接近 Townscaper，需要加入门窗、檐口、支撑、屋顶与海岸模块，再让连接规则约束组合；仅随机摆房子不足以得到那种结果。

参考：[WFC 原始项目](https://github.com/mxgmn/WaveFunctionCollapse)；球面 Web 体验参考：[Abeto Messenger](https://messenger.abeto.co/)。本工程使用自己的模型与实现。

## 7. 后续验收应关注的限制

- 原 Web 仍包含多套历史地形、平台与建筑碰撞；本轮修复山坡采样、径向推挤等明确问题，未证明所有场景都不存在穿模。
- Web 救援动物步行时记录玩家走过的路线，并通过地形与资产碰撞，减少转角抄近路穿墙；它们不会自行规划全局绕行路径，碰到封闭通道可能停住。载具随行仍是位置插值，Godot 随行也尚未加入这一套路线处理。
- 两个英雄目前通过剧情和暂停吸食能力表达，尚未实现完整战斗 AI、演出和死亡/失败条件。战争在本轮是救援机制的一部分，不是完整战役模拟。
- 剧情中灯谜目前按 R 完成，不是自由输入的答案识别关卡。主线无严格失败倒计时。
- 原生版尚无完整存档、触屏操作与 Web 导出预设。现有 Web 保持浏览器发布路径，本轮没有发布或替换线上版本。
- 现有大世界材质、地标造型与音乐仍需要逐区域审美验收。最有效的下一步是记录具体位置、镜头和期望，再对应改碰撞、模型或光照。

建议先完整体验原生路线，再在 Web 检查最喜欢的书店、古堡和苔庭。前者展示可控的工程闭环，后者保留你已有的世界厚度；两者通过同一资产和剧情数据持续靠拢。

## 第二轮：随行与开场镜头

Web 步行随行改为沿玩家轨迹前进，狐狸与虎保留不同跟随间距。每步最大 1/120 秒，使用现有地形、平台和资产碰撞，不再因为距离超过 25 米就把步行中的动物传送到玩家身后。封闭通道应阻挡随行，不能靠穿墙追上。新增 `tools/test_escort.mjs` 验证绕建筑转角、步长上限和阻挡后的不传送行为。

书店默认开场镜头距离由 7.5 调到 14，给建筑与路线留出画面空间；已调整过的相机参数和旧出生模式保持原有设置。开场提示直接引导 R 家书主线。
