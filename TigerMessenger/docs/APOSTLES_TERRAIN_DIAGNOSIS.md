# 十二门徒地形诊断：为什么不柔和，应该怎么补

2026-11-15。针对用户截图（十二门徒岩体上建了 Townscaper 式建筑后，下方地形是硬边台阶和条纹崖壁，与原片里柔和边缘的地形不一致）。本文是代码与同机位对照得出的诊断和补全顺序，不是已完成的修复。能力网上的实时诊断在学习工坊「能力成长与闭环 → 能力网 → 场景：十二门徒」。

## 结论

1. **十二门徒跑的是一份分叉的旧能力库。** `src/world/apostlesReacode.js`、`apostlesTerrain.js` 一共 import 18 个库模块，全部来自 `src/vendor/townscaper-rea-refactoring`，其中 17 个与最新 `REACodeRefactoring` 字节不同（副本日期 2026-10-31 起）。地形相关的 `terrain/shape.js`（11.6K → 库 20.8K）、`terrain/generate.js`（7.2K → 19.6K）、`terrain/terrainmesh.js`（9.1K → 22.1K）差距最大。
2. **但把旧副本直接换成最新库并不能让它变柔和。** 同机位对照：换成最新库后崖壁折面反而更硬（库里后来加了硬边钉点，来源 1670720537662836736），崖顶多出橙色灌木带。再打开库里的「缓坡省 + 连续软坡顶面」（`terrain/soft-tops.js`，来源 1447488323845509121），台地顶面几乎没有变化，还出现一处半透明破面。
3. **不柔和的主因在高度场。** `apostlesTerrain.js` 第 2 步把高度量化成偶数层（「so cliffs are vertical」），第 4 步只去尖刺；认可的构图（`twelveApostlesTarget.js` 的叶片层级）给每块岩体一个近乎水平的顶。结果是平顶台地 + 2 层起跳的竖直崖。软坡顶面只会融掉 1 层的台阶，在这样的高度场上没有可融的地方。
4. **这条能力线在库里也没学到位。** 地形线六代里，代码完成的只到 A（2016）。与柔和地形直接相关的三代都是部分实现：
   - A+++ 2021「软坡与陡崖无缝结合」（1447488323845509121，队列 #20）：现有 XZ 层级形变不等于连续坡面 / 排水，原软坡与侵蚀实现待补。
   - A+4 2022–2023「笼形变、硬边 / 分级平滑」（1579478470098243584、1670720537662836736、1670725072540106755）：模块 / 材质三角网的硬边语义缺失，无 / 普通 / 分层三档对照未完成。
   - A+5 2024「河流先行、其余广度优先坍缩成缓坡」（1769691526924292506，队列 #26）：库里有 `relaxRiverSlopes`，完整球面联合坍缩缺失。
5. **配色**：十二门徒用自己的石灰岩主题色（`APOSTLE_TERRAIN`，草 `#9fbf55`）覆盖库的地形色（草 `#86a160`、岩 `#a7a49d`），再叠蓝灰 / 珊瑚色带。建筑用的是库的 `PALETTES.town`。两套色系来源不同，这是和 Townscaper 观感不一致的直接原因；改用库地形色的候选本轮渲染为空白，没有得到可比的画面。

## 应该怎么补（按顺序）

1. **先在库里把软坡做对，再谈场景。** 目标是地形 A+++：在 `REACodeRefactoring` 的演示岛上，缓坡省出现连续坡面、陡崖省保持竖直崖、两者之间没有直线拼缝，并修掉软坡顶面的破面。完成门槛：同一种子下 无 / 软坡 两档同机位截图有可见差别，`terrainmesh` 的封闭性检查通过。这是补学队列 #20。
2. **给十二门徒一个能出缓坡的高度场候选。** 在认可的占地和轨道净空不变的前提下，让顶面高度在缓坡省里按 1 层渐变（现在是整块平顶），陡崖省和海蚀基座保持不变。这会改变岩体顶面的轮廓，需要用户看过候选再决定，不能直接替换。
3. **硬边只留在该硬的地方。** 用库 A+4 的硬边钉点，把钉点限制在崖脚、建筑贴合边和海岸线，台地边缘交给分级平滑。需要先补完库里「无 / 普通 / 分层」三档对照（队列 #23、#24）。
4. **配色单独处理。** 做一个只换地形色的候选（库地形色或向 `PALETTES.town` 靠拢的石灰岩色），与现状同机位对照；先查清本轮空白画面的原因。
5. **最后才是同步其余旧副本**（烘焙、植被、岸线等 14 个模块），每换一个做一次同机位对照。

## 代码里留下了什么

- `src/world/apostlesLook.js`：实验开关，默认关闭。`?apostlesLook=latest` 整套换最新库，`?apostlesLook=soft` 再加缓坡省与软坡顶面（工坊 iframe 用 `localStorage['tm.apostles.look.v1']`）。两者目前都不是可采用的改进，只为后续继续对照。
- `apostlesReacode.js` / `apostlesTerrain.js`：import 改成可切换来源；不带开关时行为与原来一致（对照里的 `approved.png` 即改动后的默认路径）。
- `tests/apostles-look-browser.mjs`：同机位对照脚本。

## 边界

- 没有修改认可的岩体构图、轨道净空、用户存档或默认画面。
- 对照只看了一块岩体的一个机位；「最新库更硬」「软坡无变化」是这个机位下的观察。
- 第 3、5 条结论里「高度场是主因」「色系来源不同」来自读代码，没有做去掉偶数层量化的单独对照。
