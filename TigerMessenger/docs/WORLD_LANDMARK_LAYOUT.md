## 1 · 坐标系（先读这段，否则下面的数字会看反）

`sphereMath.js` 的换算：

```js
flatXZToLatLon(x, z, R):
  theta = hypot(x, z) / R
  lat   = 90 - deg(theta)      // ← 平面原点 = 北极
  lon   = deg(atan2(z, x))
```

**平面地块的原点就是北极。** 主岛足迹 `ISLAND_FLAT_R = 18 × WORLD_SCALE = 72`，
`R = 160` → 张角 `72/160 = 0.45 rad = 25.8°`，即主岛覆盖 **lat 64.2° … 90°**。

推论（这条最容易踩）：**camp / bookshop / moon 不是全球坐标**，
是北极那块地皮上的局部点。而 `groundLiftAt(x, z)` 在 `ISLAND_FLAT_R` 之外
返回 ~0 —— 单独把它们挪到别的经纬度会**掉到海平面**，地形不跟着走。

## 4 · 三类地标：平移的含义不同

这是布局能不能落地的关键，改任何位置前先看这张表。

### ① 自由锚点 —— 改一个常量即可球面平移

| 地标 | 改哪里 |
| --- | --- |
| 高山圣城 citadel | `buildOdysseyCitadel({ dir })` 的 `dir` |
| 西芳寺 saihoji | `SAIHOJI_HUB`（六景 lat/lon 需同步平移，它们是绝对坐标） |
| 峡谷 canyon | `CANYON.lat` —— **但 `lon` 不能动**，见 ③ |

### ② 派生锚点 —— 不能独立平移，会跟着别人走

| 地标 | 跟着谁 | 机制 |
| --- | --- | --- |
| 旧港 harbor | **高山圣城** | `loadCitadel.js` 的 `snapOldHarborToSeaCove()` 按圣城局部地形重新落位。移圣城 → 港口自动跟随；单独移港口会被这个函数拽回去 |
| 叹息之门 gate | **峡谷** | `findGateSeatU(tramCurve)` 沿轨道找入谷点。移峡谷 → 门自动跟随 |
| 白鲸海水湖 lake | 城（默认） | `citySeaLake.relocate(dir)` 可单独搬 |

### ③ 被锁住的耦合

```js
GRAND_CRYSTAL = { lat: -24, lon: CANYON.lon }   // 城的经度 = 峡谷的经度
```

主人要求**城不动** → **`CANYON.lon` 必须保持 −112**。只有 `CANYON.lat` 可动。

### ④ 平面地块局部坐标 —— 只能整块一起平移

`camp` / `bookshop` / `moon`（以及丘陵、池塘、电车轨道）都挂在北极那块地皮上。
方案二**不动它们**。

若将来要动，正确做法是**整块主岛连地形一起平移**：在 `sphereMath.js` 加一个
岛屿基准四元数，把 `flatXZToLatLon → dir` 的结果统一乘它 —— 单点改动，
所有 `placeObjectOnSphere` 的对象（含地标、丘陵、轨道）同步跟随。
逐个挪地标是错的，会把它们扔进海里。

## 6 · 与四级空间结构的关系

本文只管**位置**；分级与导航见 `WORLD_STRUCTURE_ARCHITECTURE.md`。
两者的交点是 `world/worldStructure.js` 的 `getDir()` —— 它惰性读取实体位置，
所以**本文任何位置调整都不需要改 worldStructure**，导航会自动跟随。

苔庭是 `kind: "mobile"`（骑在白鲸上，`setAnchorRadius` 升沉），
所以它的位置在运行时还会变；§2 表里的 lat 56 是**中枢锚点**，不是实时位置。
