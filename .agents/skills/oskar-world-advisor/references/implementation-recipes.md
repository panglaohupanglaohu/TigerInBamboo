# 从研究到可验证样区

这些是TigerMessenger工程设计，不是Oskar私有引擎说明。配合游戏/大会证据使用；当前请求若只要研究，不顺手替换主场景。

## 可重复输入与模块合同

保存seed、topologyVersion、moduleCatalogHash、constraintHash、surfaceRevision。宏观主峰/海崖或城堡轮廓由已认可设计决定；WFC只在剩余候选中求合法组合。

模块含共享边几何、局部朝向、高程、承托、材料语义、可种植多边形、通道端口和内部端口连通表。旋转/镜像同时作用于几何和语义。接口哈希用于筛选，最终还需比较几何误差；同色或同标签不是接缝证明。相同接口也不能随意去掉视觉上不同的变体。

## 拓扑、表现网格与形变

不规则四边形网格可复用项目irregularQuadGrid；玩法主网格和表现对偶网格分别保留。只挪方格顶点不叫改变拓扑。需要岩台时用横向可延伸的真实面状模块；纵向半径链不能声称完成横向山势。

形变前后检查共享边、反面、退化、最大位移和最窄通行宽度。软坡可松弛，硬崖/城基/铁路固定。双线性笼映射、Jacobian门槛是项目可选方案，不说作者使用同公式。

## 求解、导航与发布

复用有界传播/回溯求解器。区分solved、contradiction、budget_exhausted、cancelled；看未定单元数，不能只信第三方Run返回true。保持长铁路和港口上城路径的固定约束，避免指望局部邻接自动产生全局道路。

候选可达图可提前排除死路，最终仍验证模块内部端口连通、变形后真实宽度与列车扫掠净空。异步结果必须校验inputRevision；过期结果丢弃，合法候选通过后再事务替换旧场景。后台求解完成不等于主场景已经接入。

## 最小实证与反例

- 人工拼三根海柱+一个宽台，和相同模块的求解结果并排看；显示无云白模。
- 接口相配但模块内部堵路：必须拒绝。港口通路与铁路空域不能靠视觉看似通畅代替验证。
- 旋转90度后的坡道：检验出口和承托跟随旋转。
- 极小求解预算：返回未完成，不能强填随机柱并宣称成功。
- 快速连续编辑：旧任务晚到不得覆盖新地形。
- 地形revision变更：重新承托植物、更新云缓存；用局部坐标与世界坐标两套探针对照。

## 表现与逻辑的分离

Beyond镜像文字中的独立prop布置启发：门窗装饰和建筑体块分开；替换窗样式无需重做全部墙模块。stencil假窗是渲染效果，不是可通行实体门。切片AO与简化镜像倒影是独立性能/画面取舍；球面海湾不能直接做全局Y翻转。

Bad North开发者2017博客说明flow field邻近信息传播及任务流水线；不能因此说人物骨骼动作由WFC生成。战斗动作仍分别核验脚部接触、朝向、瞄准、运输承托和动作混合。

对应详证：docs/OSKAR_GAME_SYSTEMS_DEEP_STUDY.md、docs/OSKAR_CONFERENCE_DEEP_STUDY.md；12项大会课程含时间锚点、作者事实和项目练习之分。技能不假定课程练习已执行。

## 实施时填写的测量合同

每个样区从真实游戏配置记录：`units、actorCapsuleRadius/Height、vehicleSweptEnvelope、rootGapTolerance、edgeSeamTolerance、minPassageWidth、cloudSupportClearance、viewport、device、measurementSeconds`。前三项和交通宽度取现有角色/列车尺寸，不能从照片猜测；后续容差沿用已有通过的场景检查或在本轮试验中明确标为新选值。当前研究没有替用户指定统一数值。报告同时写实际最大误差、最小净空和样本范围；未填写/未测的字段不标为通过。
